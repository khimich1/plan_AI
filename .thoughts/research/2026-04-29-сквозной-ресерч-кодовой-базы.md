# Исследование: Сквозной ресерч кодовой базы

## Резюме
Исследованы точки входа и ключевые связи между `FastAPI`-приложением, `React SPA`, Telegram-ботом, сервисным слоем и legacy-модулями расчётов/БД. Backend поднимается через `app.main`, API v1 собирается отдельным роутером и использует cookie-сессию `app_session` для авторизации. Фронтенд использует `httpClient` с `credentials: "include"` и работает через draft-API коммерческого сценария. Бот запускается независимо, регистрирует набор aiogram-роутеров и использует те же сервисы и core-модули для сценариев КП и производства.

## Поток данных

- `React SPA (frontend/src/features/commercial-offer/*)` → `httpClient (frontend/src/shared/api/httpClient.ts)` → `FastAPI endpoint (app/api/v1/endpoints/commercial.py)` → `CommercialWorkflowService (app/services/commercial_workflow_service.py)` → `CommercialService (app/services/commercial_service.py)` → `viz_modules/procurement.py + core/kp_db.py` → `SQLite (plita.db/pb.db)` / generated files.
- `Web HTML (app/web/router.py)` → inline `fetch("/api/v1/*")` + form POST → `app/api/v1/endpoints/*` → `OffersService/ProductionService/CommercialWorkflowService` → `KpRepository/core.kp_db` → `HTML/redirect/file responses`.
- `Telegram (bot/handlers/commercial.py)` → `FSM (bot/states.py)` → `CommercialService/OptimizationService + core/viz_modules` → `core.kp_db.save_kp_to_db` → `SQLite` + Telegram document messages.
- `Script entry (run_bot.py)` → `bot/bot_main.py` → `Dispatcher + handlers` → те же сервисы и core-модули, что и backend-коммерция/производство.

## Архитектурные наблюдения
- FastAPI-приложение создаётся в `app/main.py` и переэкспортируется в `main.py`.
- API v1 подключён под `/api/v1`, web-router подключён без префикса.
- Авторизация реализована через cookie `app_session` + HMAC токен и role-based `Depends(require_roles(...))`.
- Коммерческий backend-сценарий построен вокруг черновика (`DraftStore`) и отдельного workflow-сервиса.
- Репозитории `app/repositories/*` используют `app/core/settings.py` для путей к SQLite и делегируют часть операций в `core/kp_db.py`.
- Telegram-бот запускается отдельным процессом и использует общие сервисы/legacy-модули для тех же предметных сценариев (КП/производство).
- Frontend построен по FSD-подобной структуре с отдельным shared http-клиентом и feature-level API/hooks/components.
