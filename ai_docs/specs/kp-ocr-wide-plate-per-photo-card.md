## Objective

**Проблема.** Карточка «Нестандартная ширина» одна на черновик, а списки — по фото. «Применить решения» на первом снимке ставит `wide_plates_resolved`. На втором снимке строки вроде `ПБ 56-15-8 20` и `ПБ 45-15-10 3` всё ещё в списке и подсвечены. Overlay считает их уже известными серверу, поэтому флаг остаётся истинным:

```ts
wide_plates_resolved:
  merged.length === 0 || (Boolean(draft.metadata.wide_plates_resolved) && !liveHasNewWide),
```

Карточка рисуется только при `wideLines.length > 0 && !wide_plates_resolved`. Подсветка в `buildPlateLineHighlightMap` на флаг не смотрит. Менеджер видит розовые строки и не видит «Подтвердить», «Заменить», «Исключить».

Тот же флаг после подтверждения нужен на том фото, где решение уже принято: широкая строка остаётся в списке нарочно, и карточку там открывать снова нельзя. Тест `keeps resolved flag after apply even if lines remain wide` фиксирует этот один список. На второй снимок он переносится ошибочно.

**Цель.** Переход на фото, где широкие марки ещё без решения, показывает карточку по строкам этого фото. Успешное применение на первом фото не меняет список второго и не прячет его карточку.

**Пользователь:** менеджер на шаге «Плиты», сверка нескольких фото.

**Успех:** на втором фото видна карточка «Нестандартная ширина» со строками шире 12 дм из списка этого снимка. Переключатели на месте. Список второго фото тот же, что до кнопки на первом.

### Сценарии

1. **Два фото, решение только на первом.** На первом широкая марка, «Заменить» или «Исключить» или «Подтвердить», «Применить решения» проходит. Переход на второе. В списке второго остаются его широкие марки, например `ПБ 56-15-8 20`. Карточка открыта, у каждой такой марки три переключателя, по умолчанию «Подтвердить». Список второго не подменён заменой первого.
2. **Одинаковая марка на двух фото.** На обоих есть `ПБ 56-15-8`. Решение на первом не закрывает карточку второго.
3. **Возврат на первое после успешного apply.** Заменённой и исключённой марки в списке первого нет, карточки по ней нет. Подтверждённая широкая марка в списке остаётся, карточка по ней на этом фото не открывается снова.
4. **Одно фото.** Поведение как сейчас: до apply карточка есть, после успешного apply по уже решённым строкам этого списка не открывается.
5. **«Готово, далее».** Пока второе фото не получило своё apply, а широкая марка в его списке есть, кнопка и переход к клиенту закрыты. Флаг черновика `wide_plates_resolved: true` их не открывает.
6. **Текст без фото.** Замена широкой плиты без очереди фото работает как сейчас.

## Code Style

Сейчас известная серверу широкая строка при уже истинном флаге гасит карточку на любом фото. Для второго снимка так нельзя.

```ts
wide_plates_resolved:
  merged.length === 0 || (Boolean(draft.metadata.wide_plates_resolved) && !liveHasNewWide),
```

На фото без своего apply широкие строки его списка остаются нерешёнными, даже если черновик уже `wide_plates_resolved: true` и ключ марки есть в `wide_plate_lines`. На фото с успешным apply подтверждённая широкая марка карточку не открывает: смысл теста `keeps resolved flag after apply even if lines remain wide` сохраняется для этого одного списка.

`widePlateMatchKey` не ослабляем. `ПБ 56-15-8 20` и `ПБ 56-15-8п 20` по-прежнему одна марка внутри одного списка. Совпадение марки между двумя фото не переносит решение.

## Testing Strategy

Уровень — unit. Браузер на фазе SPECIFY не требуется. Новый тест красный на текущем коде: второе фото с широкой строкой и черновик с `wide_plates_resolved: true` прячут карточку.

| Тест | Что доказывает |
|------|----------------|
| Новый, в `liveWidePlateLines.test.ts` или рядом с карточкой | Черновик уже resolved, в `wide_plate_lines` есть `ПБ 56-15-8 20`. Текст второго фото содержит эту строку, своего apply у фото не было. Карточка нужна, `wide_plates_resolved` для этого экрана ложно |
| Уже есть, сузить смыслом | `keeps resolved flag after apply even if lines remain wide` остаётся зелёным для одного списка после apply на нём |
| Новый | Успешный apply первого фото не подменяет `batchReviewText` второго |
| Новый, `PlateInputStep` или подсветка | Пока у второго фото нет своего apply, «Готово, далее» закрыта, хотя у исходного draft флаг resolved истинный |
| Регрессия | Одно фото: до apply карточка есть, после confirm широкая строка карточку не открывает |

Покрытие всего репозитория не поднимаем.

## Boundaries

- **Always:** карточка на фото, пока в его списке есть широкая марка без apply на этом фото; список другого фото не переписывать; «Готово, далее» и клиент закрыты, пока такое фото есть; прогнать команды из раздела Commands.
- **Ask first:** новый endpoint, смена `force_wide_resolved`, правка invalid width / unpriced, коммит.
- **Never:** прятать карточку второго фото флагом черновика; переносить «Подтвердить» первого фото на ту же марку второго; дописывать или снимать «п» до apply; выключать verify OCR; выдумывать пары при отказе zip; менять `tests/archived/`.
