> **Фаза SDD:** PLAN
> **Статус:** спека принята, план на ревью. Кода ещё нет.
> **Дата:** 2026-11-02
> **План:** [`ai_docs/develop/plans/2026-11-02-nomer-dogovora-pri-gotovom-fajle.md`](../develop/plans/2026-11-02-nomer-dogovora-pri-gotovom-fajle.md)
> **Идея:** [`ai_docs/ideas/nomer-dogovora-pri-gotovom-fajle.md`](../ideas/nomer-dogovora-pri-gotovom-fajle.md)
> **Заменяет в** [`spravochnik-kontragentov-s-dogovorom.md`](spravochnik-kontragentov-s-dogovorom.md) решения D5, D7, D9 и D10 в части выдачи следующего номера. Поиск клиента, «договор есть / нет», одна свободная карточка и «привязать №…» остаются.
> **Рядом, не это:** удаление строки `1032/11/26` из живой базы, сверка Excel, отправка оператору ЭДО, запись договора в 1С, дозаполнение старых карточек.

## Assumptions I'm Making

1. Пользователь — менеджер и админ. Отдельной роли юриста нет. Менеджер видит только активных клиентов.
2. Колонка `supply_contract.number` остаётся `NOT NULL UNIQUE`. Строки без номера нет. Новый договор и его номер появляются в одной вставке. Подтверждено 2026-11-02: неготовый бланк в базу не пишется.
3. Готовый бланк — то же правило, что `requisites_ready`: вид из списка, обязательные поля бланка непустые, дата есть. КПП для ООО и АО проверяется тем же правилом, что и сейчас при сохранении реквизитов.
4. Дата нового номера — календарная дата сервера в момент этой вставки. Месяц и две цифры года в номере берутся из неё. День месяца в номер не входит.
5. Старый номер вписывается как текст после `normalize_contract_number`. Дата берётся из номера через `contract_date_from_number`. Если месяц и год из номера не читаются, дата пустая, номер всё равно сохраняется.
6. Пустая карточка со старым номером по-прежнему действующий договор для счёта. Статус «нет» не значит «номера нет».
7. На клиента один действующий договор. Отмена номер не освобождает.
8. Черновик нового бланка до готового сохранения живёт только на экране. Закрытая страница его не восстанавливает: поля набирают снова, обычно повторным разбором файла. Отдельного хранилища файла у формы нет.
9. Удаление `1032/11/26` и сверка с Excel — ручной шаг на локальной базе до пользования. Этот код их не делает. Тесты живую `plita.db` не открывают.

→ Если что-то из этого неверно — править spec до плана и до кода.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| D1 | Кнопка без номера | `POST /directory/{id}/contract` без номера и без id карточки новый seq не считает и строку не создаёт |
| D2 | Старый номер | Тело `{ "number": "…" }` или `{ "contract_id": … }`. Счётчик не участвует |
| D3 | Чужой номер | Номер уже у другого клиента — отказ, база не меняется |
| D4 | Своего номера нет в базе | Вставка с вписанным текстом, именем и ИНН клиента, статус «нет», реквизиты пустые |
| D5 | Свободная карточка | `contract_id` этой карточки пишет `counterparty_id`. Номер карточки не меняется |
| D6 | Несколько карточек на ИНН | Список показывается. Сама программа ни одну не выбирает и третий номер не создаёт |
| D7 | Новый договор | Первое сохранение готового бланка вставляет строку и один раз берёт следующий seq. До этого строка не создаётся |
| D8 | Повтор бланка | Второй раз готовые реквизиты номер не меняют и вторую строку не пишут |
| D9 | Счёт | Штамп только у действующей строки с номером. Экранный черновик счёт не открывает |
| D10 | Дата номера | У нового — дата вставки. У вписанного — дата из номера, если она читается |
| D11 | Разбор файла | Поля бланка, без номера. До строки договора разбор строку не создаёт |
| D12 | Живая база | Код `1032/11/26` не удаляет и Excel не читает |

## Objective

Менеджер на КП или во вкладке «Контрагенты» либо привязывает уже существующий номер, либо вписывает номер из Excel или 1С, либо собирает новый договор. Следующий номер программа берёт только вместе с первым готовым бланком нового договора.

Успех: нажатие «в реестре договора нет» и «Завести» не создаёт `1033/11/26`. Вписанный `0882/09/25` привязывается и снимает блокировку счёта при пустых реквизитах. Готовый бланк нового клиента один раз получает следующий номер, и повторное сохранение его не сдвигает.

### Пользователь

Менеджер по продажам и администратор.

### Сценарии

1. **УНИСТРОЙ, номера в базе нет.** Кнопка не вставляет строку. Пока бланк не сохранён готовым, «Отправить в 1С» отвечает «Нет действующего договора поставки». После готового бланка появляется одна строка со следующим номером, `counterparty_id` клиента и датой этого дня.
2. **Одна свободная карточка.** «Привязать № …» пишет id клиента на неё. Новый seq не выдаётся. Пустые реквизиты счёт не держат.
3. **Несколько карточек одного ИНН.** На экране их номера и поле ввода. Без выбора и без текста новая строка не создаётся.
4. **Вписан номер, которого нет.** Создаётся карточка с этим текстом и датой из номера. Seq не растёт. Счёт этого клиента штампуется этим номером.
5. **Вписан номер другого клиента.** Отказ. Чужая строка и счётчик не меняются.
6. **Вписан номер этого клиента.** Возвращается та же строка. Второй строки нет.
7. **Повтор готового бланка.** Номер, дата в номере и id строки те же. Реквизиты обновляются.
8. **Неготовый бланк.** Обязательное поле пустое. Строки договора нет, seq не вырос, введённое остаётся на экране.
9. **Разбор файла до строки.** Поля попадают в форму. В `supply_contract` новой строки нет.
10. **Отмена.** Статус «отмена не будем работать» снимает договор с клиента. Номер остаётся занятым. Следующий готовый бланк получает seq больше этого номера.

## Code Style

Пустое действие номер не считает. Известный номер пишется как есть.

```python
def directory_contract(number: str | None, contract_id: int | None) -> str:
    if number is None and contract_id is None:
        raise ValueError("Укажите номер или карточку")
    return "link"
```

Имя функции в коде может быть другим. Смысл тот же: нет номера и нет карточки — нет вставки и нет seq.

Новый номер собирается только из seq и даты готового бланка: `format_contract_number(next_contract_seq(occupied), contract_date)`.

## Testing Strategy

pytest и vitest, временная база и моки. Живую `plita.db` тест не открывает.

- Пустой `POST .../contract` не создаёт строку и не меняет максимальный seq.
- Одна свободная карточка привязывается, её номер остаётся.
- Две карточки одного ИНН сами не выбираются. Выбранный `contract_id` привязывает одну.
- Вписанный новый номер сохраняется буквально, seq после `1031/10/26` остаётся 1031.
- Номер другого клиента возвращает отказ и не пишет строку.
- Повторный вписанный номер этого клиента возвращает ту же строку.
- Первый готовый бланк создаёт одну строку. Номер — следующий seq и месяц/год даты вставки.
- Второй готовый бланк того же клиента номер не меняет.
- Неготовое тело бланка не вставляет строку.
- Разбор файла без id строку не создаёт.
- Пустая карточка со старым номером снимает «Нет действующего договора поставки».
- Клиент без строки договор для счёта не имеет.
- Отмена не возвращает seq в выдачу.
- На КП выбор номера не закрывает ящик. «Завести» больше не вызывает выдачу seq.

## Boundaries

- Always: не выдавать seq без готового бланка нового договора; вписанный номер хранить как текст; не выбирать молча из нескольких карточек; не открывать живую базу из теста.
- Ask first: пустой `number` в схеме; хранить черновик бланка в базе; менять правило одного действующего договора на клиента.
- Never: удалять кодом строку `1032/11/26` или пачки 27, 29 и 30 октября; удалять клиента `4415`; читать Excel при запросе; отправлять договор оператору ЭДО; писать договор в 1С; коммитить `plita.db`.

## Success Criteria

| Требование | Критерий |
|---|---|
| Кнопка | Пустой вызов оставляет `supply_contract` и максимальный seq как были |
| Старый номер | Вписанный или выбранный номер стоит на клиенте. Seq не вырос. Счёт штампуется при пустых реквизитах |
| Чужой номер | Отказ. Чужой `counterparty_id` тот же |
| Несколько карточек | Без явного выбора новых строк нет |
| Новый договор | После готового бланка ровно одна новая строка. Номер — max+1 и дата этого дня |
| Повтор | Вторая запись реквизитов не меняет номер |
| Неготовый бланк | Строки нет |
| Разбор | Файл без сохранения строку не создаёт |
| Счёт | Без строки ответ «Нет действующего договора поставки» |
| Справочник | Число строк `counterparties` не меняется |
