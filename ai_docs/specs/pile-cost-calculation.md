## Assumptions I'm Making

1. **Норма зафиксирована снимком файла от 06.10.2026.** Объём, сечение и килограммы
   металла (и редкий щебень «Щ.5») лежат в данных приложения. Экономист их не
   редактирует и не перезаливает. Отдельной роли «обновить каркас» нет.
2. **Ключ нормы — `(mark, concrete_grade)`.** Объём у марки один на все классы.
   Металл у большинства марок тоже один, но в файле есть марки, где строки
   металла между классами различаются. Калькулятор не усредняет: у каждого
   класса свои килограммы из снимка.
3. **Сечение для надбавки 1,02 хранится в норме**, а не вычисляется из имени
   при каждом запросе. У обычной марки оно совпадает с числом после точки
   (`С30.20-3` → 20). Нестандартные имена («СГ 140.35», «свая-колонна»)
   получают сечение того блока листа «Прайс», где строка стояла.
4. **Инфляция 3%, коэффициент 1,2, НДС 1,22 и надбавка 1,02 — константы.**
   Экономист их не вводит. Четвёртая ручка — отдельное решение.
5. **Добавка по умолчанию — 0,6% от килограммов цемента** и поэтому едет
   за рецептом. В файле около 40 марок, где килограммы добавки вбиты числом,
   а не этой формулой. Для них в снимке лежит своё число, рецепт его не меняет.
6. **Щебень рецепта.** Классы В15, В20, В22,5 и В25 считаются по цене
   «щебень 20» (1,80). Класс «30 на граните» — по второй цене щебня (1,97).
   Колонка «Щ.5», где она заполнена и входит в формулу, тоже идёт по 1,97.
7. **Колонка «A III» оценивается ценой А500С того же диаметра**, кроме строк
   снимка, где формула файла явно ссылается на цену АIII. Снимок хранит код
   статьи цены, а не заголовок колонки.
8. **Дробные цены пишем как посчитано.** Округление до рубля не делаем.
   Сравнение с текущим прайсом: `abs(a - b) > 0.005` → цена изменилась
   (как на столе прайсов).
9. **Пропавшие марки не удаляем.** Ключ есть в `pile_prices`, нет в норме →
   в диффе `missing`, после записи старая цена остаётся.
10. **Черновик КП**, открытый в момент записи, при следующем превью может
    показать новые цены. В v1 цену в черновике не фиксируем.
11. **Живой xlsx в репозиторий не кладём.** В git — снимок нормы (килограммы,
    без коммерческой тайны сверх того, что уже в коде прайса) и золотые
    числа по двум маркам. Полная сверка с файлом — ручная приёмка.
12. **Web-only.** Новых pip/npm-зависимостей нет. Бот вне scope.
13. **Админ видит тот же экран**, что экономист. Менеджер — нет.

→ Если что-то из этого неверно — править spec до плана.

## Objective

Экономист меняет цену сырья, рецепт бетона и производственные расходы.
Программа пересчитывает цену цельной сваи для покупателя. После подтверждения
новые КП берут её из `pile_prices`. Файл Excel для этой группы больше не источник цены.

### User stories

| # | Как… | Я хочу… | Чтобы… |
|---|------|---------|--------|
| US-1 | экономист | увидеть цены, рецепт и расходы и поменять одно число | себестоимость и цена пересчитались сразу |
| US-2 | экономист | открыть марку и увидеть разложение | понять, какая строка сдвинулась |
| US-3 | экономист | подтвердить дифф | новые КП взяли эти пять цен по классам бетона |
| US-4 | экономист | уйти без подтверждения | прайс КП остался прежним |
| US-5 | менеджер | считать новое КП как раньше | не заходить в расчёт |
| US-6 | админ | открыть тот же экран | подменить экономиста, не получая его файл |

## Code Style

Константы и формула в одном модуле. Ручки приходят аргументами, норма — данными.
Ни Excel, ни SQLite внутри функции.

```python
ADDITIVE_OF_CEMENT = 0.006
INFLATION = 0.03
MARGIN = 1.2
VAT = 1.22
SECTION_SURCHARGE = 1.02
SURCHARGE_SECTIONS_CM = frozenset({30, 35, 40})

def buyer_price(
    *,
    section_cm: int,
    volume_m3: float,
    recipe: Recipe,          # кг/м³ цемента, песка, щебня
    lines: tuple[NormLine, ...],  # кг и код статьи; пусто — допустимо
    prices: PriceBook,       # руб/кг по коду статьи
    overhead: Overhead,      # четыре статьи, руб/м³
) -> PileCost:
    """Себестоимость и цена покупателя. Отрицательный объём или цена — ValueError."""
```

Порядок внутри функции, и только он:

1. `cement_kg = volume_m3 * recipe.cement_kg_m3` (песок и щебень так же).
2. `additive_kg` — число из снимка, если у марки оно вбито руками. Иначе
   `cement_kg * ADDITIVE_OF_CEMENT`.
3. Рубли материала = кг × цена своей статьи. Щебень рецепта: для
   `B30_granite` цена второй строки щебня, для остальных классов — «щебень 20».
   Металл и «Щ.5» берутся из `lines`, не из рецепта. Килограммы металла —
   те ячейки, которые формула листа «Стоимость» умножает на цену, даже если
   ссылка стоит на соседнюю строку: в прайсе уже эта цифра.
4. `overhead_rate = (general + payroll + forming + other) * (1 + INFLATION)`.
5. `cost = materials_rub + volume_m3 * overhead_rate`.
6. `buyer = cost * MARGIN * VAT`, и ещё `* SECTION_SURCHARGE`, если `section_cm` в `SURCHARGE_SECTIONS_CM`.

Стартовые ручки — числа файла 06.10.2026:

| Ручка | Старт |
|-------|------:|
| Цемент | 7.54 |
| Щебень 20 | 1.80 |
| Щебень (только «Щ.5») | 1.97 |
| Песок | 0.66 |
| Добавка | 59 |
| Общие производственные | 3186 |
| ФОТ | 3400 |
| Обслуживание формовки | 40 |

### Снимок нормы

Один JSON, один раз собранный из формул листа «Стоимость»: в строку попадает
только та ячейка расхода, которую формула умножает на цену. Соседние диаметры
«на вырост» в снимок не входят. Повторного чтения xlsx в рантайме нет.

Поля строки: `mark`, `concrete_grade`, `section_cm`, `volume_m3`,
`lines: [{article, kg}]`. `article` — стабильный код (`a500c_10`, `ai_10`,
`wire_5`, `crushed_5`, …). Цена этого кода — ручка. Килограммы — нет.

Марка в снимке хранится как в листе «Прайс», без переименования.
В `pile_prices` пишется тот же текст: ключ `(mark, concrete_grade)`.

### API

Только `admin` | `economist`. Остальные → 403.

```
GET   /api/v1/prices/pile-cost
PUT   /api/v1/prices/pile-cost
POST  /api/v1/prices/pile-cost/preview
POST  /api/v1/prices/pile-cost/apply
```

`GET` отдаёт ручки, отпечаток входов и по запросу марки — разложение пяти
классов. Полный список марок — краткий: имя, сечение, пять цен покупателя.
Тело всех ~1 500 разложений в список не кладём.

`PUT` сохраняет ручки и **не** пишет `pile_prices`. Цена ≤ 0 или рецепт < 0 → 422.
Ответ содержит новый `inputs_sha256`.

`preview` считает дифф текущих `pile_prices` и формулы при сохранённых ручках.
Не пишет. Ключ — `(mark, concrete_grade)`. Счётчики `changed` / `new` /
`missing` / `unchanged` и до 30 примеров на категорию, как у стола прайсов.
В ответе тот же `inputs_sha256`.

`apply` принимает `inputs_sha256`. Не совпал с сохранёнными ручками → 409
«расчёт изменился, посмотрите дифф ещё раз». Совпал → `INSERT OR REPLACE`
в `pile_prices` для ключей нормы. `missing` не удаляем. `price_list_date`
ставим датой записи (`YYYY-MM-DD`), `imported_at` — сейчас.

`POST /api/v1/prices/preview` и `apply` для файла с якорем `цельн` → 422
«цены цельных свай считаются на этом экране». Другие группы без изменений.

### UI

На `/prices`, над drop-zone, блок «Цельные сваи».

- Три группы полей: цены, рецепт по классу, четыре статьи расходов. Рядом
  константы только текстом: 3%, ×1,2, ×1,22, ×1,02 для сечений 30/35/40.
- Поиск марки. Карточка марки: пять классов, в каждом килограммы, рубли
  строк, себестоимость, цена покупателя.
- Пока посчитанные цены отличаются от `pile_prices`, видна плашка
  «не записано в прайс» и кнопка «Показать, что изменится».
- Дифф, затем «Отмена» / «Записать в прайс». «Записать» зовёт apply с
  `inputs_sha256` из превью.
- Drop-zone под блоком остаётся для остальных групп.

## Boundaries

**Always:**

- Считать функцией `buyer_price`, не копией листа
- Превью без записи, apply только с тем же `inputs_sha256`
- ACL на API, не только скрытие блока
- Ключ цены — существующие `GRADE_CODES`
- Тесты формулы до экрана

**Ask first:**

- Сделать 1,2 / 1,22 / 1,02 / 3% / 0,6% ручками
- Округление до рубля
- Удалять из `pile_prices` марки, которых нет в норме
- Разные ставки расходов по сечениям
- Повторная загрузка нормы из нового xlsx

**Never:**

- Редактировать килограммы арматуры и объём в UI или API
- Подключать движок формул Excel
- Писать коэффициенты 1,45–2 в цену
- Пересчитывать `unit_price` сохранённых КП
- Принимать файл «цельн» как источник `pile_prices`
- Считать этим модулем плиты, ФБС, ступени, мостовые, составные
- Класть живой xlsx и живую `pb.db` в git

## Проверено по файлу 06.10.2026

Формула выше, со щебнем гранита по 1,97 и с добавкой из ячейки, где она вбита
числом, повторяет лист «Прайс» на **1 575 из 1 580** цен (допуск 0,05 руб).

Марка `С130.35-13А**` в расчёт не входит и в `pile_prices` не пишется.
В книге у неё 600 кг арматуры Ø25, а на листе «Прайс» стоит цена соседней
С130.35-13А* (400 кг, 60 980,85 руб для В15): Excel в подстановке читает
звёздочку как «любые символы» и подставляет чужой металл. Эту марку
игнорируем. С130.35-13А* остаётся, её цена совпадает со своей строкой.
Остальные имена со звёздочкой (`С80.40-9 *` и соседние) считают свою строку.
