## ASSUMPTIONS I'M MAKING

1. На фронте нет XLSX-библиотеки. Для клиентской сборки добавляем **`exceljs`** (стили разделителя). Не SheetJS и не самописный ZIP.
2. Кнопка «Скачать шаблон» живёт только в `DeliveryScheduleEditor` — ей всегда доступны `plates` и текущий черновик `batches`. `GET /template` из этой кнопки больше не вызывается.
3. `GET /template` остаётся и переключается на **тот же двухполосный макет** от **сохранённого** графика. Иначе после закрытия модалки без сохранения менеджер снова получит полные 40 вместо остатка 30 — или, после сохранения, снова «чистый КП» без верхней полосы.
4. Заголовки полос — точные строки `Уже в поставках` и `Остаток`. Парсер их пропускает. Старые файлы без полос продолжают импортироваться.
5. Остаток позиции = `qty_КП − Σ(qty черновика по plate_id)`. Если остаток ≤ 0, строки остатка нет (превышение ловит уже существующая проверка перед «Сохранить»).
6. Верхняя полоса — по одной строке на каждый `batch.item` (не агрегат по марке). Одна марка в двух партиях = две строки сверху.
7. Даты в файле — строки `ДД.ММ.ГГГГ`, не Excel-serial: без сдвига часового пояса, тот же путь, что `parse_template`.
8. Импорт по-прежнему **заменяет** черновик. Плашки «в файле меньше, чем было» нет.
9. Порядок слева в «Позиции КП» не меняем. «Сверху» — только в XLSX.
10. Новых таблиц, полей API и ролей нет. `POST /import` и `PUT` без смены контракта.

→ Поправьте сейчас, иначе дальше план и код идут из этих допущений.

## Objective

Менеджер разбивает КП на партии в Excel по шагам: в скачанном шаблоне исправляет 40 на 10, загружает, перепроверяет в веб-таблице, при необходимости снова качает шаблон — сверху уже попавшие в поставки строки, ниже только невошедший остаток.

Пользователь: менеджер / admin (как у графика поставки).

Успех: сценарий «10 из 40 → загрузка → второе скачивание → 30 в остатке» проходит без ручного копирования строк и без записи в БД до «Сохранить».

### User stories

- Как менеджер, я скачиваю шаблон выбранного КП и вижу марки и количества из этого КП, а не пустые заголовки.
- Как менеджер, я меняю 40 на 10, проставляю партию и даты, загружаю файл — справа появляются эти 10, слева «разбито 10 из 40 · остаток 30». В БД ещё ничего нет.
- Как менеджер, я могу загрузить тот же файл с правкой 10 → 12 ещё раз — черновик заменяется целиком.
- Как менеджер, я снова жму «Скачать шаблон» и вижу сверху строку партии (10 шт.), разделитель, ниже остаток 30 с пустыми датами.
- Как менеджер, я не хочу предупреждение, если в новом файле меньше позиций, чем было в черновике.

## Макет файла

Колонки без изменений: `Партия | Поставка с | Поставка по | Произвести до | Марка | Кол-во`.

Лист: `График поставки`.

```
1  заголовки колонок
2  Уже в поставках          ← строка-разделитель, merge A–F, фон
3… строки черновика         ← партия, ДД.ММ.ГГГГ × 3, марка, qty
k  Остаток                  ← строка-разделитель, merge A–F, фон
k+1… строки остатка         ← пустые партия/даты, марка, remaining
```

Правила полос:

- Полосу и её заголовок пишем только если в ней есть строки.
- Первое скачивание (черновик пуст) — только «Остаток» = все позиции КП с `qty > 0` и непустой маркой.
- Порядок сверху: партии в порядке черновика, внутри партии — порядок `items`.
- Порядок остатка: порядок позиций КП (как `kp_plates.id ASC` / как пришло в редактор).
- Позиция без марки пропускается в обеих полосах.
- Item без `plate_id` или с `qty < 1` в верхнюю полосу не попадает и в сумму остатка не входит.

Зарезервированные заголовки полос (точное сравнение после `strip`):

- `Уже в поставках`
- `Остаток`

## Поведение

### Скачать шаблон (редактор)

1. Собрать ряды из `plates` + текущих `batches` (чистая функция, без сети).
2. Собрать XLSX через exceljs, скачать как `delivery_schedule_template.xlsx`.
3. Не вызывать `GET .../template`.

### Скачать шаблон (нет открытого черновика)

`GET /commercial/archive/{kp_id}/delivery-schedule/template`:

- есть сохранённый график → верх = сохранённые партии, низ = остаток;
- графика нет → только остаток = плиты КП.

Тот же макет и те же заголовки полос, чтобы файл из архива и файл из модалки были взаимозаменяемы.

### Импорт

Без смены контракта `POST /import`. Парсер дополнительно пропускает строку, если **любая** из ячеек A–F после trim совпадает с заголовком полосы.

Пустые партия+даты (строки остатка, ещё не заполненные) по-прежнему пропускаются.

После импорта фронт как сейчас делает `setBatches(importBatchesToDrafts(...))` — полная замена. Без сравнения с предыдущим черновиком и без жёлтой плашки.

«Сохранить» — существующий PUT.

### Закрытие модалки

Черновик не персистится. Следующее скачивание без открытой модалки идёт от сохранённого графика (или от чистого КП). Это ожидаемо; отдельный баннер не делаем.

## Code Style

Чистая функция рядов — источник истины и для клиента, и (по смыслу) для сервера. Пример ожидаемого API:

```typescript
export const SECTION_IN_SCHEDULE = "Уже в поставках";
export const SECTION_REMAINDER = "Остаток";

export type TemplateRow =
  | { kind: "section"; title: typeof SECTION_IN_SCHEDULE | typeof SECTION_REMAINDER }
  | {
      kind: "item";
      batchName: string;
      deliverFrom: string; // ДД.ММ.ГГГГ или ""
      deliverTo: string;
      produceBy: string;
      plateName: string;
      qty: number;
    };

export function buildScheduleTemplateRows(
  plates: OfferPlateForSchedule[],
  batches: BatchDraft[],
): TemplateRow[]
```

ISO `YYYY-MM-DD` черновика → `ДД.ММ.ГГГГ` только в этой сборке. Парсер на бэке не меняет формат дат.

Сервер: те же два литерала заголовков, `build_template(path, plates=, batches=)` пишет полосы; `parse_template` скипает их до матчинга марки.

## Testing Strategy

**Клиент (vitest)**

- 40 в КП, черновик пуст → только секция «Остаток» и строка с 40.
- Черновик: 10 из 40 → секция «Уже в поставках» с 10, секция «Остаток» с 30.
- Две партии одной марки (10 + 15) → две верхние строки, остаток 15.
- Полностью разбито → только верхняя полоса, секции «Остаток» нет.
- Позиция без марки не попадает ни в одну полосу.
- Smoke: exceljs отдаёт ненулевой blob, лист называется «График поставки».

**Сервер (pytest)**

- `parse_template` пропускает заголовки полос, не кладёт их в `unmatched_rows`.
- Round-trip: двухполосный файл → те же партии, что в верхней полосе; строки остатка без дат не создают партии.
- `build_template(..., batches=)` пишет заголовки полос и остаток.
- Старый файл без полос (только марки+qty) по-прежнему парсится.

Перед завершением: команды из секции Commands — зелёные.

## Boundaries

- **Always:** минимальный diff; тесты из Commands зелёные; литералы заголовков полос совпадают на клиенте и сервере; даты в файле только `ДД.ММ.ГГГГ`.
- **Ask first:** другая XLSX-библиотека вместо exceljs; менять контракт `POST /import` / `PUT`; персист черновика при закрытии модалки; плашка при урезании импорта (сознательно выключена).
- **Never:** merge импорта с предыдущим черновиком; сортировать «Позиции КП» по признаку «утверждено»; блокировать верхние строки в Excel; трогать светофор, документ клиенту, схему БД; коммитить секреты и живые БД.

## Success Criteria

1. КП с позицией qty=40. Первое скачивание из редактора: в файле есть марка и 40, партий/дат нет. Сеть на `/template` не ходит.
2. В файле ставят партию «1», даты, кол-во 10, импортируют. Справа партия с 10, слева остаток 30. «Сохранить» не нажимали — в БД графика нет (или он пустой, как был).
3. Повторный импорт того же файла с 12 вместо 10 заменяет черновик на 12. Плашки нет.
4. Второе скачивание из той же открытой модалки: сверху строка с 12 и датами, затем «Остаток», затем строка с 30 и пустыми датами.
5. Импорт файла из п.4 без заполнения остатка даёт тот же черновик (одна партия 12). Заголовки полос не в `unmatched_rows`.
6. После «Сохранить» и закрытия модалки `GET /template` отдаёт ту же двухполосную картину (12 сверху, 30 снизу).
7. `pytest` по xlsx/service и `npm run test` / `typecheck` по delivery-schedule — зелёные.
