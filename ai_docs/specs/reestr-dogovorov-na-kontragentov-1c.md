## Assumptions I'm Making

1. Менеджер на шаге «Клиент» выбирает организацию из справочника 1С. Номер договора на этом шаге не ищется.
2. В отправку попадает номер только той строки `supply_contract`, у которой `counterparty_id` уже равен клиенту этого КП. Свободная карточка с тем же ИНН в момент отправки сама не привязывается.
3. Однозначная связь — ровно один активный клиент (`is_active` и `is_client`) и ровно один неотменённый договор с этим ИНН. Таких строк в сверке 217. Файл для них уже собран: `/home/roman/Загрузки/Реестр договоров для загрузки.xlsx`, лист «ИНН без сомнений».
4. 44 строки листа «Не вошли» в эту загрузку не входят. Диалога, где менеджер выбирает один номер из нескольких, эта спека не делает.
5. Локальная очистка `supply_contract` и `supply_contract_event` — ручной шаг на этой машине до импорта. Кнопки «удалить все договоры» в продукте нет.
6. Импорт по-прежнему пишет номер, имя, ИНН и дату из номера и оставляет `counterparty_id` пустым. Связь 217 строк — отдельный шаг после импорта.
7. Сравнение ИНН снимает пробелы. У ИП Раджабова в файле загрузки уже стоит `054801782091`.
8. Название договора и название 1С совпадением не считаются.
9. Живую `plita.db` тесты не открывают и не чистят.

→ Если что-то из этого неверно — править spec до плана и до кода.

## Objective

Менеджер выбирает клиента из справочника 1С и отправляет КП в 1С с уже существующим номером договора. Номер берётся из реестра по ИНН до отправки. Второй номер программа не заводит. Если номер однозначно не находится, отправка существующий номер не выдумывает.

Успех: у клиента из 217 в файле счёта стоит номер его договора из реестра. Запрос «ООО» на шаге «Клиент» показывает карточки справочника 1С, а не `0001/09/26` и `0006/09/26`. У клиента без договора в реестре на карточке архива написано «в реестре договора нет».

### Пользователь

Менеджер по продажам и администратор. Отдельной роли нет. Очистку и импорт делает администратор.

### Сценарии

1. **Один номер.** После загрузки и связи у ДСТрой 76 на договоре `0935/04/26` стоит `counterparty_id` его карточки 1С. Отправка КП этого клиента ставит в JSON `НомерДоговора` = `0935/04/26`. Номер `0001/09/26` в базе отсутствует.
2. **Хорс.** То же для `0934/04/26` вместо `0006/09/26`.
3. **Шаг «Клиент».** Ввод «ДСТрой» открывает строку справочника 1С: имя, ИНН, КПП. Номер договора в подсказке не пишется. Выбор кладёт на КП `counterparty_id`, имя, ИНН, КПП и код.
4. **Свободное имя.** Имя без выбора строки сохраняется. `counterparty_id` пустой. В архиве бейдж «нет 1С». В производство это имя само не пускает.
5. **Клиент 1С без договора в реестре.** На карточке архива виден текст «в реестре договора нет». «Отправить в 1С» отвечает «Нет действующего договора поставки». `counterparty_id` на чужую карточку не пишется.
6. **Несколько номеров одного ИНН.** Если такие строки всё же лежат в `supply_contract` без связи, отправка ни одну не выбирает и `counterparty_id` им не пишет.
7. **Производство.** Перевод в производство тоже не вызывает автосвязь. Без уже связанного действующего договора номер в документ не подставляется.
8. **Повторная отправка.** Уже записанный `counterparty_id` не сменяется на другой договор того же ИНН.

## Code Style

Связь ставится только при одном клиенте и одном договоре. Отправка чужой `counterparty_id` не переписывает.

```python
def link_id_for_single_contract(
    client_ids: list[int],
    contract_ids: list[int],
) -> int | None:
    if len(client_ids) != 1 or len(contract_ids) != 1:
        return None
    return client_ids[0]
```

## Testing Strategy

pytest и vitest, временная база и моки. Живую `plita.db` тест не открывает.

- Шаг «Клиент» вызывает поиск справочника и не вызывает поиск карточек. Выбор пишет id, имя, ИНН, КПП и код.
- Свободное имя оставляет `counterparty_id` пустым. Бейдж «нет 1С» виден.
- Один клиент и один договор с пустым `counterparty_id`: явный шаг связи пишет id. Отправка после этого ставит номер этого договора.
- Отправка и перевод в производство при пустом `counterparty_id` договора id не пишут, даже если ИНН совпал.
- Два договора одного ИНН: ни один не получает `counterparty_id` от отправки, в документ номер не попадает.
- Две карточки 1С на один ИНН: связь не пишется.
- Договор другого клиента не становится номером этого КП.
- На карточке архива при заполненном `counterparty_id` и без действующего договора виден текст «в реестре договора нет». Бейдж «нет 1С» при этом не показывается.
- Импорт листа по-прежнему не пишет `counterparty_id`.
- Число строк `counterparties` не меняется.

Старые тесты, которые ждут поздний номер в момент отправки, переписываются под D5. Удалять проверку отказа без договора нельзя.

## Boundaries

- Always: не создавать строки `counterparties`; не связывать договор по названию; не выбирать поздний номер при отправке; не затирать уже стоящий `counterparty_id`.
- Ask first: грузить лист «Не вошли»; делать экран выбора одного номера из нескольких; чистить `supply_contract` на базе, кроме этой локальной `plita.db`.
- Never: кнопка удаления всех договоров; подставлять номер договора с пустым или чужим `counterparty_id`; коммитить `plita.db` и файл из «Загрузок»; открывать живую базу из теста.
