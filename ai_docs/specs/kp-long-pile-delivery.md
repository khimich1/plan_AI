## Assumptions I'm Making

1. **Порог — длина из справочника, строго больше 13,0 м.** Длина берётся из `pile_catalog.length_m` после `resolve_catalog_for_mark`. `С130.*` = 13,0 м и остаётся в общем котле. `С138.*` = 13,8 м уже длинная. Ключ группы — `round(length_m × 10)`: 14,0 м → `140`, 13,8 м → `138`.
2. **Обычные и мостовые сваи в одном котле длин**, как сейчас в `PILE_TRIP_PRODUCT_TYPES` (`piles`, `bridge_piles`). `C14-40T4` резолвится в 14 м и получает тариф длины 14 м. Плиты, ФБС, ступени и марши не входят.
3. **Одна длина — один тариф, даже если сечение или нагрузка разные.** `С140.35` и `С140.40` делят тариф `140`. `-12` длину не меняет.
4. **Формула рейсов внутри длины та же, что сейчас у свай, но остатки не смешиваются с другими длинами.** Полные машины — `floor(qty / pcs_per_20t)` по марке. Остатки марок этой длины с нормой — `ceil(Σ кг / 19 800)`. Марки без нормы в полные и в остаток не входят.
5. **Нет нормы — вопрос по марке, не по длине.** У 16 м три марки без `pcs_per_20t`: `С160.30`, `С160.35`, `С160.40`. У каждой свой вопрос «сколько машин». Ответ живёт в уже существующем `pile_trip_overrides`. Пустое поле ≠ 0. Явный 0 — ответ «машин не нужно». Рейсы длины = полные + остаток + сумма N этих марок.
6. **Пустой тариф длины ≠ 0 ₽.** Пока цена рейса не введена, доставка длины 0 и в документы не попадает. Явный 0 — цена введена, сумма 0.
7. **Дырка одной длины не гасит остальные.** Нет тарифа или нет N хотя бы у одной марки длины — в ноль только эта длина. Короткие сваи и другие длины уже в сумме. Это отличается от нынешнего поведения, где один пустой ответ обнуляет всю доставку свай.
8. **Марка без длины остаётся в коротком котле.** Нет записи в каталоге и нет геометрии — pending короткого котла, как сейчас. Если геометрия длиннее 13 м, а нормы нет (`C18-40T8`), это длинная группа и вопрос про машины.
9. **Старые КП не пересчитываются.** Флаг `long_pile_delivery_enabled` в metadata, по образцу `fbs_lm_delivery_enabled`. Новый драфт со сваями ставит `True`. Без флага все сваи считаются одним котлом, как сейчас.
10. **НДС, скидка, плиты 18 600 кг, ФБС/ЛС/ЛМ и `pile_catalog` не меняются.** Прочерк у `С160.*` не заполняем. Вшитая доставка в цену изделия в этот spec не входит.

→ Поправьте до PLAN, если что-то неверно.

## Objective

Менеджер собирает КП на сваи или мостовые сваи. Сваи до 13,0 м включительно едут одним тарифом рейса, как сейчас. Каждая длина длиннее 13,0 м получает свой тариф рейса в этом КП. Число машин считается по заводской норме. Спрашивается оно только у марки без нормы. Пустая одна длина не обнуляет доставку остальных свай.

### User stories

| # | Как менеджер… | Я хочу… | Чтобы… |
|---|---------------|---------|--------|
| US-1 | в КП только сваи до 13 м | одно поле «стоимость рейса» | ничего не менялось |
| US-2 | есть сваи 14 м и 16 м | ввести свою цену рейса на каждую длину | 14 м и 16 м не стоили одинаково |
| US-3 | у длины есть «шт. на 20 т» | увидеть число рейсов без ручного ввода | не считать фуры в уме |
| US-4 | есть `С160.35-12` | чтобы спросили, сколько машин на эту марку | не выдумать норму вместо прочерка |
| US-5 | не ответил по одной длинной марке | чтобы остальные сваи уже были в сумме | не обнулять всё КП из-за 16 м |
| US-6 | открываю новое КП в архиве | те же тарифы, рейсы и строки | не пересчитывать в голове |
| US-7 | открываю КП, сохранённое до этой фичи | прежнюю сумму доставки свай | не объяснять заказчику, почему итог изменился |

### Reframed success criteria

Нормы из текущего `pile_catalog`: `С100.35` — 6 шт. на 20 т, 3 100 кг; `С150.35` — 4 шт., 4 650 кг; `С160.35` — вес 4 950 кг, нормы нет.

| Требование | Критерий |
|------------|----------|
| Порог | `С130.35` остаётся в коротком котле. `С140.35` и `С150.35` — нет |
| Короткий котёл | `С100.35` × 6 и тариф 1 000 ₽ → 1 рейс, 1 000 ₽. Килограммы и штуки 14 м+ в этот `floor` и в остаток 19 800 кг не входят |
| Своя длина с нормой | `С150.35` × 5, тариф 5 000 ₽ → полная 1 машина + остаток 4 650 кг = 2 рейса, сумма 10 000 ₽ |
| Две длины | 15 м тариф 5 000 и 16 м тариф 8 000 считаются раздельно |
| Одна длина, разное сечение | `С140.35` и `С140.40` делят один тариф. Остатки этих марок складываются до одного `ceil` на 19 800 кг. С 15 м не смешиваются |
| Нагрузка | `С140.35-12` попадает в группу 14,0 м, не в отдельную |
| Нет тарифа | Тариф 16 м пуст → сумма 16 м = 0, строки в PDF нет. Короткий котёл и 15 м в итоге есть |
| Нет нормы | `С160.35-12` × 4 без N → длина 16 м не готова, сумма 0. N=2 и тариф 7 000 → 14 000 ₽. Явный N=0 → марка закрыта, лишних рейсов нет |
| Явный тариф 0 | Длина готова, доставка 0, строки в документах нет |
| Мостовая | `C14-40T4` входит в группу 14,0 м |
| Флаг выкл | Тот же заказ без флага: все сваи, включая 16 м, в одном котле. Пустой N по `С160` обнуляет всю доставку свай, как сейчас |
| Регрессия | Плиты 18 600 кг и ФБС/ЛС/ЛМ без смены ожиданий. `pcs_per_20t` у трёх `С160.*` остаётся пустым |

## Code Style

Расчёт остаётся в `core/pile_trip_pricing.py`. Деньги с `round(..., 2)` в `calculate_total_cost`, как сейчас. Пустой тариф и пустое N в JSON не пишутся. Явный 0 пишется.

```python
LONG_PILE_LENGTH_M_MIN = 13.0  # строго больше

@dataclass(frozen=True)
class LongPileLengthQuote:
    length_key: int          # round(length_m * 10), 140 = 14,0 м
    trips: int
    trip_cost: float | None  # None = тариф не введён
    pending_marks: tuple[str, ...]
    amount: float            # 0, пока нет тарифа или есть pending

    @property
    def ready(self) -> bool:
        return self.trip_cost is not None and not self.pending_marks
```

Тарифы длин:

```json
{"140": {"trip_cost": 5000}, "160": {"trip_cost": 7000}}
```

Число машин по марке без нормы остаётся в `pile_trip_overrides`, ключ — марка строки (`С160.35-12`), как сейчас.

## Architecture

### Flow

```
флаг выкл
  → все сваи: pile_logistics_cost × рейсы нынешней формулы
  → один pending обнуляет всю доставку свай

флаг вкл
  → сваи length_m ≤ 13: тот же котёл, без длинных марок
  → сваи length_m > 13: группа на length_key
        марки с pcs: полные + остаток только этой длины / 19800
        марки без pcs: N из pile_trip_overrides, иначе pending
        нет trip_cost или есть pending → amount 0
        готова → amount = round(trip_cost × рейсы, 2)
  → доставка КП += сумма amount только готовых длин
```

Плиты и ФБС/ЛС/ЛМ в эти группы не входят.

### Формула одной длины

```
полные_i     = floor(qty_i / pcs_i)                 # только марки длины с pcs ≥ 1
остаток_кг   = Σ (qty_i % pcs_i) × weight_kg_i      # только эти марки
рейсы_остат  = 0 если остаток_кг = 0 иначе ceil(остаток_кг / 19800)
рейсы_ручные = Σ N_j                                # марки длины без нормы, N уже введён
рейсы        = полные + рейсы_остат + рейсы_ручные
```

Пока хотя бы одна марка длины без нормы не имеет N, рейсы в сумму не входят.

### UI «Итоги и скидка»

| Состав | Поля |
|--------|------|
| Нет свай длиннее 13 м | Как сейчас: «Стоимость рейса» / «Рейс свай» → `pile_logistics_cost` |
| Есть короткие и длинные | То же поле для коротких. Ниже тариф на каждую длину и число рейсов |
| Марка длины без нормы | «Для {марка} ({qty} шт.) нет нормы загрузки в справочнике. Сколько машин нужно?» |
| Тариф длины пуст | Длина в сумме как 0. Остальные сваи видны |

Длину показываем в метрах с запятой: ключ 140 → «14,0 м», ключ 138 → «13,8 м».

### Документы

`kp_delivery_export_lines` дополняется готовыми длинами с `amount > 0`.

| Строка | Подпись |
|--------|---------|
| Короткие сваи, и это единственная доставка в КП | «Услуга по доставке грузов» |
| Короткие сваи, и есть ещё хоть одна доставка | «Доставка свай» |
| Длинная длина | «Доставка свай 14,0 м» |

Неготовая длина строки не получает.

### Data model

```sql
ALTER TABLE kp_meta ADD COLUMN long_pile_delivery_enabled INTEGER DEFAULT 0;
ALTER TABLE kp_meta ADD COLUMN long_pile_delivery_json TEXT;
```

Черновик хранит флаг и тот же JSON в metadata. Архивный PATCH принимает JSON целиком и пересчитывает итоги так же, как сейчас пересчитывается тариф свай: цифры сразу, файлы по кнопке.

### API

Новые поля ответа `calculate_total_cost` при флаге. Без флага ключи пустые или нулевые, `pile_delivery_total` как сейчас.

| Поле | Смысл |
|------|--------|
| `pile_delivery_total` | Только короткие сваи, если флаг включён |
| `long_pile_delivery_total` | Сумма готовых длин |
| `long_pile_lengths` | Список: `length_key`, `trips`, `trip_cost`, `pending_marks`, `ready`, `amount`, `qty` |
| `long_pile_pending_marks` | Марки длин, по которым ещё нет N |

## Boundaries

- **Always:** считать длинные сваи отдельными группами только при флаге; 19 800 кг не подменять на 18 600; пустой тариф и пустое N не записывать как 0; прочерк `С160.*` не заполнять; pytest из Commands до коммита.
- **Ask first:** вшивать длинную доставку свай в цену изделия; менять грузоподъёмность остатка; один вопрос «машин» на всю длину вместо вопроса по марке.
- **Never:** общий тариф на все длины >13 м; цена доставки за штуку; тот же котёл для плит; правка `pcs_per_20t` в `pile_catalog`; код отгрузок; смешивать остатки 14 м и 16 м в одном `ceil`.

## Success Criteria

- [ ] Свая 13,0 м остаётся в коротком котле, 14,0 м — нет
- [ ] У 14 м и 16 м разные тарифы, суммы складываются, остатки не смешиваются
- [ ] `С140.35` и `С140.40` делят один тариф и один остаток
- [ ] Пустой тариф или пустое N одной длины обнуляет только её
- [ ] `С160.*` спрашивает машины; явный 0 и явный тариф 0 не спрашивают повторно
- [ ] PDF/XLSX: «Доставка свай 14,0 м» только у готовой длины с суммой > 0
- [ ] КП без флага считает сваи прежним одним котлом
- [ ] Плиты и ФБС/ЛС/ЛМ без изменения формул
- [ ] В `pile_catalog` у трёх `С160.*` по-прежнему пустой `pcs_per_20t`
