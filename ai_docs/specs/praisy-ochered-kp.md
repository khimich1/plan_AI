## Objective

**Проблема.** Экономист открывает «Прайсы», чтобы закрыть КП: карточки в 1С нет, она её завела, теперь нужен файл выгрузки. Сейчас на `/prices` сверху таблица «Сейчас в программе», расчёт цельных свай и загрузка прайса завода. Выгрузка 1С — в середине. «Завести в 1С», «Ввести цену» и «Дубли GUID» — внизу. Цены она трогает примерно раз в месяц, очередь должна закрываться в тот же день. Поднять блоки повыше недостаточно: ритуал «завела в 1С → загрузила файл» разорван по экрану.

**Цель.** Первый экран `/prices` — очередь «Ждут решения». Не-плиту она закрывает тем же окном `Import1cDialog`, с строки или тихим входом рядом со списком. Плиту, которая уже есть в таблице, закрывает замена, «Запомнить выбор» или правило 12→12,5. Экран не обещает, что файл погасит строку плиты: запись новой карточки в `prays_plity` — следующий срез D-plate-load. Цену не-плиты вводит по марке и GUID. Дыру матрицы `prices` у плиты на «Прайсах» по GUID не вводит. Себестоимость свай и файл прайса завода — два других входа, не равные вкладки и не один пункт «Обновить цены» на всё.

**Пользователь.** Экономист и admin на «Прайсы и 1С». Менеджер эту страницу не открывает. Дыру матрицы плиты он закрывает на шаге КП, не на «Прайсах».

**Успех.** Открыла «Прайсы» — видит очередь. Пустая очередь — «задач нет», ссылки «Себестоимость» и «Обновить цены» на месте. Колокольчик `kp_guid_missing` открывает её же. Не-плита с совпавшим именем и одним GUID после файла из списка уходит. Плита от этого файла не гаснет. «Ввести цену» без номера КП и без дыры матрицы плиты. «Себестоимость» открывает тот же ручной расчёт цельных свай. «Обновить цены» — только файл прайса завода и таблица «Сейчас в программе».

## Сейчас

Чтение кода, не запись.

- `PricesView` на `/prices`: «Сейчас в программе», `PileCostPanel`, «Загрузка прайса завода», «Выгрузка из 1С», затем `TasksSection` и `DuplicatesSection`.
- `hrefForNotification` для `kp_guid_missing` возвращает `/prices` без якоря (`frontend/src/features/notifications/api/notifications.ts`).
- Списки уже три: `GuidTasksResponse.to_create_1c`, `duplicates`, `to_price`. У `Create1cTaskOut` и `DuplicateTaskOut` есть `kp_ids`. У `PriceTaskOut` полей номера КП нет: `guid`, `product_kind`, `mark`, `name`.
- `POST /api/v1/nomenclature/import-1c` пишет `nomenclature_guid` для свай, мостовых свай, блоков (ФБС), маршей и ступеней. Плиты в эту таблицу не пишутся: группа плит отвечает «Плиты не загружаются в nomenclature_guid.» (`app/services/nomenclature_import_service.py`). `status=manual` без `overwrite_manual=True` не затирается. Прайс завода этот вызов не пишет.
- `.xls` «Прайс-лист» — полный файл. `.xlsx` универсальный отчёт частичный, когда над шапкой есть «Отбор» (`core/universal_report_1c_parser.py`). Файла «на одну марку» нет.
- `prays_plity` в коде только читается (`core/kp_db_nomenclature.py`). Записи из выгрузки 1С нет.
- Дубль плиты в очереди несёт GUID без цены 1С: на карточке «цена 1С —» (`frontend/src/features/price-desk/components/DuplicatesSection.tsx`). В счёт плиты идёт цена матрицы `prices` (длина × код нагрузки), не эта подпись.
- Дыра матрицы `prices` у плиты останавливает шаг КП текстом «Сначала примите решение по позициям без цены в прайсе.» Менеджер выбирает соседнюю нагрузку или «Исключить позицию». Это не список `to_price`.

## ASSUMPTIONS I'M MAKING

1. Адрес остаётся `/prices`. Новой страницы нет. Доступ тот же: admin и economist.
2. Очередь собирается из уже существующих трёх списков. Нового поля `kp_ids` у `PriceTaskOut` нет.
3. Кнопка на строке «Завести в 1С» и тихий вход — один уже существующий `Import1cDialog`. Подпись тихого входа остаётся «Загрузить выгрузку 1С».
4. Кнопка файла стоит на строке не-плиты в `to_create_1c` (и «нет карточки», и «есть особые»). На строке плиты, в «Ввести цену» и в дублях её нет. Тихий вход рядом со списком общий.
5. Точный фрагмент ссылки колокольчика (якорь или query) выбирается в плане. Голый `/prices` целью не остаётся.
6. Новых пакетов нет. `./run+logs.sh` не останавливать. Коммит только по просьбе.

## User Stories

- Как **экономист**, открываю «Прайсы» и сразу вижу очередь «Ждут решения».
- Как **экономист**, при пустой очереди вижу «задач нет» и ссылки «Себестоимость» и «Обновить цены».
- Как **экономист**, закрываю не-плиту файлом выгрузки: строка гаснет, когда имя совпало и GUID один.
- Как **экономист**, плиту, которая уже есть в таблице, закрываю заменой, «Запомнить выбор» или правилом 12→12,5. Файл эту строку не обещает закрыть.
- Как **экономист**, ввожу цену по марке и GUID, без номера КП. Дыру матрицы плиты и цену плиты по GUID здесь не ввожу.
- Как **экономист**, открываю себестоимость свай отдельным входом, тем же ручным расчётом.
- Как **экономист**, из колокольчика `kp_guid_missing` попадаю в очередь.
- Как **менеджер**, при номере плиты без ячейки матрицы `prices` вижу «Сначала примите решение по позициям без цены в прайсе» и выбираю соседнюю нагрузку или убираю позицию.

## Code Style

Один уже существующий диалог. Строка не-плиты не заводит второй загрузчик.

```ts
export function hrefForNotification(item: NotificationItem): string | null {
  if (item.kind === "kp_guid_missing") {
    return pricesQueueHref(); // открывается «Ждут решения», не голый "/prices"
  }
  // остальные виды — как сейчас
}
```

Кнопка строки и тихий вход вызывают один `setImport1cOpen(true)`. Подпись плиты не обещает, что файл её погасит. Пустой список — текст «задач нет»; ссылки «Себестоимость» и «Обновить цены» остаются.

## Testing Strategy

vitest на экран и колокольчик. pytest на импорт, списки и сверку — зелёные без смены правил.

- `/prices` первым показывает «Ждут решения», не таблицу «Сейчас в программе» и не расчёт свай.
- Пустой список показывает «задач нет». Ссылки «Себестоимость» и «Обновить цены» на экране. Ссылку цен не прятать.
- `kp_guid_missing` открывает эту очередь. Тест колокольчика, который ждёт голый `/prices`, обновляется под новый href.
- Строка не-плиты в `to_create_1c` и тихий вход открывают один `Import1cDialog`.
- У строки плиты в `to_create_1c` кнопки, которая обещает гашение от файла, нет. После успешного импорта строка плиты на месте.
- `to_create_1c`, `duplicates` и `to_price` на экране три блока. У «Ввести цену» нет номера КП. Дыра матрицы `prices` у плиты этим блоком не рисуется. Поля «ввести цену плиты по GUID» нет.
- «Себестоимость» открывает тот же ручной расчёт цельных свай.
- «Обновить цены» показывает файл прайса завода и «Сейчас в программе». Расчёта свай в этом входе нет.
- Импорт по-прежнему: имя совпало и GUID один — не-плита уходит из `to_create_1c`; два GUID — в `duplicates`; чуть другое имя строку не закрывает; `manual` не затирается; цены завода не пишутся; плиты в `nomenclature_guid` не пишутся.

## Boundaries

- **Всегда:** очередь — первый экран; пустая очередь — «задач нет» и обе ссылки, ссылку цен не прятать; три списка отдельно; плита без обещания «файл погасит строку»; колокольчик открывает очередь; окно импорта, дифф, расчёт свай, сверка, разбор и замена остаются прежними путями; тесты на фикстурах; `./run+logs.sh` не останавливать.
- **Сначала спроси:** другой адрес вместо `/prices`; перенос данных цельных свай; файл себестоимости; другие изделия внутри «Себестоимости».
- **Никогда:** живая связь с 1С; грузить себестоимость файлом; давать «Ввести цену» номер КП; три равные вкладки; менять разбор GUID и замену; сливать три списка в один ответ; переписывать окно импорта, дифф прайса и расчёт свай; дублировать сверку очереди с КП; заменять всю `prays_plity` файлом; класть плиты в `nomenclature_guid`; вводить цену плиты по GUID.
