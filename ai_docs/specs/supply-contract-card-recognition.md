## Assumptions I'm Making

1. Менеджер по-прежнему подтверждает форму глазами. Номер договора эта спека не выдаёт.
2. Неверная цифра ИНН, КПП, ОГРН, ОГРНИП, расчётного счёта, корсчёта или БИК в поле хуже пустого поля.
3. КПП не имеет контрольной суммы. Для него проверка — ровно 9 цифр.
4. Контроль расчётного счёта считается вместе с БИК. Нет БИК — счёт верной длины остаётся в поле и подсвечивается, счёт неверной длины очищается.
5. Корсчёт проверяется длиной 20. Отдельной контрольной суммы, завязанной на БИК покупателя, у него нет.
6. Word, Excel и PDF с текстом не вызывают GigaChat. Зрение — только фото и PDF без текстового слоя, провайдер тот же, что у КП (`OCR_PROVIDER`).
7. Повторный вызов модели — один, и только по цифровым полям, которые контроль не прошли. Поле, прошедшее контроль, повтор не меняет.
8. Несколько расчётных счетов показываются списком. В поле формы попадает выбранный менеджером.
9. Паспорт, коммерческое предложение и прочий файл без реквизитов не открывают пустую форму как успешный разбор.

→ Если что-то из этого неверно — править spec до плана.

## Objective

Менеджер загружает карточку покупателя в уже существующий экран договора и видит поля, которым можно верить. Цифра, которая не сходится с контролем, на экран не попадает.

Успех на корпусе папки: Word и PDF с текстом не вызывают GigaChat; фото «ДСТРОЙ 76» не кладёт в форму счёт из 18 цифр и корсчёт с неверной девяткой; ОГРН из шапки либо заполнен верно, либо поле пустое и подсвешено; при двух счетах менеджер выбирает один.

### Пользователь

Менеджер по продажам (`admin` / `manager`), карточка КП в архиве. Контрагент уже привязан. Подтверждение формы и номер договора остаются в спеке договора поставки.

### Сценарии

1. **Word или PDF с текстом.** Файл разбирается локально. Поля заполнены там, где подпись и значение нашлись. Сомнительное и пустое обязательное поле подсвешено. GigaChat не вызывается.
2. **Фото или скан.** Один вызов зрения. Цифры проходят тот же контроль, что и текстовый путь. Не сошлось — поле пустое, подсвешено, один повтор только по этим полям.
3. **Два банка.** Под формой список расчётных счетов. Пока менеджер не выбрал, в поле счёта пусто.
4. **Паспорт или КП.** Ответ «это не карточка контрагента». Поля формы не затираются угаданными значениями.
5. **ИНН и КПП в одной ячейке, банк отдельной строкой, глава КФХ, два подписанта.** Разбор берёт пару чисел по своим подписям, название банка без обязательного слова «банк», ФИО главы хозяйства, основание того человека, чьё ФИО попало в поле подписанта.
6. **Перетаскивание.** Менеджер бросает файл на экран договора. Разбор тот же, что у кнопки «Выберите файл»: Word, Excel, PDF, JPEG, PNG. Зона подсвечивается, пока файл над ней. Второй и следующие файлы одного броска не читаются.

## Чтение

Локальный разбор остаётся в `core/supply_contract_card_parse.py`. Он дополняется, а не заменяется промптом марок.

- Подпись и значение могут стоять на соседних строках и в соседних ячейках таблицы.
- Строка «ИНН / КПП» с двумя числами через слэш раскладывается на ИНН и КПП, а не кладёт ИНН в КПП.
- ОГРН и ОГРНИП читаются и из шапки «ИНН … КПП … ОГРН …», и из отдельной строки.
- Банк — строка с отделением или словом «банк», не только шаблон «Банк:».
- Подписант: директор, генеральный директор, индивидуальный предприниматель, глава КФХ. Если в файле и устав, и доверенность другого лица, основание берётся у того, чьё ФИО записано в поле подписанта.
- Расчётные счета собираются все. В одно поле молча не схлопываются.
- Excel читается в тот же текст, что Word.

Зрение остаётся на `complete_vision_json` выбранного `OCR_PROVIDER`. Промпт Extract говорит модели: шапка с ИНН, КПП и ОГРН обязательна, даже если ОГРН нет в таблице; счёт и корсчёт копируются по цифрам, повторы `0` и `7` не сжимаются; ячейка «БИК … в <банк>» делится на БИК и название банка. Слова «устав», «устава» и «доверенность» из ответа модели приводятся к `устав` или `доверенность` до формы. Род и вид принимаются только как пункты списка; чужое слово в эти поля не кладётся.

Контроль после обоих путей:

| Поле | Длина | Контроль |
|---|---|---|
| ИНН | 10 или 12 | контрольная сумма |
| КПП | 9 | только длина |
| ОГРН | 13 | контрольная сумма |
| ОГРНИП | 15 | контрольная сумма |
| БИК | 9 | контрольная сумма |
| Расчётный счёт | 20 | контрольный ключ вместе с БИК, если БИК уже принят |
| Корсчёт | 20 | только длина |

Не прошёл контроль — значение в `fields` не кладётся, имя поля попадает в `doubtful`. Несколько счетов отдаются отдельным списком `accounts`, выбранного значения в `fields.account` нет, пока менеджер не выбрал.

## Code Style

Контроль цифры живёт в одном месте и не знает, пришёл текст из Word или из модели.

```python
def accept_inn(raw: str) -> str | None:
    digits = normalize_digits(raw)
    if len(digits) not in (10, 12):
        return None
    if not inn_checksum_ok(digits):
        return None
    return digits
```

Пустой результат значит «в поле не класть». Сомнительность помечается списком имён полей, как сейчас.

## Testing Strategy

| Слой | Где | Что |
|---|---|---|
| Текст | `tests/test_supply_contract_card_parse.py` | ИНН/КПП через слэш не путаются; банк без слова «банк»; глава КФХ; два подписанта не переключают основание на доверенность; два счёта возвращаются списком, в поле счёта пусто |
| Контроль | там же | счёт из 18 цифр не попадает в fields; ИНН с неверной суммой пустой и в doubtful; корсчёт неверной длины пустой |
| Зрение | `tests/test_supply_contract_card_ocr.py` | при `OCR_PROVIDER=gigachat` PNG идёт в mock, OpenAI не вызывается; повтор вызывается только для поля с сорванным контролем и не меняет прошедший ИНН |
| Отказ | `tests/test_supply_contract_card_parse.py` | текст без ИНН, ОГРН, счёта и БИК — ошибка «это не карточка контрагента» |
| UI | `SupplyContractDrawer.test.tsx` | список счетов виден, выбор записывает один счёт в форму; drop файла вызывает тот же разбор, что кнопка |

Фикстуры — короткие строки и минимальный docx, не файлы покупателей из папки знаний.

## Boundaries

- **Always:** неверную цифру не класть в `fields`; Word и текстовый PDF не отправлять в GigaChat; тесты без живого API; ошибки по-русски.
- **Ask first:** новая зависимость для Excel; смена провайдера зрения по умолчанию; сохранение выбранного счёта отдельной колонкой в базе.
- **Never:** второй полный проход по всей карточке; затирать контрольно верное поле ответом повтора; коммитить карточки покупателей и сканы; подставлять первый счёт молча; выдавать номер договора на этом шаге.

## Success Criteria

- Разбор docx с текстовым слоем не вызывает `complete_vision_json`.
- ИНН с неверной контрольной суммой отсутствует в `fields` и присутствует в `doubtful`.
- Строка `407028105771000149` не становится расчётным счётом.
- Ответ разбора с двумя счетами содержит оба в `accounts` и пустой `fields.account` до выбора.
- Файл без реквизитов возвращает сообщение «это не карточка контрагента».
- Повтор зрения в тесте с mock не меняет ИНН, который уже прошёл контроль.
- Перетаскивание файла на экран договора запускает тот же разбор, что кнопка выбора.
