# Spec: «Занести контрагента» ищет карточки договоров

> **Статус:** SPECIFY. Код по этой спеке ещё не менялся.  
> **Дата:** 2026-10-27  
> **План:** [`ai_docs/develop/plans/2026-10-27-archive-bind-contract-cards.md`](../develop/plans/2026-10-27-archive-bind-contract-cards.md)  
> **Отменяет:** решение от 21 октября, что архивный поиск «Занести контрагента» остаётся на всём справочнике 1С. Мастер нового КП уже ищет карточки и здесь не переписывается.  
> **Не это:** переименование `imported_name`, проход по всей серверной базе, `EXCHANGE_EXPORT_DIR`, пустой GUID контрагента.

## Assumptions I'm Making

1. «Только контрагенты с договором» — это строки `supply_contract`, те же, что список карточек. Клиент из `counterparties` без карточки в окно не попадает. Отдельной базы нет: и справочник, и карточки лежат в одной `plita.db`.
2. Выбор карточки должен оставить на КП клиента 1С и на этой карточке его `counterparty_id`, чтобы «Отправить в 1С» нашло номер именно этой карточки.
3. Карточка без уже записанной связи всё равно показывается. Если её ИНН указывает ровно на одного активного клиента, занесение само записывает эту связь. Новый клиент в справочник из этого окна не создаётся.
4. Имя на КП после занесения — имя справочника, как уже делает текущая привязка. Имя на карточке эта задача не переписывает.
5. Неполный бланк в списке остаётся. Печать договора он по-прежнему запрещает, занесение и отправку в 1С — нет.

→ Если в списке нужно оставить только карточки, у которых связь уже стоит, и не связывать остальные по ИНН — это другое окно, в этой спеке его нет.

|---|------|---------|
| B1 | Список | `OfferDetailsDrawer` ищет `searchSource="contract-cards"`. `GET /counterparties/search` это окно больше не вызывает |
| B2 | Строка списка | Имя карточки и подпись `ИНН … · номер`. Неполная карточка дописывает `· не полные`. КПП справочника в подсказке нет |
| B3 | Короче двух символов | Пустой список. Все карточки разом не показывать |
| B4 | Занесение | Кнопка шлёт id выбранной карточки. Поля «Код 1С», «ИНН», «КПП» и создание клиента без карточки из окна убираются |
| B5 | Кто записывается на КП | Активный клиент с карточки, если связь живая. Иначе единственный активный клиент с тем же ИНН. Ноль или несколько таких клиентов — отказ, КП и карточка не меняются |
| B6 | Какая карточка связывается | Выбранная. Более поздний договор того же ИНН сам не подменяет её. Если у этого клиента уже есть другая действующая карточка, связь не переносится, КП всё равно получает этого клиента |
| B7 | Что пишется на КП | `counterparty_id`, `customer_name`, `customer_inn`, `customer_kpp` из справочника. Номер договора на КП не хранится |
| B8 | Старые маршруты | `PATCH /counterparty` по id справочника и `POST /counterparty` с кодом 1С остаются в API. Это окно их не вызывает |

## Objective

Менеджер в архиве открывает КП без клиента и в «Занести контрагента» видит только карточки договоров. После выбора карточки с однозначным клиентом бейдж «нет 1С» снимается, а отправка в 1С может взять номер этой карточки.

### Сценарии

1. **Гефест.** В списке по запросу «гефест» есть карточка `ООО "ПСК "ГЕФЕСТ"`, ИНН `7604304420`, номер `0808/03/25`. Справочной строки `ПСК ГЕФЕСТ ООО` отдельной строкой нет. Занесение пишет на КП клиента `2819` и на карточку тот же `counterparty_id`. Имя на КП становится `ПСК ГЕФЕСТ ООО`.
2. **Олимп без карточки.** Запрос «ОЛИМП» больше не показывает два `ОЛИМП ООО` из справочника. Карточка `СК ОЛИМП-СТРОЙ` видна, потому что в её имени есть «ОЛИМП».
3. **Два клиента на один ИНН.** Карточка в списке есть. Занесение отвечает отказом и не записывает ни КП, ни карточку.
4. **У клиента уже есть другая карточка.** Новая выбранная карточка остаётся без `counterparty_id`. КП получает уже связанного клиента. Номер в 1С остаётся номером уже связанной карточки.
5. **Мастер нового КП.** Его поиск карточек и сохранение без id не меняются.

## Code Style

Окно только выбирает карточку. Связь клиента и договора пишет сервис, не форма:

```tsx
<CounterpartyAutocomplete
  searchSource="contract-cards"
  selected={bindSelected}
  onSelect={setBindSelected}
  placeholder="Найдите карточку договора"
/>
```

Запрос уносит id карточки, не id справочника и не код 1С.

## Testing Strategy

Сначала pytest на временной базе: выбор карточки с живой связью, выбор карточки с пустой связью и одним ИНН, отказ при двух клиентах на ИНН, отказ переносить уже занятую связь. Потом маршрут. Потом vitest: окно больше не вызывает поиск справочника, в кнопке нет полей кода, ИНН и КПП, уходит id карточки.

Поиск `search_wizard_cards` заново не тестировать: его покрывает поиск мастера. Гейт GUID и каталог обмена не входят в эти тесты.

## Boundaries

- Always: список только из карточек; занесение не создаёт строку `counterparties`; выбранная карточка получает связь, только если у клиента ещё нет действующей; тесты на временной базе.
- Ask first: удалить `POST /counterparty`; менять мастер КП; переписывать `imported_name`; править серверную базу.
- Never: показывать клиента справочника без карточки; подменять выбранный договор более поздним; писать номер договора в `KP_offers`; ослаблять проверку GUID при отправке.

## Success Criteria

- В архиве запрос «ОЛИМП» не возвращает два `ОЛИМП ООО` без договора.
- Занесение карточки `0808/03/25` ставит на КП клиента с ИНН `7604304420` и тот же id на эту карточку.
- После этого подсказка «Сначала занесите контрагента» у этого КП пропадает.
- Поля кода, ИНН и КПП в блоке «Занести контрагента» не рисуются.
- Мастер нового КП и `GET /counterparties/search` для остальных экранов работают как раньше.
