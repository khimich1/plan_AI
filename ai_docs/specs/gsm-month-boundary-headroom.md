# Spec: ГСМ — последний день месяца видит первую заправку следующего

Дата: 2026-10-24. Статус: confirmed.
Идея: [`../ideas/gsm-month-boundary-headroom.md`](../ideas/gsm-month-boundary-headroom.md).
База: [`gsm-first-fill-headroom.md`](gsm-first-fill-headroom.md)
(запас и `q_next` — первая кластерная заправка, лист и коридор — сумма
дня), [`gsm-month-close-kit.md`](gsm-month-close-kit.md) (защёлка комплекта).

## ASSUMPTIONS I'M MAKING

1. **Один лист на водителя на день.** Километры внутри дня не делятся.
   Бак, нормы и `max_daily_km` не меняются. Жёлтый `balance_route`
   остаётся допустимым.
2. **Одинаковая метка времени — одно событие.** Литраж — алгебраическая
   сумма `qty_liters` строк с этим `ts`. События по возрастанию времени.
   Хелперы те же: `_fill_events`, `_first_fill_liters`.
3. **На листе и в коридоре — сумма дня.** `fuel_issued` путевого и
   `q_today` в `_fits_corridor` не переключаются на первую заправку.
   Запас и lookahead по-прежнему берут первую кластерную заправку, не
   сумму дня.
4. **Подсказка не якорь.** `generate()` получает первую заправку после
   периода отдельным аргументом. Транзакции следующего месяца в список
   якорей не дописываются, путевой на подсмотренную дату не создаётся.
5. **Живую SQLite это изменение не трогает.** Ни схемы, ни транзакций,
   ни уже выписанных листов. Август Palisade этим коммитом не
   пересобирается и руками не правится.

## Objective

Бухгалтер закрывает месяц. Последний топливный день внутри периода
должен оставить место под первую кластерную заправку строго после
`period_to`. Если место уже не сходится, комплект не собирается.

**Пользователь:** бухгалтер (`accountant`).

**Критерий успеха на числах Palisade** (это тест, не переписывание
продовых листов):

| | |
|---|---|
| Машина | Hyundai Palisade О 521 УХ 44, vehicle id 1 |
| Бак / летняя норма | 70 л / 14,5 л/100 км |
| Лист 2026-08-31 сейчас | старт 32,8 л, выдача 20 л, 12 км, конец 51,06 л |
| Следующие транзакции | 2026-09-01 09:40:57 +30 л и 09:41:44 +26,6 л |
| Цель конца 31.08 | ≤ 40 л (`бак − первая заправка 30`) |
| Хватает | около 88 км за день; свой маршрут id 23 — 45 км в одну сторону, 90 км за день |
| Сумма карты 01.09 | 56,6 л остаётся суммой того дня, не выдачей 31.08 |

С выключенным peek 31 августа заканчивается выше `бак − 30`. Со
включённым — не выше 40 л, `fuel_issued` этого дня по-прежнему 20 л,
путевого на 2026-09-01 нет. Сентябрь как часть августовского вызова не
генерируется. Нет более поздней заправки — поведение как сегодня.

## Code Style

```python
@dataclass(frozen=True, slots=True)
class BoundaryLookahead:
    """First clustered fill after the period. Not an anchor."""

    liters: float
    station_ids: tuple[int, ...] = ()
    period_from: date | None = None
    period_to: date | None = None
```

`generate(..., boundary_lookahead: BoundaryLookahead | None = None)`.
`None` или `liters <= 0` — сегодняшний путь. Подсказка подставляется в
`next_fuel` только последнему топливному дню, у которого нет более
поздней топливной заправки уже внутри загруженных якорей. Дата
подсказки в список свободных дней не попадает: `free_until_next` для
этого lookahead пустой, чтобы не отложить сжигание на дни, которые этот
вызов не выпишет.

Если день сам не дожигает `q_next` в пределах `max_daily_km`,
дополнительный burn-in идёт по свободным будням `>= period_from` и
`<= period_to`, строго раньше якоря, и только по тем, что ещё не заняты
обычным запасом под сегодняшнюю первую заправку. Дни после `period_to`
не выпускаются.

## Поведение

```
Q_next = первая кластерная заправка первого дня после period_to,
         у которого она > 0; иначе подсказки нет
последний топливный день периода:
    lookahead q_next = Q_next
    q_today и fuel_issued = сумма дня, как сейчас
    если круг ≤ max_daily_km доводит конец ≤ бак − Q_next — удлинить день
    иначе — свободные будни месяца до этого якоря
путевой на дату Q_next не создаётся

комплект (purpose=kit), не генерация:
    если Q_next есть и fuel_end_last > бак − Q_next —
        отказ «Пересчитайте {Месяц}: нет места под первую заправку следующего месяца»
    если Q_next нет — правило молчит
порядок причин комплекта, как раньше, затем защёлка:
    красные дни → хвост → разрыв цепочки → граница месяца
```

Код отказа: `gsm_kit_boundary`. Тот же текст в `planKit`, рядом с
красными днями и «Сначала выгрузите …». Генерация (`purpose=generate`)
этим кодом не блокируется.

## Данные

Это изменение **не мигрирует и не перегенерирует** продовые путевые и
не читает продовую `plita.db` в тестах. Починка уже выгруженного августа
Palisade — отдельный пересчёт генератором после выкладки, не часть
коммита и не правка строки 31.08.

## Testing Strategy

| Уровень | Что покрывает |
|---------|---------------|
| Unit, генератор | Цепочка как 31.08: бак 70, норма 14,5, старт 32,8, выдача 20. Без peek конец > 40 (около 51,06 на 12 км). С peek конец ≤ 40, маршрут 45 км в одну сторону, `fuel_issued` того же дня не меняется, даты 2026-09-01 в днях нет |
| Unit, генератор | Подсказки нет — тот же короткий день, что и без аргумента |
| Unit, генератор | День один не сжигает `q_next` при потолке библиотеки — свободный будень месяца до якоря; дней после якоря и в следующем месяце нет |
| Unit, защёлка | `evaluate_vehicle`: остаток 51,06, бак 70, первая заправка 01.09 = 30 (вторая строка 26,6 не входит) → комплект запрещён, генерация разрешена. Нет более поздней заправки → комплект этим правилом не режется |
| Service | `generate()` августа получает подсказку 30 л и не видит транзакций 01.09 в списке якорей |
| Регрессия | `tests/test_gsm_generator.py`, `tests/test_gsm_generation_service.py`, `tests/test_gsm_generation_api.py` без ослабления старых проверок |

## Boundaries

- **Always:** минимальный diff; сумма дня на листе; первая заправка
  только в запасе и в `q_next`; сервер отклоняет комплект сам; тесты не
  ослаблять.
- **Ask first:** смена бака, норм, `max_daily_km`, схемы БД.
- **Never:** не писать в продовую `plita.db`; не пересобирать август на
  сервере; не править выписанные листы руками; не резать сентябрьские
  заправки; не выпускать якоря и дни сжигания после `period_to` ради
  peek; не гасить жёлтый `balance_route`.

## Success Criteria

1. SC-1: без подсказки день с выдачей 20 л со старта 32,8 заканчивается
   выше `70 − 30`; с подсказкой 30 л — не выше 40 л.
2. SC-2: `fuel_issued` этого дня одинаковый с подсказкой и без неё и
   равен выдаче дня (20), не сумме карты следующего дня (56,6).
3. SC-3: в результате нет путевого на дату подсмотренной заправки.
4. SC-4: нет более поздней заправки — выбор дня совпадает с вызовом
   без нового аргумента.
5. SC-5: комплект с конечным остатком выше `бак − первая заправка`
   получает `gsm_kit_boundary` и текст про пересчёт месяца; без
   следующей заправки этот код не ставится. Генерация при том же
   остатке разрешена.
6. SC-6: регрессия генератора, сервиса и API генерации зелёная.
7. SC-7: коммит не содержит миграции и пересборки продовых данных.
