## Assumptions I'm Making

1. Проверка дубля срабатывает на форме «Новая карточка»: кнопка «Создать карточку» или файл в зоне этой формы. Импорт реестра и остальные вставки строки этот диалог не показывают.
2. Сейчас кнопка сразу вызывает `POST /api/v1/commercial/archive/contract-cards`. Файл идёт так: `POST /contract-cards/parse` (строку не пишет), затем сразу тот же `POST` создания. Имя из разбора — краткое, иначе полное, иначе имя файла без расширения. ИНН берётся из `fields.inn`, если после обрезки пробелов он непустой. Номер из файла не берётся, номер из поля формы при броске тоже не уходит. Успех открывает блок «Карточка договора»; у файла бланк заполнен разбором и в базу реквизитов не попадает, пока не нажмут «Сохранить реквизиты». Отказ разбора остаётся текстом на форме, создания нет.
3. Список «Занесённые карточки» — все строки `supply_contract` (`list_for_search`). Пустой поиск их и показывает. Фильтр от двух символов — подстрока без регистра по `imported_name`, `full_name`, `short_name`, ИНН и номеру. Это другой жест. Его эта спека не меняет и для дубля не использует: подстрока как раз принимает «5024» внутри длинного ИНН и «Строй» внутри «Строймонтаж».
4. `create_card` сегодня вставляет вторую строку с тем же ИНН и тем же именем. Так и должно остаться у импорта реестра и у кнопки «Всё равно создать»: один ИНН уже держит несколько карточек. Уникален только номер, ответ «Номер {number} уже есть». Запрет «молча не создавать» в `create_card` не переносится. Иначе сломается уже принятое правило нескольких договоров на один ИНН.
5. Расхождение с фразой «строка в базу не пишется»: прямой `POST /contract-cards` по-прежнему вставляет дубль. Молчание убирается на форме. Она не вызывает этот `POST`, пока поиск дубля пуст или не нажата «Всё равно создать». Принято: пункт 1.
6. Имя на карточке, которое видит менеджер, — `_card_display_name`: `imported_name`, иначе `full_name`, иначе `short_name`. В колонке «Имя» то же поле `name`. Дубль сравнивает введённое имя только с ним. Полное и краткое, если они другие, совпадением не считаются. Принято: пункт 2.
7. «Редактировать» открывает ту же панель, что клик по строке списка: блок «Карточка договора», без подстановки разобранного бланка. Файл на уже открытой карточке по-прежнему разбирается своим `POST /supply-contracts/{id}/parse` и в эту спеку не входит. Принято: пункт 3.
8. ИНН в строке хранится как ввели: `_optional_inn` только обрезает края. «5024 243403» может лежать с пробелом. Сравнение само вынимает цифры и хранимое значение не переписывает. Контрольная сумма ИНН для дубля не нужна. Если разбор положил ИНН в `fields.inn` и пометил `doubtful`, в проверку идёт эта же непустая строка, как сейчас в создание.
9. Пустое имя после свёртки пробелов не ищем. Пустой ИНН и строка без единой цифры не совпадают ни с кем, в том числе с карточкой без ИНН. Две пустоты совпадением не являются.
10. В сравнение имени не входят ё/е, кавычки и организационная форма. «Сёмка» и «Семка» — разные имена. `ООО «Ромашка»` и `ООО Ромашка` — тоже. Лишние пробелы — края и повторы любого пробельного символа. Пробел внутри слова остаётся: «ОООРомашка» не равно «ООО Ромашка».
11. В набор попадают все строки `supply_contract`, включая статус «отмена не будем работать», неполный бланк и уже лежащий договор. Отдельного фильтра списка нет.
12. JPEG и PNG зона формы уже принимает тем же путём, что Word, Excel и PDF. Проверка дубля стоит после любого успешного разбора на этой форме, не по расширению.
13. Закрытие диалога крестиком, Escape или щелчком по фону строку не создаёт. Введённые в форму имя, ИНН и номер остаются. Разобранный файл создаётся только кнопкой «Всё равно создать», пока диалог открыт. После закрытия этот разбор пропадает: чтобы завести карточку из файла, его бросают снова.
14. Гонка двух менеджеров не сериализуется. Уникального индекса на имя или ИНН нет и не появляется.

→ Если что-то из этого неверно — править spec до плана.

| # | Тема | Решение |
|---|------|---------|
| D1 | Где ищем | Только строки `supply_contract`, тот же набор, что список «Занесённые карточки». Справочник `counterparties` не читается |
| D2 | ИНН | Совпадение строк из цифр целиком. «5024» не равно «5024243403». Пробелы, дефисы и буквы вокруг цифр на равенство не влияют |
| D3 | Имя | Равенство без регистра и без лишних пробелов. Не подстрока. «Строй» не предлагает карточки, в имени которых это лишь кусок |

| D6 | Список | Несколько совпадений — список в том же диалоге. Менеджер выбирает, какую редактировать. Порядок — по `id`, как `list_for_search` |
| D7 | Всё равно | Кнопка «Всё равно создать» есть и при одной найденной карточке. Новая строка с формы появляется только после неё, либо сразу, если совпадений нет |

| D9 | Имя из файла | Одна строка, которой форма называет карточку сейчас: краткое, иначе полное, иначе имя файла без расширения. Второе имя из того же файла отдельно не ищется |

## Objective

Менеджер на форме «Новая карточка» не получает вторую карточку молча, если ИНН или имя уже есть у карточки договора. Программа показывает найденные и даёт открыть одну из них. Вторая фирма с тем же именем по-прежнему заводится, но только кнопкой «Всё равно создать».

Успех: при совпадении диалог есть, а строки в `supply_contract` нет, пока менеджер явно не создаст её или пока поиск дубля пуст. Справочник 1С, мастер КП и «Занести контрагента» ведут себя как до этой спеки.

### Пользователь

Менеджер по продажам и администратор. Роли те же, что у создания карточки: `admin` и `manager`. Новой роли нет.

### Сценарии

1. **Форма, то же имя.** В списке есть «ООО Ромашка», ИНН `7701000001`, номер `0001/10/26`. Менеджер вводит «ооо  ромашка» и другой ИНН, жмёт «Создать карточку». Диалог «Такая карточка уже есть» показывает это имя, ИНН и номер. `POST` создания не уходит.
2. **Редактировать.** В том же диалоге «Редактировать» закрывает диалог и открывает блок «Карточка договора» с номером `0001/10/26`. Новой строки нет.
3. **Всё равно создать.** Та же форма, та же кнопка. Уходит обычное создание с тем именем, ИНН и номером, которые менеджер ввёл. Открывается новая карточка, поля формы очищаются, как сейчас после успешного создания.
4. **Только ИНН.** Имя новое, ИНН по цифрам равен уже лежащему. Диалог со всеми карточками этого ИНН, даже если имена разные. «5024» при лежащем «5024243403» диалог не открывает и карточку создаёт.
5. **Несколько.** Три карточки с одним ИНН. Диалог — список из трёх. «Редактировать» у выбранной строки открывает её номер. «Всё равно создать» одна на весь диалог.
6. **Файл.** Бросок первого `.docx` / `.xlsx` / `.pdf` (и уже принимаемых JPEG, PNG) вызывает разбор. Совпало имя или ИНН из этого разбора — диалог, строки нет. «Всё равно создать» создаёт карточку без номера из файла и открывает её с заполненным бланком. Бланк в базу по-прежнему пишет только «Сохранить реквизиты».
7. **Совпадения нет.** Форма и файл создают карточку сразу, диалога нет. Тело создания то же, что сегодня.
8. **Мусор.** «это не карточка контрагента» — текст на форме. Поиска дубля нет, строки нет. Пустое имя с кнопки не отправляется. Разбор без имени показывает «Укажите имя контрагента» и тоже ничего не ищет.
9. **Закрыть.** Диалог закрыт без двух кнопок действия — строки нет. Повторная отправка снова спрашивает, если совпадение живо.
10. **Чужие места.** Поиск в «Занесённые карточки» по куску «секлюц» по-прежнему находит карточки подстрокой. Мастер КП и «Занести контрагента» не показывают этот диалог.

## Code Style

Ключи сравнения живут рядом с карточками, в сервисе. Пустой ключ не равен никакому другому, включая второй пустой. Регистр имени — тот же `casefold`, что у поиска списка.

```python
def duplicate_name_key(value: object) -> str:
    if not isinstance(value, str):
        return ""
    return " ".join(value.split()).casefold()


def duplicate_inn_key(value: object) -> str:
    if not isinstance(value, str):
        return ""
    return "".join(ch for ch in value if ch.isdigit())
```

«ООО  Ромашка» и «ооо ромашка» дают один ключ имени. «Строй» и «Строймонтаж» — разные. «5024 243403» и «5024243403» дают один ключ ИНН. «5024» и «5024243403» — разные.

Имя кандидата сравнивается с отображаемым именем карточки (принятый пункт 2). ИНН кандидата — с колонкой `inn` той же строки. Карточка попадает в ответ, если совпал хотя бы один непустой ключ.

## Данные

Кандидат с формы — то тело, которое сегодня собрал бы `buildCreatePayload`: имя с обрезанными краями, ИНН только если после обрезки непустой, номер если вписан. Поиск дубля номер не получает.

Кандидат с файла — то тело, которое сегодня собрал бы разбор: одно имя по D9, ИНН если он есть. Номера в нём нет.

Ответ поиска — те же поля карточки, что список: `name`, `inn`, `number`, `id`. ИНН в диалоге как в колонке списка: пустой показан «—». Имя — `name`. Номер — как записан.

«Всё равно создать» отправляет отложенное тело в существующий `POST /contract-cards`. С формы в теле есть номер, если его ввели. С файла номера нет, бланк открывается через тот же `intake`, что сейчас после броска. Ошибка занятого номера показывается на форме, карточка не открывается, введённый номер остаётся.

## API

Роли: `admin`, `manager`.

| Метод | Путь | Поведение |
|---|---|---|
| GET | `/api/v1/commercial/archive/contract-cards/duplicates?name=&inn=` | Совпадения по D2–D4 и D6. Пустые `name` и `inn` → `{items: [], count: 0}`. Строку не пишет. Справочник не читает |
| POST | `/api/v1/commercial/archive/contract-cards` | Как сейчас: вставляет карточку. Форма вызывает его только без совпадений или по «Всё равно создать» |

Маршрут `duplicates` регистрируется рядом с `parse` и `import`, раньше `/{card_id}`.

Принятый пункт 1 оставляет этот `POST` без нового флага: прямой вызов вставляет дубль. Форма сама не вызывает его, пока поиск пуст или не нажата «Всё равно создать».

## Testing Strategy

pytest, временная база, без `plita.db` и без сети. Имя и ИНН задаёт сам тест.

Обязательные случаи поиска:

- ИНН `5024243403` находит карточку с этим ИНН. Запрос `5024` при хранимом `5024243403` пуст. Хранимое `5024-243-403` и запрос `5024 243403` — одна карточка. Ведущие нули различают `05024243403` и `5024243403`.
- Пустой ИНН, пробелы и «нет» не возвращают карточки без ИНН и не возвращают чужие.
- «ооо  ромашка» находит «ООО Ромашка». «Строй» не находит «Строймонтаж» и «ООО Строй».
- Пустое имя возвращает пустой список и не цепляет карточку с пустым отображаемым именем.
- Одна карточка, совпавшая и по имени, и по ИНН, в списке один раз. ИНН одной и имя другой дают обе, по возрастанию `id`.
- Строка `counterparties` с тем же именем и ИНН в ответ не входит. Строка договора со статусом «отмена не будем работать» входит.
- Вызов поиска не меняет число строк `supply_contract`. Тот же проверка у GET.

vitest, `ContractCardList.test.tsx`. Поиск дубля замокан. Существующие тесты, где совпадения нет, получают пустой ответ и по-прежнему ждут один `createContractCard` с тем же телом.

Обязательные случаи диалога:

- Совпадение по форме: диалог с именем, ИНН и номером, `createContractCard` не вызван. «Редактировать» открывает регион «Карточка договора» этого номера. «Всё равно создать» вызывает создание один раз с тем телом, что ушло бы сегодня.
- Две строки: «Редактировать» у второй открывает её номер, создания нет.
- Бросок файла при совпадении: есть `parseContractCardFile`, нет `createContractCard`. «Всё равно создать» создаёт без номера и открывает бланк из разбора.
- Бросок без совпадения: разбор, пустой поиск, одно создание, диалога нет, бланк открыт.
- Отказ «это не карточка контрагента»: поиска дубля нет, создания нет.
- Закрытие диалога: создания нет, повторная отправка снова показывает диалог.

## Boundaries

- Always: гонять команды из Commands на затронутом коде; на форме сначала узнать совпадения и только потом создавать; у файла сначала разбор, и при отказе разбора ничего не искать; не читать `counterparties` в поиске дубля.
- Ask first: уникальный индекс по имени или ИНН; отказ `POST /contract-cards` без кнопки; сравнение с `full_name` и `short_name`, когда они отличаются от отображаемого имени; подстановка бланка файла в уже существующую карточку по «Редактировать»; смена подстрочного поиска списка, мастера КП или «Занести контрагента».
- Never: править `ai_docs/specs/archive-counterparty-cards.md` в этой задаче; открывать или менять `plita.db`; считать дублем подстроку; считать пустой ИНН совпадением; создавать строку в момент показа диалога; звать импорт реестра с этой формы.

## Success Criteria

Критерии написаны под принятые 2026-10-21 ответы Open Questions.

| Требование | Критерий |
|---|---|
| ИНН целиком | Поиск по `5024243403` возвращает карточку. Поиск по `5024` при хранимом `5024243403` пуст |
| Цифры ИНН | `5024 243403` и хранимое `5024-243-403` — одна карточка. `05024243403` не равно `5024243403` |
| Пустой ИНН | Пустой запрос ИНН не возвращает карточки с пустым ИНН |
| Имя | `ооо  ромашка` возвращает карточку с отображаемым именем `ООО Ромашка`. `Строй` не возвращает `Строймонтаж` |
| Пустое имя | Пустое имя даёт пустой список |
| Один раз | Карточка, совпавшая по имени и по ИНН, одна. Две разные карточки идут по `id` |
| Не справочник | Строка только в `counterparties` с тем же именем и ИНН не возвращается. Число строк справочника не меняется |
| Отменённая | Карточка со статусом `отмена не будем работать` возвращается |
| Запись | Поиск и GET не увеличивают число строк `supply_contract` |
| Диалог | При совпадении виден диалог с именем, ИНН и номером. `createContractCard` не вызван, пока не нажата «Всё равно создать» |
| Редактировать | «Редактировать» открывает блок «Карточка договора» выбранного номера и не создаёт строку |
| Всё равно | «Всё равно создать» вызывает создание один раз с тем телом, что форма или разбор отправили бы сегодня |
| Файл | При совпадении после разбора создания нет. После «Всё равно создать» карточка без номера из файла открыта, в бланке ИНН из разбора, `saveContractRequisites` не вызван |
| Нет совпадения | Пустой поиск — диалога нет, создание одно, тело прежнее |
| Мусор | Ответ «это не карточка контрагента» не вызывает поиск дубля и не создаёт строку |
| Список | Поиск «секлюц» по-прежнему подстрока по карточкам. Этот жест диалог дубля не открывает |
| Мастер и bind | Подсказки мастера КП ищут карточки договоров. «Занести контрагента» ищет справочник 1С. Диалога дубля там нет |

## Open Questions

Принято 2026-10-21. Все три пункта — рекомендуемый вариант.

1. **Где обрывается вставка.** Принято: только форма «Новая карточка» и перетаскивание файла на ней. `GET .../duplicates` ничего не пишет. `POST /contract-cards` и `create_card` вставляют, как сейчас, в том числе вторую карточку с тем же ИНН. Форма не вызывает `POST`, пока поиск пуст или не нажата «Всё равно создать». Прямой `POST` дубль создаёт.
2. **С каким именем сравнивать.** Принято: только отображаемое имя (`imported_name`, иначе `full_name`, иначе `short_name`) — колонка «Имя». Не подстрока. «Ромашка» не открывает карточку, у которой в списке «Завод», даже если в `short_name` лежит ровно «Ромашка». Пустой ИНН и пустое имя совпадение не ищут.
3. **Куда девается файл, если выбрали «Редактировать».** Принято: открыть найденную карточку как клик по списку. Разбор файла в бланк не подставляется и в базу не пишется.
