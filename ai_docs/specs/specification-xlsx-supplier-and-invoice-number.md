# Spec: Спецификация XLSX не прячет текст поставщика, номер счёта из 1С попадает в заголовок

> **Статус:** SPECIFY. План и код не писать до приёмки.  
> **Дата:** 2026-10-21  
> **Пример:** спецификация КП №16, договор `0797/02/25` от 01.02.2025. PDF полный, в XLSX блок «Поставщик» наезжает сам на себя.  
> **Рядом, не это:** смена номера договора поставки, заполнение GUID контрагента, правка сумм НДС.

## Assumptions I'm Making

1. «Пропадает часть текста» — это блок подписи поставщика внизу листа, не преамбула. В шаблоне `templates/specification.xlsx` ячейка `B28:M30` хранит три строки: `ООО «ЖБК СТАРТ»`, `ИНН 4401082520, КПП 440101001`, `Директор`. Перенос включён, высота каждой из трёх строк 15 пунктов. Excel рисует их друг на друге. PDF собирается из той же книги через LibreOffice и сам увеличивает строку, поэтому там текст виден.
2. Сборщик уже увеличивает высоту преамбулы, итогов и условий (`_grow_merged_row`). Блок поставщика статический, через этот расчёт не проходит.
3. Номер счёта из 1С — это `KP_offers.order_number_1c`. Ответ `otvet_*.json` должен записать его туда. Скачивание спецификации в момент сборки подставляет этот номер в заголовок: «Спецификация по счету № …». Пока ответа нет, в заголовке `_____`, как на снимке КП №16.
4. Номер договора поставки (`0797/02/25`) ответом 1С не заменяется. В договор Word/PDF и в фразу «к Договору поставки № …» по-прежнему идёт номер из `supply_contract`.
5. Сейчас модуль приёма ответа не импортируется: в `app/schemas/notifications.py` нет `KIND_INVOICE_NUMBER_RECEIVED`, а `invoice_reply_import.py` его импортирует. Четыре теста `tests/test_invoice_reply_import.py` падают на этом импорте. Пока это так, номер из файла ответа на КП не запишется.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| X1 | Текст | В XLSX видны все три строки блока поставщика: название, ИНН и КПП, должность. Они не наезжают на подпись «Шишов А. В.» |
| X2 | PDF | Состав текста PDF не меняется. Чинится высота книги, из которой PDF и так печатается |
| X3 | Номер счёта | После записи `order_number_1c` следующее скачивание спецификации (xlsx и pdf) ставит этот номер в заголовок и в имя файла |
| X4 | Договор | Номер договора поставки ответом 1С не меняется |
| X5 | Приём ответа | `import_otvet_file` снова записывает номер, УИД заказа и УИД КП на строку `KP_offers` и удаляет принятый файл |

## Objective

Менеджер открывает спецификацию в Excel и видит блок поставщика целиком, как в PDF. Когда из 1С приходит номер счёта, он появляется в заголовке следующей спецификации. Договор поставки остаётся со своим номером.

## Tech Stack

openpyxl, существующий шаблон `templates/specification.xlsx`, pytest. Новых зависимостей нет. LibreOffice для проверки самого XLSX не требуется: тест смотрит высоту объединённой ячейки.

## Code Style

Высота считается по уже существующему правилу длинной ячейки, не отдельной магией для поставщика.

```python
def _grow_merged_row(sheet, cell) -> None:
    merged = _merge_containing(sheet, cell.row, cell.column)
    if merged is None:
        return
    # width → число строк → высота 15 на строку плюс запас
```

Блок поставщика — ячейка, в тексте которой есть `4401082520`. После сборки сумма высот её объединения не меньше, чем три строки по 15 пунктов.

## Testing Strategy

- XLSX с тремя позициями, как у КП №16: в тексте книги есть `4401082520`, `440101001` и `Директор`; сумма высот объединения с ИНН поставщика не меньше 49 пунктов.
- Заголовок без номера содержит `_____`. Заголовок с `order_number_1c = ЯР-15` содержит `№ ЯР-15` и по-прежнему `к Договору поставки № 0797/02/25`, если в шапку передан этот договор.
- `otvet_*.json` с номером счёта пишет `order_number_1c` и не меняет ни одной строки `supply_contract`.

## Boundaries

- Always: не убирать строки из блока поставщика; номер договора в заголовке спецификации оставлять номером `supply_contract`.
- Ask first: увеличивать высоту правкой самого файла шаблона вместо расчёта при сборке.
- Never: записывать номер счёта 1С в `supply_contract.number`; коммитить выгруженный `new_16_*.json`.

## Success Criteria

| Требование | Критерий |
|---|---|
| Поставщик в Excel | В ячейке с `4401082520` три строки видны: название, ИНН и КПП, «Директор». Высота объединения не меньше 49 |
| PDF | Те же три строки остаются в книге, из которой печатается PDF |
| Номер счёта | Ответ с номером `703` для КП записывает `order_number_1c = 703`. Следующая спецификация содержит `№ 703` в заголовке |
| Договор | После того же ответа номер в `supply_contract` не меняется, в заголовке остаётся `к Договору поставки № …` прежний |
| Приём | `tests/test_invoice_reply_import.py` импортирует модуль и проходит |
