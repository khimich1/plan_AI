# Spec: нагрузка 12 и 12,5 — одна карточка плиты в поиске GUID

**Статус**: SPECIFY ✅ · IMPLEMENT ✅  
**Дата**: 2026-10-01

## Objective

**Проблема.** В рабочем прайсе нет отдельной серии `12п`: в `prices` нагрузка 12,5 записана кодом `12`, в выгрузке 1С (`prays_plity`) имя карточки — `12,5п`. Строка КП `Плиты ПБ 71-12-12п` не находит эту карточку, и счёт останавливается с «нет GUID 1С».

**Цель.** Поиск GUID плиты считает написания нагрузки `12`, `12,5`, `12.5` и `12,50` одной карточкой. Одна карточка `12,5п` — GUID берётся сам, счёт уходит без менеджера. Две карточки — прежний путь «Дубли GUID».

**Пользователь.** Менеджер отправляет счёт в 1С. Экономист по-прежнему один раз выбирает GUID, если у карточки `12,5п` дубль.

**Успех.** `Плиты ПБ 71-12-12п` при единственной карточке `Плиты ПБ 71-12-12,5п` получает её GUID. Текст строки КП, цена и варианты длины и ширины не меняются.

## ASSUMPTIONS I'M MAKING

1. Равенство только у суффикса нагрузки плиты. Длина и ширина ищутся как сейчас (`7` → `7,0`, `71` → `71,0`).
2. Алиас включается, только если карточки с написанной нагрузкой нет, а карточка `12,5п` есть. Появится настоящая `12п` — берётся она.
3. Два GUID на имя `12,5п` программа не выбирает. Выбор уже лежит в `plate_guid_choice` по имени карточки из «Дубли GUID».
4. Сваи, ФБС, марши и ступени не схлопываются.
5. Имя в КП, прайс `prices` и печать клиенту не переписываются.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| **D-where** | Где алиас | Только `core/guid_gate.py`, после промаха обычного поиска плиты |
| **D-spell** | Написания | Хвост `12п`, `12.5п`, `12,5п`, `12,50п` (число 12 или 12,5) ищет имя с хвостом `12,5п` |
| **D-guard** | Обе карточки есть | Точное имя выигрывает, алиас не включается |
| **D-dup** | Два GUID у `12,5п` | `REASON_DUP`, как сейчас. Уже сохранённый выбор по имени карточки 1С подходит и строке `12п` |
| **D-text** | Текст КП | В счёте и в тексте ошибки остаётся марка из КП |
| **D-other** | Другие нагрузки и виды | `8п`, `10п`, не-плиты без алиаса |

## Code Style

Алиас — функция рядом с `_lookup_plate`. Имя строки КП не подменяется в `OrderLine`. Повторный поиск идёт тем же `_lookup_plate`, чтобы варианты ширины и длины применились к имени `12,5п`.

## Testing Strategy

pytest, без живой `pb.db`: фикстура `prays_plity` в `tests/test_guid_gate.py`.

- единственная `12,5п` находится по `12п`, `12.5п`, `12,50п`;
- две `12,5п` дают «дубль»; выбор, записанный на имя `12,5п`, закрывает строку `12п`;
- если есть своя карточка `12п`, берётся её GUID;
- `8п` и свая не алиасятся;
- ширина `7` по-прежнему находит `7,0` уже у имени `12,5п`.

## Boundaries

- Always: не выбирать GUID из дубля автоматически; не менять текст марки в КП.
- Ask first: распространить алиас на не-плиты или на длину и ширину.
- Never: писать в живую `pb.db` из теста; останавливать `./run+logs.sh`.

## Success Criteria

- [x] Строка плиты с хвостом `12п` при одной карточке `12,5п` готова к счёту с GUID этой карточки.
- [x] Строка с хвостом `12п` при двух карточках `12,5п` блокируется как дубль, пока нет `plate_guid_choice` на имя карточки.
- [x] Своя карточка `12п` не подменяется карточкой `12,5п`.
- [x] `pytest tests/test_guid_gate.py` зелёный.
