# Спецификация: серверные контрагенты как локальные

> **Статус:** утверждена 2026-10-30. План ещё не утверждён, код на сервер не выкладывался.  
> **План:** [`ai_docs/develop/plans/2026-10-30-server-kontragent-kak-lokal.md`](../develop/plans/2026-10-30-server-kontragent-kak-lokal.md)  
> **Дата замера:** 2026-10-30, около 15:42 МСК.  
> **База:** локальная `plita.db` и серверная `/data/plita.db` в томе `web_split_data`.  
> **Рядом, не это:** пересборка образа бэкенда, выкладка широкой плиты, копирование всей `plita.db`, перенос тестовых контрагентов и журнала событий.

## Допущения

1. Сайт — `zavodstart.ru` на `himych`, каталог `/opt/plan_zavod`, compose `docker-compose.split.yml`. Живая база — `/data/plita.db`. Файл `/opt/plan_zavod/plita.db` от 14 сентября сайт не читает.
2. Справочник 1С на сервере уже совпадает с локальным по id 1–4405. Его заново не заливаем. Тестовые карточки 4406–4414 на сервер не переносим.
3. Код этого захода — коммит `602d2fe`. Прайс цельных свай уже работает в текущем контейнере бэкенда (файл от 29 октября). Коммит `7d0c9b7` отдельно не выкладываем. Широкую плиту Алексея не выкладываем.
4. Образ бэкенда не пересобираем. Обычный перезапуск контейнера сохраняет и прайс свай, и скопированные файлы. Создание контейнера заново из образа прайс стирает.
5. Id строк `supply_contract` не копируем. На сервере id 1 — это `0998/07/26`, локально id 1 — это `0785/01/25`.
6. Номера сравниваются первой тройкой «число/число/число». `752/09/24` и `0752/09/24` — один номер. У существующей серверной строки текст номера не переписываем.
7. Локальный снимок берётся через SQLite backup, вместе с WAL. Иначе 160 договоров от 30 октября 15:32 в выгрузку не попадают.

## Цель

Менеджер на `zavodstart.ru` находит клиента КП в справочнике 1С и отправляет счёт с номером уже привязанного договора. Поиск МД-СТРОЙ на сайте даёт карточку id 3379. В реестре есть те же привязанные номера, что в локальной базе на 30 октября 2026, 15:32, с исключениями L1–L3.

Локально 383 договора, все с клиентом. На сервере на момент замера 185 договоров, привязаны три, последняя запись реестра от 22 октября. Мастер КП на сайте ищет только карточки договоров.

### Сценарии

1. **МД-СТРОЙ.** В новом КП ввод «МД-СТРОЙ» показывает ИНН `7604364780`, КПП и код `00-00002227`. Надписи «Не найдено среди карточек» нет. В реестре `651/03/24` связан с id 3379.
2. **Берг.** Следующая отправка КП клиента 403 кладёт в файл номер `752/09/24`. Карточка `0002/10/26` остаётся в реестре отменённой, с реквизитами БЕРГ1. БЕРГ1 (id 404) получает `459/02/23`.
3. **Капиталстрой и Стройассистент.** Номера и клиенты те же. Юридическое имя, адрес, банк и подписант на сервере остаются заполненными.
4. **Трест, Секлюцкий, Капиталгруппстрой, птицефабрика.** Старые серверные номера из L2 удалены. В отправку попадает локальный действующий номер этих клиентов.

## Стратегия тестирования

Новый тест на выкладку не пишем. До копирования файлов проходит `tests/test_kp_invoice_existing_contract.py`. После кода на сайте открывается новое КП и вводится «МД-СТРОЙ». После правки базы счётчики и пять контрольных номеров читаются из `/data/plita.db`.

## Границы

- Всегда: снимок `/data/plita.db` до первой записи в реестр. Тест отправки до копирования кода. Вставка по именам колонок. Сверка номера тройкой чисел. Сначала код, потом реестр: старая отправка ещё вызывает автопривязку по ИНН.
- Сначала спроси: очистка всего `supply_contract`, удаление `0002/10/26`, затирание реквизитов, перенос тестовых контрагентов, сборка нового образа бэкенда, перенос журнала, выкладка `7d0c9b7` и широкой плиты.
- Никогда: `docker compose down -v`. Копирование локального `plita.db` поверх серверной базы. Коммит `plita.db` и секретов. Правка контейнеров `chim-*`. Подмена серверного `frontend/nginx.docker.conf`.

## Критерии успеха

- В мастере КП запрос «МД-СТРОЙ» возвращает id 3379, ИНН `7604364780`, код `00-00002227`. Надпись «Не найдено среди карточек» для этого имени не появляется.
- `651/03/24` связан с `counterparty_id` 3379. `459/02/23` связан с 404. Активный договор id 403 — `752/09/24`.
- У `0002/10/26` статус «отмена не будем работать». Строка и реквизиты БЕРГ1 на месте.
- 170 общих номеров имеют тот же `counterparty_id`, что локально. У `0998/07/26` и `0787/01/25` `full_name` по-прежнему заполнен.
- 211 локальных номеров есть на сервере и привязаны. Пять номеров из L2 удалены. Семь номеров из L2 на месте и без `counterparty_id`.
- В `supply_contract` 391 строка: 172 общих, 211 новых, 8 оставшихся серверных (`0002/10/26` и семь из L2).
- `counterparties` по-прежнему 4405 строк. Число строк `KP_offers` равно числу, снятому в шаге backup.
- В контейнере `archive_service.py` не содержит `link_unique_inn_contracts`. `import_pile_prices_from_xlsx` на месте. `https://zavodstart.ru/health` отвечает 200. В nginx сайта `client_max_body_size 50m`.
- Журнал событий не заменён локальными 383 строками.
