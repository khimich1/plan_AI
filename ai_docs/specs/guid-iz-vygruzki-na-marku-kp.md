**Родитель**: [guid-demand-queue.md](./guid-demand-queue.md), [guid-price-sync-round2.md](./guid-price-sync-round2.md)

## Objective

**Проблема.** КП на сваи `С120.35-12`, `С140.35-12`, `С160.35-12` считается: марки есть в `pile_prices`. Счёт в 1С не уходит: строки в `nomenclature_guid` нет. Экономист заводит карточки и присылает универсальный отчёт с УИД. Загрузка смотрит только в уже существующие строки справочника, прайс не открывает и кладёт эти три имени в «нет в прайсе программы» / «Ввести цену». GUID не записывается, «Завести в 1С» и жёлтая плашка на шаге 3 остаются.

**Цель.** Единственный GUID из файла записывается на марку, которая уже есть в прайсе этой группы, либо на договорную марку из архивного КП. Цену второй раз не спрашиваем и в прайс не копируем. Очередь «Завести в 1С» и плашка шага 3 гаснут. Два GUID на одно имя по-прежнему выбирает экономист, и только если изделие сохранили в КП.

**Пользователи.** Экономист загружает файл на «Прайсы и 1С». Менеджер видит шаг 3 того же КП.

**Успех.** Файл `Номенклатура с УИД сваи.xlsx` (три строки, отбор, группа «сваи») даёт три строки `nomenclature_guid` со статусом `auto`. Число строк `pile_prices` не меняется. Задач «завести» и «ввести цену» по этим маркам нет. Повторная проверка GUID черновика больше не возвращает эти марки.

## ASSUMPTIONS I'M MAKING

1. **Две двери, одна труба.** Дверь «прайс»: марка есть в прайс-таблице группы (`pile_prices`, `bridge_pile_prices`, `fbs_prices`, `march_prices`, `step_prices`). Дверь «договорная»: марки в прайсе нет, но есть открытая строка `guid_demand` этой группы с `field=guid_1c` или `guid_1c_u` после архива. Несохранённый черновик источником не является.
2. **Цена договорной строки остаётся на КП** (`price_source=oneoff`). В прайс-таблицу не пишем.
3. **Один файл — одна группа**, как сейчас (`infer_product_kind` / явный `product_kind`). Сопоставление только внутри этой группы.
4. **Имя сходится тем же кандидатом, что сверка** (`nomenclature_sync`: «Сваи С 120.35-12» → `С120.35-12`, латиница `C` ≡ `С`, суффикс «у» → `guid_1c_u`). Соседняя марка не заполняется.
5. **Два GUID — не пишем.** Как родительская спека: автовыбора нет. Если по этой марке есть открытый спрос, `sweep` переводит задачу в «Дубли GUID».
6. **Имя ни в прайсе, ни в открытом спросе** остаётся `unmatched_1c` и попадает в «Ввести цену», как сейчас.
7. **Плиты не заводим в `nomenclature_guid`.** Их GUID живёт в `prays_plity`.
8. **`manual` не перезаписываем.** Уже заполненный `auto` с тем же GUID — без изменений. Другой единственный GUID при `auto` обновляется по текущему правилу сверки.
9. **Частичный отчёт** (`Отбор:` → `partial`) не помечает остальные марки исчезнувшими.
10. **Без новых npm/pip.** Коммиты — по просьбе. `./run+logs.sh` не убивать.

→ Если это не так — поправить до плана.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| **D-door-price** | Марка в прайсе, строки GUID нет | Создать `nomenclature_guid` (`auto`) и записать единственный GUID. Прайс не трогать. В `price_queue` не класть |
| **D-door-oneoff** | Марки в прайсе нет, есть open `guid_demand` | То же: только GUID. Договорную цену в прайс не копировать. В `price_queue` не класть |
| **D-oneoff-source** | Откуда договорная марка | Только открытый `guid_demand` архивного КП, не черновик |
| **D-dup** | Два GUID на имя | Не записывать. Выбор — существующий блок «Дубли GUID», если спрос этой марки открыт |
| **D-stranger** | Нет ни в прайсе, ни в спросе | Как сейчас: `unmatched_1c` → «Ввести цену» |
| **D-plates** | Плиты | Не создавать строки `nomenclature_guid` |
| **D-partial** | Файл с «Отбор:» | `disappeared` пустой |
| **D-close** | «Завести в 1С» | Уже есть `sweep_guid_demand` после импорта. После новой записи sweep видит GUID и закрывает задачу |
| **D-banner** | Плашка шага 3 | Успешный импорт сбрасывает react-query `["commercial", "guid-check"]`. Проверка читает `nomenclature_guid`, отдельной записи в черновик нет |
| **D-u** | Карточка «у» | Поле `guid_1c_u`, если кандидат сверки — суффикс «у». Обычная карточка — `guid_1c` |

## User Stories

- Как **экономист**, загружаю файл с тремя сваями, которые уже в прайсе. GUID записывается, цену не ввожу, строки пропадают из «Завести в 1С».
- Как **менеджер**, оставляю открытым шаг 3. После загрузки файла экономистом жёлтая плашка по этим маркам гаснет без нового черновика.
- Как **экономист**, получаю файл по договорной марке из архивного КП. GUID записывается, цена этого КП остаётся договорной, в общий прайс не попадает.
- Как **экономист**, вижу два GUID на одно имя из сохранённого КП и выбираю сам. Программа не выбирает.
- Как **экономист**, загружаю имя, которого нет ни в прайсе, ни в КП. Оно по-прежнему в «Ввести цену».

## Code Style

Слои не смешивать: решение «куда писать GUID» в `core/nomenclature_sync.py`, оркестрация импорта остаётся в сервисе. Прайс-таблицы только читаем. Русские сообщения об ошибках как сейчас.

Эскиз развилки на одну нормализованную группу строк файла (один GUID):

```python
mark, field = match_existing_catalog(kind, norm_name)  # как сейчас, по nomenclature_guid
if mark is None:
    mark, field = match_price_or_open_demand(conn, kind, norm_name)
if mark is None:
    unmatched.append(...)          # «Ввести цену», как сейчас
else:
    upsert(conn, kind, mark, **{field: guid}, match_status="auto")
```

`match_price_or_open_demand` возвращает марку, только если она есть в прайс-таблице группы или в открытом `guid_demand` этой группы. Два GUID в группе — ветка не вызывается, срабатывает уже существующая неоднозначность.

## Testing Strategy

pytest, без браузера. Фикстуры на временной `pb.db`.

- Прайс содержит `С120.35-12`, справочника нет, файл «Сваи С 120.35-12» с одним GUID → строка `auto`, цена в `pile_prices` та же, `price_queue` пуст, `sweep` закрывает спрос.
- Рядом в прайсе `С120.35-13`, в файле её нет → строка справочника для неё не появляется.
- Договорная марка: в прайсе нет, open `guid_demand`, один GUID → справочник записан, прайс-таблица не выросла, `price_queue` пуст.
- Два GUID на имя при открытом спросе → справочник без нового GUID, задача уходит в дубли.
- Имя ни в прайсе, ни в спросе → `unmatched_1c` и открытая `price_queue`.
- `manual` с другим GUID не затирается.
- Файл с «Отбор:» не наполняет `disappeared`.

Фронт: успешный импорт инвалидирует ключ `guid-check`. Отдельный e2e не нужен.

## Boundaries

- **Always:** тесты из Commands до коммита; минимальный diff; плиты не писать в `nomenclature_guid`; частичный файл не объявляет исчезнувшими марки вне файла.
- **Ask first:** смена контракта `POST /import-1c`, новая таблица, запись договорной цены в прайс.
- **Never:** автовыбор из двух GUID; ручной ввод GUID; коммит секретов; остановка `./run+logs.sh`; чистка тестовых мостовых свай и `ЛС11` в этой задаче.

## Success Criteria

- Загрузка файла с тремя сваями из прайса пишет три GUID и не меняет `pile_prices`.
- «Завести в 1С» по этим маркам пустеет. «Ввести цену» по ним не появляется.
- Договорная марка из архивного КП получает GUID, её цена в прайс не попадает.
- Два GUID не записываются; выбор остаётся у экономиста по спросу из КП.
- Открытый шаг 3 после импорта больше не показывает эти марки.
- Повторная загрузка того же файла не плодит строки и не затирает `manual`.
