# Spec: GSM lookahead-генератор с географией (round-trip, направление к следующей заправке)

Дата: 2026-08-15. Статус: draft, на ревью.
Идея: [`ai_docs/ideas/gsm-geo-lookahead-generator.md`](../ideas/gsm-geo-lookahead-generator.md) (2026-08-15).
Базовая спека модуля: [`gsm-module-putevye-listy.md`](gsm-module-putevye-listy.md) (2026-08-14).

## ASSUMPTIONS I'M MAKING

1. Это **доработка** существующего модуля ГСМ, а не новый модуль. Меняется
   логика `core/gsm/generator.py`, добавляется `core/gsm/geo.py`, меняется
   контракт `POST /gsm/waybills/generate` (частичная генерация вместо 422).
2. База машин — **две точки**: Кострома (Кузнецкая 18Б) и Ярославль
   (Домостроителей). Подтверждено данными: 144/95/97/123 маршрута из Костромы,
   44/23/24 из Ярославля. «Вернуться домой» = в одну из этих баз.
3. Геокодинг станций — через существующий кэш `ГСМ/geo_cache/addresses.json`
   (Nominatim), как в базовой спеке (assumption 7). Новых внешних сервисов нет.
4. `max_daily_km = 700` — дефолт в `gsm_setting`, переопределяется через UI
   настройки. Значение 700 покрывает дальние round-trip (Москва ~340 км плечо →
   680 round-trip) и делает все реальные плотные участки решаемыми **без
   ночёвок** (проверено на истории: жёстких случаев, требующих ночёвки для
   баланса, нет ни у одной машины).
5. Существующие поля БД не меняются; новых таблиц нет. Меняется только
   наполнение `gsm_route.typical_station_ids` (было пусто у всех 610) и
   `gsm_station.lat/lon` (у 27 станций NULL) — это **data-миграции**, не схема.
6. День = **2 плеча (туда + обратно)** — соответствует истории (все 4
   импортированных ПЛ имеют ровно 2 плеча, реальные дни 400–410 км).
   **Ночёвки вынесены в фазу 2** (см. Objective): данные показывают, что для
   сходимости баланса они не нужны — плотные заправки почти всегда идут рядом
   с базой (Кострома, 0–5 км), а заправки «в пути» (Ярославль 63 км, Реутов
   300 км) решаются длинным round-trip.

## Objective

Устранить массовые падения генерации (422) на плотных участках заправок.
Для Palisade и Tug952 **43–44% интервалов между заправками не имеют свободных
будней** — дожигание невозможно, генератор v1 неизбежно падает.

Генератор v2:

1. **Lookahead:** перед выбором маршрута якоря смотрит на следующую заправку
   и подбирает длину маршрута так, чтобы освободить место в баке.
2. **География:** маршрут следует направлению движения от текущей заправки к
   следующей (заправки — точки реального пути, не телепортация).
3. **Round-trip:** день = 2 плеча (туда + обратно); lookahead подбирает длину
   так, чтобы освободить место под следующую заправку, в пределах
   `max_daily_km`.
4. **Частичная генерация:** локально нерешаемый якорь → draft
   `manual_intervention`, период собирается целиком, а не валится в 422.

**Фаза 2 (вне MVP):** дальний рейс с ночёвкой как «улучшатель правдоподобия» —
если round-trip превышает порог «долгого дня» (~500 км), генератор предпочитает
разбить поездку на 2 дня (туда/обратно), даже когда баланс сходится и так. Это
про реалистичность ПЛ (10 ч в дороге за день выглядит хуже, чем «уехал 20-го,
вернулся 21-го»), а не про сходимость бака. Данные показали: для баланса
ночёвки не требуются.

**Пользователь:** бухгалтер (`accountant`).

**Критерий успеха:** Palisade май 2026 (04.05–31.05, старт 28 л / 128327 км)
собирается без 422; ≤ 2–3 дней `manual_intervention` на группе 20–22.05;
маршруты правдоподобны (следуют логистике заправок).

## Code Style

```python
# core/gsm/geo.py
from __future__ import annotations

from dataclasses import dataclass
from math import asin, atan2, cos, radians, sin, sqrt


@dataclass(frozen=True, slots=True)
class GeoPoint:
    lat: float
    lon: float


def haversine_km(a: GeoPoint, b: GeoPoint) -> float:
    """Расстояние по сфере, км."""
    r = 6371.0
    dlat = radians(b.lat - a.lat)
    dlon = radians(b.lon - a.lon)
    h = sin(dlat / 2) ** 2 + cos(radians(a.lat)) * cos(radians(b.lat)) * sin(dlon / 2) ** 2
    return round(2 * r * asin(sqrt(h)), 2)


def bearing_deg(a: GeoPoint, b: GeoPoint) -> float:
    """Азимут a→b в градусах [0, 360)."""
    dlon = radians(b.lon - a.lon)
    x = sin(dlon) * cos(radians(b.lat))
    y = cos(radians(a.lat)) * sin(radians(b.lat)) - sin(radians(a.lat)) * cos(radians(b.lat)) * cos(dlon)
    return (atan2(x, y) * 180.0 / 3.141592653589793 + 360.0) % 360.0


def angle_diff_deg(x: float, y: float) -> float:
    """Минимальная разница двух азимутов [0, 180]."""
    d = abs(x - y) % 360.0
    return min(d, 360.0 - d)
```

## Algorithm (core/gsm/generator.py v2)

**Вход:** транзакции, библиотека маршрутов (с `typical_station_ids` и
координатами станций), нормы + сезон, стартовые `остаток/одометр`, настройки
(`max_daily_km`, базы, `hook_threshold_km`).

### Шаги

1. **Якоря** — как в v1 (каждая транзакция → день-якорь, мойка = якорь без
   литров). Дополнительно: для каждого якоря вычисляется `next_anchor`
   (дата + `fuel_issued` следующей заправки) и `free_weekdays_between`.

2. **Lookahead на якоре.** Если до следующего якоря **нет свободных будней**
   (или дожигание не успевает), вычисляется необходимое сжигание:

   ```
   headroom_needed = tank_volume − Q_next            # остаток к утру след. заправки
   fuel_after      = fuel_before + Q_today            # после сегодняшней заправки
   burn_needed     = fuel_after − headroom_needed     # сколько сжечь сегодня
   km_needed       = burn_needed / норма × 100
   ```

   Если `burn_needed ≤ 0` — lookahead не нужен, обычный выбор маршрута.

3. **Выбор маршрута с учётом географии.** Кандидаты — маршруты из библиотеки.
   Сначала **отбор по сходимости бака** (km достаточный, чтобы
   `fuel_end` попал в коридор), затем **мягкая сортировка по географии**:

   | Приоритет | Условие |
   |---|---|
   | 1 | Станция сегодняшней заправки на маршруте **И** направление к след. АЗС (`angle_diff ≤ 90°`) |
   | 2 | Станция на маршруте (направление любое) |
   | 3 | Подходящий km, станция крюком (`hook_above_threshold`) |

   Среди кандидатов одного приоритета — **минимальный достаточный km**
   (не жечь лишнего), tie-break — частота, `route_id`, seed.

4. **Round-trip.** День = 2 плеча (туда + обратно): для выбранного маршрута
   km (одно плечо) дневной пробег = `2×km`, сжигается `burn(2×km)`. Это дефолт,
   соответствует истории. Ограничение: `2×km ≤ max_daily_km`. Маршруты с
   `2×km > max_daily_km` не используются в MVP (плечо длиннее 350 км при
   лимите 700 — отсутствует в библиотеке Palisade, макс. плечо 360).

5. **Частичная генерация.** Если ни один маршрут не решает lookahead
   (даже максимальный) — якорь **не валит период в 422**, а сохраняется как
   `draft` с warning `manual_intervention` (маршрут — лучший доступный,
   баланс помечен как нарушенный). Генерация продолжается со следующего якоря
   (баланс пересчитывается от фактического `fuel_end`).

### Детерминизм

Один вход → один выход. Все tie-break'и — через явные ключи сортировки
(частота, route_id, seed). Геометрия детерминирована по координатам.

## API (diff)

## Boundaries

- **Always:** TDD (тест на lookahead/round-trip до реализации); `pytest`
  зелёный; детерминизм солвера; оригиналы `ГСМ/**` read-only.
- **Ask first:** сетевые вызовы Nominatim из `scripts/` (геокодинг станций);
  изменение контракта `generate` (частичная генерация) — уже согласовано в
  этой спеке; новые warning-коды в UI.
- **Never:** не ломать v1-поведение на простых периодах (регрессионные тесты);
  не геокодить из backend в runtime (только `scripts/`); не удалять существующие
  данные при data-миграциях (UPDATE только NULL/пустых полей).

## Data Migrations (scripts/)

### `scripts/geocode_gsm_stations.py`

Разовый. Для каждой `gsm_station` с `lat IS NULL`: запрос к Nominatim (через
существующий кэш `ГСМ/geo_cache/addresses.json`), запись `lat/lon`,
`geocode_source='nominatim'`. Rate-limit 1 req/s (политика Nominatim). 27
станций. Большинство — трассовые («М8, 87 км») — геокодируются по трассе.

### `scripts/link_route_stations.py`

Разовый. Заполнение `gsm_route.typical_station_ids`:

1. **Из истории:** для 4 импортированных ПЛ — станция заправки дня привязывается
   к маршруту дня (данных мало, но точные).
2. **По географии:** для каждого маршрута геокодить адреса A и B (кэш), станция
   считается «на маршруте», если её отклонение от отрезка A→B < 15 км
   (point-to-segment distance). Результат — `typical_station_ids`.

## Success Criteria

1. **SC-G1 (Гео):** все 76 станций имеют координаты; `geo.py` корректно считает
   расстояние/азимут на контрольных парах (Кострома↔Ярославль ~63,5 км / ~257°,
   Кострома↔Москва ~300 км / ~224°).
2. **SC-G2 (Привязка):** `typical_station_ids` заполнены у маршрутов, проходящих
   мимо известных АЗС; Palisade имеет маршруты через станцию id=1 (КТК
   Магистральная) — раньше было 0.
3. **SC-G3 (Lookahead):** на плотных якорях (Palisade 4–6, 14–15, 20–22 мая)
   генератор выбирает удлинённый маршрут и освобождает место под следующую
   заправку, где это физически возможно при `max_daily_km=700`.
4. **SC-G4 (Дальний round-trip):** цепочка 20.05 Ярославль → 21.05 Москва →
   22.05 Кострома собирается длинными round-trip (21.05 ~600 км через Реутов);
   баланс сходится без ночёвок.
5. **SC-G5 (Частичная генерация):** нерешаемый якорь → draft
   `manual_intervention`, период собран, ответ 200 с `problematic_days`, UI
   показывает день для ручной доработки.
6. **SC-G6 (Acceptance):** Palisade май 2026 собирается без 422; ≤3 manual
   days; маршруты правдоподобны. Все существующие тесты зелёные (регрессия v1).

**Фаза 2 (после MVP):** ночёвки как улучшение правдоподобия — round-trip
свыше ~500 км разбивается на 2 дня (туда/обратно) с `overnight_trip` /
`return_leg`, проверкой топлива на ночёвке и бейджем «ночёвка: {город}».
Для сходимости баланса не требуется (проверено на истории).

## Open Questions

- Порог `angle_diff ≤ 90°` для «направления к следующей АЗС» — стартовый;
  пересмотреть после первого acceptance (возможно, 60° точнее).
- Отклонение станции от линии маршрута `< 15 км` — стартовое; на трассовых
  АЗС может понадобиться увеличить (станция «на 87 км трассы» может быть далеко
  от прямой A→B).
- `max_daily_km=700` — дефолт; проверить, не даёт ли он «фантастических» ПЛ
  (время в пути 9–10 ч) на приёмке у бухгалтера.
