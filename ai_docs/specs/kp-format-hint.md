## Assumptions (locked after idea review)

```
ASSUMPTIONS:
1. Пользователь — менеджер на шаге ввода КП. Он вставляет текст клиента
   как есть и не должен спрашивать коллегу, как собрать строку.
2. Успех первой версии — правило видно после вставки текста и его можно
   открыть одним кликом. Замер «перестали писать в чат» — вне этой спеки.
3. Слово «Подсказка» над полем списка, между подписью («Список плит» и т.п.)
   и PlateListEditor. Не сбоку, не под полем, не в FieldWrapper.hint
   (тот hint рисуется под контролом).
4. Старт каждый раз свёрнутый. Клик по слову раскрывает, повторный клик
   прячет. Состояние не запоминается (нет localStorage, нет «уже открывал»).
5. Внутри: общий каркас на все 7 типов + свой образец и своё пояснение
   состава строки. Пояснение — про марку, количество, класс бетона и порядок,
   не про разбор письма.
6. Образец копируется одним кликом. В поле списка он не подставляется.
   Placeholder поля не меняется и по-прежнему пропадает, когда поле непустое.
7. Тексты один раз в productTypeConfig.ts. Админки нет. Бэкенд и парсеры
   не меняются.
8. Блок есть и на пустом поле, и когда текст уже вставлен, и в режиме
   «Добавить к списку» (hasDraft). Один и тот же SourceInputCard.
9. Подсказка не открывается сама на красной строке и не подменяет lint.
10. Мобильная вёрстка отдельно не проектируется: блок в потоке над полем,
    на узком экране просто выше редактора.
```

Черновик формулировок — в разделе «Тексты». При переходе к плану тексты приняты as drafted, если ревью не попросит иное.

## Objective

Менеджер на шаге ввода любого типа продукции открывает над полем короткую подсказку: как выглядит правильная строка и из чего она состоит. Образец можно скопировать. Поле заявки при этом не меняется.

Типы: плиты, сваи, ступени, марши, мостовые сваи, составные сваи, ФБС.

### User stories

| # | Как менеджер… | Я хочу… | Чтобы… |
|---|----------------|---------|--------|
| US-1 | вставляю текст клиента | видеть слово «Подсказка» над полем | понять, что правило есть, и не искать пример в чате |
| US-2 | открываю подсказку | прочитать пояснение состава строки и увидеть образец | собрать строку самому |
| US-3 | образец подходит | скопировать его одним кликом | не перепечатывать марки |
| US-4 | подсказка больше не нужна | скрыть её тем же словом | поле и кнопки снова без лишнего блока |
| US-5 | уже вставил текст и правлю его | открыть ту же подсказку | пример не пропал вместе с placeholder |

### Acceptance criteria (MVP)

- [ ] На шаге ввода всех семи типов над полем есть кнопка-слово «Подсказка»
- [ ] До клика видны только слово и маркер свёрнутости. Пояснение и образец в DOM скрыты (не `visibility`, а отсутствие раскрытого блока)
- [ ] Клик раскрывает блок, повторный клик прячет. `aria-expanded` совпадает с видом
- [ ] Раскрытый блок содержит общий каркас, пояснение этого типа и образец этого типа
- [ ] «Скопировать образец» пишет в буфер только строки образца, поле списка не меняется
- [ ] Placeholder, lint, распознавание и режим «Добавить к списку» ведут себя как сейчас
- [ ] Смена текста в поле не сворачивает и не раскрывает подсказку

## Поведение

### Где стоит

Внутри `FieldWrapper` с `label={listLabel}`, **между** подписью и `PlateListEditor`. Фото, галерея, кнопки распознавания и блок «Дополнительно» не сдвигаются выше подсказки.

Визуальный жест как у уже существующей кнопки «▸ Дополнительно» / «▾ Дополнительно»: текстовая кнопка без заливки, `type="button"`.

### Состояния

| Состояние | Что видно |
|-----------|-----------|
| Свёрнуто (старт) | «▸ Подсказка» |
| Раскрыто | «▾ Подсказка», затем каркас, пояснение типа, образец, кнопка «Скопировать образец» |

Локальный `useState`. Сброс только при размонтировании карточки. Ошибка lint и непустой `sourceText` состояние не трогают.

### Копирование

Кнопка копирует `sample` как есть, с переводами строк. В `onTextChange` не зовёт.

| Исход | UI |
|-------|-----|
| Успех | подпись кнопки на короткое время «Скопировано», затем снова «Скопировать образец» |
| Отказ буфера | текст «Не удалось скопировать». Образец остаётся выделенным текстом в блоке. Поле не меняется |

Пояснение и общий каркас в буфер не попадают.

### Тексты

Общий каркас один на все типы, константа рядом с конфигом (не седьмой дубль в каждом типе):

> Одна позиция — одна строка. Количество — число в конце строки. Шапку, цены и адрес из письма не копируйте.

Образец типа — дословный текущий `placeholder` (уже зафиксирован тестом). Пояснение — черновик ниже; автор правит до реализации.

| Тип | Образец (как placeholder) | Пояснение (черновик) |
|-----|---------------------------|----------------------|
| plates | `ПБ 78-12-8п 2` / `71-12-8 3` / `ПБ 66-12-8п 4` | Марка, затем количество штук. Нагрузка входит в марку (`8п`). |
| piles | `С120.35-12 B25 5` / `С120.35-13и 3` | Марка, класс бетона, количество. Класс можно не писать — как во второй строке. |
| steps | `ЛС11 10` / `ЛС14-1лев 5` / `ЛС11-Б-1 2` | Марка, затем количество. Класса бетона в строке нет. |
| marches | `1ЛМ 27-11-14-4 B25 5` / `ЛМ 2,8 3` | Марка, класс бетона, количество. Класс можно не писать — как во второй строке. |
| bridge_piles | `C10-35B7 B25 2` / `C10-35T1 B25 3` | Марка, класс бетона, количество. |
| composite_piles | `С140.30-С 5` / `С60.30-ВС.1 3` | Марка секции, затем количество. Класс бетона, если он есть в заявке, стоит перед количеством. |
| fbs | `ФБС 12.4.3-Т B25 2` / `ФБС 12.4.6-Т B25 3` | Марка, класс бетона, количество. |

Порядок в раскрытом блоке: каркас, пояснение, образец (`white-space: pre-line` или `<pre>`), кнопка копирования.

## Data Model

Новых таблиц нет. Поле только на клиенте:

```ts
type ProductFormatHint = {
  /** Состав строки этого типа. Без образца. */
  explanation: string;
  /** Строки образца. Равно labels.placeholder. */
  sample: string;
};
```

`sample` не дублировать вручную: брать `labels.placeholder`, чтобы пример в подсказке и в пустом поле не разъехались.

## Code Style

- Тексты и состав — данные в `productTypeConfig`, не JSX на каждый тип.
- Кнопка раскрытия не submit. Рядом с «Дополнительно», но это другой контрол: подсказка не прячет распознавание.
- Пример разметки:

```tsx
<button type="button" aria-expanded={open} onClick={() => setOpen((value) => !value)}>
  {open ? "▾ Подсказка" : "▸ Подсказка"}
</button>
{open && (
  <div>
    <p>{FORMAT_HINT_SHARED}</p>
    <p>{explanation}</p>
    <pre>{sample}</pre>
    <button type="button" onClick={copySample}>Скопировать образец</button>
  </div>
)}
```

## Boundaries

**Always:** подсказка над полем на всех семи типах; старт свёрнутый; копирование не пишет в поле; `placeholder` не переписывать.

**Ask first:** другой визуальный язык, не как «Дополнительно»; хранение «уже открывал»; правка общих формулировок каркаса после согласования текстов.

**Never:** автоподстановка образца в поле; автооткрытие на красной строке; админка текстов; смена парсеров ради подсказки; подсказка только на плитах.

---

## Success Criteria

1. На каждом типе свёрнутое слово «Подсказка» стоит над полем и при уже вставленном тексте.
2. Раскрытие показывает каркас, пояснение этого типа и его образец; повторный клик прячет блок.
3. «Скопировать образец» кладёт в буфер строки образца. Текст в поле тот же, что до клика.
4. Существующие тесты placeholder и lint карточки остаются зелёными.
