# Spec: Атомарная запись плана (A30 → A29 → S21 → S20)

**Статус**: IMPLEMENT · A30 ✅ · A29 ✅ · S21 ✅ · S20 ✅
**Дата**: 2026-10-26
**Источник**: [аудит 2026-10-26](../develop/audits/2026-10-26-production-audit.md), реестр [FINDINGS.md](../develop/audits/FINDINGS.md)
**Рядом, не этот скоуп**: [целостность атрибуции A24–A26](./целостность-плана-производства.md)

## Objective

Планировщик сохраняет плиты из очереди «в производстве» в план и, если выбрал склад, резервирует СГП. Сейчас пометка плит, документ плана и резерв СГП — три соединения SQLite и три `commit`. Обрыв посередине оставляет плиты «в плане» без документа или план с резервом, которого на складе нет.

**Пользователь:** мастер производства (`admin` / `production`). Менеджер видит последствие: плита пропала из очереди и не появилась в плане.

**Порядок.** Солвер не входит в транзакцию. Сначала один `commit` пометки плит и документа плана (A30). Сразу следом — резерв СГП на том же соединении до `commit` и актор этого резерва (A29, узкий Q40). Затем удаление плана одним `commit` (S21). Затем `expected_version` только на дозаписи в существующий план (S20).

Этот документ не закрывает A4, A5, A6, A22 и остальные точки пустого актора.

## ASSUMPTIONS I'M MAKING

1. База — SQLite `plita.db`. Схемы таблиц не меняем. Новых зависимостей нет.
2. Солвер, `fill_targets` и обнуление `active_plan_id` при датах мастера не меняем. Мастер по-прежнему создаёт новый план.
3. Параметр называется `_external_conn` и ведёт себя как в `return_plates_to_production`: не передан — функция сама открывает соединение, коммитит и закрывает; передан — не делает `commit` / `rollback` / `close`, исключения пробрасывает.
4. `commit_plan_plates` без `_external_conn` по-прежнему коммитит сам. Так остаются зелёными `tests/test_plan_commit.py` и вызов из `bot_archived/` (архив не развиваем). Живой `persist` передаёт соединение и коммитит после `create`/`save`.
5. Погашение обещаний (`_settle_promises_on_commit`) входит в тот же `commit`, что плиты и документ. Решение принято 2026-10-26: иначе списание обещаний сохранится при откате документа. Просрочка не роняет сборку и пишется в ту же транзакцию.
6. `set_active` остаётся отдельным `commit` после основного. Сбой метки «активный план» не откатывает плиты и документ. Механику, кнопку и `active_plan_id` не убираем. Живой мастер с `fill_targets` по-прежнему создаёт новый план. Решение принято 2026-10-26.
7. Q40 в этом скоупе — только актор `reserve_on_conn` при сборке: `username`, если пусто — `str(id)`. Снятие дорожки, завершение дня, ёмкость дня и прочие вызовы СГП не трогаем. ID Q40 в реестре целиком не закрываем.
8. Удаление (S21) снимает `plan_id` у строк СГП и не возвращает складские плиты в производство (как комментарий SGP-503 в `plan_storage.delete_plan`).
9. Текст ошибки клиенту не меняем: `PlanBuildError("Не удалось сохранить план.")`. Меняется только состояние базы.
10. `tests/archived/` и `bot_archived/` не правим.

Пункты 5 и 6 согласованы 2026-10-26. Остальное беру из согласованного порядка работ.

## Code Style

Тот же приём, что у `return_plates_to_production`. Имя аргумента не переименовывать.

```python
def mark_plates_as_planned(
    kp_id: int,
    plate_name: str,
    qty_to_plan: int,
    plan_id: str,
    db_path: str = DEFAULT_DB,
    *,
    actor: str | None = None,
    day_number: int | None = None,
    _external_conn: sqlite3.Connection | None = None,
) -> dict[str, object]:
    own_conn = _external_conn is None
    conn = _connect(db_path) if own_conn else _external_conn
    try:
        if own_conn:
            conn.execute("PRAGMA foreign_keys = ON")
        # ... существующие UPDATE / INSERT ...
        if own_conn:
            conn.commit()
        return {"success": True, ...}
    except Exception:
        if own_conn:
            conn.rollback()
        raise
    finally:
        if own_conn:
            conn.close()
```

`persist` открывает соединение после солвера, передаёт его в `commit_plan_plates` и в `repo.create` / `repo.save`, затем один `commit`. При исключении до `commit` — `rollback` и прежний `PlanBuildError`. Отдельный вызов `return_plan_plates_to_production` на этом пути убирается: откатывать ещё нечего.

Актор резерва на сборке:

```python
actor = user.get("username") or (str(user["id"]) if user.get("id") is not None else None)
```

Пустую строку в журнал не писать.

## Testing Strategy

pytest, без нового фреймворка и без порога coverage.

| Уровень | Где | Что доказывает |
|---|---|---|
| Сборка через API | `tests/test_production_fill_integrity.py` | Обрыв записи плана после пометки: нет строки плана, плиты «в производстве» |
| Тот же файл | существующий `test_sgp_reserve_fail_after_build_compensates_no_plan_plates_not_in_plan` | После A29 остаётся зелёным: нет плана, плиты не «в плане», свободная строка СГП на месте. Механизм — `rollback`, не удаление уже записанного плана |
| Коммит плит без HTTP | `tests/test_plan_commit.py` | Вызов без `_external_conn` по-прежнему фиксирует плиты |
| Удаление | `tests/test_production_api_integration.py` | Фаза S21: после DELETE плиты снова «в производстве», документа нет |
| Дозапись | тест сборки с `active_plan_id` и устаревшей версией | Фаза S20: 409, документ и плиты не изменились |

Новый тест A30 не использует `sgp_reservations`. Имя: `test_plan_save_fail_after_plate_mark_rolls_back_no_plan_plates_stay_in_production`. Падение — исключение из `create`/`save` репозитория, не из солвера.

## Boundaries

- Always: солвер снаружи транзакции; один `commit` на фазу записи; при внешнем соединении не коммитить внутри; не глотать исключение отката; прогон pytest из корня до объявления фазы готовой; сначала падающий тест, потом правка.
- Ask first: смена схемы SQLite; включение `set_active` в тот же `commit`; закрытие Q40 целиком; правка `bot_archived/`; смена текста или HTTP-кода ошибки сборки; коммит в git.
- Never: трогать ILP и `core/optimization/`; метить плиты до конца солвера; удалять падающий тест, чтобы «починить» прогон; писать секреты; развивать `bot_archived/` и `tests/archived/`; в этом скоупе выносить журнал исключений, резать `ProductionCompletionService` и чинить matplotlib.
