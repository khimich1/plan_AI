## Assumptions I'm Making

1. **Web-only.** React-мастер КП. Бот вне scope.
2. **`product_type = "composite_piles"`**, UI «Составные сваи». **`product_kind = "composite_pile"`** в прайсе, `nomenclature_guid` и `guid_gate` — тот же разрез, что `bridge_piles` / `bridge_pile`.
3. **Свои таблицы:** `composite_pile_prices`, `composite_pile_assemblies`, `kp_composite_piles`. В `pile_prices` и `kp_piles` составные не пишутся.
4. **Классы те же, что у цельных свай:** `B15`, `B20`, `B22_5`, `B25`, `B30_granite`. Колонки листа «Прайс»: `15`, `20`, `22.5`, `25`, `30 на граните`. Пустая ячейка — не цена.
5. **В КП и PDF хранится канон**, не написание менеджера. Это сознательно иначе, чем у мостовых свай.
6. **Слияние строк:** один ключ — канон + класс бетона. Разный класс — разные строки (как Q16 у цельных свай).
7. **Целая марка не из 123 строк** остаётся неразобранной. Менеджер правит текст. Парсер пару секций не угадывает.
8. **Секция, которой нет в прайсе,** разбирается, но расчёт блокируется, пока нет цены. Как у цельных свай.
9. **Хвостовая «у» цельных свай** на составные не распространяется. `guid_1c_u` для этого вида нет.
10. **Суффикс стыка — часть ключа.** Сопоставление с комплектацией идёт по полной марке: `-Св.ВП` раньше `-Св`, `-Св` раньше `-С`.
11. **Простой КП.** Ветка `isSimpleKp` и `SimpleProductInputStep`. Отдельный каркас мастера не строится.
12. **Стол цен и CLI** вызывают один парсер листа «Прайс». Остальные листы книги (себестоимость, расход) не импортируются.
13. **GUID — отдельный импорт**, не загрузка прайса. Книга сопоставления в репозиторий не коммитится. Тесты гоняют урезанный fixture.
14. **Сохранение в архив не блокируется** пустым GUID. Очередь спроса — уже существующий путь архива (`check_invoice_guids` → `guid_demand`). Ворота счёта, если они есть у других видов, для `composite_piles` подключаются той же картой видов и новым поведением save не становятся.
15. **Клиент, скидка, НДС, логистика, нумерация `kp_id`** — как у цельных свай. В этой спеке заново не описываются.

→ Если что-то неверно — поправьте до перехода к PLAN.

## Objective

Дать менеджеру отдельное КП на составные сваи серии 1.011.1-10 вып. 8. Заявка может содержать и целую сваю (`С140.30-С`), и секцию (`С60.30-ВС.1`). В таблице, PDF и XLSX остаются только канонические секции с ценой из прайса 18.09.2026. Точный GUID из листа 1С приклеивается сам. Пустой GUID уходит экономисту и КП не останавливает.

### User stories

| # | Как менеджер… | Я хочу… | Чтобы… |
|---|---------------|---------|--------|
| US-1 | создаю КП | выбрать «Составные сваи» отдельно от «Сваи» | не смешать каталоги |
| US-2 | в заявке `С140.30-С 5` | увидеть две секции по 5 штук | не раскладывать сваю по серии вручную |
| US-3 | в заявке уже секция, в любом написании | увидеть одну строку `С60.30-ВС.1` | цена и GUID искались по одному ключу |
| US-4 | одна секция пришла и из сваи, и отдельно | увидеть одну строку с суммой количества | не дублировать позицию в КП |
| US-5 | марки нет в комплектации или в прайсе | увидеть ошибку до PDF | не отдать клиенту выдуманный раскрой или цену |
| US-6 | сохраняю КП | получить PDF/XLSX только из секций и бейдж в архиве | клиент видел то, что продаётся |
| US-7 | у секции нет GUID | сохранить КП | экономист заведёт карточку отдельно, сделка не встанет |

### Reframed success criteria

| Требование | Критерий |
|------------|----------|
| «Как сваи» | Выбор типа → текст/фото/ИИ → таблица марка/класс/количество/цена → клиент → PDF/XLSX → архив |
| «Взрыв» | `С140.30-С × 5` даёт `С60.30-ВС.1 × 5` и `С80.30-НС.1 × 5` |
| «Канон» | `Сваи С 60.30-ВС.1`, `С 60.30-ВС.1`, латинские `C`/`B` становятся `С60.30-ВС.1` до цены и GUID |
| «Стыки не путаются» | `С140.30-С`, `С140.30-Св`, `С140.30-Св.ВП` дают три разные пары секций |
| «100% из прайса» | `get_composite_pile_price(canon, grade)`; нет пары — расчёт не проходит |
| «PDF» | В файле нет марки целой сваи |
| «GUID» | 41 точных совпадения листа 1С пишутся как `auto`. 31 имя не из серии не пишется. Архив без GUID сохраняется и открывает спрос |
| «Чужой каталог» | Составная позиция не появляется в `pile_prices` / `kp_piles` и не в производстве |

## Architecture

```
Picker «Составные сваи»
  → SimpleProductInputStep (текст / фото / ИИ)
  → нормализация марки до канона
  → целая марка есть в composite_pile_assemblies → 2 секции, qty копируется
  → иначе марка секции → 1 строка
  → иначе строка не разобрана
  → одинаковые (канон, класс) суммируются
  → Preview: Марка | Класс ▼ | Кол-во | Цена
  → Client → PDF/XLSX только секции → Archive
  → пустой GUID → guid_demand, save проходит
```

### Разбор строк

Порядок на одну строку заявки:

1. Снять префикс `Сваи`, пробелы, привести латинские `C`/`B` в марке к `С`/`В`. Регистр стыка: `Всв` → `ВСв`, `Нсв` → `НСв`. Слипшийся индекс `ВСв4` → `ВСв.4`. Класс бетона (`B25`, `22.5`) этим шагом не портится.
2. Класс и количество — тем же правилом, что `parse_pile_line`. Нет класса → `B25`. Нет количества → 1.
3. Если канон есть в `composite_pile_assemblies` — две секции, у каждой тот же класс и то же количество.
4. Иначе если канон — секция (`ВС` / `НС` / `ВСв` / `НСв`) — одна строка.
5. Иначе строка не разобрана (`pattern_not_matched`). Расчёт не идёт, пока менеджер не поправит список.

Ключ комплектации — полная марка. `С140.30-Св.ВП` не совпадает с `С140.30-Св` и не совпадает с `С140.30-С`.

Примеры:

```
С140.30-С 5
  → С60.30-ВС.1  B25  5
  → С80.30-НС.1  B25  5

С140.30-С B20 2
С60.30-ВС.1 3
  → С60.30-ВС.1  B20  2
  → С80.30-НС.1  B20  2
  → С60.30-ВС.1  B25  3

С140.30-С 2
С 60.30-ВС.1 3
  → С60.30-ВС.1  B25  5
  → С80.30-НС.1  B25  2

Сваи С 60.30-ВС.1 4
  → С60.30-ВС.1  B25  4

С140.30-Св 1          → пара ВСв / НСв, не стаканный стык
С140.30-Св.ВП 1       → пара с индексом .6
С999.30-С 1           → не разобрано
```

### Данные

`composite_pile_assemblies` — импорт листа «Комплектация»:

```sql
CREATE TABLE IF NOT EXISTS composite_pile_assemblies (
    pile_mark TEXT PRIMARY KEY,          -- канон С140.30-С / С140.30-Св / С140.30-Св.ВП
    joint_type TEXT NOT NULL,            -- стаканный | сварной | сварной с поперечным армированием
    upper_mark TEXT NOT NULL,            -- канон верхней секции
    lower_mark TEXT NOT NULL             -- канон нижней секции
);
```

Инвариант данных, не правило парсера: длина верхней + длина нижней = длина сваи (числа из марки, в дециметрах). Импорт 123 строк. Файл комплектации уже лежит в `банк знаний/`.

`composite_pile_prices`:

```sql
CREATE TABLE IF NOT EXISTS composite_pile_prices (
    mark TEXT NOT NULL,                  -- канон секции
    concrete_grade TEXT NOT NULL,        -- B15 | B20 | B22_5 | B25 | B30_granite
    price REAL NOT NULL,
    price_list_date TEXT,
    imported_at TEXT DEFAULT (datetime('now')),
    PRIMARY KEY (mark, concrete_grade)
);
```

Имя в прайсе `Сваи С 60.30-ВС.1` сохраняется как `С60.30-ВС.1`. Строка, которая не становится каноном секции, валит импорт, а не пропускается молча. Нулевая и пустая ячейка ценой не считаются.

`kp_composite_piles` — как `kp_piles`: канон, класс, количество, цена, цена со скидкой. Поля «исходная свая» нет.

### GUID

Импорт листа «Сваи составные — только в 1С» в `nomenclature_guid`:

- `product_kind = composite_pile`, ключ — канон секции.
- Имя 1С проходит тот же нормализатор. Совпало с каноном секции из комплектации или прайса, и GUID один — `match_status = auto`.
- Два GUID на один канон — `ambiguous`, автовыбор не делается (как у цельных свай).
- Имя не стало каноном секции (комплект, целая свая, «гранит», марка не из серии) — строка не пишется.
- `Прайс сваи составные.xls` не читается ни как цена, ни как GUID.

На архиве линии `composite_piles` идут в `order_lines_from_order_data` через карту `composite_piles → composite_pile`. Нет GUID — запись спроса и колокольчик, как у остальных видов. `assert_invoice_guids` на кнопку сохранения архива не вешается.

### Стол цен

`classify_price_filename`: подстрока `составн` даёт `composite_pile`. Токен `composite`, который сейчас только отвергается, заменяется. Превью и apply пишут `composite_pile_prices`. Ключ diff — пара (марка, класс), как у свай.

### PDF / XLSX

Колонки как у цельных свай: марка (канон), класс бетона, количество, цена, сумма. Строк целой сваи нет.

## Testing Strategy

| Уровень | Что |
|---------|-----|
| Unit | Нормализатор: пробел, префикс «Сваи», `C`/`B`, `Всв`, слипшийся индекс. Класс `B25` не превращается в кириллицу |
| Unit | Три стыка `С140.30-*` дают три разные пары. `С140.30-С × 5` → две секции × 5. Смешанный список суммирует только одинаковый канон и класс |
| Unit | `С999.30-С` не разобран. Секция без цены блокирует расчёт |
| Unit | Импорт комплектации: 123 строки, суммы длин. Импорт прайса: канон, пять классов, пустая ячейка не цена, кривое имя — ошибка |
| Unit | GUID: точное совпадение → `auto`; комплект и целая свая из листа не пишутся; два GUID → `ambiguous` |
| Integration | create → expand → grade → calculate → PDF без целой марки → save `kp_composite_piles` |
| Price desk | Файл «Прайс на составные сваи…» даёт preview `composite_pile`, не 422 |
| Archive | Бейдж и фильтр. Save без GUID проходит и открывает спрос |
| Regression | Плиты, цельные сваи, мостовые, ФБС, ступени, марши остаются зелёными |

Покрытие: каждый новый модуль `core/composite_pile_*` имеет pytest на примеры из этой спеки. Порог процентов на весь репозиторий не задаётся.

## Boundaries

### Always

- pytest и затронутый vitest до сдачи среза
- `product_type` после создания черновика не меняется
- Расчёт и сохранение состава блокируются, пока есть неразобранная строка или секция без цены
- Производство по-прежнему только плиты
- Канон пишется до lookup цены и GUID
- Раскрой только из `composite_pile_assemblies`

### Ask first

- Схема SQLite и новая зависимость
- Общий фреймворк на все виды КП
- Смена правила слияния (канон + класс)
- Подключение `assert_invoice_guids` к сохранению архива
- Импорт листов книги прайса кроме «Прайс»

### Never

- Писать составные в `pile_prices` / `kp_piles`
- Считать цену целой сваи одной позицией
- Угадывать пару секций, если марки нет в 123 строках
- Нечёткий GUID
- Брать цену или GUID из `Прайс сваи составные.xls`
- Класть марку целой сваи в PDF/XLSX
- Коммитить живую БД, секреты и книгу сопоставления GUID
- Тащить мостовые составные в этот срез
