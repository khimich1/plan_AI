## Assumptions I'm Making

1. Менеджер сверяет фото с полями в той же модалке «Договор поставки». Отдельное окно и второй проход зрения не нужны.
2. Предупреждение называет только цифры, которые контроль не принял: ИНН, КПП, ОГРН, расчётный счёт, корсчёт, БИК. Названия, адрес, почта и банк в эту фразу не входят.
3. Заполненное полное или краткое наименование не подсвечивается. Краткое имя, уже стоявшее у контрагента, пустой ответ модели не затирает и жёлтым не становится.
4. Пустой расчётный счёт, который не прошёл длину или ключ с БИК, остаётся пустым. Отбракованные цифры в поле не показываются.
5. Несколько принятых счетов по-прежнему выбираются списком. Это не «не прочитано», и счёт в предупреждение не попадает.
6. Масштаб есть только у фото. Word, Excel и PDF без картинки превью не увеличивают.
7. Жесты те же, что у исходного фото КП в `SourceImageQueueDrawer`: «−», «+», «По ширине», Ctrl+колёсико. Диапазон 50–300%, шаг 25%. Колёсико без Ctrl только прокручивает.
8. Колонка фото — половина модалки, не уже 320px. При прокрутке полей она остаётся наверху модалки. Отдельное окно по-прежнему не нужно.

→ Если что-то из этого неверно — править spec до плана.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| R1 | Предупреждение | После успешного разбора, если среди ИНН, КПП, ОГРН, счёта, корсчёта и БИК есть поле в `doubtful`, сверху `Alert` с тоном warning: «Проверьте по карточке: {подписи через запятую}.» Порядок подписей: ИНН, КПП, ОГРН, расчётный счёт, корсчёт, БИК |
| R2 | Пустой счёт | На фото «ДСТРОЙ 76» счёт не принят: поле пустое, жёлтая рамка есть, фраза называет «расчётный счёт». Цифр из ответа модели в поле нет |
| R3 | Названия | Непустое полное и краткое наименование не в `doubtful` и без жёлтой рамки. В предупреждение не входят |
| R4 | Список счетов | При двух и больше принятых счетах поле счёта пустое до выбора, но в предупреждении «расчётный счёт» нет. Выбор остаётся кнопками |
| R5 | Масштаб | Превью фото в модалке: кнопки «Уменьшить», «Увеличить», «По ширине», подпись процентов. Новый файл сбрасывает масштаб на 100%. Колонка не уже 320px и прилипает к верху модалки, пока листаются поля |
| R6 | Нет дыр в цифрах | Все шесть реквизитов приняты — предупреждения нет |

## Objective

Менеджер после разбора карточки сразу видит, какую цифру сверить с фото, и может увеличить снимок, не уходя с формы.

Успех на фото «ДСТРОЙ 76»: полное имя и «ДСТРОЙ 76 ООО» без жёлтой рамки; пустой расчётный счёт с рамкой; фраза «Проверьте по карточке: расчётный счёт.»; снимок увеличивается и уменьшается рядом с полями.

### Пользователь

Менеджер по продажам (`admin` / `manager`) на экране договора в архиве КП. Подтверждение и номер договора эта спека не меняет.

### Сценарии

1. **Фото, счёт не принят.** Разбор успешен. Счёт пустой и жёлтый. Предупреждение называет только его. Менеджер вписывает номер с увеличенного фото.
2. **Названия уже есть.** Полное имя пришло из карточки, краткое стояло у контрагента. Оба видны и не подсвечены. Предупреждение про них молчит.
3. **Два принятых счёта.** Список кнопок на месте. Предупреждение про счёт не говорит. Другая непрошедшая цифра, если она есть, в фразе остаётся.
4. **Все цифры приняты.** Предупреждения нет. Жёлтой рамки у этих шести полей нет.
5. **Word или PDF с текстом.** Превью-картинки нет, кнопок масштаба нет. Предупреждение по тем же правилам, если цифра не принята.
6. **Новое фото.** Масштаб снова 100%. Ctrl+колёсико меняет его, обычное колёсико не меняет.

## Экран

Предупреждение стоит над формой создания, под ошибкой разбора, если она есть. Подписи в фразе — человеческие, не ключи `inn` и `account`.

Жёлтая рамка остаётся у поля из `doubtful`. Для полного и краткого имени непустое значение само по себе снимает и рамку, и имя из `doubtful`. Рамку пустого счёта это не снимает.

Масштаб рисуется только когда слева есть изображение карточки. Колонка не уже 320px. При прокрутке модалки она остаётся у верхнего края, поля уезжают. Картинка шире колонки прокручивается внутри неё.

Контроль цифр, повтор зрения и отказ «это не карточка контрагента» остаются в спеке распознавания.

## Code Style

Фраза собирается из фиксированного порядка подписей. В тест попадает текст, который видит менеджер.

```tsx
const DIGIT_WARNING_LABELS = [
  ["inn", "ИНН"],
  ["kpp", "КПП"],
  ["ogrn", "ОГРН"],
  ["account", "расчётный счёт"],
  ["corr_account", "корсчёт"],
  ["bik", "БИК"],
] as const;
```

При двух и больше счетах ключ `account` в эту фразу не берётся.

## Testing Strategy

| Слой | Где | Что |
|---|---|---|
| Экран | `SupplyContractDrawer.test.tsx` | после разбора с пустым счётом и заполненными именами видна фраза «Проверьте по карточке: расчётный счёт.»; имена без `data-doubtful`; счёт с `data-doubtful` |
| Два счёта | там же | два счёта в списке, фраза про расчётный счёт отсутствует |
| Чисто | там же | ни одного сомнительного реквизита из шести — предупреждения нет |
| Масштаб | там же | «Увеличить» поднимает подпись выше 100%, «По ширине» возвращает 100%, Ctrl+колёсико меняет масштаб, колёсико без Ctrl не меняет |
| Имена | `tests/test_supply_contract_card_ocr.py` или тест экрана | непустое полное и краткое имя не подсвечиваются, даже если краткое пришло из контрагента, а не из ответа модели |

Карточку «ДСТРОЙ 76» в git не класть. Тест передаёт поля и `doubtful` через мок разбора.

## Boundaries

- **Always:** не показывать отбракованный счёт в поле; не включать названия в предупреждение; тесты без живого API.
- **Ask first:** вынос зума в общий компонент; другая фраза предупреждения; подсветка адреса и почты по новым правилам.
- **Never:** второй полный проход зрения; новый npm-пакет для масштаба; коммитить фото покупателей; выдавать номер договора на этом шаге.

## Success Criteria

- Разбор, где счёт в `doubtful`, а имена заполнены, показывает «Проверьте по карточке: расчётный счёт.» и не красит названия.
- Краткое имя, которое уже было в форме, остаётся после разбора с пустым `short_name`.
- Два счёта в `accounts` не добавляют «расчётный счёт» в предупреждение.
- Ответ без сомнительных цифр не показывает это предупреждение.
- У фото есть «Уменьшить», «Увеличить» и «По ширине»; масштаб не выходит за 50–300%.
- У загрузки Word кнопок масштаба нет.
