## Assumptions I'm Making

1. **Подтверждено в идее 2026-10-26.** Пользователь — менеджер на шаге «Плиты», сверка фото. Продукт только `plates`.
2. **Подтверждено.** ОК сразу записывает одну широкую строку активной страницы в её `batchReviewText`. «Применить решения» вызывает ту же запись для каждого слота этой страницы, где ОК ещё не нажат. Отдельной очереди помимо ненажатых ОК нет.
3. **Подтверждено.** Радио по умолчанию — «Подтвердить». Нижняя кнопка подтверждает и такие карточки.
4. **Подтверждено.** Поле замены не пересчитывается, когда менеджер правит марку. Первый раз, когда на этом слоте выбрано «Заменить» и поле пустое, в него один раз кладётся текущая подсказка `buildAutoSplitSuggestion`. Дальше текст поля не трогаем.
5. **Подтверждено.** Строка стала не шире 12 дм или её удалили до ОК — слот и выбор исчезают, замена в список не пишется. Текст, который менеджер уже набрал в списке, остаётся как он его набрал.
6. **Подтверждено.** После ОК «Подтвердить» правка той же строки, если она всё ещё шире 12 дм, снимает ОК. Радио и текст поля замены остаются.
7. **Принимаю, пока не поправят.** ОК «Подтвердить» живёт в сессии мастера на странице фото. Полная перезагрузка черновика может снова открыть карточку по широкой строке, которую подтвердили как есть: в тексте марка осталась. «Заменить» и «Исключить» переживают перезагрузку, потому что широкой строки в тексте уже нет.
8. Текстовый ввод без фото по-прежнему идёт в `POST .../wide-plates/resolve`. Этот путь не переписываем.
9. Суффикс нагрузки, verify OCR, гейты заводского реза и позиций без цены не меняем.
10. Коммит агент не делает без явной просьбы.

→ Если пункт 7 неверен — править spec до плана.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| D1 | К чему привязан блок | К слоту строки текста активной страницы. Не к `normalizeLineKey`, не к `live-wide-${index}` как к вечному id |
| D2 | Когда писать список | В момент ОК и в момент «Применить решения». Оба зовут одну функцию. Сервер в этот момент не зовём |
| D3 | Что делает низ | Нажимает все ненажатые ОК активной страницы, сверху вниз |
| D4 | Поле замены | Липкое. Правка заголовка его не меняет |
| D5 | Две одинаковые марки | Два слота. Правка первой не меняет вторую |
| D6 | Вставка строки выше | Слот остаётся на прежней плите |
| D7 | «Подтвердить» | Строка в списке та же, слот закрыт. Карточка не открывается, пока строку снова не сделают другой широкой |
| D8 | «Заменить» | Строка слота заменяется непустыми строками поля как есть, без пересчёта и без подгонки `п` |
| D9 | «Исключить» | Строка слота удаляется из текста страницы |
| D10 | Пустая замена | Текст страницы не меняется, ОК не ставится, на блоке ошибка |
| D11 | Чужое фото | ОК и низ пишут только активную страницу |
| D12 | «Готово, далее» | Широкая плита его больше не держит, когда на каждой странице очереди нет открытого слота. «Список верен» на сверке по-прежнему нужен сам по себе |
| D13 | Что не меняем | Контракт `wide-plates/resolve`, путь без фото, invalid width, unpriced, verify OCR |

## Objective

**Проблема.** На сверке фото блок «Нестандартная ширина» теряет решение, когда менеджер исправляет ложно распознанную строку. Словарь решений помнит марку (`normalizeLineKey`, `pruneWidePlateActions`) и номер `live-wide-${index}`. Правка текста марки для этого словаря — удаление выбора или перенос его на другую строку. Запись через `wide-plates/resolve` вдобавок расходилась со списком у фото.

**Цель.** Блок — живой вид одной строки списка у этого снимка. Правка строки меняет заголовок и количество этого блока. ОК и нижняя кнопка одной функцией пишут решение в текст этой страницы. Сервер видит уже записанный текст, когда список уходит дальше.

**Пользователь:** менеджер, шаг «Плиты», экран сверки с фото.

**Успех:** после ОК или после нижней кнопки список у этого фото содержит результат решения, карточка по закрытому слоту не возвращается от старого OCR этой страницы, соседний снимок не меняется. Исправление марки до ОК попадает в тот же блок. Текстовый ввод без фото ведёт себя как сейчас.

### Сценарии

1. **Одно фото, замена.** В списке `ПБ 76-15-8 13`. «Заменить», в поле две строки подсказки. ОК. В тексте страницы эти две строки, `76-15-8` нет. Карточки по этой строке нет. Запроса `wide-plates/resolve` нет.
2. **Нижняя кнопка.** Три широкие строки, радио не трогали (везде «Подтвердить»). «Применить решения» закрывает все три как подтверждённые. Строки в списке те же. Широкая плита больше не держит «Готово, далее».
3. **Часть уже с ОК.** На первой нажат ОК «Исключить», строка исчезла. На второй выбран «Заменить», ОК не нажат. Низ записывает вторую и не возвращает первую.
4. **Ложный OCR до ОК.** Слот показывает `ПБ 76-15-8 13`, выбрано «Заменить», в поле `ПБ 76-12-8 13` и `ПБ 76-3.0-8 13`. Менеджер в списке меняет строку на `ПБ 68-15-8 13`. Тот же блок: заголовок и количество от новой строки, радио «Заменить», поле по-прежнему про 76. ОК записывает в список именно текст поля.
5. **Правка в узкую.** Та же строка стала `ПБ 76-12-8 13` или её удалили до ОК. Блока нет. Подсказка замены в список не дописывается.
6. **Две одинаковые.** Две строки `ПБ 76-15-8 13`. Правка первой меняет только первый блок. Вторая остаётся со своим радио и своим полем.
7. **Вставка выше.** Над широкой строкой добавили другую. Решение остаётся на широкой, не на новой верхней.
8. **Подтвердить и поправить.** ОК «Подтвердить» закрыл блок, строка на месте. Менеджер меняет её на другую марку шире 12 дм. Тот же блок снова открыт, радио и поле те, что были, ОК снят.
9. **Пустая замена.** «Заменить», поле пустое или из одних пробелов. ОК и низ не меняют строку. На блоке ошибка. ОК не считается нажатым.
10. **Два фото.** ОК на первом меняет текст первого. Текст второго тот же. Переключение показывает список выбранного снимка. «Список верен» не возвращает уже заменённую марку первого.
11. **Текст без фото.** `ПБ 68-15-8п 2` по-прежнему решается через `wide-plates/resolve`, как сейчас.
12. **Сбой одной карточки в пачке.** Низ идёт сверху вниз. Успешные слоты остаются записанными. Слот с пустой заменой остаётся открытым с ошибкой, следующие за ним в этот клик не записываются.

## Code Style

Слот держится за строку текста. Одинаковая длина списка — тот же индекс. Длина изменилась — совпавшие строки в прежнем порядке сохраняют слот, одинаковые подряд не схлопываются. В одном разрыве между совпавшими ровно одна старая и одна новая строка — это правка того же слота. Остальные новые строки получают новые слоты. Старая строка без пары забирает слот с собой.

Запись одна и для ОК, и для низа. «Подтвердить» не меняет текст. «Исключить» удаляет строку по индексу. «Заменить» подставляет непустые строки поля вместо этой строки. Пустое поле — отказ, текст прежний.

```ts
type WideSlotDecision = {
  action: "confirm" | "replace" | "exclude";
  replacementText: string;
  accepted: boolean;
};

const applyWideSlot = (
  lines: string[],
  index: number,
  decision: WideSlotDecision,
): { ok: true; lines: string[] } | { ok: false; error: string } => {
  if (decision.action === "confirm") {
    return { ok: true, lines };
  }
  if (decision.action === "exclude") {
    return { ok: true, lines: lines.filter((_, lineIndex) => lineIndex !== index) };
  }
  const replacement = decision.replacementText
    .split("\n")
    .map((line) => line.trim())
    .filter(Boolean);
  if (replacement.length === 0) {
    return { ok: false, error: "Укажите заменяющие позиции." };
  }
  return {
    ok: true,
    lines: [...lines.slice(0, index), ...replacement, ...lines.slice(index + 1)],
  };
};
```

Поиск решения по `normalizeLineKey` для этого экрана не используется. `sourceLine` не ключ слота.

## Testing Strategy

Уровень — unit на чистые функции и тесты секции. Браузерный прогон этой спекой не требуется: сценарии воспроизводятся текстом страницы и состоянием слота.

| Тест | Что доказывает |
|------|----------------|
| Равная длина, одна строка изменилась | Слот с тем же радио и тем же полем, заголовок равен новой строке |
| Вставка строки выше | Слот остаётся на прежней плите |
| Две одинаковые марки, правка первой | Второй слот не меняется |
| Ширина стала ≤ 12 или строка удалена | Слота нет, текст замены в список не попал |
| `applyWideSlot` replace | В тексте строки поля, исходной марки нет |
| `applyWideSlot` exclude | Строки нет, соседи на месте |
| `applyWideSlot` confirm | Текст тот же, слот `accepted` |
| Пустое поле replace | Текст тот же, `ok: false` |
| ОК подтверждения, затем другая широкая марка той же строки | `accepted` снят, радио и поле прежние |
| Низ при одном отказе посередине | Верхние слоты записаны, отказавший открыт, нижние в этот вызов не записаны |
| Регрессия секции | Радио раскрывает поле только для «Заменить», на блоке есть ОК |

Путь без фото существующими тестами `flushThenResolveWidePlates` не ломаем: мастер на сверке фото их не вызывает. Покрытие всего репозитория не поднимаем.

## Boundaries

- **Always:** одна функция записи для ОК и низа; слот не искать по марке; поле замены не пересчитывать после первого заполнения; пустую замену не записывать; писать только активную страницу; прогнать команды из раздела Commands.
- **Ask first:** новый endpoint, правка `wide-plates/resolve`, сохранение ОК «Подтвердить» после полной перезагрузки, правка invalid width / unpriced / verify OCR, коммит.
- **Never:** откатывать выбранный «Заменить» в «Подтвердить» из-за несовпадения марки; дописывать замену, если строка уже не шире 12 дм; звать resolve с ОК или низа на сверке фото; писать секреты; удалять падающий тест без замены, которая ловит тот же разрыв.
