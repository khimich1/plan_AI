# Spec: Бланк спецификации как в № 650

> **Продолжает:** [`specification-on-approval.md`](specification-on-approval.md). Кнопки, абзацы, ворота производства и пустой номер счёта не меняются.  
> **План:** [`2026-09-30-specification-print-form.md`](../develop/plans/2026-09-30-specification-print-form.md)  
> **Фаза SDD:** SPECIFY ✅ → PLAN ✅, код по принятому плану  
> **Статус:** реализовано, коммита нет  
> **Дата:** 2026-09-30  
> **Образец:** `Спецификация № 650 от 18.09.2026`, лист «Лист_1».  
> **Связанные модули:** `core/specification_xlsx.py`, `core/specification_text.py`, `build_preamble` в `core/supply_contract.py`, бланк договора `templates/supply_contract.docx`.  
> **Рядом, не это:** новые схемы оплаты, склонение ФИО, правка сохранённого договора, отправка файла в 1С.  
> **PDF:** отдельная кнопка — [`specification-pdf.md`](specification-pdf.md). Этот бланк xlsx не меняется.

Эта spec заменяет сборку книги в `build_specification_xlsx`: лист больше не рисуется восемью колонками. Текст абзацев по-прежнему приходит из `render_specification`.

## Assumptions I'm Making

1. Менеджер сверяет скачанный xlsx с № 650 на экране и в печати A4. Успех — тот же бланк: рамка, сетка, шрифт, поля, подписи двумя колонками.
2. В репозиторий кладётся пустой бланк, снятый с № 650: стили, объединения, ширины, печать. Одна строка товара как образец и подвал. 42 позиции, покупатель «ЭТАЛОН», ИНН `9726099814` и суммы этой сделки в файл не входят.
3. Число строк в КП любое. Генератор повторяет строку-образец и сдвигает подвал. Номера строк № 650 (товар с 15-й, итог на 58-й) в коде не зашиты.
4. В ячейки условий пишутся уже собранные абзацы. Перед ними остаются подписи бланка: «Условия оплаты:», «Условия поставки:», «Вид поставки:».
5. Имя покупателя чинится только при печати спецификации. `build_preamble` для docx договора не меняется. Сохранённое полное имя в договоре не переписывается.
6. Родительный падеж должности и ФИО не вычисляется. В «в лице» попадает то, что лежит в карточке договора.
7. Поставщик в бланке статический, как в № 650: ООО «ЖБК СТАРТ», ИНН `4401082520`, КПП `440101001`, Шишов А. В. Шапка КП «Комбинат ЖБК» по-прежнему не используется.
8. Марки бетона в образце № 650 нет. Отдельная строка «Марка бетона» в эту печать не добавляется.

→ Если что-то из этого неверно — править spec до плана.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| D1 | Источник вида | `templates/specification.xlsx`. Код подставляет значения и размножает строку товара. Колонки, рамки и шрифт в коде не задаются |
| D2 | Чужие данные | Заполненный № 650 в репозиторий не коммитится. Бланк без позиций, сумм и покупателя той сделки |
| D3 | Строки | Одна строка-образец между шапкой и «Итого:». Для каждой позиции — копия её объединений и стиля. Подвал сдвигается на число позиций минус одна |
| D4 | Сдвиг объединений | Диапазоны переносятся явно. Полагаться на то, что `insert_rows` сам починит объединения, нельзя |
| D5 | Условия | Три ячейки подвала. Текст: подпись бланка, пробел, абзац `render_specification`. Схемы оплаты не заменяются двумя суммами из № 650 |
| D6 | Преамбула | Каркас № 650: полное имя поставщика, «именуемое в дальнейшем «Поставщик»», «с одной стороны», покупатель, «с другой стороны», «Стороны», «настоящую Спецификацию», «изготовить и отгрузить». Второго «в лице» нет |
| D7 | Повтор формы | Если полное имя уже начинается с «Общество с ограниченной ответственностью» или «Акционерное общество», эта форма в кавычки второй раз не оборачивается. Для остальных видов — как `build_preamble` сейчас |
| D8 | Подпись покупателя | Краткое имя из договора. Приставка «ООО» добавляется только если в кратком имени ещё нет ни «ООО», ни «Общество с ограниченной ответственностью» |
| D9 | Падеж | Не склонять. «Директор Либинзон Дмитрий Евгеньевич» печатается так, если так записано в договоре |
| D10 | Пропись итога | Как в ячейке № 650: цифры, затем пропись в скобках с заглавной и копейками, затем «в т.ч. НДС». Это заменяет короткую пропись текущей книги только в xlsx |
| D11 | Номер и дата | Номер счёта по-прежнему «_____», пока пуст `order_number_1c`. Дата спецификации — дата первого сохранения. Дата договора берётся из договора, пустой «от года» из № 650 не копируется |
| D12 | API | `GET .../specification/file` по-прежнему отдаёт байты и в папку обмена не пишет |

## Objective

Менеджер открывает спецификацию рядом с № 650 и видит тот же бланк. Меняются номер, дата, стороны, таблица и три абзаца условий. Рамка и подписи двумя колонками не разъезжаются от числа позиций.

Успех: книга с одной позицией и книга с сорока позициями обе печатаются на ширину A4, подвал с «Условия оплаты:» и двумя подписями на месте, в тексте нет второго «Общество с ограниченной ответственностью» вокруг имени, где форма уже есть.

### Пользователь

Менеджер КП. Сверяет xlsx с образцом № 650.

### Сценарии

1. **Одна позиция.** Строка товара одна. Под ней «Итого:», пропись, три абзаца с подписями бланка, слева поставщик, справа покупатель, у каждого «М.П.».
2. **Сорок позиций.** Сорок копий строки-образца. Подвал ниже последней. Объединения первой и последней строки товара совпадают с образцом строки, сдвинутым на номер строки.
3. **Имя уже с формой.** Полное имя «Общество с ограниченной ответственностью «Специализированный застройщик «МД-Строй»». В преамбуле форма один раз. В подписи краткое имя из договора; «ООО» не приписывается повторно, если оно уже есть.
4. **Имя без формы.** Полное имя «ЭТАЛОН», вид ООО. Преамбула содержит «Общество с ограниченной ответственностью «ЭТАЛОН»». Подпись: «ООО» и краткое имя, если в кратком ещё нет формы.
5. **Падеж как в карточке.** Должность «Директор» и ФИО в именительном попадают в «в лице» без склонения.
6. **Условия.** Ячейка начинается с «Условия оплаты:» и дальше содержит абзац выбранной схемы, в том числе «50% + доля + остаток». То же для поставки и вида поставки.
7. **Пустой номер.** В заголовке «№ _____». Дата договора заполнена. После появления `order_number_1c` номер подставляется, сетка та же.

## Бланк

Лист «Лист_1». Узкие колонки и объединения как в № 650, не A–H.

Строка товара: №, наименование, количество, «шт», цена, ставка НДС, сумма НДС, сумма. Шапка таблицы: «Товары (работы, услуги)».

Подвал, который код находит по подписи ячейки, а не по номеру строки:

| Якорь | Что пишет код |
|---|---|
| Заголовок спецификации | номер счёта или `_____`, дата спецификации, номер и дата договора |
| Город и дата прописью | «г. Кострома» и дата спецификации, как в бланке |
| Преамбула | каркас D6 и покупатель по D7–D8 |
| Строка товара | наименование, количество, цена, 22, сумма НДС, сумма |
| «Итого:» | итог к оплате |
| «В т.ч. НДС (22%):» | сумма НДС по строкам |
| «Итого с НДС:» | тот же итог |
| Строка «Всего наименований» | число позиций, цифры итога, пропись с копейками, НДС |
| «Условия оплаты:» | подпись и абзац оплаты |
| «Условия поставки:» | подпись и абзац срока |
| «Вид поставки:» | подпись и абзац вида поставки |
| «Поставщик» / «Покупатель» | блоки подписи на одной горизонтали |

Блок поставщика в бланке не переписывается кодом, кроме короткого «Шишов А. В.» там, где бланк уже так напечатан.

## Code Style

Генератор возвращает байты. Якорь ищется по тексту ячейки бланка.

```python
workbook = load_workbook(template)
sheet = workbook["Лист_1"]
fill_preamble(sheet, buyer_paragraph)
replicate_item_row(sheet, lines)
fill_anchor(sheet, "Условия оплаты:", payment_paragraph)
```

Договорный docx этот модуль не открывает.

## Testing Strategy

| Слой | Где | Что |
|---|---|---|
| Имя | `tests/test_specification_buyer.py` | полное имя с «Общество с ограниченной ответственностью» не удваивается; голое «ЭТАЛОН» оборачивается один раз; «Директор Иванов Иван Иванович» остаётся в именительном; краткое имя без «ООО» получает приставку, имя с «ООО» — нет |
| Книга | `tests/test_specification_xlsx.py` | 1 и 40 строк; у первой и последней строки товара те же объединения, что у строки-образца; «Условия оплаты:» ниже последней позиции; «Поставщик» и «Покупатель» в одной строке; в файле нет «ЭТАЛОН», `9726099814`, `3554802`; печать `fitToWidth = 1` |
| Регрессия текста | `tests/test_specification_text.py` | схемы оплаты и ворота абзацев как раньше |

Живой Excel менеджера в тестах не открывается. Сверка «рядом с № 650» — ручная, после приёмки плана.

## Boundaries

- **Always:** вид из `templates/specification.xlsx`; строка товара копируется; подвал сдвигается; три абзаца наши, с подписями бланка; форма покупателя не удваивается; договор в базе не правится; байты не пишутся в папку обмена.
- **Ask first:** склонение ФИО; правка `build_preamble` для docx; другой файл-образец вместо № 650; возврат восьми колонок.
- **Never:** коммитить заполненный № 650 с чужими позициями и ИНН покупателя; зашивать номер строки 58; рисовать рамку и ширины в коде; подменять выбранную схему текстом двух сумм из № 650.
