# Spec: Карточка заказа «На согласовании»

> **Источник идеи:** [`ai_docs/ideas/archive-on-approval.md`](../ideas/archive-on-approval.md)  
> **План:** [`ai_docs/develop/plans/2026-09-28-archive-on-approval.md`](../develop/plans/2026-09-28-archive-on-approval.md)  
> **Фаза SDD:** SPECIFY ✅ → PLAN  
> **Статус:** номер счёта приходит обратным JSON из 1С. Разбор ответа и ручной ввод в этот контур не входят. Код не писать до приёмки плана.  
> **Дата:** 2026-09-28  
> **Связанные модули:** карточка архива (`OfferDetailsDrawer`), вкладки (`ArchiveSectionTabs`), перевод в производство (`move_to_production`), договор (`attach_contract_number`), ворота GUID (`assert_invoice_guids`), пример JSON `docs/specs/1c-kp-export-example.json`, ТЗ `docs/specs/1c-integration-tz-v2.md`.  
> **Рядом, не это:** спецификация к заказу, sync-агент, разбор `invoice_ack`, поле ввода номера, график поставки, живой HTTP в 1С.
> **Контракт файла с 2026-10-01:** имя «Счёт на оплату», ключи `event` / `action` / `НомерЗаказа` и имена `invoice_create_` / `invoice_update_` заменены спекой [`kp-1c-delta.md`](kp-1c-delta.md). Карточка, вкладки, оплата и ворота производства этой заменой не отменяются.

## Assumptions I'm Making

1. Пользователь карточки — менеджер КП, роли `admin` и `manager`. Тот же доступ, что у архива.
2. Статус хранится строкой в `kp_meta.status`, как «в архиве» и «в работе». Новое значение — `на согласовании`.
3. Одна запись КП меняет заголовок: в архиве это КП, после первой выгрузки это счёт. Отдельной сущности «счёт» нет.
4. Исходящий документ называется «Счёт на оплату». `attach_contract_number` принимает это имя так же, как сейчас принимает «КоммерческоеПредложение».
5. Номер счёта — колонка `KP_offers.order_number_1c`. Её заполнит разбор обратного JSON из 1С. Этого разбора ещё нет: контур номер не пишет и поле ввода не показывает. Пустая колонка оставляет шапку «номер ещё не пришёл из 1С».
6. Оплата — отметка менеджера `kp_meta.paid_at`. Кнопка «В производство» включается, когда `paid_at` непустой и `order_number_1c` непустой.
7. «Отправка» — запись UTF-8 JSON в `settings.exchange_export_dir`. HTTP-вызова 1С нет.
8. Суммы в JSON — те же, что карточка уже показывает по этому `kp_id`. Отдельную формулу НДС сборщик не вводит.
9. «Добавить» и «Редактировать» на согласовании открывают тот же конструктор, что в архиве, и сохраняют тот же `kp_id`.
10. График поставки и блок готовности на статусе «на согласовании» не показываются.

→ Если что-то из этого неверно — править spec до плана.

## Decisions locked

| # | Тема | Решение |
|---|------|---------|
| D1 | Вкладки | «В архиве», «На согласовании», «В производстве», «Выполненные». Заказ в одной вкладке |
| D2 | Статус | `на согласовании` попадает только в новую вкладку. «в работе» и «На СГП» остаются в «В производстве» |
| D3 | Карточка | Три полки: шапка с одним действием, итоги и состав, документы. JSON на экран не выводится |
| D4 | Первая отправка | Кнопка «Отправить в 1С» только из «в архиве». Успех записи файла переводит статус |
| D5 | Исправление | Кнопка «Отправить исправление» только при непустом `order_number_1c` и отличии состава от последнего успешно ушедшего снимка |
| D6 | Номер | Шапка читает `order_number_1c`. Поля ввода нет. Пусто — «номер ещё не пришёл из 1С» |

| D8 | Производство | «В производство» видно на согласовании и серое, пока нет оплаты или номера. По нажатию — сегодняшний диалог срока, затем статус «в работе» |
| D9 | Контрагент и договор | Оба нужны до первой отправки. Смена контрагента после отправки не входит. Договор создаётся в архиве; на согласовании полка документов открывает уже существующий |
| D10 | GUID | `assert_invoice_guids` до записи файла. Одна строка без GUID блокирует весь счёт |

| D12 | Спецификация | На карточке нет пустого блока «спецификация» |

## Objective

Менеджер в архиве видит, где заказ, сколько он стоит и какое одно действие сейчас доступно. Отправка собирает счёт для 1С и переносит заказ в «На согласовании». Там заказ ещё можно править. В цех он уходит, когда отмечена оплата и в `order_number_1c` уже лежит номер счёта.

Успех: из архива нельзя уйти в производство, минуя счёт; исправление не уходит без номера; без оплаты или без номера кнопка производства не срабатывает; карточка не показывает файл обмена.

### Пользователь

Менеджер по продажам в карточке коммерческого архива.

### Сценарии

1. **Архив, нет контрагента.** Шапка содержит форму «Занести контрагента». Кнопка «Отправить в 1С» серая, под ней «Сначала занесите контрагента».
2. **Архив, контрагент есть, договора нет.** Формы привязки нет. Кнопка серая, причина «Нет действующего договора поставки».
3. **Архив, готов к отправке.** Шапка: клиент, ИНН, КПП, менеджер, дата, строка «КП · ещё не в 1С» и фиолетовая «Отправить в 1С». Итоги с «(+ Добавить)» и «Редактировать». Состав. Полка «Документы»: PDF, XLSX, XLSX (доставка в цене), схема, договор. «Удалить КП» отдельно от полки.
4. **Отправка.** Программа проверяет контрагента, действующий договор и GUID строк. Пишет `invoice_create_{kp_id}_{ts}.json`. Статус становится «на согласовании». Заказ исчезает из «В архиве» и появляется в «На согласовании». Снимок состава запоминается.
5. **На согласовании, номера нет.** Заголовок «Счёт · номер ещё не пришёл из 1С». Поля ввода нет. «Добавить» и «Редактировать» работают. Если состав уже изменён, под шапкой «Исправление отправится, когда номер будет известен». «В производство» серое, подпись «нужен номер счёта».
6. **Номер уже в колонке, правок нет, оплаты нет.** Заголовок «Счёт {номер}». Тихая строка «В 1С ушло без правок». «В производство» серое, подпись «после оплаты».
7. **Номер есть, состав изменён.** Фиолетовая «Отправить исправление». Файл `invoice_update_{kp_id}_{ts}.json` содержит `НомерЗаказа`. Статус не меняется. После успеха снимок обновляется, кнопка снова гаснет.
8. **Оплата и номер.** «Оплачен» при уже лежащем в колонке номере включает «В производство». Диалог срока тот же, что сегодня. После подтверждения статус «в работе», заказ во вкладке «В производстве». `paid_at` сохраняется. Оплата без номера кнопку не включает.
9. **Снять оплату.** Доступно только в «на согласовании». `paid_at` очищается, «В производство» снова серое.
10. **Ошибка GUID.** Файл не пишется, статус не меняется. Менеджер видит русскую причину по строке («нет GUID 1С» и что сделать), не тело JSON.

## Карточка

Ширина остаётся как у текущего drawer. Три полки сверху вниз.

**Шапка.** Клиент, ИНН / КПП, менеджер, дата. Одна строка фазы и одна фиолетовая кнопка. Форма контрагента только в сценарии 1. Номер только текстом из `order_number_1c`, без поля ввода.

| Фаза | Строка фазы | Фиолетовая кнопка |
|---|---|---|
| в архиве, нельзя отправить | причина серым под кнопкой | «Отправить в 1С» серая |
| в архиве, можно | «КП · ещё не в 1С» | «Отправить в 1С» |
| на согласовании, нет номера | «Счёт · номер ещё не пришёл из 1С» | нет. Серое «В производство», подпись «нужен номер счёта» |
| на согласовании, номер есть, оплаты нет | «Счёт {номер}» | «Отправить исправление», если снимок изменился. Серое «В производство», подпись «после оплаты» |
| оплачен и номер есть | «Счёт {номер}» | «В производство». «Отправить исправление», если снимок изменился |

**Итоги и состав.** Для «в архиве» и «на согласовании» итоги только для чтения. «(+ Добавить)» и «Редактировать» открывают конструктор. Скидка в шапке итогов не редактируется отдельным полем: она меняется в конструкторе, как сегодня в архиве.

**Документы.** PDF, XLSX, XLSX (доставка в цене), схема, договор. Договор на согласовании открывает существующий, новый из этого статуса не создаётся. «Удалить КП» стоит отдельно, правила удаления этой спекой не меняются.

Блок готовности и «График поставки» появляются с переходом в «в работе», как сегодня для производства.

## JSON

Кодировка UTF-8. Каталог — `exchange_export_dir`. Имя файла: `invoice_create_{kp_id}_{ts}.json` или `invoice_update_{kp_id}_{ts}.json`. `ts` — метка времени, чтобы повтор не затирал предыдущий файл.

Обязательная шапка:

| Поле | Откуда |
|---|---|
| `event` | `invoice_export` |
| `action` | `create` или `update` |
| `Документ` | `Счёт на оплату` |
| `НомерВПриложении` | `kp_id` |
| `НомерДоговора` | действующий договор контрагента, сразу после `Контрагент` |
| `НомерЗаказа` | только `update`: `order_number_1c` |
| `Дата` | дата КП |
| `Контрагент` | имя, код 1С, GUID если есть, ИНН, КПП |
| `Менеджер` | менеджер КП |
| `ПроцентСкидки`, суммы, `Товары` | цифры карточки этого `kp_id` |
| GUID строки | `assert_invoice_guids` |

`create` поле `НомерЗаказа` не содержит. `update` без номера не пишется.

Статус в базе меняется только после успешной записи файла. Если запись не удалась, статус остаётся прежним и менеджер видит ошибку. Повторное нажатие в архиве может создать второй `create`, если первый файл уже лежит, а статус не сменился. Дедуп на стороне 1С — по `НомерВПриложении`. Отдельной таблицы исходящих файлов нет.

Снимок — хеш канонического состава: строки (номенклатура, количество, цена, скидка), скидка заказа, доставка, итог. Пишется в `KP_offers.invoice_snapshot_hash` вместе с успешной записью. Кнопка исправления сравнивает текущий состав с этим хешем.

## Данные

На `kp_meta`:

```sql
paid_at TEXT
```

Пустое `paid_at` — не оплачен. Непустое — момент отметки, ISO-строка локального времени, как остальные метки в архиве.

На `KP_offers` колонки `order_number_1c` и `order_status_1c` уже есть. Эта спека добавляет:

```sql
invoice_snapshot_hash TEXT
```

`order_status_1c` эта кнопка не заполняет.

Группировка списка в `core/kp/offers_read.py`: статус `на согласовании` → секция `on_approval`. Остальные секции не меняют состав своих статусов.

`move_to_production` принимает исходный статус `на согласовании`, непустое `paid_at` и непустой `order_number_1c`. Из «в архиве» перевод в производство отказывается. Оплата без номера и номер без оплаты оба дают отказ. Конструктор дополнения (`commercial_draft_lifecycle`) принимает «в архиве» и «на согласовании». При сохранении конструктора статус «на согласовании» не сбрасывается в «в архиве».

Привязка контрагента по-прежнему только из «в архиве».

## API

Маршруты под тем же доступом, что карточка архива. КП читает автор или admin, как остальные правки архива.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/commercial/archive/{kp_id}/invoice-export` | Сценарий 4. Тело пустое. Ответ — карточка со статусом «на согласовании» |
| POST | `/commercial/archive/{kp_id}/invoice-correction` | Сценарий 7 |
| POST | `/commercial/archive/{kp_id}/payment` | `{ "paid": true }` или `{ "paid": false }`. `false` только пока статус «на согласовании» |
| POST | существующий move-to-production | Дополнительно требует статус «на согласовании», `paid_at` и `order_number_1c` |

Отказы — 422 с русским текстом, как остальные ошибки архива.

Список архива принимает `section=on_approval`.

## Code Style

Ошибки по-русски, статус — русская строка, как у соседних статусов. Сборщик возвращает словарь, не пишет файл. Файл пишет сервис после ворот.

```python
document = build_invoice_document(offer, contract_number=number, action="create")
attach_contract_number(document, counterparty_id, active_contract)
assert_invoice_guids(lines, conn)
```

Кнопка на клиенте не собирает JSON сама. Она вызывает маршрут и рисует вернувшуюся карточку.

## Boundaries

- **Always:** одна вкладка на заказ; статус меняется после записи файла; исправление содержит `НомерЗаказа`; производство только из «на согласовании» и только при `paid_at` вместе с номером счёта; ошибки по-русски; тесты на ворота, хеш и запрет производства из архива.
- **Ask first:** другое имя документа или ключа `НомерЗаказа`; авторазбор `invoice_ack`; отметка оплаты из файла 1С; смена контрагента после отправки; хранить тело JSON в БД.
- **Never:** HTTP в 1С; поле ввода номера; показывать JSON и GUID менеджеру; пустой блок спецификации; переводить в производство из «в архиве»; слать `update` без номера; сбрасывать «на согласовании» в «в архиве» при сохранении конструктора; коммитить файлы из папки обмена.

## Success Criteria

- [ ] Вкладки четыре. Заказ со статусом «на согласовании» виден только в «На согласовании»
- [ ] В архиве одна фиолетовая кнопка «Отправить в 1С». PDF и договор не стоят с ней в одном ряду. «Удалить КП» отдельно
- [ ] Без контрагента, без договора или без GUID файл не создаётся и статус не меняется
- [ ] Успешный create пишет `invoice_create_*.json` с «Счёт на оплату» и `НомерДоговора`, статус становится «на согласовании»
- [ ] Суммы JSON совпадают с суммами этой карточки
- [ ] На согласовании «Добавить» и «Редактировать» открывают конструктор и оставляют статус «на согласовании»
- [ ] Пока `order_number_1c` пуст, на карточке нет поля ввода и исправление не отправляется
- [ ] «Отправить исправление» пишет `invoice_update_*.json` с `НомерЗаказа` только если снимок состава изменился
- [ ] «В производство» из архива недоступно. На согласовании оно серое, пока нет `paid_at` или пуст номер счёта, и переводит в «в работе» только когда есть оба и подтверждён срок
- [ ] На согласовании нет графика поставки, блока готовности и пустой спецификации

## Open Questions

Блокирующих нет. Имя «Счёт на оплату» и ключ `НомерЗаказа` сверяются с 1С при первой живой передаче файла; экран от переименования ключа не меняется.
