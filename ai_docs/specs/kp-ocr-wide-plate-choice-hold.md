## Assumptions I'm Making

Подтверждено в этом чате 2026-10-24, если не сказано иное.

1. **Подтверждено.** Обычный путь родителя остаётся. Несколько готовых фото этой сессии, «Применить решения», партии не схлопываются, список замены лежит на своём фото, сообщения про число списков нет. Эту спеку тот путь не переоткрывает.
2. **Подтверждено.** «Радио» в ревью — три переключателя карточки «Нестандартная ширина»: «Подтвердить», «Заменить», «Исключить». Баг: после розовой ошибки менеджер видел «Заменить», а следующая запись черновика сама ставит «Подтвердить».
3. **Подтверждено по ревью кода.** Сразу после отказа zip переключатель ещё на месте. Ломается следующая запись черновика: следующее фото, «Список верен», правка строки, смена марки бетона. Ожидание 15 секунд и возврат фокуса в окно сами по себе переключатель не меняют.
4. **Подтверждено.** Неширокая правка OCR, которая до «Список верен» не попадает в партию, в эту спеку не входит. Это следствие D9 родителя, не баг удержания выбора.
5. **Подтверждено.** Запасная ветка `?? storeText` в сборщике flush на экран не влияет. В этой спеке её не трогаем.
6. **Подтверждено.** Суффикс «п», потолок в две строки, verify OCR, заводской рез и позиции без цены остаются как в родителе. Нового endpoint нет. Коммит без явной просьбы не делать.

## Objective

**Проблема.** Родитель закрыл обычную сверку: список замены пишется на своё фото. Если zip всё же отказывает (в очереди есть `pending` или `error`, либо партий и страниц разное число), на карточке «Нестандартная ширина» остаётся розовая ошибка «Число списков не совпадает с числом фото. Список у снимков не изменён.», а в списке у фото остаётся старая марка, например `ПБ 76-15-8 13`.

Сразу после ошибки переключатель ещё стоит на «Заменить» или «Исключить». Дальше ломаются два места.

1. Перед resolve мастер ставит `widePlateChoicesHeld`. Успех и ошибка самого запроса флаг снимают. Ветка `!layout.ok` в `handleApplyWidePlates` выходит без снятия. Пока флаг истинный, `hydrate-draft` делает `return state` и выбрасывает весь новый черновик: шаг, клиента, текст, `lastDraft`.
2. Карточка берёт строки не из store, а из черновика react-query, прогнанного через `overlayDraftWithLiveWideLines`. Кэш запроса после отказа специально не обновляют. Следующая запись (`update` следующего фото, «Список верен», правка строки, смена марки) кладёт в кэш уже разрешённый черновик. Старых id широких строк в нём нет. В списке у фото марка ещё есть, overlay даёт `live-wide-0`. Выбор в store лежит под прежним id. `WidePlatesInlineSection` не находит его и показывает «Подтвердить». Повторное «Применить решения» видит пустой серверный список, выходит до resolve и снимает удержание, страницу не записав.

Боковая колонка смотрит на серверный черновик без overlay. После обновления кэша `wide_plates_resolved` уже истинно, и переход к клиенту может открыться, пока карточка на шаге «Плиты» снова показывает старую марку. Кнопка «Готово, далее» на самом шаге смотрит на overlay и остаётся закрытой. Два входа расходятся.

**Цель.** После розовой ошибки переключатель остаётся тем, что выбрал менеджер, вместе с текстом замены. Следующее фото и «Список верен» по-прежнему обновляют черновик. Список чужого фото не выдумывается. Обычный успешный путь родителя не меняется.

**Пользователь:** менеджер на шаге «Плиты», экран сверки с фото, карточка «Нестандартная ширина».

**Успех:** розовая ошибка на месте, в списке у фото по-прежнему `ПБ 76-15-8 13`, переключатель по-прежнему «Заменить» и в поле те же строки. После распознавания следующего снимка store получил новый черновик, а переключатель на этой марке не стал «Подтвердить».

### Сценарии

1. **Отказ zip, менеджер ничего больше не нажимает.** Две страницы, одна ещё `pending` или `error`, либо партий не столько, сколько страниц. «Заменить», в поле две или четыре строки, «Применить решения». Ошибка про число списков есть. Список страниц не выдуман. Переключатель «Заменить», текст поля на месте. «Исключить» в том же сценарии остаётся «Исключить».
2. **Следующее фото после отказа.** Распознавание следующего кадра дописывает свою партию и обновляет store: шаг, `lastDraft`, текст нового снимка. На прежнем фото переключатель той же марки не становится «Подтвердить». Текст замены не пропадает.
3. **Повтор «Применить решения».** Серверный `wide_plate_lines` уже пуст, потому что resolve прошёл, а страница не записана. Кнопка снова шлёт «Заменить» или «Исключить» по марке со страницы. Она не выходит как пустой список и не снимает выбор, не записав страницу. Если длины снова не сошлись, ошибка остаётся, переключатель тоже.
4. **Успешный путь родителя.** Все фото `ready`, длины совпали. Ошибки нет, у активного фото строки замены, этой широкой марки нет, переключатель по ней не нужен. Соседнее фото не получает чужой список.
5. **«Список верен» при открытой ошибке.** Кнопка доступна и шлёт текст страниц, включая ещё не заменённую марку. Ответ update не выбрасывается из store. После сброса очереди смысл `mode: "replace"` тот же, что в родителе.
6. **Переход к клиенту.** Пока список на экране сверки содержит эту широкую марку, боковая колонка не пускает на шаг клиента из‑за одного только `wide_plates_resolved: true` на сервере. «Готово, далее» тоже остаётся закрытой, пока марка в overlay.
7. **Текст без фото.** Замена широкой плиты без очереди фото работает как сейчас. Флаг удержания её не глушит.

## Code Style

Сейчас удержание выглядит как защита выбора, а по факту глушит черновик. Так делать нельзя.

```ts
case "hydrate-draft": {
  if (state.widePlateChoicesHeld) {
    return state;
  }
```

И карточка не находит выбор после смены id:

```ts
const currentDecision = decisions[item.id] ?? { action: "confirm", replacementText: "" };
```

Новый черновик сливается как обычный `hydrate-draft`. Выбор «Заменить» или «Исключить» для марки, которая ещё есть в тексте страницы, сохраняется, даже если в пришедшем черновике `wide_plates_resolved === true` и id строки другой. «Подтвердить» по-прежнему запасной вариант только для марки, по которой менеджер ничего не выбирал.

Повторная сборка решений для apply смотрит на строки списка страницы. Пустой серверный `wide_plate_lines` их не отменяет:

```ts
if (decisions.length === 0) {
  return;
}
```

Эта ветка остаётся для случая, когда широких марок на странице нет. Она не срабатывает, когда марка на странице есть и по ней уже выбран «Заменить» или «Исключить».

`normalizeLineKey` и `widePlateMatchKey` не ослабляем: `ПБ 76-15-8 13` и `ПБ 76-15-8п 13` по-прежнему одна марка. Список у фото до apply не переписываем.

## Testing Strategy

Уровень — unit. Браузерный прогон этой спекой не требуется: расхождение видно по тому, переживает ли «Заменить» смену id и проходит ли следующий `hydrate-draft`. Сквозной прогон мастера — на фазе IMPLEMENT, если в сессии есть стенд.

Новые тесты красные на текущем коде: `hydrate-draft` при флаге возвращает прежний state, а карточка по `live-wide-0` показывает «Подтвердить», хотя выбор записан на прежний id той же марки.

## Boundaries

- **Always:** после отказа zip сохранять «Заменить» и «Исключить» по марке, пока строка есть в списке у фото; следующие hydrate принимают остальные поля черновика; пары страниц не угадывать; успешный путь родителя не ломать; прогнать команды из раздела Commands.
- **Ask first:** новый endpoint, новое поле в `update` или `wide-plates/resolve`, смена смысла `mode: "replace"`, правка invalid width / unpriced, коммит.
- **Never:** дописывать или снимать «п» до apply; выключать verify OCR; ограничивать замену двумя строками; класть список одной страницы на другую; глушить весь `hydrate-draft` одним флагом; писать секреты; менять `tests/archived/`; удалять падающий тест без замены, которая ловит тот же разрыв.
