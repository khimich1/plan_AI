## Assumptions I'm Making

1. «Занесённые карточки» — все строки `supply_contract`: 184 из реестра, уже лежащий `0001/10/26` и карточки, созданные в разделе «Контрагенты» потом. Тот же набор, что у поиска карточек в архиве. Справочник `counterparties` (около 4413 строк) в этот поиск не входит.
2. Правило поиска то же, что у карточек: подстрока без учёта регистра по имени карточки (занесённое, полное, краткое), ИНН и номеру договора. Короче двух символов — пустой список. `%` и `_` — обычные символы, не маски.
3. Свободный ввод имени без выбора строки остаётся. Так можно сохранить КП в архив без привязки к 1С. ИНН при этом пустой. Меняется только набор подсказок.
4. Карточка с заполненным `counterparty_id` на активного клиента 1С при выборе подставляет этого контрагента: id, код 1С, имя, ИНН, КПП — как сейчас при выборе из справочника. В списке подсказок всё равно видны имя, ИНН и номер карточки, даже если имя в справочнике другое.
5. Карточка без `counterparty_id` (так у импорта реестра) пишет в КП имя и ИНН с карточки. `counterparty_id` остаётся пустым. Новую строку в `counterparties` не создаём.
6. Если `counterparty_id` на карточке есть, но строки нет или это не активный клиент, справочник не пополняем и битый id в КП не кладём. Выбор ведёт себя как карточка без связи: имя и ИНН карточки, id пустой.
7. Неполные карточки (`requisites_complete: false`) в выдаче есть. Подпись «не полные» в строке подсказки можно показать, если это дёшево. Прятать их нельзя.
8. Гейт «в производство» не ослабляется. Без активного клиента 1С в производство по-прежнему нельзя. Сохранение нового КП «в работе» без id тоже по-прежнему отказ.
9. Сейчас при сохранении нового КП без `counterparty_id` ИНН в строку КП не попадает. Это дыра относительно пункта 5. Её закрывает реализация этой спеки, сейчас она не закрыта.
10. Блок архива «Занести контрагента» по-прежнему ищет справочник 1С через нынешний `GET /counterparties/search`. Этот поиск не сужать.

→ Если что-то из этого неверно — править spec до плана и до кода.

## Objective

На шаге «Клиент» менеджер находит договорную карточку по имени, ИНН или номеру и подставляет её в новое КП. Весь справочник 1С в этих подсказках не появляется. Архивная привязка контрагента к уже сохранённому КП остаётся поиском по справочнику.

Успех: фрагмент имени карточки находит её и не находит контрагента только из `counterparties`. Карточка без `counterparty_id` не создаёт строку справочника, в КП лежат её имя и ИНН, id пустой. Карточка со связью подставляет контрагента 1С. Неполная карточка находится. «Занести контрагента» по-прежнему зовёт старый поиск.

### Пользователь

Менеджер по продажам и администратор. Отдельной роли нет.

### Сценарии

1. **Имя карточки.** На шаге «Клиент» менеджер вводит «секлюц». В списке карточки Секлюцкого из раздела «Контрагенты», с именем, ИНН и номером. Контрагента, который есть только в справочнике и не на карточке, в списке нет.
2. **ИНН и номер.** Тот же список открывается по ИНН карточки и по куску номера. Регистр не важен. `%` и `_` ничего лишнего не открывают.
3. **Короткий ввод.** Один символ поиск не запускает.
4. **Карточка со связью.** Выбор подставляет контрагента 1С: id, код, имя, ИНН, КПП. Дальше КП ведёт себя как после выбора из справочника, включая открытый гейт производства.
5. **Карточка без связи.** В КП записываются имя и ИНН карточки. `counterparty_id` пустой. В `counterparties` новой строки нет. В архив сохранить можно. В производство — нет, пока контрагента 1С не занесут отдельно.
6. **Неполная карточка.** Она в списке. Если подпись «не полные» сделана, она видна и карточку не прячет.
7. **Архив.** В карточке КП блок «Занести контрагента» по-прежнему ищет справочник 1С, не карточки договоров.
8. **Свободное имя.** Имя, набранное без выбора карточки, сохраняется как сейчас: без id и без ИНН. В производство это имя само по себе не пускает.

## Поиск и запись в КП

Подсказка — карточка, не произвольная строка справочника.

| Откуда | Что в списке | Что попадает в КП |
|---|---|---|
| Карточка с активным клиентом 1С | имя, ИНН и номер карточки | id, код 1С, имя, ИНН, КПП этого контрагента |
| Карточка без связи или со сломанной связью | имя, ИНН и номер карточки; «не полные», если бланк не готов | имя и ИНН карточки, id пустой, КПП пустой |
| Только справочник | не показывается | — |
| Текст без выбора | подсказок нет, если нет карточки | имя как введено, id и ИНН пустые |

Номер договора в строку КП этой спекой не пишется. Он нужен, чтобы отличить карточки в списке.

Сохранение нового КП в архив без id пишет имя и, если карточка выбрана, ИНН. Сохранение «в работе» без id — отказ, как сейчас. Перевод уже лежащего КП в производство без id — отказ, как сейчас.

## API

Роли чтения: `admin`, `manager`.

| Метод | Путь | Кто зовёт | Поведение |
|---|---|---|---|
| GET | `/api/v1/counterparties/search` | архив, «Занести контрагента» | Как сейчас: справочник, клиенты, не карточки |
| GET | новый маршрут только мастера | шаг «Клиент» | Карточки. `q` короче 2 символов — пусто. Ответ — карточки, у связанной вложен контрагент 1С |

Тело нового ответа не подменяет тело `/search`. Иначе общий клиент архива начнёт читать карточки.

## Testing Strategy

Сначала тест, потом код. Живую `plita.db` тесты не открывают.

Обязательные случаи:

- Поиск мастера по фрагменту имени карточки находит её.
- Контрагент только из `counterparties` этим поиском не находится.
- Карточка без `counterparty_id` не увеличивает число строк справочника.
- После выбора такой карточки новое КП в архиве хранит её имя и ИНН, `counterparty_id` пустой.
- Сохранение «в работе» без id по-прежнему отказ, даже если ИНН карточки передан.
- `GET /counterparties/search` на то же имя справочника по-прежнему находит справочник.
- vitest: мастер вызывает новый поиск, autocomplete архива — старый.

## Boundaries

- Always: сузить только шаг «Клиент» мастера. Фильтр брать из `search_cards`. Неполные карточки не прятать. Гейт производства не ослаблять. Не писать в `counterparties` из-за выбора карточки без связи.
- Ask first: запрет свободного имени, запись номера договора в КП, скрытие карточки со сломанной связью, лимит короче полного списка совпавших карточек.
- Never: сузить `GET /counterparties/search` или «Занести контрагента». Отметить эту фичу сделанной в `archive-counterparty-cards.md` до приёмки кода. Коммитить и запускать приложение в рамках одной только спеки. Менять живую `plita.db` ради проверки поиска.

## Success Criteria

| Требование | Критерий |
|---|---|
| Список | Фрагмент имени карточки возвращает эту карточку. В строке есть имя, ИНН и номер |
| Не справочник | Контрагент без карточки в ответ мастера не попадает и по-прежнему находится старым `/search` |

| Маски | Запрос с `%` или `_` не открывает все карточки |
