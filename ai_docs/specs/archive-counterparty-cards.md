## Assumptions I'm Making

1. Отмеченный список — все 184 строки листа. Отдельной колонки с галочкой в файле нет.
2. Ключ карточки — номер договора. Одна строка списка — одна карточка. Один ИНН может дать несколько карточек.
3. ИНН и номер из строки списка актуальные. Справочник `counterparties` эта загрузка не читает для выбора дубля и не обновляет.
4. В файле нет статуса подписи, даты отдельным полем и реквизитов бланка. Загруженная карточка получает статус «нет». Месяц и год из номера становятся датой договора, день — 01. Реквизиты бланка пустые, пока менеджер не заполнит блок договора.
5. Номер новой карточки выдаётся как сейчас: `next_contract_seq` по всем уже занятым номерам, формат `{seq:04d}/{mm}/{yy}` от даты карточки. После загрузки списка следующий номер — `1034/10/26`, если дата — октябрь 2026.
6. Менеджер и админ правят все поля карточки, включая номер. Смена номера не пересчитывает дату.
7. Уже существующий договор `0001/10/26` виден в разделе «Контрагенты» наравне с загруженными. Импорт его не переписывает. Кнопка «Договор» на КП в этом релизе убирается, открывается он из нового списка.
8. Повторный запуск загрузки не затирает карточку, которую менеджер уже правил. Совпавший номер пропускается.

→ Если что-то из этого неверно — править spec до плана.

## Objective

Менеджер в архиве видит карточки актуальных договоров из отмеченного списка, находит нужную по имени, ИНН или номеру и правит её сам. Новая карточка получает номер по тому же правилу, что и раньше, и этот номер тоже можно сменить.

Успех: 184 номера из файла и уже существующий `0001/10/26` ищутся и открываются; справочник 1С на тех же ИНН не изменён; второй такой же номер сохранить нельзя; кнопка «Договор» на КП отсутствует.

### Пользователь

Менеджер по продажам и администратор. Контрагенты и их договоры — зона менеджера. Отдельной роли не добавляем.

### Сценарии

1. **Поиск.** В архиве раздел «Контрагенты». Строка поиска одна. «секлюц» показывает три карточки. `440117229007` показывает те же три. `0793/02` открывает одну, с номером `0793/02/25`.
2. **Пустой поиск.** Список не вываливает 4413 клиентов справочника. Пока запрос короче двух символов, показываем подсказку ввести имя, ИНН или номер.
3. **Карточка из списка.** Видны имя из файла, ИНН и номер. Реквизитов бланка нет. Менеджер открывает блок договора, заполняет его и сохраняет. После этого доступны Word, PDF и соглашение об ЭДО.
4. **Новая карточка.** Менеджер вводит имя. ИНН можно оставить пустым. Программа ставит номер. Менеджер может поменять номер до или после сохранения. Дальше тот же блок договора, что в сценарии 3.
5. **Смена номера.** На уже сохранённой карточке менеджер меняет номер по любой причине. Дата договора остаётся. Старый номер в поиске ничего не находит. Номер, который уже есть у другой карточки, не сохраняется.
6. **Статус и скан.** На карточке менеджер меняет статус, отметку скана и файл скана так же, как сейчас в реестре договора.
7. **КП.** В карточке коммерческого предложения кнопки «Договор» нет. Занести контрагента из 1С на КП можно по-прежнему.

## Code Style

Ручная замена номера принимает формы из списка. Автовыдача остаётся четырёхзначной.

```python
def normalize_contract_number(value: str) -> str:
    number = " ".join(value.split())
    number = number.replace(" ", "")
    if not number or not any(ch.isdigit() for ch in number):
        raise ValueError("В номере договора нужна хотя бы одна цифра")
    if len(number) > 32:
        raise ValueError("Номер договора длиннее 32 символов")
    return number
```

`0786/1/25`, `0844-06-25`, `966/06/26КП`, `ТБ-3/08/26Б` проходят. Пустая строка, `без цифр` и строка длиннее 32 символов — нет. Новый номер по-прежнему собирает `format_contract_number`.

## Данные

Карточка — строка `supply_contract`.

| Что в списке | Куда |
|---|---|
| номер договора | `number`, как в файле, без переформатирования |
| имя контрагента | `imported_name` |
| ИНН | `inn` |

Видимое имя карточки при однозначном ИНН равно имени в справочнике 1С.

`counterparty_id` у загруженной и у новой карточки пустой, пока отдельная задача не свяжет её со справочником.

Дата: из номера достаются месяц и год, если они там есть. `0785/01/25` → `2025-01-01`. `0786/1/25` → `2025-01-01`. `0844-06-25` → `2025-06-01`. `966/06/26КП` → `2026-06-01`. `ТБ-1/10/25` → `2025-10-01`. Год `00`–`69` — 2000-е, `70`–`99` — 1900-е. Если месяца и года в номере нет, дата пустая.

Статус загруженной карточки — `нет`. Менеджер КП — пусто, пока карточку не откроют и не сохранят блок договора.

Реквизиты бланка (`legal_form`, имена, подписант, ОГРН, адреса, банк, email и остальные обязательные сегодня колонки) для такой карточки пустые. Схему нужно ослабить: эти колонки и `contract_date` допускают пустое значение, пока блок договора не сохранён. Сохранение блока заполняет их по нынешним правилам `SupplyContractCreate`. Скачивание Word, PDF и соглашения об ЭДО до этого сохранения отвечает отказом «Сначала заполните реквизиты договора». Карточка без полного бланка помечена «не полные»: в ответе `requisites_complete: false`, та же проверка, что запрещает сборку Word и PDF.

Смена номера пишет строку в `supply_contract_event`: поле `number`, старое и новое значение, пользователь, время. Дата в этой записи не меняется.

## Поиск и выдача номера

Поиск: подстрока без учёта регистра по `imported_name`, заполненным имени и краткому имени, ИНН и номеру. Запрос короче двух символов возвращает пустой список. `%` и `_` не являются масками.

В список попадает каждая строка `supply_contract`: 184 карточки загрузки, уже существующий `0001/10/26` и карточки, созданные в разделе потом. Загрузка меняет только те номера, которых ещё нет. `0001/10/26` в файле нет, поэтому его имя, ИНН, реквизиты, дата и статус остаются как были.

Новый номер: `next_contract_seq` смотрит все номера в `supply_contract`, включая `0001/10/26`, отменённые и загруженные. Префикс `ТБ-1` в счётчик не идёт: первый сегмент до `/` не состоит из цифр. Префикс `1033` идёт. Следующий — `1034`, месяц и год — от даты карточки.

## API

Роли на чтение и запись: `admin`, `manager`.

| Метод | Путь | Поведение |
|---|---|---|
| GET | `/api/v1/commercial/archive/contract-cards?q=` | Поиск карточек. `q` короче 2 символов → `{items: [], count: 0}` |
| POST | `/api/v1/commercial/archive/contract-cards` | Тело: `name`, необязательный `inn`, необязательный `number`. Без номера программа ставит следующий. Ответ — карточка |
| PATCH | `/api/v1/commercial/archive/contract-cards/{id}` | Смена номера и полей карточки, которые уже лежат на строке: имя, ИНН. Чужой номер → 400 |
| POST | `/api/v1/commercial/archive/contract-cards/import` | Тело — xlsx из трёх колонок. Только `admin`. Повтор номера пропускается |

Блок договора существующей карточки остаётся на нынешних маршрутах договора по `contract_id`: правка статуса, скана и даты, разбор карточки реквизитов, сохранение реквизитов, скачивание Word и PDF. Создание договора «от КП» (`POST /{kp_id}/supply-contract`) из интерфейса больше не вызывается.

## Testing Strategy

pytest, без сети и без файла из «Загрузок» внутри теста: фикстура собирает такой же xlsx в `tmp_path`.

Обязательные случаи:

- 184 строки фикстуры, повторяющей боевые исключения: три номера одного ИНН, `0786/1/25`, `0844-06-25`, `966/06/26КП`, `ТБ-3/08/26Б`.
- После импорта число строк `counterparties` то же. `counterparty_id` у новых договоров пустой.
- Поиск по куску номера возвращает одну карточку. Поиск по общему ИНН — все её карточки.

- Новая карточка без номера получает следующий seq. При занятом `1033` и дате в октябре 2026 это `1034/10/26`.
- Менеджер меняет номер. Событие в `supply_contract_event` есть, дата договора прежняя. Повтор чужого номера — 400.
- Скачивание Word у карточки без реквизитов — отказ с текстом «Сначала заполните реквизиты договора».

Frontend, vitest: раздел «Контрагенты» шлёт поиск; в карточке КП нет кнопки «Договор».

## Boundaries

- Always: гонять pytest из секции Commands на затронутом бэкенде; хранить номер из файла буквально; не писать в `counterparties`.
- Ask first: удаление или перенумерация `0001/10/26` при загрузке, импорт «спорных ИНН», смена гейта производства, связка карточки со справочником по ИНН.
- Never: коммитить xlsx реестра; выбирать строку справочника по похожему имени; подставлять выдуманный код 1С; пересчитывать номер при смене даты.

## Статусы

Колонка статуса отвечает на вопрос, где подпись договора. Она не выбирает, какой номер из реестра актуальный. Актуальный номер — это сам номер на карточке.

| Статус | Что означает |
|---|---|
| `нет` | Подпись ещё не отмечена. Так стартует и новый договор, и строка из списка: в xlsx колонки подписи нет |
| `подписан по ЭДО` | Подписали электронно, бумажный оригинал в бухгалтерию не сдавали |
| `оригинал в бухгалтерии` | Бумажный оригинал сдан в бухгалтерию |
| `подписан с синей печатью оригинал` | Есть бумажный оригинал с живой печатью |
| `отмена не будем работать` | По этому номеру работать не будем. Для карточки с пустым `counterparty_id` это только метка. Номер остаётся занятым |

Рядом, отдельным полем, живёт отметка скана: пусто, `получен скан`, `внесены правки`. К ней можно приложить файл. Смена статуса скан не ставит и не снимает.

Загруженные 184 карточки получают `нет`. Менеджер ставит нужный статус, когда откроет карточку. `0001/10/26` сохраняет статус, который у него уже записан.

## Приём файла карточки

> **Фаза SDD:** SPECIFY ✅ → PLAN ✅ → IMPLEMENT  
> **Дата:** 2026-10-21

### Assumptions I'm Making

1. Файл принимается в двух местах: форма «Новая карточка» (под поиском) и блок «Реквизиты договора» уже открытой карточки. Поля имя, ИНН и номер на форме остаются: карточку по-прежнему можно создать без файла. Номер, если его не вписали, ставит программа.
2. Это тот же разбор, что у бывшей кнопки «Договор»: карточка контрагента, не реестр из трёх колонок. Реестр по-прежнему грузит только админ отдельным импортом. Импорт `POST /contract-cards/import` этот жест не вызывает.
3. Форматы те же: Word `.docx`, Excel `.xlsx`, PDF, плюс JPEG и PNG. Открытая карточка читает их в `POST /supply-contracts/{id}/parse`. Форма «Новая карточка» читает их в `POST /contract-cards/parse`: тот же результат, без id и без записи строки.
4. Успешный разбор на форме создаёт строку договора: имя — краткое, иначе полное, иначе имя файла без расширения; ИНН — из разбора, если он есть. Номер из файла не берётся. Карточка сразу открывается, бланк заполнен разбором (`doubtful`, счета, банки). В базу реквизиты бланка попадают только по «Сохранить реквизиты».
5. Отказ «это не карточка контрагента» или другая ошибка разбора показывается текстом на форме. Новая строка договора не остаётся в базе.

### Decisions locked

| # | Тема | Решение |
|---|------|---------|
| F1 | Место | Зона файла на форме «Новая карточка» и в блоке реквизитов открытой карточки |
| F2 | Форматы | `.docx`, `.xlsx`, `.pdf`, JPEG, PNG |
| F3 | Жест | Кнопка выбора и перетаскивание в ту же зону. Из броска берётся первый файл. Подпись «или перетащите файл сюда» |
| F4 | Экран | На открытой карточке слева источник, справа поля. Картинка и скан PDF без текста — картинка и масштаб. Word, Excel и PDF с текстом — имя файла и текст ответа `source_text` |
| F5 | Поля | Разбор заполняет бланк, подсвечивает `doubtful`, даёт выбор счёта и банка, как старый ящик |
| F6 | Отказ | «это не карточка контрагента» показывается текстом. На открытой карточке уже введённые поля не затираются. На форме «Новая карточка» строка договора не создаётся |
| F7 | Сохранение | Реквизиты бланка пишет только «Сохранить реквизиты». Имя и ИНН новой карточки сохраняются в момент создания строки, чтобы она появилась в «Занесённые карточки» |
| F8 | Новая карточка | Сначала `POST /contract-cards/parse` (роли `admin` и `manager`), без пустой строки. После успеха клиент вызывает создание карточки с именем и ИНН, без номера из файла, и открывает её с уже заполненным бланком |

### Success Criteria

| Требование | Критерий |
|---|---|
| Выбор | Файл `.docx`, `.xlsx` или `.pdf` в зоне открытой карточки вызывает `POST /supply-contracts/{id}/parse` с этим файлом |
| Бросок | Перетаскивание первого файла в зону делает то же. Второй файл из того же броска не уходит |
| Новая карточка | Бросок docx на форме вызывает `POST /contract-cards/parse`, затем создаёт карточку без номера из файла и открывает её с заполненным бланком |
| Текст | После `.docx` на открытой карточке видны имя файла и `source_text`, кнопок масштаба нет |
| Картинка | После JPEG видна картинка и масштаб |
| Поля | ИНН из разбора появляется в бланке до «Сохранить реквизиты» |
| Мусор | Ответ «это не карточка контрагента» не создаёт строку на форме и не меняет уже введённые поля открытой карточки |
| Реестр | Этот жест не вызывает `POST /contract-cards/import` |

`SupplyContractDrawer` не меняется. Старый ящик остаётся эталоном жеста, со страницы КП он по-прежнему не открывается. Дроп внутри уже открытой карточки вызывает прежний `POST /supply-contracts/{id}/parse`.

### Boundaries

- Always: на форме сначала разбор без id, строка только после успеха. На открытой карточке прежний `parse` по `contract_id`. Тест на бросок и на отказ.
- Never: скармливать этот файл импорту реестра; сохранять реквизиты бланка самим фактом выбора файла; создавать пустую карточку до успешного разбора; брать номер из файла карточки.

## Удаление карточки

На открытой карточке, в блоке реквизитов под «Сохранить реквизиты», кнопка «Удалить карточку». Удаление начинается только после слова `УДАЛИТЬ` — заглавными, без лишних пробелов. Слово проверяет экран, сервер его не спрашивает.

`DELETE /api/v1/commercial/archive/contract-cards/{id}` — роли `admin` и `manager`, как у правки. Удаляется строка `supply_contract`, события `supply_contract_event` этой строки и файл скана. Справочник `counterparties` не меняется. Номер снова свободен. Чужой id — 404. Карточка пропадает из «Занесённые карточки», открытая карточка закрывается.
