## Assumptions I'm Making

1. **Ручное число остаётся только у плит.** Ключи `pile` и `fbs_lm` в `trip_counts_json` на сумму не влияют. Реисы этих котлов снова формула: сваи как в `pile_trip_pricing`, ФБС/ЛС/ЛМ как `ceil(кг / 20 000)`. Старый JSON не вычищаем.
2. **«Сколько машин» не трогаем.** `pile_trip_overrides` по марке без нормы — это не ручное число котла. Оно работает как до фичи.
3. **Архив не пересчитывает плиты.** Сейчас `get` деталей вызывает `calculate_total_cost` и при другом JSON пишет `trip_counts_json`. Из-за этого КП №21 само сменило 57 на 49. Просмотр берёт сохранённое число плит, даже если вес уже другой, и файл не пишет. Сброс по массе и плашка «было / стало» случаются только в конструкторе.
4. **Строка доставки остаётся.** Скобки «(N рейсов)» показывают те рейсы, которые вошли в сумму строки, а не живой `ceil` от веса на карточке. У плит это сохранённое число. У свай и ФБС — формула.
5. **Плашки «Рейсов свай» и «Рейсов ФБС» в архиве остаются**, если они были до поля «Кол. рейсов». Это чтение формулы, не правка.

→ Поправьте до кода, если что-то неверно.

## Objective

Менеджер по-прежнему вписывает число рейсов плит в конструкторе, и это число идёт в сумму и в файлы. Сваи и ФБС считаются как до ручного числа. Карточка архива ничего в рейсах не меняет и не даёт их править: правка начинается с «Редактировать».

### User stories

| # | Как менеджер… | Я хочу… | Чтобы… |
|---|---------------|---------|--------|
| US-1 | открываю КП №21 в архиве | увидеть прежние 57 рейсов плит, без плашки | просмотр не переписывал КП |
| US-2 | жму «Редактировать» | поле «Кол. рейсов» только у плит | поправить число там, где собираю КП |
| US-3 | в КП есть сваи или ФБС | чтобы их рейсы снова считались сами | ручная цифра не ломала формулу |
| US-4 | смотрю строку доставки в архиве | видеть те рейсы, которые в сумме | не сравнивать 49 в скобках и другие деньги |

### Reframed success criteria

Вес плит на скрине 899 947,5 кг → формула `ceil(899947.5 / 18600) = 49`. Сохранённое число до открытия — 57.

| Требование | Критерий |
|------------|----------|
| Открытие архива | В ответе и в `trip_counts_json` рейсы плит остаются 57. Плашки нет. Поля «Кол. рейсов» нет |
| Повторное открытие | Второй GET не меняет JSON |
| Конструктор, тот же вес | Поле показывает 57. OK на 40 пишет 40. `logistics_cost` не меняется |
| Смена веса плит в конструкторе | Поле становится новой формулой. Если целое сменилось, плашка «было / стало» только на этом шаге |
| Сваи | `trip_counts.pile.accepted = 125` не влияет. `pile_trips` равен формуле. Доставка свай = `pile_logistics_cost × формула` |
| ФБС | Сохранённое ручное число не влияет. Рейсы = `ceil(кг / 20000)`, пока котёл готов |
| Нет нормы у сваи | Вопрос «сколько машин» и `pile_trip_overrides` как до фичи |
| Строка доставки | Сумма совпадает с итогом доставки. В скобках рейсы этой суммы: плиты 57 плюс формула остальных котлов |
| Файлы | PDF и XLSX берут те же рейсы, что сумма |

## Code Style

Сваи и ФБС в `resolve_trip_counts` всегда получают формулу. Сохранённый `accepted` этих котлов не читается. Сброс плит по массе включается аргументом и в архивном просмотре выключен.

```python
def resolve_trip_counts(..., *, reset_plate_on_mass_change: bool = True) -> ResolvedTrips:
    ...
```

Архивный `calculate_total_cost` вызывается с `reset_plate_on_mass_change=False`. Запись JSON после этого вызова удаляется.

## Architecture

```
конструктор, пересчёт черновика
  плиты: accepted, сброс по массе, плашка
  сваи и ФБС: только формула
  → metadata.trip_counts пишется здесь

архив, GET карточки
  плиты: accepted как в JSON, без сброса и без плашки
  сваи и ФБС: формула
  → trip_counts_json не пишется

архив, UI
  нет «Кол. рейсов» и нет «было / стало»
  строка доставки = сумма доставки и её рейсы
```

## Testing Strategy

| Уровень | Где | Что |
|---------|-----|-----|
| Unit | `test_commercial_logistics_cost.py` | accepted свай 125 игнорируется; accepted плит 57 при том же весе живёт; с флагом архива смена массы плит не сбрасывает 57 и не ставит notice |
| Unit | ФБС | ручное число не подменяет `ceil(кг / 20000)` |
| API | archive GET | JSON с 57 после чтения тот же; второй GET тоже |
| Vitest | шаг итогов | поле и плашка есть у плит, нет у свай и ФБС |
| Vitest | drawer | нет поля и нет плашки; строка доставки на месте |

Тесты, которые ждут ручные рейсы свай или сброс свай по массе, переписываются на формулу.

---

## Boundaries

- **Always:** сваи и ФБС считать формулой; архивный просмотр не писать `trip_counts_json`; поле плит оставить в конструкторе.
- **Ask first:** вычищать старые ключи из JSON; прятать строку доставки; менять `pile_trip_overrides`.
- **Never:** снова показывать «Кол. рейсов» в архиве; применять `trip_counts.pile.accepted` и `trip_counts.fbs_lm.accepted`; сбрасывать 57 на 49 при открытии карточки.
