## Assumptions I'm Making

1. Пользователь — менеджер и админ. Отдельной роли нет. Менеджер видит только клиентов (`is_client = 1`, `is_active = 1`), как `GET /counterparties/search`.
2. «Договор есть» — неотменённая строка `supply_contract` с этим `counterparty_id`. Так же решает «Отправить в 1С». Пустой бланк кнопку не держит.
3. Поиск от двух символов, по имени и ИНН. Пустой запрос ничего не возвращает. Лимит 10, как у справочника. Код 1С и номер договора в запрос не входят.
4. На одного клиента один действующий договор. Отменённый индекс не занимает. В локальной базе на 2026-11-02 отменённых нет, свободных карточек нет, следующий номер без ручного ввода — `1032/11/26`.
5. Свободная карточка — неотменённый договор с пустым `counterparty_id`. Привязка только если таких карточек с ИНН клиента ровно одна, активный клиент с этим ИНН ровно один и у него ещё нет действующего договора. Это то же правило, что `select_contract_client_links`.
6. Несколько свободных карточек на ИНН номер не выбирают. «Завести» создаёт новый номер и старые не трогает.
7. После «Завести» и «Привязать» карточка договора сама не открывается. На вкладке остаётся список, в строке виден номер. С КП ящик КП остаётся открытым, предупреждение снимается.
8. Номер меняется в уже открытой карточке, как сейчас. Поля номера до сохранения нет.
9. Живую `plita.db` тесты не открывают.

→ Если что-то из этого неверно — править spec до кода.

## Objective

Менеджер на вкладке «Контрагенты» находит клиента 1С по имени или ИНН, видит, есть ли действующий договор, и заводит или привязывает договор этому клиенту. После этого «Отправить в 1С» на его архивном КП перестаёт отвечать «Нет действующего договора поставки».

Успех: клиент без договора получает номер с его `counterparty_id`, строка показывает этот номер, ящик договора сам не открывается. Клиент с договором открывает уже существующую карточку. Одна свободная карточка на однозначный ИНН привязывается. Две свободные карточки сами не выбираются.

### Пользователь

Менеджер по продажам и администратор.

### Сценарии

1. **УНИСТРОЙ, договора нет.** Поиск по имени или ИНН показывает клиента и «договор нет». «Завести» создаёт номер от сегодняшней даты с его `counterparty_id`. Список остаётся, в строке этот номер. На КП №185 «Отправить в 1С» доступна до заполнения банка и подписанта.
2. **Договор уже есть.** Та же строка показывает номер. Действие открывает карточку. Новой строки `supply_contract` нет.
3. **Одна свободная карточка.** ИНН есть у одного активного клиента, у него нет действующего договора, свободный номер один. Строка предлагает привязать этот номер. После привязки `counterparty_id` стоит на старой карточке, новый номер не выдан.
4. **Две свободные карточки.** Ни одна не получает `counterparty_id` сама. «Завести» создаёт третий номер и пишет id клиента на него.
5. **Два кода на один ИНН.** Свободная карточка не привязывается ни к одному. «Завести» создаёт договор только выбранной строки.
6. **С КП.** На архивном КП с клиентом и без договора строка «в реестре договора нет» выполняет то же правило. Ящик КП не закрывается. Бейдж «нет 1С» этим действием не снимается: клиента на КП по-прежнему заносят отдельно.
7. **Короткий запрос.** Пустая строка и один символ список не показывают.
8. **Повтор.** Повторный «Завести» при уже созданном договоре возвращает тот же номер и вторую строку не пишет.

## Code Style

Запись повторяет правило связи. Несколько свободных карточек не выбирают номер.

```python
def contract_to_keep(free_ids: list[int]) -> int | None:
    if len(free_ids) != 1:
        return None
    return free_ids[0]
```

Имя метода в коде может быть другим. Смысл тот же: одна карточка привязывается, две и больше нет.

## Testing Strategy

pytest и vitest, временная база и моки. Живую `plita.db` тест не открывает.

- Пустой запрос и один символ дают пустой список. Два символа ищут имя и ИНН среди активных клиентов и не ищут код 1С.
- В строке есть номер действующего договора либо пометка, что его нет.
- «Завести» пишет `counterparty_id`, имя и ИНН из справочника. Номер — следующий seq и дата вызова.
- Повтор возвращает тот же договор и не увеличивает seq.
- Одна свободная карточка при одном коде привязывается, seq не растёт.
- Две свободные карточки остаются без id. Новый договор создаётся отдельно.
- Два кода на один ИНН свободную карточку не получают.
- Чужой действующий договор не переписывается.
- После записи с заполненным `counterparty_id` блок «Нет действующего договора поставки» снимается, даже если бланк пустой.
- Вкладка больше не шлёт поиск и создание на `/contract-cards`. Файл внутри открытой карточки остаётся.
- Строка на КП вызывает ту же запись и не закрывает ящик. КП без `counterparty_id` эту строку не показывает.

## Boundaries

- Always: писать `counterparty_id` выбранного клиента; не выбирать номер из нескольких свободных карточек; не открывать карточку договора сразу после записи; не открывать живую базу из теста.
- Ask first: искать по коду 1С или номеру договора; делать окно выбора из нескольких номеров; показывать отдельный список карточек без клиента; требовать заполненный бланк до отправки в 1С.
- Never: удалять `GET/POST /contract-cards`; склеивать `counterparties` и `supply_contract`; создавать строку справочника с этой вкладки; коммитить `plita.db`.

## Success Criteria

| Требование | Критерий |
|---|---|
| Поиск | «УНИ» и ИНН клиента находят строку справочника. Один символ и пустой запрос не находят ничего |
| Нет договора | «Завести» создаёт один договор с id клиента. В строке виден номер. Ящик договора закрыт |
| Есть договор | Открывается существующая карточка. Второй строки нет |
| Одна свободная | Привязан старый номер. Новый seq не выдан |
| Несколько свободных | Старые id пустые. Новый договор принадлежит выбранному клиенту |
| Два кода | Свободная карточка ни к кому не привязана |
| КП | После записи «Отправить в 1С» на этом архивном КП доступна при пустом бланке |
| Повтор | Второй вызов не создаёт договор |
| Справочник | Число строк `counterparties` не меняется |
