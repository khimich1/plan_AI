> **Образец текста:** соглашение об ЭДО от 22.09.2026, ООО «ЖБК СТАРТ» и ИП Бисеров. Это экземпляр, не пустой бланк.

## Assumptions I'm Making

1. Соглашение печатается из уже сохранённого договора. Отдельной записи и отдельной формы нет.
2. Дата соглашения равна `contract_date`. Смена даты договора меняет и соглашение при следующем скачивании. Номер договора в текст соглашения не входит.
3. PDF обоих документов — конвертация того же docx через `soffice --convert-to pdf`. Reportlab для этих файлов не используется.
4. Роли те же, что у договора: `admin` и `manager`.
5. Основной ОКВЭД необязателен. Пустое поле не мешает ни подтвердить договор, ни скачать соглашение.
6. У ИП основание в преамбуле соглашения — «ОГРНИП» и значение `ogrn`, даже если в форме договора стоит «устав».
7. Строка импорта без реквизитов покупателя соглашение не собирает. Скачивание договора для таких строк не меняется.
8. Пиксельное совпадение с PDF Бисерова не требуется. Требуются те же разделы, тот же текст пунктов и подставленные реквизиты.

→ Если что-то из этого неверно — править spec до плана.

## Objective

Менеджер, подтвердив договор, скачивает два PDF и отдаёт их клиенту на электронную подпись: договор поставки и соглашение об ЭДО. Word каждого документа — тот же текст, что ушёл в PDF.

Успех: у покупателя с карточки вроде «ПромСтройКонструкции» в соглашении стоят его имя, ИНН, ОГРН, адрес, почта и ОКВЭД `23.61`, а не Бисеров. Без ОКВЭД на карточке соглашение всё равно скачивается, строки ОКВЭД у стороны-2 нет.

### Пользователь

Менеджер по продажам (`admin` / `manager`), карточка КП в архиве, действующий договор уже подтверждён формой.

### Сценарии

1. **Карточка с ОКВЭД.** Менеджер загружает карточку. В форме рядом с ИНН стоит `23.61`. Он подтверждает договор. «Соглашение об ЭДО» → PDF: сторона-2 — это ООО, в реквизитах есть `ОКВЭД 23.61`. Дополнительные коды в файл не попали.
2. **Карточка без ОКВЭД.** Поле пустое, жёлтой рамки нет. Договор подтверждается. В соглашении строки ОКВЭД у покупателя нет.
3. **ИП.** Преамбула: «Индивидуальный предприниматель …, действующий на основании ОГРНИП …». КПП нет.
4. **Повтор.** Тот же договор, другая дата в реестре. Оба файла при скачивании показывают новую дату. Номер договора в соглашении по-прежнему отсутствует.
5. **Импорт листа.** Кнопки соглашения на месте. Сервер отвечает отказом, файл не скачивается.
6. **Нет LibreOffice.** Word скачивается. PDF отвечает ошибкой, карточка показывает её текст. Подмена PDF на Word не делается.

## Поле ОКВЭД

| | |
|---|---|
| Имя | `okved` |
| Где | форма договора, `supply_contract.okved`, ответ карточки договора |
| Обязательность | нет |
| Что храним | код, например `23.61` или `46.73.6`. Название деятельности не храним |
| Откуда | первая строка с подписью «ОКВЭД». Берётся первый код `\d{2}(?:\.\d{1,2}){1,3}` до «Доп.» |
| Контроль цифр | нет. Длина ИНН и контрольная сумма к ОКВЭД не применяются |
| Сомнительное | подпись «ОКВЭД» есть, кода нет — поле в `doubtful`. Подписи нет — пусто и не в `doubtful` |
| Дыры модели | в `_HOLE_FIELDS` не входит. Отсутствие кода само по себе модель не вызывает |
| Зрение | ключ есть в наборе полей карточки. Повторный проход по сорванным цифрам ОКВЭД не трогает |

Пример с карточки «ПромСтройКонструкции»: в поле `23.61`. В поле нет `52.29` и текста «Производство изделий из бетона…».

## Текст соглашения

Бланк — `templates/edo_agreement.docx`. Юридические пункты и приложение 1 переносятся из образца от 22.09.2026. Меняются дата, преамбула стороны-2 и блок реквизитов. Год в дате берётся из `contract_date`, а не зашитая «2026».

Колонтитул страницы: «Сторона-1» и «Сторона-2», дата `дд.мм.гггг`.

### Сторона-1, константа

- ООО «ЖБК СТАРТ», директор Шишов Александр Васильевич, устав
- ИНН `4401082520`, КПП `440101001`, ОГРН `1074401011200`, ОКВЭД `23.61`
- Юридический и почтовый адрес: 156005, г. Кострома, ул. Кузнецкая, дом 18б, помещение 6
- Почта: `start@gbkstart.ru`, `buh@gbkstart.ru`, `pravo@gbkstart.ru`
- Оператор ЭДО: ООО «Тензор», идентификатор `2BE8508b4c4e53411e2925a005056917125`
- Подпись: директор, Шишов Александр Васильевич

Банк, телефон и ярославский склад в соглашение не входят.

### Сторона-2

| Вид | Преамбула |
|---|---|
| ООО, АО | как `build_preamble`, сторона называется «Сторона-2» |
| ИП | «Индивидуальный предприниматель {full_name}», род из `signatory_verb`, основание «ОГРНИП {ogrn}» |
| КФХ, физлицо | как преамбула договора, сторона называется «Сторона-2» |

Реквизиты: полное имя, ИНН, КПП только у ООО и АО, ОГРН или ОГРНИП, юридический адрес. Почтовый адрес для пунктов про бумагу — `postal_address`, иначе юридический. Почта — `email`. ОКВЭД — строка «ОКВЭД {код}», только если поле непустое. Оператор покупателя — только если заполнен `edo_operator` или `edo_id`.

Подпись: должность из договора; у ИП — «Индивидуальный предприниматель». Расшифровка — `signatory_name` целиком. Род и падеж не склоняем: печатается то, что лежит в договоре.

## API

Существующий `GET /api/v1/commercial/archive/{kp_id}/supply-contract/document` получает `format=docx|pdf`. Без параметра остаётся docx, как сейчас.

Новый `GET /api/v1/commercial/archive/{kp_id}/supply-contract/edo-agreement?format=docx|pdf`. По умолчанию docx.

Имена файлов: `dogovor-1028-09-26.docx`, `dogovor-1028-09-26.pdf`, `soglashenie-edo-1028-09-26.docx`, `soglashenie-edo-1028-09-26.pdf`. Слэш в номере заменяется на `-`.

Отказ по пустым реквизитам импорта — 400, текст: «В договоре не хватает реквизитов покупателя для соглашения об ЭДО».

Нет `soffice` или конвертация не удалась — 503, русский текст про LibreOffice. Тело ответа не является docx.

Карточка договора в `SupplyContractDrawer`, когда договор есть и это не замена:

- Договор — Word, PDF
- Соглашение об ЭДО — Word, PDF

Кнопка «Скачать docx» уходит. Ошибка PDF показывается в карточке, Word при этом скачивается своим запросом.

## Code Style

Подстановка в docx — тот же приём, что `render_supply_contract_docx`: плейсхолдеры в бланке, не сборка пунктов кодом. ОКВЭД наружу — строка или `null`, не пустая строка в JSON, если менеджер поле стёр.

```python
def buyer_okved_line(okved: str | None) -> str | None:
    code = (okved or "").strip()
    if not code:
        return None
    return f"ОКВЭД {code}"
```

## Boundaries

- **Always:** текст пунктов не переписывать при подстановке; PDF получать из только что собранного docx; пустой ОКВЭД не печатать; импорт без реквизитов не отдавать.
- **Ask first:** смена юридического текста бланка, обязательность ОКВЭД, запись второго оператора ЭДО, правка уже выданного договора.
- **Never:** подставлять в соглашение данные Бисерова; дорисовывать PDF поверх его файла; звать модель только из-за пустого ОКВЭД; класть дополнительные ОКВЭД в поле.

## Success Criteria

- С карточки «ПромСтройКонструкции» в сохранённом договоре `okved` равен `23.61`.
- PDF и Word соглашения содержат этого покупателя, ИНН `7814192061`, почту `info@gbi-psk.ru` и не содержат «Бисеров».
- Договор без ОКВЭД подтверждается, соглашение скачивается, строки «ОКВЭД» у стороны-2 нет.
- У ИП в преамбуле «ОГРНИП» и номер из `ogrn`.
- В разделе 12 есть почты «ЖБК СТАРТ» и оператор ООО «Тензор».
- Импортированная строка без реквизитов получает отказ, а не пустой бланк.
- `GET .../supply-contract/document` без параметра по-прежнему отдаёт docx.
