## ASSUMPTIONS I'M MAKING

1. **Чиним только нормализатор**, не OCR, не промпт, не прайс, не `make_plate_name`.
2. **Точность важнее покрытия.** Непонятная строка остаётся как есть; обычный парсер (`parse_line`) уже ест `.` и `,` в длине/ширине.
3. **Голый каталог `ПБ56.05-10` — живой формат**, его сохраняем (есть в `tests/test_plate_normalizer.py`).
4. **Каталог с «п» без третьего числа** (`ПБ 59.12-8п`) — это каталог: суффикс `п` уже съедается `_CATALOG_CORE_RE`, остаток пустой. Не ломаем.
5. **Правило остатка сильнее, чем «есть −число»:** каталог применяется **только если после матча остаток пустой или это количество** (`5`, `5 шт`). Любой другой хвост (`-8п`, `-8п 3`, `доб. …`) → не каталог. Это закрывает и десятичную длину, и неподдержанный добор без реализации добора.
6. **Успешный каталог по-прежнему пишет warning** `'src' → 'dst'` (тесты и текущий UI). Отказ от каталога / откат сторожа — **без жёлтой строки в UI** (исходник корректен, шум не нужен); в лог — `debug`.
7. **Добор с явными размерами вне MVP.** После фикса строка `…доб. 70.5-1.25-8` не будет искромсана в одну фейковую марку; на две позиции не развернётся.
8. **Схема БД, API, фронт не меняются.** Предпросмотр просто перестанет получать ложные catalog-warnings и кривые `normalized_lines`.
9. **Бот и веб делят один нормализатор** — правка в `core/` покрывает оба.

→ Поправьте сейчас, если что-то не так. Дальше — PLAN.

## Objective

Менеджер КП вставляет ведомость с десятичной длиной через точку (`ПБ 70.5-12-8п 1`). Система **не подменяет** её на другую плиту и **не съедает количество**. Каталожные марки (`ПБ 59.12-8Вр1400-25`, `ПБ56.05-10`) нормализуются как сейчас.

**Пользователь:** менеджер КП (веб-мастер), тот же нормализатор в боте.  
**Успех:** ноль тихих подмен на обычном формате; каталог без регресса; эталонная ведомость = 32 плиты с исходными размерами.

### User stories

- Как менеджер, я вставляю `ПБ 47.5-12-8п 2` и вижу плиту 4,75×1,2 м, 8п, 2 шт — не `ПБ 47-5,0-12п`.
- Как менеджер, я не вижу жёлтых стрелок `'47.5-…' → '47-5,0-…'`.
- Как менеджер, я по-прежнему могу вставить заводской каталог `ПБ 59.12-8Вр1400-25` и получить `ПБ 59-12-8п`.
- Как менеджер, запятая в длине (`47,5`) и точка (`47.5`) дают одну и ту же плиту.

## Почему ломается сейчас

`_CATALOG_CORE_RE` требует точку: `(\d+)\.(\d{1,2})`.

| Ввод | Каталог | Дальше |
|------|---------|--------|
| `ПБ 47.5-12-8п 2` | L=47, W=5, load=12; остаток `-8п 2` **отброшен** | `ПБ 47-5,0-12п`, qty=1 |
| `ПБ 47,5-12-8п 2` | нет (`\.` не матчится) | обычный парсер: 4,75×1,2, 8п, 2 шт |

Место бага — `parse_catalog_mark`: остаток, не похожий на qty, игнорируется, функция всё равно возвращает кортеж.

Рабочая ведомость (14 строк): 10 сломаны, 32 плиты → 25.

## Behaviour

### Правило каталога (D1)

После `m = _CATALOG_CORE_RE.search(s)` и существующих фильтров (L≥20, 1≤W≤15):

```
remainder = s[m.end():].strip()
если remainder и не _QTY_RE.match(remainder):
    return None
```

Следствия:

| Ввод | Остаток | Каталог? |
|------|---------|----------|
| `ПБ 59.12-8Вр1400-25` | `""` (суффикс в regex) | да → `ПБ 59-12-8п` |
| `ПБ56.05-10` | `""` | да → `ПБ 56-5,0-10п` |
| `ПБ56.05-10 3 шт` | `3 шт` | да, qty=3 |
| `ПБ 59.12-8п` | `""` (`п` в суффиксе) | да |
| `ПБ 70.5-12-8п` | `-8п` | нет |
| `ПБ 70.5-12-8п 1` | `-8п 1` | нет |
| `ПБ 47.5-10.7-8  4` | `-8  4` | нет |
| `ПБ 70.5-10.7-8п доб. 70.5-1.25-8` | `-8п доб. …` | нет (не сплит, не порча) |

### Сторож (D2)

Если `parse_catalog_mark` вернул кортеж и собрана каноническая строка:

1. Разобрать канон тем же `parse_catalog_mark` **или** разобрать числа из канона (`ПБ L-W-Nп [qty]`).
2. Сравнить (L, W, load, qty) с исходным кортежем (load — с допуском float).
3. Не сошлось → вернуть строку после `basic_text_cleanup` + `normalize_plate_prefixes`, `warn=None`.

Сторож не сравнивает «все цифры в строке» (иначе `Вр1400-25` даст ложный откат).

### Обычный формат после отказа

Строка идёт в `parse_line` как сейчас. Точка и запятая уже эквивалентны в `_length_dm_to_m` / `_normalize_dimension`.

### Эталонная ведомость → ожидаемый разбор

```
ПБ 58-12-8п 4          → 5.8 × 1.2,  8, 4
ПБ 58-10.7-8 2         → 5.8 × 1.07, 8, 2
ПБ 47.5-5.3-8п 1  ×4   → 4.75 × 0.53, 8, 1 каждая
ПБ 70.5-10.7-8п 3      → 7.05 × 1.07, 8, 3
ПБ 70.5-12-8п 1        → 7.05 × 1.2,  8, 1
ПБ 43.0-12-8п 5        → 4.3 × 1.2,   8, 5
ПБ 43.0-10.7-8 4       → 4.3 × 1.07,  8, 4
ПБ 47.5-10.7-8  4      → 4.75 × 1.07, 8, 4
ПБ 47.5-12-8п 2        → 4.75 × 1.2,  8, 2
ПБ 60.5-12-8п 2        → 6.05 × 1.2,  8, 2
ПБ 60.5-10.7-8п 1      → 6.05 × 1.07, 8, 1
Итого qty = 32
```

Жёлтых `'…47.5…' → '…47-5,0…'` нет.

## Code Style

Имена и комментарии — как в файле (русский в docstring, английский в идентификаторах). Минимальный diff: логику остатка держать в `parse_catalog_mark`, не плодить второй regex каталога.

```python
remainder = s[m.end():].strip()
qty = 1
if remainder:
    qty_m = _QTY_RE.match(remainder)
    if not qty_m:
        # Хвост не количество: это не каталог L.W-load
        # (десятичная длина 70.5-12-8п, добор, мусор).
        return None
    qty = max(1, int(qty_m.group(1)))
```

Хорошо: `return None` на непустом не-qty остатке — одна развилка.  
Плохо: `text.replace(".", ",")` до каталога; новый модуль «реестра форматов».

| Уровень | Что |

| Негатив сторожа | Если канон собран криво (мок/внутренний сбой) — исходник, `warn is None` |

Покрытие: каждый ряд таблицы «Ввод / Остаток / Каталог?» — отдельный assert. Не требовать % coverage.

## Boundaries

- **Always:** прогнать команды из Commands перед тем как считать задачу сделанной; не менять ожиданий существующих каталожных тестов без правки этого spec; не коммитить без явной просьбы.
- **Ask first:** менять `_CATALOG_CORE_RE`; трогать `dobor_split` / OCR / прайс; показывать в UI warning об отказе от каталога; склеивать дубли.
- **Never:** слепая замена всех `.` → `,`; удалять падающие тесты; расширять MVP добором и реестром форматов.

## Success Criteria

Конкретные, проверяемые:

1. `canonicalize_plate_line("ПБ 70.5-12-8п 1")` → строка содержит `70.5` или `70,5`, **не** `70-5,0-12`; `warn is None`.
2. `parse_line` после нормализации: 7.05 м × 1.2 м, load 8, qty 1.
3. `ПБ 70.5-10.7-8п 3` → qty **3**, не 1; 7.05 × 1.07, load 8.
4. `ПБ 47,5-12-8п 2` и `ПБ 47.5-12-8п 2` → одинаковые length/width/load/qty.
5. `ПБ 59.12-8Вр1400-25` → `ПБ 59-12-8п`, warning есть.
6. `ПБ56.05-10` → `ПБ 56-5,0-10п`, warning есть.
7. `ПБ 57-7,2-8п + доб 5-шт` — сплит как сейчас (регресс `test_dobor_split`).
8. Эталонная ведомость: Σ qty=32; в `normalize_order_text(...).warnings` нет стрелок вида `47.5` → `47-5,0`.
9. `pytest tests/test_plate_normalizer.py tests/test_dobor_split.py` — green.
