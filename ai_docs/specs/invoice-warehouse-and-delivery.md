## Assumptions I'm Making

1. Пользователь — менеджер КП, роли `admin` и `manager`. Тот же доступ, что у отправки счёта.
2. «Отправка» по-прежнему пишет UTF-8 JSON в `settings.exchange_export_dir`. Вызова 1С нет.
3. Склад — одна строка на весь документ, в шапке. Пять допустимых значений зашиты в программе.
4. Поле `Самовывоз` есть в каждом файле. Истина и ложь покрывают оба случая. Второго флажка «Доставка» нет.
5. Цена рейса уже включает НДС. Скидка заказа на доставку не умножается: сначала скидка с изделия, потом надбавка на штуку.
6. НДС в JSON всегда «в том числе 22%»: `round(сумма строки × 22/122, 2)` по каждой строке `Товары`, затем сумма. Порог старых КП (`vat_amount × 0,22` для id меньше 27) на карточке и в PDF не меняется. Файл для 1С этот порог не использует.
7. `Цена` и `ПроцентСкидки` в обоих случаях — цена товара до скидки и скидка заказа, как в сегодняшнем JSON. Скидка не умножается на доставку. Доля котла — поле строки `СуммаДоставки`: сумма на всю строку в рублях, не цена штуки. При самовывозе она `0`. Сумма строки = цена после скидки × количество + `СуммаДоставки`.
8. Котёл доставки длинных свай режется по длине: сумма длины ложится только на сваи этой длины.
9. Excel «доставка в цене» этой спекой не меняется. В JSON котлы ФБС/ступеней/маршей и длинных свай вшиваются, хотя в том Excel они ещё отдельными строками.

→ Если что-то из этого неверно — править spec до плана.

| # | Тема | Решение |
|---|------|---------|
| D1 | Где выбор | Список из пяти складов открывается кнопкой «Отправить в 1С». Нажатие названия пишет файл. «Отмена» не пишет |
| D2 | Когда список | После тех же ворот, что сейчас: контрагент, договор, GUID. Пока они не пройдены, кнопка серая и списка нет |
| D3 | Память | Выбранное имя хранится на КП. Исправление с уже сохранённым складом список не открывает |
| D4 | Пустой склад у старого счёта | Если счёт ушёл до этой спеки и колонка пуста, «Отправить исправление» один раз открывает тот же список, сохраняет имя и пишет `update` |
| D5 | Склад в JSON | Одно поле `Склад` в шапке. На строках `Товары` склада нет |
| D6 | Самовывоз | Сумма всех котлов 0 и ни один котёл не висит неготовым. `Самовывоз` = истина. Цены как на карточке |
| D7 | Доставка | Иначе, когда все котлы посчитаны и сумма больше нуля. `Самовывоз` = ложь. Строки доставки в `Товары` нет. Скидка остаётся на товаре. Доля котла — `СуммаДоставки` строки |
| D8 | Котлы | Плиты ← плитная доставка. Сваи и мостовые сваи ← обычная свайная. ФБС, ступени, марши ← их котёл. Длинные сваи ← сумма своей длины |
| D9 | Шапка денег | `СуммаДокумента` — сумма новых строк. `СуммаНДС` — построчный 22/122 этих строк. Итог к оплате равен изделиям после скидки плюс доставка |
| D10 | Неготовый котёл | Не самовывоз. Файл не пишется. Причина по-русски называет котёл и марки без веса или без тарифа |
| D11 | Договор | `НомерДоговора` не меняется. Имени договора нет |
| D12 | Чужое имя склада | Отказ по-русски, файл не пишется, статус не меняется |

## Objective

Менеджер при первой отправке называет склад 1С. В каждом JSON счёта есть этот склад и признак самовывоза. Скидка всегда про товар. Если доставка назначена, её деньги лежат в `СуммаДоставки` своих строк и прибавляются после скидки. Шапка сходится с этими строками.

Успех: без выбора склада файл не появляется; в файле нет пустого `Самовывоз`; при доставке нет отдельной строки доставки и нет второй скидки; неготовый котёл не маскируется под самовывоз.

### Пользователь

Менеджер по продажам в карточке коммерческого архива.

### Сценарии

1. **Архив, ворота не пройдены.** Кнопка «Отправить в 1С» серая, как сейчас. Списка складов нет.
2. **Архив, можно отправить.** Кнопка фиолетовая. Нажатие открывает пять названий и «Отмена». «Отмена» закрывает список, файл не создаётся.
3. **Выбран склад, доставки нет.** Пишется `invoice_create_{kp_id}_{ts}.json`. `Склад` — выбранная строка. `Самовывоз` — истина. Цены и процент скидки как в сегодняшнем JSON. Статус становится «на согласовании». Имя склада сохраняется.
4. **Выбран склад, доставка посчитана.** Тот же переход статуса. `Самовывоз` — ложь. В `Товары` только изделия. `Цена` и `ПроцентСкидки` те же, что без доставки. `СуммаДоставки` строки — доля её котла. `СуммаДокумента` и `СуммаНДС` сходятся со строками.
5. **Котёл не готов.** Нажатие названия склада не пишет файл и не меняет статус. Менеджер видит русскую причину, не тело JSON.
6. **Исправление, склад уже сохранён.** «Отправить исправление» пишет `invoice_update_*.json` с тем же `Склад` и заново посчитанным `Самовывоз` и ценами. Список не открывается.
7. **Исправление, склада в базе нет.** Кнопка открывает тот же список. После выбора пишется `update`, имя сохраняется.
8. **После отправки.** На карточке склад виден текстом. JSON на экран не выводится.

## JSON

Кодировка и имена файлов те же, что в спеке «На согласовании». Новые поля шапки стоят рядом с контрагентом и номером договора.

| Поле | Когда |
|---|---|
| `Склад` | Всегда. Одна из пяти строк ниже |
| `Самовывоз` | Всегда. `true` или `false` |
| `Цена` строки | Всегда цена карточки до скидки |
| `ПроцентСкидки` | Всегда, в шапке и на строке, как сейчас. Скидка только на `Цену` |
| `СуммаДоставки` | Всегда на строке. Самовывоз — `0`. Доставка — доля котла на всю строку, после скидки |
| `СуммаНДС`, `СуммаДокумента` | Из строк этого файла, не из `vat_amount` карточки |

Склады, сравнение строк полное:

- `Склад Готовой Продукции`
- `Склад покупных товаров (для перепродажи)`
- `БСУ склад`
- `Сырье склад производства`
- `Полуфабрикаты склад производства`

Пример при доставке. Скидка 10 % снимается только с `Цены`. `СуммаДоставки` прибавляется после.

```json
{
  "Склад": "Склад Готовой Продукции",
  "Самовывоз": false,
  "ПроцентСкидки": 10.0,
  "Товары": [
    {
      "Номенклатура": "Плиты ПБ 65-12-8п",
      "Количество": 2,
      "GUID": "…",
      "Цена": 23643.0,
      "ПроцентСкидки": 10.0,
      "СуммаДоставки": 1500.0
    }
  ]
}
```

Сумма этой строки = `23643 × 0,9 × 2 + 1500`. При самовывозе `Самовывоз` равен `true`, а `СуммаДоставки` равна `0`.

Раскладка надбавки — те же копейки, что у плит и свай в `embed_delivery_in_unit_prices`: сумма котла в копейках делится на число штук, остаток добивается на первые позиции. В JSON пишется сумма этих копеек на строку, не цена одной штуки: иначе копейка теряется, когда цену снова умножают на количество. Σ сумм строк = изделия после скидки + доставка. Длинные сваи считаются отдельным котлом на каждую длину.

НДС: для каждой суммы строки `round(сумма × 22/122, 2)` половиной вверх, затем сумма. Это число пишется в `СуммаНДС`. Карточка старого КП может показать другой налог. Файл для 1С от карточки не наследует `× 0,22`.

## Данные

На `KP_offers`:

```sql
invoice_warehouse TEXT
```

Пусто, пока менеджер не выбрал склад. После выбора — одна из пяти строк. Исправление не затирает имя, если тело запроса склад не передаёт.

Снимок состава (`invoice_snapshot_hash`) по-прежнему про строки, скидку, доставку и итог карточки. Склад в хеш не входит: смена склада сама по себе не включает «Отправить исправление».

## API

Тело первой отправки:

```json
{ "warehouse": "Склад Готовой Продукции" }
```

Исправление: тело пустое, если `invoice_warehouse` уже заполнен. Если пуст — то же тело, что у первой отправки.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/commercial/archive/{kp_id}/invoice-export` | Сценарии 3–5. Ответ — карточка |
| POST | `/commercial/archive/{kp_id}/invoice-correction` | Сценарии 6–7 |

Отказ — русский текст, как у текущей отправки. Файл не создаётся, статус не меняется. Чужой `warehouse`, пустой склад на первой отправке и неготовый котёл — такие отказы.

Карточка отдаёт сохранённый склад, чтобы шапка показала его текстом после отправки.

## Code Style

Сборщик по-прежнему не пишет файл. Имя склада проверяет сервис до сборки. Ошибки по-русски.

```python
WAREHOUSES = (
    "Склад Готовой Продукции",
    "Склад покупных товаров (для перепродажи)",
    "БСУ склад",
    "Сырье склад производства",
    "Полуфабрикаты склад производства",
)

document["Склад"] = warehouse
document["Самовывоз"] = not delivery_embedded
```

Кнопка на клиенте не собирает JSON. Она передаёт выбранную строку и рисует вернувшуюся карточку.

## Testing Strategy

| Слой | Где | Что |
|---|---|---|
| Самовывоз | `tests/test_archive_invoice_export.py` | доставка 0 → `Самовывоз` true, цена до скидки, процент скидки на месте, склада на строке нет |
| Доставка | там же | `Самовывоз` false, нет строки доставки, `ПроцентСкидки` на месте, `СуммаДоставки` не попала под скидку, сумма строк = изделия после скидки + доставка, НДС = построчный 22/122 |
| Котлы | `tests/test_embed_delivery_in_unit_price.py` | ФБС не попадает на плиту; длина сваи не попадает на другую длину; скидка не умножает надбавку |
| Ворота | экспорт | чужое имя, пустой warehouse, неготовый котёл — файла нет и статус «в архиве» |
| Память | экспорт | create сохраняет имя; correction без тела повторяет его; correction при пустой колонке принимает тело и сохраняет |
| UI | `OfferDetailsDrawer.test.tsx` | серая кнопка список не открывает; «Отмена» не вызывает POST; выбор названия вызывает POST с этой строкой |

Живая 1С и папка завода в тестах не используются.

## Boundaries

- **Always:** `Склад` и `Самовывоз` в каждом новом файле; один склад на документ; скидка не на доставку; неготовый котёл не пишет файл; исправление повторяет сохранённый склад; ошибки по-русски.
- **Ask first:** другие ключи JSON; шестой склад; склад на строку; менять Excel «доставка в цене»; другая ставка НДС.
- **Never:** второй флажок «Доставка»; HTTP в 1С; класть долю доставки внутрь `Цены`; умножать скидку на `СуммаДоставки`; считать нулевую доставку при неготовом котле; показывать JSON на карточке; коммитить файлы из папки обмена.

## Success Criteria

- [ ] «Отправить в 1С» открывает пять складов. «Отмена» файл не создаёт
- [ ] Без выбора склада, с чужим именем или с неготовым котлом файла нет и статус не меняется
- [ ] В `invoice_create_*.json` и `invoice_update_*.json` есть `Склад` и `Самовывоз`
- [ ] `Самовывоз: true` при нулевой посчитанной доставке. Цены и скидка как в сегодняшнем JSON
- [ ] `Самовывоз: false` при доставке. В `Товары` нет строки доставки. `Цена` и `ПроцентСкидки` как у товара. `СуммаДоставки` прибавляется после скидки
- [ ] `СуммаДокумента` равна сумме строк файла. `СуммаНДС` — построчный 22/122
- [ ] Исправление со сохранённым складом не спрашивает список и пишет то же имя
- [ ] На карточке после отправки склад виден текстом

## Open Questions

Блокирующих нет. Имена полей `Склад` и `Самовывоз` можно сменить по просьбе 1С, не меняя экран.
