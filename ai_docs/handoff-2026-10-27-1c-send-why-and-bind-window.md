# Хэндофф: почему КП не уходит в 1С и что делать с окном «Занести контрагента»

Дата: 27 октября 2026, вечер. Файл для нового окна. Код в этом диалоге не менялся, коммита нет. Серверная база не правилась.

Прошлый хэндофф, 19–21 октября: `ai_docs/handoff-2026-10-27-counterparties-and-1c.md`. Там карточки, связь по ИНН и отправка. Этот файл — почему на живом сайте файл сейчас не уходит.

## Коротко

Файл в 1С не создаётся. Номер договора кладётся только внутрь этого файла. Чтобы файл появился, на КП должен быть клиент из справочника, и у этого же клиента должна быть карточка договора. Сейчас связь карточки пустая, окно «Занести контрагента» ищет весь справочник 1С, а папка, откуда 1С забирает JSON, пустая с 9 октября.

Таблица `supply_contract` не пустая. На сервере 185 карточек. Пустая колонка связи: `counterparty_id` заполнен у 3, у 182 он пустой.

## Сервер

Хост `himweb`, `5.129.200.30`, `ssh himweb`. Контейнер `plan_zavod-backend-1`, образ собран 24 октября. Живая база:

`/var/lib/docker/volumes/plan_zavod_web_split_data/_data/plita.db`

Ноутбучная `plita.db` — другая база. В ней 7 тестовых КП. На сайте КП №140–162. Справочник и карточки на сервер с ноутбука не копировались.

В слое контейнера новых `new_*.json` нет. Контейнер помечен unhealthy: `docker exec` не стартует (`procReady not received`). HTTP `/health` при этом отвечает 200. Приложение не останавливали.

| Поле JSON | Откуда |

| Имя, код, ИНН, КПП, GUID клиента | `counterparties` по `KP_offers.counterparty_id` |

Имя карточки (`imported_name`) в файл не входит. Номер договора на КП не хранится.

## Почему Гефест не ушёл

КП №162, 27 октября. В 19:16 нажали «Занести контрагента»: `PATCH /api/v1/commercial/archive/162/counterparty`. Это поиск справочника `GET /counterparties/search`, не карточек.

На КП записано: клиент `ПСК ГЕФЕСТ ООО`, id `2819`, код `00-00000017`, ИНН `7604304420`, КПП `760401001`. Статус «в архиве». `order_number_1c` пустой. Склада нет. Снимка отправки нет.

Карточка id 21: номер `0808/03/25`, ИНН `7604304420`, имя `ООО "ПСК "ГЕФЕСТ"`, `counterparty_id` пустой. Кнопка занесения карточки не открывает. «Отправить в 1С» ищет договор по `counterparty_id = 2819`, не находит, файл не пишет.

Запроса `POST` отправки счёта в журнале за этот вечер нет.

## Окно, которое пользователь нашёл

Архив, карточка КП, блок «Занести контрагента». На снимке КП №140, запрос «ОЛИМП»: два `ОЛИМП ООО` с разными ИНН и КПП и `ОЛИМПГРУПП ООО`. Подпись строки — `ИНН · КПП`. Это справочник.

Код: `OfferDetailsDrawer.tsx` не передаёт `searchSource`, поэтому `CounterpartyAutocomplete` остаётся в режиме `directory` и зовёт `GET /api/v1/counterparties/search`. Тест прямо запрещает переключать это окно на карточки. Мастер нового КП уже на `searchSource="contract-cards"`. Решение от 21 октября «архивный поиск не сужать» этим вечером отменено пользователем: окно должно показывать карточки.

Карточек `ОЛИМП ООО` нет. Есть `СК ОЛИМП-СТРОЙ`, `0871/08/25`. У Экостроя, Геостроя и Олимпа в справочнике по два активных клиента с одним именем и нет карточки на это имя. У Атлантстройгрупп и Стройтеха клиент один, карточки нет.

## Что уже написано и не сделано

Спека: `ai_docs/specs/archive-bind-contract-cards.md`  
План: `ai_docs/develop/plans/2026-10-27-archive-bind-contract-cards.md`

Окно ищет карточки. Кнопка шлёт id карточки на новый `PATCH /api/v1/commercial/archive/{kp_id}/contract-card`. Если у карточки нет связи, а ИНН указывает на одного активного клиента, этот клиент пишется на КП и на выбранную карточку. Более поздний договор выбранную карточку не подменяет. Поля кода, ИНН и КПП из окна убираются. Старые `PATCH` и `POST /counterparty` в API остаются. Мастер КП не трогать.

Четыре задачи плана, все не начаты: тест, сервис, маршрут, окно. Пользователь сказал «переходи к имплементу», затем разговор ушёл в объяснение, код так и не писался.

Рядом лежит спека данных, тоже не выполнялась: `ai_docs/specs/server-kp-cards-rename-and-1c-send.md`. Она про серверную базу: переименовать карточки в имя справочника, привязать КП, один пробный файл скопировать в папку 1С. Код ею не чинится. Пользователь потом ушёл в баг окна, эту спеку в новом окне не начинать, пока не попросят.

## Что не делать без новой просьбы

- Не коммитить.
- Не править серверную `plita.db` и не писать `order_number_1c` руками.
- Не копировать ноутбучную базу на сервер.
- Не создавать карточки для фирм, у которых их нет.
- Не удалять `POST /counterparty`.
- Не чинить в том же заходе `EXCHANGE_EXPORT_DIR` и обнуление ИНН при сохранении КП без клиента (`app/services/offers_service.py`, ветка без `counterparty_id`). Это следующая дырка: новый КП из несвязанной карточки теряет ИНН.
- Два файла высоты подписи Excel в начале дня откатили к HEAD: `core/specification_xlsx.py`, `tests/test_specification_xlsx.py`. Снова их не трогать.
