# Логистика — инструкция пользователя

Раздел «Логистика» заменяет общий Excel-реестр отгрузок. Здесь логист планирует рейсы,
собирает состав из реальных плит склада готовой продукции (СГП), оформляет документы
и отмечает выезд. Система сама списывает плиты со склада и показывает менеджерам
прогресс по каждому заказу.

**Для кого:** логист (основной пользователь) и владелец/администратор (настройка).

---

## 1. Доступ и вход

- Раздел виден только двум ролям: **логист** и **администратор**. Менеджер и мастер
  производства раздел не видят (и не смогут открыть даже по прямой ссылке).
- Ссылка «Логистика» находится в верхнем меню приложения, рядом с остальными разделами.
  У пользователя с ролью «логист» раздел открывается сразу после входа.
- Внутри раздела две вкладки: «Реестр рейсов» и «Перевозчики».

**Если «Логистики» в меню нет** — у вашей учётной записи другая роль. Попросите
администратора выдать вам роль «логист» (см. раздел 2).

---

## 2. Подготовка (один раз, админ/владелец)

Выполняется на сервере перед стартом работы. Порядок важен.

### Шаг 0 — инвентаризация (обязательно)

Система собирает рейсы только из тех плит, которые числятся на складе СГП в программе.
Поэтому до первого рейса:

1. Сверьте по каждому КП физический остаток плит на площадке с остатком в системе.
2. Устраните расхождения штатными средствами склада.
3. Только после этого начинайте рейсы — иначе «Предложить состав» будет предлагать
   плиты, которых нет (или не видеть те, что есть).

### Шаг 1 — завести пользователя логиста

Выполняется на сервере командой (пароль программа спросит дважды при вводе):

```bash
./.venv/bin/python scripts/create_admin.py --username logist --role logistics
```

Отдельного экрана заведения пользователей в веб-интерфейсе пока нет — только эта
команда (или администратор через служебное обращение).

### Шаг 2 — загрузить справочник перевозчиков

Берётся из старого Excel-реестра отгрузок (листы «Перевозчики» и «Транспортные Компании»):

```bash
./.venv/bin/python scripts/import_carriers.py --xlsx "Реестр отгрузок от 12082021.xlsx"
```

Скрипт сам склеивает очевидные дубли (разное написание «ООО», кавычки, буква «ё»)
и печатает отчёт: сколько добавлено, сколько пропущено, какие дубли схлопнуты.
Повторный запуск безопасен. Оставшиеся похожие названия потом сливаются вручную
в справочнике (раздел 5).

### Шаг 3 — загрузить каталог свай (для автовеса)

Берётся из прайса на сваи, лист «Вес и объем» (44 марки с весом):

```bash
./.venv/bin/python scripts/import_pile_catalog.py --xlsx "Прайс на цельные сваи от 27.07.2026.xlsx"
```

Без этого каталога свободные строки со сваями работать будут, но вес придётся
вписывать вручную. При выходе нового прайса команду просто запускают ещё раз —
марки обновятся.

### Шаг 4 — неделя пилота

- Выберите один тип выдачи (доставка ИЛИ самовывоз) и ведите его неделю только в системе.
- Старый Excel-реестр с этого момента — **только для чтения**: новые строки туда не вбиваем.
  История (17 тыс. строк) в систему не переносится и остаётся архивом снаружи.
- В конце недели администратор смотрит долю рейсов, которые система собрала без ручной
  правки (цель — не меньше половины): `./.venv/bin/python scripts/shipment_propose_hitrate.py --verbose`,
  и повторно сверяет склад.

### Настройки сервера (справочно для администратора)

| Настройка | По умолчанию | Что это |
|-----------|--------------|---------|
| Лимиты веса по классам ТС | 20 000 кг / 30 000 кг | вес груза нетто для предупреждения о перегрузе |
| Событие для 1С | выключено | включится позже, при интеграции с 1С |

## 3. Реестр рейсов

Вкладка «Реестр рейсов» — главный экран. Одна строка = один рейс (одна машина),
а не один заказ. Колонки:

| Колонка | Что показывает |
|---------|----------------|
| Дата | дата рейса |
| Заказы | номера заказов: ЯР (или «КП №…», если ЯР ещё не заполнен); несколько — списком |
| Заказчики | заказчики этих КП |
| Д/С | «Д» — доставка, «С» — самовывоз |
| Перевозчик / доверенность | перевозчик, а для самовывоза — «дов. …» (номер доверенности) |
| Водитель, ТС, УПД, Стоимость план | как заполнено в карточке; пусто — прочерк |
| Вес | суммарный вес состава |
| Статус | «В работе» (синий) или «Обработано» (зелёный) |
| ⚠️ | флаг «внимание»; наведите мышь — увидите комментарий |

Клик по строке открывает карточку рейса. Кнопка «Новый рейс» — создание (раздел 4).
В конце строки — «На основе» (`title` «Создать на основе»): новый рейс с копией
только транспорта (перевозчик, водитель, ТС, класс, доверенность); УПД, № заявки
и состав **не** копируются. Клик по кнопке не открывает карточку исходного рейса.

### Фильтры и зачем они

| Фильтр | Когда использовать |
|--------|--------------------|
| «Дата с» / «Дата по» | рейсы за период (неделя, день) |
| «Заказ (№ КП / ЯР / заказчик)» | найти рейс по номеру КП (введите число, например 154) или по тексту — номеру ЯР / названию заказчика (подсказка в поле: «например 154 или ЯР-0001») |
| «Перевозчик» | все рейсы конкретной транспортной (поиск от 2 букв) |
| «Тип»: «Все» / «Доставка» / «Самовывоз» | отделить самовывоз от доставки |
| «Без УПД» | **что догнать сегодня**: рейсы, по которым ещё не вписан номер УПД |
| «Внимание» | **проблемные**: только рейсы с флажком ⚠️ (кран, доски, «БЕЗ ЦЕН!») |

Кнопка «Сбросить» появляется, когда включён хотя бы один фильтр, и очищает всё.
Если под фильтры ничего не подходит, система честно напишет: «Рейсов по выбранным
фильтрам нет.»

## 4. Карточка рейса — пошагово

### 4.1. Создание рейса

1. Нажмите «Новый рейс».
2. Заполните «Дата рейса» (по умолчанию — сегодня) и «Тип выдачи» («Доставка» или «Самовывоз»).
3. В блоке «Заказы (КП)» найдите заказ: введите номер КП или название заказчика в поле
   «Номер КП или заказчик», нажмите «Найти», затем «Добавить» у нужной строки.
   Если поиск ничего не дал («Ничего не найдено. Можно добавить КП по номеру напрямую.»),
   впишите номер и нажмите «Добавить по номеру».
4. Так можно добавить **несколько КП в один рейс** — они появятся метками под полем
   (ненужную убирают крестиком).
5. Нажмите «Создать рейс» — откроется карточка нового рейса со статусом «В работе».

**Создать на основе прошлого рейса.** В реестре нажмите «На основе» у нужной строки —
откроется тот же диалог (дата = сегодня, тип Д/С из источника). Выберите КП и
«Создать на основе»: транспорт подставится сам, состав и УПД будут пустыми.

Номер заказа (ЯР) на этом шаге **не нужен** — рейс можно планировать до документов.

### 4.2. Шапка карточки

Заголовок окна — «Рейс №… от …». В шапке:

- «Дата рейса» и «Тип выдачи» — можно менять, пока рейс в работе.
- Флажок «Внимание» + поле комментария (подсказка: «Работа крана!», «БЕЗ ЦЕН!») —
  рейс с флажком светится ⚠️ в реестре и ловится фильтром «Внимание».
- «Заказы в рейсе»: у каждого КП поле «№ заказа (ЯР)» (подсказка «ЯР-0000000»).
  Если по этому КП уже был рейс, система сама подставит ЯР из него — проверьте.
  Кнопка «Добавить КП» добавляет ещё один заказ; лишний заказ убирается крестиком
  (последний оставшийся убрать нельзя).
- После любых правок шапки нажмите «Сохранить шапку» (кнопка видна, только когда
  есть несохранённые изменения).

### 4.3. Состав: «Предложить состав»

1. Сначала задайте «Класс ТС» в блоке «Рейс и документы» и нажмите «Сохранить поля» —
   от класса зависит лимит веса при подборе.
2. Нажмите «Предложить состав». Система пройдёт по складу СГП и подставит в редактор
   **свободные** плиты по заказам рейса: сначала самые ранние по дате изготовления
   (очередь FIFO), с посчитанным весом. Появится сообщение «Предложенный состав
   подставлен в редактор — проверьте и утвердите.»
3. Если в класс ТС всё не влезло, остаток показывается в жёлтом блоке «Не влезло
   в лимит класса ТС:» — его **не выбросили молча**: у каждой такой строки есть
   кнопка «Добавить всё равно».
4. Если свободных плит нет, система скажет: «Свободных плит по заказам рейса на СГП
   не найдено.»

Важно: «Предложить состав» **заменяет** текущее содержимое редактора. Поэтому сначала
предложение, потом ручная правка (а не наоборот).

### 4.4. Правка состава

Таблица редактора: «№», «Позиция», «Размер», «КП», «Кол-во», «Вес, кг», «Заметка».

- **Количество** — правьте число в «Кол-во». Под полем видна подсказка «свободно: N» —
  сколько этих плит реально доступно на складе с учётом других рейсов в работе.
- **Убрать строку** — крестик в конце строки.
- **Добавить плиту со склада** — «+ Плита со СГП»: откроется список свободных плит,
  сгруппированный по КП («КП №…»), у каждой — размер, класс нагрузки, «свободно N шт»,
  вес за штуку и кнопка «Добавить».
- **Добавить сваи/прочее** — «+ Свободная строка»: в поле «Марка (С60.30)» начните
  вводить марку и выберите из подсказки — вес подставится сам («автовес: … кг / шт»).
  Вес строки считается автоматически, но его можно перебить вручную в «Вес, кг».
  Колонкой «КП» свободную строку можно привязать к конкретному заказу рейса.
- «Заметка» — заметки укладки для склада (попадут в лист отгрузки).
- «Сбросить правки» — вернуться к последнему утверждённому составу.

Проверки при утверждении: «Количество в каждой строке должно быть целым числом не
меньше 1.», «У свободной строки заполните марку (например, С60.30).»

### 4.5. Панель веса и перегруз

Под таблицей: «Σ веса: … кг», рядом «Лимит ТС (до 20 т / 30 т+): … кг».
Если состав тяжелее лимита — красное «Перегруз: состав тяжелее лимита на … кг».
Это **предупреждение, а не запрет**: рейс можно утвердить и закрыть, решение остаётся
за логистом. Если класс ТС не задан, система напомнит: «Укажите класс ТС в полях
рейса, чтобы видеть лимит веса.» Вес в системе — ориентир для планирования;
учётный вес для УПД — в 1С.

### 4.6. «Утвердить состав»

Кнопка видна, когда есть правки. Нажатие сохраняет состав и **резервирует** плиты
за рейсом: для других рейсов и для операций на складе это количество становится
недоступным. Появится подтверждение «Состав утверждён и сохранён.» Пока рейс
в работе, состав можно пересобирать сколько угодно раз (резерв пересчитается).

### 4.7. Поля «Рейс и документы»

Заполняются по мере готовности, кнопка «Сохранить поля»:

- «Перевозчик» (для доставки) — начните вводить название и выберите из справочника
  (поиск от 2 букв; выбирается точное совпадение названия). Для самовывоза вместо
  перевозчика — поле «№ доверенности».
- «Водитель», «ТС (а/м, прицеп)» — свободный текст.
- «Класс ТС»: «до 20 т» или «30 т+» — влияет на лимит веса.
- «УПД» — номер УПД (готовится заранее, вписывается до выезда; фильтр «Без УПД»
  в реестре помогает не забыть).
- «№ заявки на фрахт», «Стоимость план, ₽».

### 4.8. «Лист отгрузки (XLSX)»

Скачивает файл вида «Лист_отгрузки_12.xlsx» — печатную форму для склада: шапка рейса
(тип выдачи, заказы, заказчик, перевозчик/доверенность, водитель, ТС) и позиции
в порядке укладки с весом и заметками. Доступна в любой момент, в том числе после
выезда (для архива).

### 4.9. «Выезд» — закрытие рейса

Нажимайте в день фактического выезда. Система сначала проверит:

- шапка сохранена («Сначала сохраните шапку — есть несохранённые изменения.»);
- у всех заказов заполнен «№ заказа (ЯР)» («Заполните № заказа (ЯР) для: КП №…»);
- состав не пуст и плит всё ещё хватает на складе.

Затем спросит подтверждение: «Подтвердить выезд? Плиты состава будут списаны со
склада СГП, рейс перейдёт в "Обработано". Действие необратимо.» — «Да, выезд».

Что происходит дальше (одним действием):

- плиты состава списываются со склада СГП и записываются в журнал склада
  (кто, когда, сколько, каким рейсом);
- рейс получает статус «Обработано» и становится **только для чтения**;
- в архиве КП обновляется бейдж «отгружено X/M» (раздел 6);
- если этим рейсом заказ отгружен полностью и на складе по нему ничего не осталось,
  КП сам уходит в «выполнено».

### 4.10. «Отменить рейс»

Доступна только пока рейс «В работе». Подтверждение: «Отменить рейс? Состав рейса
будет удалён, зарезервированные плиты вернутся в свободные на СГП.» — «Да, отменить
рейс». Рейс исчезает из реестра, плиты снова доступны всем. На складе при отмене
ничего не списывается.

### 4.11. Пример рейса от начала до конца

Заказ: КП №154 («СтройМонтаж»), 10 плит ПБ 60-12-8 (≈2 700 кг каждая) лежат на СГП.
Машина — 20-тонник.

1. «Новый рейс» → дата 01.08.2026, «Доставка», поиск «154» → «Добавить» → «Создать рейс».
2. В «Рейс и документы»: «Класс ТС» = «до 20 т» → «Сохранить поля».
3. «Предложить состав» → в редакторе 7 плит (18 900 кг — самые ранние по дате);
   в жёлтом блоке «Не влезло в лимит класса ТС» — оставшиеся 3 (8 100 кг).
4. Правка: водитель подтвердил, что возьмёт 8. Меняем «Кол-во» с 7 на 8
   (под полем «свободно: 10»). Под таблицей: «Σ веса: 21 600 кг», красное
   «Перегруз: состав тяжелее лимита на 1 600 кг» — осознанно оставляем.
   «Утвердить состав» → «Состав утверждён и сохранён.» (резерв: 8 плит за нашим рейсом).
5. Шапка: «№ заказа (ЯР)» = «ЯР-0001467» → «Сохранить шапку».
6. Поля: «Перевозчик» = «ТрансЛогистик» (выбрать из подсказки), «Водитель»,
   «ТС (а/м, прицеп)», «УПД» = «1234», «№ заявки на фрахт», «Стоимость план, ₽»
   → «Сохранить поля».
7. «Лист отгрузки (XLSX)» — файл уехал на склад, грузят по бумаге.
8. Машина выехала → «Выезд» → «Да, выезд». Статус стал «Обработано», со склада
   списалось 8 плит (осталось 2, свободны для всех).
9. Что видно в архиве: у КП №154 рядом с «…на СГП» появился бейдж «отгружено 8/10».
   КП **не** «выполнено» — заказ отгружен не полностью. Когда вторым рейсом увезут
   оставшиеся 2 и склад по КП опустеет, бейдж станет «отгружено 10/10», а КП сам
   уйдёт в «выполнено».

## 5. Справочник перевозчиков

Вкладка «Перевозчики». Таблица: «Название», «Источник» (из какого листа Excel
пришла запись), «Рейсов» (сколько рейсов уже привязано), «Активен», «Действия».
Поиск — поле «Поиск по названию».

### Слияние дублей — «Слить с…»

Когда сливать: один и тот же перевозчик заведён дважды с разным написанием
(«ТрансЛогистик» и «Транс-Логистик»), либо поменялось название, а историю терять
нельзя. Дубли портят автоподсказку в карточке рейса и рвут статистику.

1. У дубля нажмите «Слить с…» (кнопка только у активных).
2. В окне «Слить: …» прочитайте предупреждение: «Все рейсы дубля (N) будут перенесены
   на выбранного перевозчика, дубль станет неактивным.»
3. В поле «Слить с перевозчиком» выберите **правильное** название (подсказка
   «Начните вводить название целевого»). Система покажет: «Будет перенесено рейсов:
   N → «название».»
4. «Подтвердить слияние». Результат: ««дубль» слит с «правильным»: перенесено
   рейсов — N.»

После слияния дубль неактивен: в подсказках его больше нет, а все его рейсы
(включая прошлые) числятся за правильным перевозчиком.

Если нужного перевозчика нет в подсказке поля «Перевозчик», завести его через
интерфейс нельзя — сообщите администратору: название появится в справочнике при
следующем импорте из обновлённого Excel-реестра (или правкой на сервере).

## 6. Что видят другие роли

- **Менеджер и администратор** (раздел «Архив КП»): у заказа рядом с бейджем
  «N/M на СГП» появляется «отгружено X/M» — сколько плит уже уехало обработанными
  рейсами из заказанного количества. Звонить логисту не нужно.
- **Мастер производства**: видит актуальный склад — списанные рейсом плиты исчезают
  из свободных сразу после выезда; зарезервированные рейсом «В работе» нельзя
  отвязать (см. раздел 8).
- **Логист** архив КП не видит — ему достаточно реестра.

## 7. Типовые сценарии

### 7.1. Доставка наёмным ТС

- [ ] «Новый рейс» → «Доставка» → добавить КП → «Создать рейс».
- [ ] «Класс ТС» → «Сохранить поля» → «Предложить состав» → правка → «Утвердить состав».
- [ ] «Перевозчик» (из подсказки), «№ заявки на фрахт», «Стоимость план, ₽» → «Сохранить поля».
- [ ] Когда известны: «Водитель», «ТС (а/м, прицеп)», «УПД» → «Сохранить поля».
- [ ] «№ заказа (ЯР)» у каждого КП → «Сохранить шапку».
- [ ] «Лист отгрузки (XLSX)» → на склад.
- [ ] День выезда → «Выезд» → «Да, выезд».

### 7.2. Самовывоз по доверенности

Отличия от 7.1: «Тип выдачи» = «Самовывоз»; вместо «Перевозчик» заполните
«№ доверенности». В реестре колонка покажет «дов. …», а в листе отгрузки строка
перевозчика будет «Доверенность № …». «ТС (а/м, прицеп)» — можно вписать машину
клиента свободным текстом.

### 7.3. Мульти-заказный рейс (несколько КП в одной машине)

- [ ] При создании добавьте все КП (или потом — «Добавить КП» в шапке).
- [ ] «Предложить состав» собирает плиты по всем заказам рейса по очереди; в редакторе
  у каждой строки виден её «КП».
- [ ] «№ заказа (ЯР)» нужен **по каждому** КП — без этого «Выезд» не сработает.
- [ ] Прогресс и закрытие в «выполнено» система посчитает по каждому КП отдельно.

### 7.4. Рейс со сваями (или смешанный)

- [ ] Плиты — как обычно («Предложить состав»).
- [ ] «+ Свободная строка» → в «Марка (С60.30)» выберите марку из подсказки →
  вес подставится из каталога; при необходимости перебейте вручную.
- [ ] Колонкой «КП» привяжите строку к заказу (необязательно).
- [ ] Сваи со склада СГП не списываются (у них нет складского учёта) — они едут
  «по бумаге» в листе отгрузки.

### 7.5. Частичная отгрузка

- [ ] В составе оставьте только то количество, что едет сейчас (правка «Кол-во»).
- [ ] «Выезд» спишет ровно это количество; остаток останется на складе и будет
  предложен следующим рейсом.
- [ ] В архиве: «отгружено X/M»; КП остаётся «в работе»/«на СГП», пока не уедет всё.

### 7.6. Особый рейс — «Внимание»

Кран на площадке, нужны доски, «БЕЗ ЦЕН!» в документах:

- [ ] В шапке включите «Внимание» и впишите комментарий (коротко: «Работа крана!»).
- [ ] «Сохранить шапку». В реестре у рейса появится ⚠️ (комментарий — по наведению).
- [ ] Утром фильтр «Внимание» покажет все проблемные рейсы разом.

## 8. Ошибки и что делать

Сообщения приведены как в системе; вместо «…» подставляются ваши значения.

| Сообщение | Что значит | Что делать |
|-----------|------------|------------|
| «Недостаточно «…» на СГП: свободно X, требуется Y» | Эти плиты уже зарезервированы другим рейсом «В работе» (или уехали, или на складе меньше, чем в системе) | Уменьшите «Кол-во» до «свободно: X» или уберите строку, затем снова «Утвердить состав». Если уверены, что плиты есть, — сверьтесь со складом и поправьте остаток |
| «Плита зарезервирована рейсом #N от …: свободно X из Y, запрошено Z» (на складе, при отвязке плиты от КП) | Количество, которое вы трогаете, стоит в составе рейса «В работе» | Найдите рейс #N в реестре и: завершите его («Выезд»), отмените («Отменить рейс») или уберите/уменьшите эту плиту в его составе и нажмите «Утвердить состав» |
| «Не заполнен номер заказа (ЯР) для КП #…» / «Заполните № заказа (ЯР) для: КП №…» | К выезду у каждого заказа рейса должен быть ЯР | В шапке впишите «№ заказа (ЯР)» у указанного КП → «Сохранить шапку» → повторите «Выезд» |
| «Состав рейса пуст — нечего отгружать» | «Выезд» без утверждённого состава | «Предложить состав» или добавьте строки вручную → «Утвердить состав» → «Выезд» |
| «Рейс #… уже обработан — изменения недоступны» | Попытка править/отменить уехавший рейс | Обработанный рейс не редактируется (см. раздел 9). Если выехало не то — фиксируйте расхождение и сообщите администратору |
| «Рейс #… не найден» | Рейс отменён (удалён) или ссылка устарела | Обновите реестр; рейс уже не существует |
| «КП #… не найдено» | КП с таким номером нет в архиве коммерческих предложений | Проверьте номер; КП должен существовать до создания рейса |
| «Плита СГП #… не найдена на складе» / «Плита СГП #… не привязана к КП» | Состав ссылается на строку склада, которой больше нет / которую отвязали | Уберите строку и соберите состав заново («Предложить состав») |
| «КП №… уже в рейсе.» | Этот КП уже добавлен в шапку | Ничего — дубли в одном рейсе не нужны |
| «Количество в каждой строке должно быть целым числом не меньше 1.» | В «Кол-во» пусто, ноль или дробь | Впишите целое число ≥ 1 |
| «У свободной строки заполните марку (например, С60.30).» | Свободная строка без марки | Впишите марку или удалите строку |
| «Стоимость план должна быть числом.» | В «Стоимость план, ₽» буквы | Впишите число (копейки — через точку или запятую) |
| «Сначала сохраните шапку — есть несохранённые изменения.» | «Выезд» с несохранённой шапкой | «Сохранить шапку» → «Выезд» |
| «Нельзя слить перевозчика самого с собой.» / «Выберите целевого перевозчика.» | В окне слияния не выбран или неверно выбран целевой | Выберите из подсказки другое название |
| «Нельзя слить в неактивного перевозчика «…»» | Целевой перевозчик уже слит/погашен | Выберите активное название |
| «Ошибка формирования листа отгрузки» | Технический сбой формирования Excel | Повторите; если повторяется — администратору |
| «Укажите дату рейса.» / «Добавьте хотя бы один заказ (КП).» | Не заполнены обязательные поля создания | Заполните и повторите «Создать рейс» |
| «Укажите номер КП (целое число больше 0)…» | В «Добавить по номеру» не число | Впишите номер КП цифрами |

## 9. Правила, которые нельзя обойти (и почему)

1. **ЯР обязателен к выезду, но не при создании.** Рейс планируют заранее, когда
   документов ещё нет; но машина не «уедет» из системы без номера заказа — иначе
   рейс не привязать к счёту в 1С.
2. **Уехавший рейс не редактируется и не отменяется.** «Обработано» = факт: плиты
   уже списаны со склада и записаны в журнал. Откат отгрузки — отдельная будущая
   функция, пока расхождения решаются через администратора.
3. **КП закрывается в «выполнено» только при полной отгрузке.** Система сама ставит
   «выполнено», когда отгружено всё заказанное количество **и** на складе по этому
   КП ничего не осталось. Частичная отгрузка — только бейдж «отгружено X/M».
   «Выполнено» — это факт, а не обещание.
4. **Зарезервированные рейсом плиты нельзя отвязать на складе.** Иначе склад уберёт
   плиты из-под собранной машины. Сначала освободите резерв (правка состава,
   «Выезд» или «Отменить рейс»).
5. **Excel-реестр — read-only архив.** История за 2021–2026 не переносится в систему
   и новыми строками не пополняется: с пилота все рейсы живут только здесь, иначе
   учёт раздвоится.
6. **Перегруз — предупреждение, а не запрет.** Система подсветит превышение лимита
   класса ТС, но решение о выезде принимает логист — вес в программе ориентировочный,
   учётный вес для УПД считается в 1С.
7. **Рейс без заказа (КП) не заводится.** Строка реестра всегда привязана хотя бы
   к одному КП — это единственный способ честно считать прогресс и склад.
