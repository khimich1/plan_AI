# Склад СГП: группировка и сворачивание КП

> Ideation session: 2026-08-02  
> Контекст: вкладка «Склад готовой продукции» (`SgpWarehouseView`), плоская таблица с повторяющимися данными КП.  
> Связанные модули: `frontend/src/features/production/components/SgpWarehouseView.tsx`, `KpCandidatesTable`, `app/services/sgp_service.py`.

## Problem Statement

**Как сделать так, чтобы мастер производства и логист быстро находили нужный заказ на складе СГП, не прокручивая десятки одинаковых строк с повторяющимися «#1 · заказчик · срок»?**

## Recommended Direction

**Accordion-таблица с группировкой по `kp_id`**, переиспользуя UX из wizard планирования (`expandedKpIds`, chevron `▸/▾` в `KpCandidatesTable` / `KpCandidateRow`).

По умолчанию **все группы свёрнуты**. Шапка группы показывает: № КП, заказчик, срок, число позиций, суммарный qty, бейдж **N/M на СГП** (из `sgp_progress`). При развороте — строки плит без повторения данных КП: плита, размер, qty, N/M, дата, действия (отвязать / перепривязать).

Плиты без КП — **псевдо-группа «Без КП»** с тем же collapse/expand. Действия на уровне плиты сохраняются (inline unlink, modal relink). Добавить кнопки **«Свернуть все / Развернуть все»**.

Backend не меняем: группировка и агрегаты считаются на клиенте из flat-списка `items[]`; `sgp_progress` уже приходит с каждой linked-плитой.

### Целевые пользователи

- **Мастер производства** — быстро найти плиту и отвязать/перепривязать.
- **Логист / менеджер** — обзор по заказам перед отгрузкой.

### Масштаб (ориентир UX)

| Ситуация | Что на экране | Решение |
|----------|---------------|---------|
| Мало | 1–3 КП, ~20–40 строк | Группировка убирает повторы |
| Средне | 5–15 КП, 50–200 строк | Accordion + collapse all |
| Много | 20+ КП, 200+ строк | + поиск по № КП (v2) |

Проектировать под **средний** масштаб с запасом на большой.

## Key Assumptions to Validate

- [ ] Свёрнутый вид по умолчанию не мешает точечным действиям (отвязка одной плиты) — проверить с мастером на реальном экране
- [ ] Сводки в шапке группы (позиций, Σ qty, N/M) достаточно для логиста без разворота — проверить на 5+ КП
- [ ] Псевдо-группа «Без КП» сверху в фильтре «Все» не мешает работе с привязанными заказами
- [ ] Client-side группировка flat-списка не деградирует при 200+ строках — профилировать при необходимости
- [ ] Переиспользование паттерна из wizard понятно без обучения — usability check

## MVP Scope

**In:**

- Группировка linked-плит по `kp_id`
- Псевдо-группа «Без КП» (`kp_id === null`)
- Свёрнуто по умолчанию; chevron expand/collapse per group
- Сводка в шапке: позиций, Σ qty, N/M, заказчик, срок
- Кнопки «Свернуть все / Развернуть все»
- Фильтры «Все / С КП / Без КП» работают как сейчас
- Сохранение существующих действий: inline unlink, modal relink
- Тесты на группировку и expand/collapse

**Out (v2+):**

- Массовая отвязка всего КП — высокий риск, нужен отдельный confirm-flow
- Поиск / фильтр по № КП — до появления боли при 20+ КП
- Свёртка одинаковой номенклатуры внутри группы — конфликт с split qty
- Master-detail layout (боковая панель КП + детали)
- Persist expanded state в localStorage / sessionStorage
- Backend endpoint «groups» или сортировка групп на сервере

## Not Doing (and Why)

- **Backend endpoint «groups»** — избыточно; flat list + client group достаточно при текущих объёмах
- **Bulk unlink в MVP** — высокий риск операционной ошибки; редкий сценарий
- **Объединение строк по номенклатуре** — ломает модель «одна строка = одна запись `completed_plates`»
- **Отдельная страница на каждый КП** — overkill для склада
- **Smart auto-expand «проблемных» КП** — усложняет логику; отложить до feedback

## Open Questions

- [ ] Нужна ли **массовая отвязка** в первой версии, или достаточно сводки + построчных действий?
- [ ] Где показывать «Без КП» в фильтре «Все»: **сверху** (приоритет свободных) или **снизу**?
- [ ] Сортировка групп: по **№ КП**, по **сроку**, или по **% готовности N/M**?
