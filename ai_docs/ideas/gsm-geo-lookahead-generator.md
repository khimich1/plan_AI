# GSM: lookahead-генератор с географией (round-trip, направление к следующей заправке)

## Problem Statement

Как сделать так, чтобы генератор путевых листов не падал с 422 на плотных
участках заправок (несколько заправок подряд без свободных будней между ними),
а строил **правдоподобные маршруты**, которые следуют реальной логистике
движения машины — от одной заправки к следующей?

## Контекст: почему текущий генератор падает

Генератор v1 (`core/gsm/generator.py`) устроен так:

- **Якорный день** (день заправки/мойки): маршрут выбирается как «самый частый»
  из библиотеки (95 км), без учёта того, сколько топлива нужно сжечь до
  следующей заправки. Берётся **одно плечо** (туда), хотя в истории день —
  это **два плеча** (туда + обратно).
- **Дожигание** (сжигание лишнего топлива) происходит **только на свободных
  буднях между якорями**. Между якорями, идущими подряд, свободных будней нет
  → топливо негде сжечь → переполнение бака → 422 `insufficient_headroom`.

Замер на реальных данных (апрель–июнь 2026):

| Машина | Заправок подряд (0 будней между) | Доля |
|---|---|---|
| Palisade | 53 из 122 интервалов | **43%** |
| Tug952 | 53 из 120 | **44%** |
| Tug848 | 34 из 100 | 34% |
| Monjaro | 0 из 54 | 0% |

То есть для Palisade и Tug952 плотные заправки — **норма, а не исключение**.
Май 2026 Palisade не собирается вообще: 12 якорей, из них группы 4–6, 14–15,
20–22 мая идут подряд.

## Recommended Direction

Дополнить генератор тремя механизмами:

1. **Lookahead на якоре.** Перед выбором маршрута дня генератор смотрит на
   **следующую заправку**: сколько литров она добавит (`Q_next`), значит к её
   утру в баке должно быть `≤ бак − Q_next`. Если между якорями нет свободных
   будней — сжечь разницу нужно **на самом якоре**, выбрав более длинный
   маршрут.

2. **География.** Маршрут якоря выбирается не «самый частый», а **по
   направлению к следующей заправке**: заправки — это точки реального пути
   (пример из истории: 20.05 Ярославль → 21.05 Москва/Реутов → 22.05 Кострома).
   Маршрут «следует логистике», а не телепортируется.

3. **Round-trip (день = туда + обратно).** Машина всегда возвращается на базу
   (Кострома или Ярославль) в тот же день; lookahead подбирает длину плеча так,
   чтобы освободить место под следующую заправку, в пределах `max_daily_km`.

**Фаза 2 (после MVP) — дальний рейс с ночёвкой:** если round-trip превышает
порог «долгого дня» (~500 км), поездка разбивается на 2 дня (туда/обратно,
возврат следующим будним днём). Данные показали, что для **сходимости бака**
ночёвки не нужны (ни одного жёсткого случая в истории при `max_daily_km=700`) —
это «улучшатель правдоподобия» длинных поездок, а не необходимость.

Дополнительно — **смягчение контракта**: вместо «422 на весь период» при
локальной нерешаемости генератор сохраняет проблемный день как `draft` с
warning `manual_intervention`, а остальной период собирает. Бухгалтер видит
конкретные проблемные дни и дорабатывает руками.

## Принятые решения (по итогам обсуждения 2026-08-15)

| # | Вопрос | Решение |
|---|---|---|
| 1.1 | 27 станций без координат | Геокодить автоматически (nominatim) |
| 1.2 | Базы машин | **Две:** Кострома (Кузнецкая 18Б) и Ярославль (Домостроителей) — из данных |
| 1.3 | Направление к след. заправке | **Мягкая сортировка**, не жёсткий фильтр (3 уровня приоритета) |
| 2.1 | Потолок дня | **`max_daily_km = 700`** (настраиваемо в `gsm_setting`) |
| 2.2–2.4 | Ночёвки (возврат, точка, топливо) | **Фаза 2** — для баланса не нужны; round-trip 700 км покрывает все реальные случаи |
| 3.1 | Привязка маршрутов к станциям | (а) статистика из истории + (б) геокодинг адресов маршрутов (станция <15 км от линии A→B) |
| 3.2 | Синтетические маршруты | Только если нет реального с нужным km; метка `source="synthetic"` |
| 4.1 | Приоритет | Сходимость бака > география (сначала отбор по km, потом сортировка по направлению) |
| 4.2 | Точность сжигания | Минимальный достаточный km (не жечь лишнего) |
| 4.3 | Плотные заправки (нерешаемо) | `draft` + warning `manual_intervention`, НЕ 422 на весь период |

## Key Assumptions to Validate

- [ ] Геокодинг 27 трассовых станций («М8, 87 км») даёт достаточную точность
  для определения направления (погрешность в км не критична)
- [ ] `max_daily_km = 700` решает большинство плотных участков; остающиеся
  (3 заправки по 50+ л подряд) — редки и уходят в `manual_intervention`
- [ ] Маршрут 700 км за день правдоподобен для налоговой (время в пути
  9–10 ч корректно отражается в ПЛ `time_dep`/`time_ret`)
- [ ] Привязка `typical_station_ids` по истории + геокодингу восстанавливает
  достаточно связей, чтобы lookahead почти всегда находил маршрут через АЗС
- [ ] Две базы (Кострома/Ярославль) — корректная модель «дома» для всех машин

## MVP Scope

- **Data:** геокодинг станций без координат; заполнение
  `gsm_route.typical_station_ids` (история + гео); `max_daily_km` в настройках
- **Core (`core/gsm/`):**
  - `geo.py` — расстояния/направления между станциями, «станция на пути A→B»
  - `generator.py` — lookahead на якоре, round-trip (2 плеча), мягкая
    сортировка по направлению, минимальный достаточный km
  - частичная генерация: нерешаемый якорь → draft `manual_intervention`
- **API:** `generate` возвращает частичный результат + список проблемных дней
  (изменение контракта — сейчас либо всё, либо 422)
- **UI:** бейджи «маршрут для баланса бака», «требует ручной доработки»

## Not Doing (and Why)

- **Полный солвер с произвольным числом плеч** — в MVP ограничиваемся
  round-trip (2 плеча). Дальний рейс с ночёвкой и составные дни из 3+ плеч —
  фаза 2.
- **Заправка «сегодня, дожиг завтра»** (перенос дожигания после заправки) —
  ломает инвариант «остаток дня ≥ 0», добавляет путаницу.
- **GPS/реальные треки** — источник истины остаётся транзакции + библиотека.
- **Время в пути как жёсткое ограничение** — только правдоподобная генерация
  времён, без валидации «влезает ли в световой день».

## Open Questions

- Граница `manual_intervention`: сколько дней в типовом месяце допустимо
  отправлять на ручную доработку, чтобы это не стало «генератор ничего не
  делает»? (Замерить на мае–июне после реализации.)
- Нужна ли калибровка `max_daily_km` по машине (Tug952 реально ездит 530 км
  плечо, Palisade — до 360)?

## Данные на старте (замер 2026-08-15)

- 4 машины, 76 станций (27 без координат), 610 маршрутов (typical_station_ids
  пустые у всех), 509 транзакций
- Базы: Кострома (Кузнецкая 18Б) — 144/95/97/123 маршрута; Ярославль
  (Домостроителей) — 44/23/24
- Медиана плеча 110–178 км; p90 280–345 км; макс 360–530 км
- Реальные дни в истории: 400–410 км (2 плеча по ~205)
- Средняя заправка в день: Palisade 49 л (max 120,6), Tug848 32 л
