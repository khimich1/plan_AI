# Мульти-КП: прозрачный выбор типа (галочки + «Уже в КП»)

> Ideation session: 2026-09-02  
> Контекст: визард КП, append loop уже реализован (`kp-multi-nomenclature-append`).  
> Спека: [`../specs/kp-multi-type-picker-transparency.md`](../specs/kp-multi-type-picker-transparency.md)

## Problem Statement

**How might we** сделать так, чтобы при новом круге добавления номенклатуры менеджер сразу видел, что уже забито в КП, и спокойно дополнял список — без ощущения «всё сбросилось»?

## Recommended Direction

**Прозрачный append (малый UX на `ProductTypePicker`).**

Оставить текущий flow: Result → «Добавить другое наименование» → picker → ввод типа → append. Backend `startAppendCycle` не меняем.

В режиме дополнения:

1. Полоска состава: **«Уже в КП: Плиты · ФБС»** (и т.д.).
2. Разное поведение плиток:
   - **Тип ещё не в КП** — вся плитка активна (как сейчас) → выбор типа.
   - **Тип уже в КП** — галочка; клик по фону плитки **не** стартует действие; крупные **(+)** и **(i)**.
3. **(+)** → дописать позиции этого типа (существующий append).
4. **(i)** → боковой `Drawer` (read-only): уже добавленные изделия этого типа из `order_data`.
5. Copy: убрать «в одном КП только один тип».
6. Append-шапка: вместо «Создание КП» — **менеджер + заказчик**; кнопка «К результату».
7. Drawer: только наименование + количество (без цен).

Cold start: без галочек/полоски состава; вся плитка кликабельна; обновлённый нейтральный copy (не «только один тип»).

## Key Assumptions to Validate

- [ ] Полоски типов без счётчиков позиций хватает, чтобы снять путаницу
- [ ] Разделение (+) / (i) на уже добавленных типах понятнее, чем одна кликабельная плитка с ✓
- [ ] Read-only Drawer без редактирования строк достаточен на MVP
- [ ] Тот же picker на cold start с новым copy не ломает привычку старта

## MVP Scope

**In**
- Props: `mode`, уже выбранные типы, строки draft для Drawer
- UI: полоска «Уже в КП», ✓, (+) / (i) на добавленных, вся плитка на новых
- Drawer справа на `shared/ui/Drawer` — список позиций выбранного типа
- Wire из `CommercialOfferWizard` при `isPickingProductType`
- Повторный (+) = дописать, не заменить

**Out**
- Chips / выбор типа с Result
- Мультивыбор нескольких типов за один заход
- Редактирование/удаление строк из Drawer
- Счётчики позиций на карточках
- Изменения append / export / save API

## Not Doing (and Why)

- **Полноэкранная замена flow на «один экран состава»** — избыточно для снятия путаницы
- **Chips на Result** — ускоряет, но выходит за малый объём; отложить, если путаница останется
- **Запрет повторного выбора типа** — ломает «ещё плиты в том же КП»
- **Edit в Drawer** — дублирует Result; MVP = только просмотр
