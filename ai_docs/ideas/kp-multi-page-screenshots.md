# КП: несколько скриншотов страниц на первом шаге

> Ideation: 2026-08-31  
> Спека: [`../specs/kp-multi-page-screenshots.md`](../specs/kp-multi-page-screenshots.md)  
> Follow-up (wait + AI on review): [`kp-ocr-wait-and-ai-on-review.md`](./kp-ocr-wait-and-ai-on-review.md)

## Problem Statement

**How might we** дать менеджеру загрузить несколько страниц большого КП, начать править **первую** распознанную страницу, пока остальные ещё бегут — с переключением «фото ↔ её список» и полным OCR-пайплайном на **каждый** кадр — почти не трогая append?

## Recommended Direction

**Гибрид: страница-сессия + прогрессивный конвейер.**

1. **Галерея превью** вместо Alert «Выбран файл»: ряд миниатюр с ✕, paste/file дописывают в очередь страниц (порядок = порядок загрузки).
2. **«Распознать»** не ждёт весь батч: первая готовая страница сразу открывает сверку (фото + её текст); остальные доезжают в фоне.
3. **MVP (направление 2):** очередь на фронте — последовательные вызовы **существующего** single-image OCR (тот же preprocess / verify / upscale на каждый файл). Append / «Добавить к списку» почти не трогаем.
4. **Следом (направление 1), если упрёмся:** server-side job + progress API, тот же UX снаружи.

Итог захода = конкатенация **подтверждённых** страниц в порядке. Не один общий textarea на все скрины.

## Key Assumptions to Validate

- [ ] Менеджеру удобна постраничная сверка, а не один слитый список сразу
- [ ] Переиспользование текущего OCR на файл сохраняет качество «ухищрений» на каждой странице
- [ ] Фронтовый конвейер достаточен, пока вкладка открыта; закрытие вкладки mid-batch — редкий кейс
- [ ] Лимит ~10–15 страниц за заход терпим по стоимости/времени OCR
- [ ] Multi-page только на первом replace-заходе; append откладываем без ломки

## MVP Scope

**In:** галерея + ✕; прогрессивное OCR; навигация страница ↔ её список; «Список верен» по странице; merge в draft по подтверждённым; все типы с `SourceInputCard`.

**Out:** Redis/Celery; multi-image vision; перестановка страниц drag-and-drop; глубокая переработка append; AI-инструкции на батч.

## Not Doing (and Why)

- **Merge всех OCR в один textarea** — ломает сверку «эта страница = этот кусок»
- **OCR при каждом drop** — пользователь явно хочет старт только по «Распознать»
- **Трогать append в MVP** — неясен сценарий; риск размазать scope
- **Склейка картинок в один vision-запрос** — теряем per-page пайплайн и границы страниц
