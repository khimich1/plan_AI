# Пример ФБС и мостовых свай из прайса

**Дата**: 2026-09-14  
**Spec**: [../specs/2026-09-14-kp-fbs-bridge-placeholder.md](../specs/2026-09-14-kp-fbs-bridge-placeholder.md)

## Problem Statement

Как дать менеджеру и админу в шаге 1 ФБС и мостовых свай пример списка, который можно вставить как есть и получить цены из прайса — не подставляя формат обычных свай `С120.35…`?

## Recommended Direction

При реализации открыть текущий прайс (`PRICE_DB_PATH` / `pb.db`). Для ФБС и отдельно для мостовых свай взять **две марки с ненулевой ценой** (стабильный порядок, например первые две по `mark`). Класс бетона — только тот, для которого в БД есть цена. Количество — любые маленькие целые (2 и 3).

Эти строки записать в `labels.placeholder` в `productTypeConfig.ts`. Пин-тесты конфига — на фактические строки. Парсер, OCR и расчёт не трогать. Менеджер и админ — один мастер.

Если в таблице прайса меньше двух пригодных марок — плейсхолдер **пустая строка**. Не подставлять чужой тип изделия и не выдумывать марки.

## Key Assumptions to Validate

- [ ] В рабочем `pb.db` у ФБС и мостовых свай ≥ 2 марки с ценой — иначе в UI будет пустое поле (это ок по решению)
- [ ] Строка вида `марка [класс] кол-во` из этих SKU проходит «Обработать текст» с ценой, без «не найдено в прайсе»
- [ ] Алиас мостовой марки берётся как в таблице; lookup его принимает
- [ ] Плейсхолдер виден только в пустом поле; старый текст черновика — другой баг

## MVP Scope

**In:** 2+2 SKU из текущей БД (или `""`) → два плейсхолдера → тесты конфига. Ручная проверка менеджер/админ: вставить пример → цены; на пустом прайсе поле без примера.

**Out:** рандом при рендере, эндпоинт «дай пример», кнопка «Вставить пример», легенда, автокомплит, OCR, другие типы КП.

## Not Doing (and Why)

- Живой пример с бэка при каждом открытии шага — прайс меняется редко
- Случайные марки каждый раз — нестабильный UX и тесты
- Фоллбек на пример свай или тестовые `ФБС 9.3.6-Т` / `C8-35T1`, если БД пустая — снова «не из этой базы»
- Разные тексты для менеджера и админа — один конфиг
