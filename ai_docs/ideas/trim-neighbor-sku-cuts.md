# Trim: соседние марки не воруют резы

_Дата: 2026-09-03 · Источник: разбор КП (ПБ 56-7-8п vs ПБ 65-9-8п)_  
_Спека:_ [`../specs/trim-neighbor-sku-cuts.md`](../specs/trim-neighbor-sku-cuts.md)

## Problem Statement

Как начислять каждый рез плана ровно одной марке в КП и цеховой смете, не сломав правило завода: при двух плитах с одного реза и остатке ≤ 20 мм второй рез не делают и не тарифицируют?

## Recommended Direction

Связка **допуск марки 10 мм (1 см) → ключ заказа при краже с Δ>10 мм**. Порог 20 мм остаётся правилом **отхода/кромки**.

Шаг 1: `_width_matches_cut` с `PLATE_WIDTH_MATCH_TOLERANCE_MM = 10`. `|700−720|=20` — не матч. На живом заказе ПБ 56-7-8п забирала secondary ПБ 56-7,2-8п (`cuts: [720]`, источник 6,3 м). Эталон — ПБ 65-9.

Шаг 2: только если матрица покажет `cuts ≠` ширине заказа. Тогда `target_order_key` (+ id реза), каждый рез — одна строка сметы. Не возвращать допуск 20 мм в матчинг SKU.

Не менять `MIN_BILLABLE_TRIM_MM`, формулу числа продольных резов и `tolerance_width` геометрии.

## Key Assumptions to Validate

- [ ] В `cuts` — ширина этой марки; 20 мм сидят в `waste` / pieces — матрица пар; контрпример 710/720 включает шаг 2
- [ ] Две плиты с полосы, `waste=20`: один продольный рез, не два — регрессия, шаг 1 её не ломает
- [ ] Каскад 665 / rest 670 / `cuts: [665]` живёт при точном матче
- [ ] После шага 1: 56-7 — 1 поперечный, остаток 0,40 м, без `460 × 6,3`; 56-7,2 забирает свой 6,3 м; 65-9 без регрессии

## MVP Scope

**Шаг 1:** `_width_matches_cut` ≤ 10 мм; регрессия 5,6×700 vs 5,6×720; матрица (Δ=20 не делят; 710/720 Δ=10 в допуске); кейс «2 плиты + отход 20 мм → 1 продольный».

**Шаг 2 (если матрица красная):** `target_order_key` / `secondary_instance_id` в snapshot; матч по ключу; рез списывается один раз.

**Out:** ILP, раскладка, допуск 20 мм в геометрии и тарификации отхода, UI формулы остатка, пересчёт архива.

## Not Doing (and Why)

- **Убирать `MIN_BILLABLE_TRIM_MM` / `tolerance_width=20` в геометрии** — это правило «второй рез (кромка) не делают»
- **Возвращать 20 мм в матчинг SKU** — снова 56-7/56-7,2; 10 мм — допуск марки по документации, 20 мм — кромка
- **Правило по вёдрам `plate_lists`** — 300 и 320 в одном ведре
- **Потолок «поперечных ≤ qty»** — ломает две легитимные поперечные на одной марке
- **Счёт со схемы / полный граф раскроя** — уже вне MVP в `plate-pricing-fix.md`
- **Подпись формулы остатка (0,40 vs 2 147)** — баг отображения, не атрибуции
- **Пересчёт архивных КП**
