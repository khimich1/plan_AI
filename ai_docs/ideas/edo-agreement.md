## Problem Statement

How might we отдать менеджеру вместе с договором поставки соглашение об использовании ЭДО, уже заполненное тем же покупателем, чтобы клиент подписал PDF электронной подписью, а Word остался тем же текстом?

## Recommended Direction

Соглашение не заводится отдельно. Его реквизиты — это сохранённый договор плюс константы «ЖБК СТАРТ» из бланка договора. Дата соглашения — дата договора. Номер договора в текст не подставляется: приложение 1 само покрывает все договоры между сторонами.

В карточке договора две строки. У договора и у соглашения по два файла: Word и PDF. Клиенту уходят PDF. PDF — это тот же docx, прогнанный через LibreOffice, а не вторая вёрстка.

С карточки покупателя в форму договора добавляется один необязательный основной ОКВЭД. В соглашении строка печатается только если код сохранён. Дополнительные коды, ОКАТО, ОКТМО, ОКПО и второй идентификатор ЭДО в договор не пишутся.

## Key Assumptions to Validate

- [x] Клиент подписывает два отдельных PDF электронной подписью. Один архив и один общий файл не нужны.
- [x] Word остаётся. Менеджер сверяет или правит его до отправки, PDF не должен разъехаться с этим Word.
- [x] После подтверждённой формы данных хватает. Не хватает только основного ОКВЭД, и он необязателен: без него соглашение всё равно собирается.
- [x] Строка из листа юриста без ИНН, адреса и почты соглашение не собирает.
- [x] PDF на сервере собирает LibreOffice. Пакета в образе ещё нет, установка входит в план. Без него Word скачивается, PDF отвечает ошибкой.

## MVP Scope

Поле «ОКВЭД» в форме договора и в разборе текстовой карточки. Бланк соглашения с текстом образца от 22.09.2026, подстановка стороны-2 и даты. Скачивание Word и PDF для договора и для соглашения из карточки действующего договора.

## Not Doing (and Why)

- Печать реквизитов поверх PDF Бисерова — в текстовом слое останется чужой покупатель, длинное имя сдвинет строки.
- Сборка PDF в reportlab — у договора уже есть утверждённый docx, второй движок разойдётся с юристом.
- Страница в страницу с заполненным PDF — это экземпляр на Бисерова, не пустой бланк. Линейный клон не обещаем.
- Обязательный ОКВЭД — на части карточек строки нет, договор из-за этого не блокируем.
- Дополнительные ОКВЭД, ОКАТО, ОКТМО, ОКПО, сайт, фактический адрес, главный бухгалтер — соглашение их не печатает.
- Второй идентификатор ЭДО (СБИС и Диадок на одной карточке) — в реквизитах соглашения оператор покупателя не обязателен, сторона-1 уже «Тензор».
- Правка ОКВЭД после выдачи номера — как ИНН: только до подтверждения.
- Импорт листа юриста — пустые реквизиты не дописываем угадыванием.

## Open Questions

Блокирующих нет. Если юрист позже пришлёт свой пустой docx, заменяется файл бланка, поля и кнопки не меняются.
