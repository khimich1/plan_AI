# Рейсы свай и мостовых свай в КП

> Ideation: 2026-09-01  
> Источник веса/загрузки: `банк знаний/сваи вес и объем.xlsx`  
> Сопоставление мостовых: `C14-40T4` ≡ `С140.40` (длина × сечение; Тn и класс бетона на массу не влияют)  
> Смежные: [`kp-piles.md`](kp-piles.md), [`kp-bridge-piles-and-fbs.md`](kp-bridge-piles-and-fbs.md), отгрузки (`pile_catalog`, код не меняем)

## Problem Statement

**Как менеджеру КП получить число рейсов и сумму доставки по обычным и мостовым сваям из заводской таблицы загрузки — не выдумывая массу и не смешивая это с рейсами плит?**

Сейчас «стоимость рейса» считается только по плитам (18,6 т) и на КП без плит поле выключено. У мостовых в `bridge_pile_prices` нет веса. `pile_catalog` уже умеет `weight_kg` + `pcs_per_20t`, но пуст.

## Recommended Direction

Один физический справочник в `pile_catalog` (импорт Excel). Мостовые резолвятся по **длине × сечению**. В КП и архиве — гибридный счёт рейсов свай. Код отгрузок не трогаем.

### Утверждённые решения

| Тема | Решение |
|------|---------|
| Где | КП (итоги/скидка) + архив |
| Отгрузки | Код не меняем. Побочный эффект данных: канон `С60.30` начнёт давать вес |
| Справочник | Excel → `pile_catalog` (`weight_kg`, `volume_m3`, `pcs_per_20t`). Отдельной таблицы мостовых нет |
| Резолв мостовых | Длина × сечение (`C14-40T4` → 14 м × 400 мм → `С140.40`) |
| Адреса | Один пул на КП |
| Рейсы свай (есть норма) | По марке: полные = `floor(qty / pcs_per_20t)`. Остатки известных марок: `ceil(Σ(остаток × кг) / 19800)`. Итого = полные + рейсы остатков |
| Геометрия остатков | Не в MVP (длина в кузове позже) |
| Нет нормы (C18, «-» у 16 м) | Не в полные и не в кучу остатков. **Вопрос:** «Сколько машин нужно на эти N шт.?» Менеджер вводит **число рейсов N**, не шт. в машине. N только в этом черновике |
| Пока N не введён | Доставку свай **не считаем** (состав и цена изделий остаются). По каждой такой марке — свой вопрос |
| Смешанное КП | **Две** строки доставки в сумме: плиты (18,6 т) и сваи (гибрид + ручные N). В одну фуру плиты и сваи не кладём |
| Тариф | По-прежнему вводит менеджер; система считает **число** рейсов |
| Ж/д / контейнер | Не в MVP; «рейс» = авто |

### Формула (есть норма в Excel)

```
полные_i     = floor(qty_i / pcs_per_20t_i)
остаток_кг   = Σ (qty_i - полные_i × pcs_i) × weight_kg_i   # только марки с нормой
рейсы_остат  = ceil(остаток_кг / 19800)
рейсы_ручные = Σ N_j   # ответы «сколько машин» по маркам без нормы
рейсы_свай   = Σ полные_i + рейсы_остат + рейсы_ручные
доставка     = тариф × рейсы_свай
```

Пример тендера без ответа по C18: 39 полных + 3 от остатков = **42**.  
C18-40T8 × 49: в сумме изделий есть, в авто-рейсах нет, пока не введут N машин.

### Почему так

- Заводская колонка «шт. на 20 т» уже учитывает габарит однородной загрузки; чистый тоннаж как у плит врёт на длинных сваях.
- Остатки разных марок мешать по 19,8 т — сознательный черновик; геометрию отложили.
- C18 нет в справочнике (макс. 16 м, и тот на авто с прочерком). Формула L×a² выглядела бы как факт завода. Честнее спросить число машин.
- Один `pile_catalog` + геометрия — чтобы потом переиспользовать в отгрузках, без второго каталога.

## Key Assumptions to Validate

- [ ] Вес/загрузка цельной `С140.40` официально = мостовой `С14-40Т4`
- [ ] 19,8 т — верная грузоподъёмность для кучи остатков (Excel 20 т, плиты 18,6 т)
- [ ] Остатки разных марок в одной фуре по тоннажу допустимы до учёта длины
- [ ] Заполнить пустой `pile_catalog` ок для логиста, если он впишет канон `С60.30`

## MVP Scope

- Импорт `сваи вес и объем.xlsx` в `pile_catalog` (лист `Лист1`; импортёр сейчас ждёт «Вес и объем»).
- Резолв `piles` и `bridge_piles` по длине × сечению.
- Гибридный расчёт рейсов в КП + те же цифры в архиве.
- Включить «стоимость рейса» на КП без плит.
- Две строки доставки, если в КП есть и плиты, и сваи.
- Марки без нормы: обязательный вопрос «сколько машин», N в черновике; без ответа доставку свай не считаем.

## Not Doing (and Why)

- Код модуля отгрузок — отдельно; этот релиз только КП/архив + данные справочника
- Геометрия остатков / раскладка в кузове — позже
- Два адреса = два пула рейсов — в MVP один пул
- Ж/д 66 т и контейнер 68 т
- Оценка C18 по формуле в авто-сумму
- Отдельный `bridge_pile_catalog`
- Писать ручное N в справочник
- Мешать плиты и сваи в одном рейсе
