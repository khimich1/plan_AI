# КП: свободное имя клиента, контрагент 1С — на производстве

**Направление**: A (имя сейчас, 1С на производстве)  
**Spec**: [../specs/kp-counterparty-bind-on-production.md](../specs/kp-counterparty-bind-on-production.md)  
**Plan**: [../develop/plans/2026-09-17-kp-counterparty-bind-on-production.md](../develop/plans/2026-09-17-kp-counterparty-bind-on-production.md)

## Problem Statement

How might we дать менеджеру посчитать и положить КП в архив по любому имени клиента, не выдумывая карточку 1С — и не выпускать КП в производство, пока контрагент из 1С не привязан?

## Recommended Direction

Одно поле «клиент». Если запись есть в справочнике — выбираем её, как сейчас. Если нет — оставляем набранное имя и идём дальше. В архив КП уходит с `customer_name` и пустым `counterparty_id`. Стопор один: «В производство» требует живого клиента из 1С (`require_active_client`). Привязка — в карточке архива, когда карточка появилась импортом, не ручным заведением из мастера.

Это болеутоляющее для менеджера (расчёт сегодня, юрлицо завтра) и дешёвое относительно текущей модели: `customer_name` уже пишется в КП, `counterparty_id` уже nullable, производство уже отдельный гейт из архива. Два имени (рабочее vs юрлицо) и живой поиск 1С не нужны, пока не доказано, что после привязки приходится перепечатывать КП.

Справочник не пополняется свободным текстом. Диалог «Добавить контрагента» с копированием кода 1С из мастера — ловушка: он либо блокирует расчёт, либо плодит теневые записи.

## Key Assumptions to Validate

- [ ] «КП не уходит» = перевод в производство, а не выдача PDF/XLSX клиенту. Проверить с менеджером: файлы из архива с рабочим именем можно отдавать.
- [ ] После привязки карточки 1С `customer_name` / ИНН / КПП перезаписываются из справочника. Если имя в уже отданных файлах нельзя менять — это направление B, не A.
- [ ] Клиента нет в списке потому, что его ещё нет в 1С, а не потому, что поиск плохой. Если поиск не находит существующих — сначала чинить поиск.
- [ ] Офис привяжет карточку до производства и не будет обходить гейт.

## MVP Scope

**В мастере (шаг «Клиент»):**

- Автокомплит справочника остаётся. Нашёл — привязал `counterparty_id`, имя и реквизиты из карточки.
- Не нашёл — можно продолжить с любым непустым названием. `counterparty_id` не ставится. Кнопка «Рассчитать КП» не требует id.
- Убрать из мастера создание контрагента (`NewCounterpartyDialog` / `POST /counterparties` из этого шага).
- Свободное имя не пропускает шаг «Клиент» само по себе (как сейчас: skip только при `counterparty_id`, append, resume).

**В архив:**

- Первое сохранение не вызывает `require_active_client`. Пишет `customer_name` = набранное имя, `counterparty_id` = null.
- Если карточка уже выбрана — поведение как сейчас (снапшот имени, ИНН, КПП).
- PDF/XLSX по-прежнему генерируются при сохранении, с тем именем, что в КП.
- В списке и карточке: бейдж «нет 1С», если `counterparty_id` пустой.
- В карточке архива: тот же автокомплит — «Занести контрагента». Выбор активной карточки-клиента заполняет `counterparty_id` и перезаписывает снапшот.

**Производство:**

- `move_to_production` отклоняет КП без активного клиента из справочника. Кнопка «В производство» неактивна, пока не привязали.
- После привязки — обычный диалог срока и ёмкости.

**Append / resume:** шапка липкая, как сейчас. Если 1С уже привязан — шаг «Клиент» пропускается. Если нет — имя остаётся рабочим, привязка по-прежнему в архиве.

## Not Doing (and Why)

- Два поля «имя в КП» и «контрагент 1С» — пока не доказано, что юрлицо часто не совпадает с тем, что печатают клиенту.
- Живой поиск/создание в 1С из приложения — чужая система, не лечит «посчитать сегодня».
- Ручное создание записи в справочнике без кода 1С (и с кодом из мастера) — теневые карточки, ломают правило «без 1С не в производство».
- Стопор на скачивание PDF/XLSX из архива — пользователь явно разрешил архив с именем; файлы — часть архива.
- Менять skip-логику append/resume — шапка уже липкая; не плодить второй шаг «Клиент» на дописке партий.

## Open Questions

- Нужен ли фильтр архива «без 1С» в MVP или достаточно бейджа в карточке? (фильтр — если очередь привязки появится сразу)
- Перегенерировать ли файлы автоматически после привязки 1С, или только при следующем «сохранить изменения»?
- Кто имеет право привязывать: только автор КП или любой, кто видит архив?
