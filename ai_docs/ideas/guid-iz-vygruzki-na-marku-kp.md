# GUID из выгрузки 1С на марку КП

> Дата: 2026-09-23. Статус: реализовано.
> Спека: `ai_docs/specs/guid-iz-vygruzki-na-marku-kp.md`.
> План: `ai_docs/develop/plans/2026-09-23-guid-iz-vygruzki-na-marku-kp.md`.
> Родитель: `ai_docs/ideas/guid-demand-queue.md`, `ai_docs/ideas/guid-price-sync-loop.md`.

## Problem Statement

Как записать GUID из файла экономиста на сваю, у которой цена уже есть или введена в КП, чтобы и очередь «Завести в 1С», и жёлтое предупреждение на шаге 3 отпустили счёт в 1С, не спрашивая цену второй раз?

## Recommended Direction

При загрузке универсального отчёта имя из 1С сопоставляется с маркой тем же правилом, что и ворота счёта. Если GUID один, он записывается в `nomenclature_guid` в двух случаях.

Марка уже есть в прайсе. Цена остаётся прайсовой, заново её не вводят. Так закрываются `С120.35-12`, `С140.35-12` и `С160.35-12`.

Марки в прайсе нет, но менеджер ввёл договорную цену и КП сохранили в архив. GUID записывается, договорная цена остаётся на этом КП и в общий прайс не копируется.

После записи строка «Завести в 1С» снимается. Открытый черновик перепроверяет GUID сразу, не через 15 секунд кэша.

Если на одно имя два GUID, выбор не делается. Экономист видит существующий блок «Дубли GUID», и только потому что это изделие сохранили в КП.

## Key Assumptions to Validate

- [ ] Имя «Сваи С 120.35-12» из файла сходится с маркой `С120.35-12` тем же нормализатором, что и ворота счёта, и не цепляет соседнюю марку
- [ ] Договорная цена не попадает в прайс-таблицу; после загрузки число строк прайса не меняется
- [ ] Открытое КП на шаге 3 теряет жёлтую плашку без создания нового черновика

## MVP Scope

Запись единственного GUID для марки из прайса и для договорной марки из архивного КП. Снятие «Завести в 1С» и обновление предупреждения на шаге 3. Частичный файл с «Отбор:» не помечает остальные марки как исчезнувшие.

## Not Doing (and Why)

- Ввод цены второй раз — для этих свай она уже в прайсе, для договорных её уже ввёл менеджер
- Новая марка и новая цена из файла 1С — файл приносит только GUID
- Автовыбор, если GUID два — экономист выбирает сам, и только по изделию из сохранённого КП
- Полная перезаливка всех марок прайса без GUID — этот файл закрывает конкретные дырки КП
- Чужие тестовые строки мостовых свай и `ЛС11` в очереди — к файлу экономиста они не относятся

## Open Questions

Нет. Договорная марка опознаётся по открытой задаче архивного КП (`guid_demand`), не по несохранённому черновику: колокольчик и файл экономиста появляются только после архива. Плашка на шаге 3 гаснет, потому что проверка читает уже записанный GUID.
