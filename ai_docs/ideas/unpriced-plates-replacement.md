# Подсветка непроизводимых плит с заменой в wizard КП

_Дата: 18.08.2026 · Статус: направление подтверждено · Источник: баг ПБ 75-12-12п (unit_price = 0 в черновике fb656f71)_

## Problem Statement

Как помочь менеджеру мгновенно заметить плиту, которой нет в прайсе (нулевая/пустая цена = завод не производит эту комбинацию длина×нагрузка), и в 2 клика заменить её на производимый вариант — до того, как КП с нулевой строкой уйдёт клиенту?

## Контекст бага

- В `pb.db.prices` для нагрузки 12п цены заканчиваются на 72 дм; 73–90 дм хранят `price = 0` (осталось от старого прайса 19.08.24; в новом прайсе 14.07.26 эти ячейки пустые и импорт их не затирает).
- `lookup_plate_price` бросает `PriceNotFoundError` только при отсутствии строки; строка с `price = 0` считается «найденной».
- Черновик цену берёт из строки сметы (`commercial_service.py::_build_order_data`), где `unit_price` всегда float с дефолтом `0.0` — никогда `None`. Поэтому существующий гейт wizard `unpriced_position_labels` (пропускает всё, что `is not None`) для плит никогда не срабатывал.
- Панель плит на фронтенде (`KpPlatePreviewPanel`) рендерит `null` как `"0"` через `formatOfferNumber`; паттерн «нет в прайсе» есть только у свай/ступеней/маршей/ФБС.
- Цена проверяется на этапе сметы — когда 2D-оптимизация уже посчитана для несуществующей плиты.

## Recommended Direction

**Релиз 1 — предохранитель (гигиена, часы):**
- `_build_order_data`: нулевая/отсутствующая цена сметы → `unit_price = None`.
- `lookup_plate_price`: `price <= 0` → `PriceNotFoundError`.
- `KpPlatePreviewPanel`: `unit_price === null` → «нет в прайсе» (паттерн как у свай).
- После этого существующий гейт wizard сам блокирует шаг результата с сообщением «Нет цен для позиций: …».

**Релиз 2 — флоу замены (зеркало wide-plates):**
- Детекция сразу после парсинга (до оптимизации): строки с нулевой ценой → `unpriced_plate_lines` в метаданных черновика.
- Новый `ERR_UNPRICED_PLATES` блокирует wizard аналогично `ERR_WIDE_PLATES`.
- На шаге ввода — inline-секция (клон `WidePlatesInlineSection`): по каждой строке выпадающий список замен «10п — 31 890 ₽ / 8п — 29 316 ₽», ближайшая меньшая нагрузка с ценой предвыбрана.
- Кнопка «Применить» → endpoint `resolve_draft_unpriced_plates` переписывает строки заказа (имя, load_class, сброс unit_price) → штатный `calculate` перезапускает оптимизацию уже для реальной плиты.

## Key Assumptions to Validate

- [ ] Наличие цены в прайсе = плита производится (прокси). Проверка: звонок на завод — правда ли 7.3+ м выпускаются только до 10п.
- [ ] Менеджер согласовывает понижение нагрузки с заказчиком (клиент увидит другое имя в КП). Смягчение: подсветка в UI «замена требует согласования».
- [ ] Граничный случай без замен (длины 91+ дм — только 6п; за 96 дм — ничего): сценарий «нет производимых замен — удалите позицию / запросите цену у завода».

## MVP Scope

Релиз 1 целиком. Релиз 2: детекция по `prices` (length_dm × load_code), предложения = меньшие нагрузки той же длины с ценой > 0, одна кнопка применения.

## Not Doing (and Why)

- **Ограничение ввода только производимыми комбинациями** — ввод это OCR чужих документов, заказчика не ограничить.
- **Журнал спроса для завода** — отдельная фича; максимум одна строка лога при детекции.
- **Telegram-бот** — ботом больше не пользуемся (подтверждено 18.08.2026).
- **Полная переоптимизация без плиты** — избыточно для MVP; замена нагрузки покрывает реальные кейсы (12п → 10п/8п).
- **Ручной ввод договорной цены** — выбрана замена на меньшую нагрузку, не ручная цена.
