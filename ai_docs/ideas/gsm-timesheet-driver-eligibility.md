# ГСМ: табель Т-13 решает, кого можно подписать в путевой

Дата: 2026-10-12. Статус: **planned** (спека + план 2026-10-12).
Контекст: сессия idea-refine 2026-10-12. Предшественники:
[`gsm-module-putevye-listy.md`](gsm-module-putevye-listy.md) (водитель — поле бланка,
`primary_driver_id`), [`gsm-month-close-kit.md`](gsm-month-close-kit.md) (замки комплекта).
Данные: табели Т-13 № 44 (июль) и № 47 (август) 2026, ООО «ЖБК СТАРТ».

## Problem Statement

How might we не дать закрыть месяц комплектом, в котором один человек подписан
двумя путевыми на одну дату или стоит в листе в день, когда по табелю он
отсутствовал (ОТ / больничный / командировка / учёба), — при этом генерация
сама подставляет свободного, а бухгалтер не разводит фамилии руками каждый день?

Сейчас уникальность только `(vehicle_id, date)`; пара `(driver_id, date)` не
контролируется. Generate штампует `primary_driver_id` машины на каждый день,
ручной ПЛ и PATCH проверяют только «водитель существует». Обе Tugella (О 848,
О 952) закреплены за Кулигиным → любой общий будний день даёт два бланка с
одним ФИО, и zip это спокойно выгружает.

## Правила (зафиксированы в сессии)

**Загрузка табеля.** Бухгалтер загружает Т-13 (.xlsx) за месяц до генерации.
Без табеля на этот месяц генерация **запрещена**. Из файла берутся строки, чей
разобранный табельный номер есть в справочнике `gsm_driver`; цвет заливки не
используется. Разбор номера: `СЭ00-00470` → `470` (отрезать серию с дефисом,
убрать ведущие нули; `СЭ0В-00001` → `1`). Стыковка по номеру, не по ФИО и не
по цвету.

**Кого можно подписать в день.** Только того, у кого в табеле на эту дату
**Я или В**, и кто ещё не стоит в другом ПЛ на эту же дату.

- `В` (выходной) **никого не красит**: ни основного, ни запасного. День с
  человеком в его выходной — жёлтый `weekend_driver` («подписан в свой
  выходной»), комплект закрывается с confirm-диалогом. Субботняя заправка
  директора остаётся подписанной директором.
- Всё, что не Я и не В — `ОТ`, больничный, командировка, учёба — **жёсткий
  запрет** и для основного, и для запасного.

**Подстановка (2А + ротация).** Основной доступен (Я/В, не занят) → он.
Основной занят другой машиной или в отсутствии → свободный с **меньшим
счётчиком подстановок за месяц** (лист не на своей машине); при равенстве —
меньший табельный. Группы: сначала без своей машины (Полякова/Скрябин), потом
чужие основные. Эффект: запасные чередуются (П, С, П, С…), «всегда Полякова»
не получается; отпуск запасного даёт честную серию второму. На дне — просто
другая фамилия, **без пометки** «подставлено».

**Три жёстких стопа (красный день, комплект не закрывается).**
1. Один человек в двух ПЛ на одну дату.
2. Человек в `ОТ`/отсутствии стоит в листе.
3. День машины без единого доступного человека (все в ОТ/заняты).

Бухгалтер разводит красный день в `WaybillDayDrawer`. Проверка действует на
generate / create / PATCH / комплект-export — те же ворота, что коридор бака.

**Подтверждённые данные.** Табельные в справочнике совпадают у Кулигина (143),
Лоншаковой (470), Скрябина (29), Поляковой (1). Шишов: в табелях `СЭ00-00438`,
в ГСМ ошибочно `241` → правится вручную на `438` до загрузки августа (через UI
справочника, без подсказок/блокировок импорта). Табель июля: Скрябин ОТ 1–9.07,
Лоншакова ОТ 27–31.07; август: Лоншакова ОТ 1–9.08, Шишов ОТ 18–31.08.

## Key Assumptions to Validate

- [ ] Субботние заправки директора — реальная практика: жёлтый «свой выходной»
  честен, табель кадры правят отдельно (не модуль).
- [ ] Полякова на 952 — обычная подмена, а не скрытое «основной водитель 952»;
  справочник машин не меняем.
- [ ] Т-13 всегда формы ОКУД 0301013 с серией `СЭхх-ххххх`; коды только Я/В/ОТ
  у водителей (Б/К/ПК появятся позже — запрет уже заложен).

## MVP Scope

- Импорт табеля за месяц (xlsx, форма Т-13): парсер строк + разбор номера,
  сохранение явок по (driver, date), отчёт «строка без водителя в ГСМ».
- Хранилище явок: таблица `gsm_timesheet` (batch) + `gsm_timesheet_day`
  (driver_id, date, code) в `plita.db`.
- Пул водителей дня в генерации: generate по машине получает resolver
  (date → ordered available drivers), а не один `driver_id`.
- Bulk generate распределяет людей по всем машинам дня (вторая Tugella видит,
  что Кулигин занят 848-й).
- Гейт «нет табеля за период» на generate; жёлтый `weekend_driver`; три
  красных стопа на generate/create/PATCH/export-комплекте.
- UI: загрузка табеля на вкладке «Справочники» (или «Транзакции»), просмотр
  сетки явок по жёлтым, ошибки стопов с понятной фразой
  («Кулигин уже в О 848 12.07», «Лоншакова в отпуске 05.08»).

## Not Doing (and Why)

- Подмена «на неделю/месяц» одним запасным — выбрана ротация по счётчику
  подстановок (чередуются сами); жёсткая привязка лечится справочником,
  не солвером.
- Переподписание уже выгруженных месяцев под табель — правило только вперёд;
  якорь 30.06 (Кулигин на обеих Tugella, `exported`) не трогаем, разводить
  руками только если решим ставить UNIQUE в БД.
- Назначение Поляковой основной у 952 — решение о справочнике, не про солвер.
- Стыковка по цвету заливки или по ФИО — хрупко; ключ — табельный номер.
- Жёлтая пометка «подставлено» на дне — отклонено (plain: просто фамилия).
- Авто-совет «отдайте пятничную заправку другой машине» — отдельная идея,
  не входит.
- Подсказка/блокировка импорта при несовпавшем номере Шишова — правка ручная,
  до загрузки.
