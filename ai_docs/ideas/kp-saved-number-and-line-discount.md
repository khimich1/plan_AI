# КП: номер после сохранения и цены со скидкой в таблице

## Problem Statement

How might we дать менеджеру и офису один и тот же номер и те же цены на 3-м шаге конструктора, в PDF/XLSX и в архиве — без `WEB_*` после появления настоящего `kp_id`, и без таблицы, которая врёт про скидку?

## Recommended Direction

**Канон после сохранения (направление A).** Черновик может быть черновым: номер `WEB_{draft[:8]}` и файлы `kp_{draft[:8]}_{время}`. Как только КП записано в архив, identity = `str(kp_id)`, документы пересобираются с этим номером, зелёная плашка показывает его же.

Скидка на шаге результата — баг отображения, не ценообразования. `unit_price` в `order_data` остаётся прайсом (нужен целевой сумме). Таблица показывает `unit_price × (1 − discount%/100)`, как PDF/XLSX и `discounted_price` в архиве.

Не предсказывать `MAX(kp_id)+1` до записи: два менеджера получат один номер, офис будет искать не то КП. Не резервировать `kp_id` при старте мастера — это смена модели архива, не багфикс.

## Key Assumptions to Validate

- [x] Пользователи: менеджеры + офис (поиск по номеру с бумаги, сверка с PDF) — подтверждено 2026-09-09
- [x] Номер в документах и плашке = `kp_id` как строка (`"1188"`), без префикса `КП-` — так уже в архиве
- [x] `WEB_*` допустим только у несохранённого черновика
- [x] В таблице шага 3 заменить отображаемую цену/сумму на цену со скидкой (не две колонки)
- [ ] После save менеджер пользуется файлами с экрана, а не старым скачанным WEB-PDF — иначе нужен запрет скачивания до архива (направление C, не это MVP)

## MVP Scope

- Identity: unsaved → `WEB_*`; saved / resume → `str(kp_id)` и `file_stem` с этим номером
- После первого save: сначала получить `kp_id`, затем сгенерировать PDF/XLSX (и breakdown, если уже был) с этим номером; плашка «в архиве: 1188»
- Шаг 3: колонки «Цена» / «Сумма» = цена со скидкой для всех типов строк; `unit_price` в данных не затирается
- Оба дефекта в одном заходе

## Not Doing (and Why)

- **Предсказание следующего номера** — гонка, офис ищет по ложной цифре
- **Резерв `kp_id` при создании черновика** — дырки в нумерации, статус «черновик» в архиве
- **Прятать «Скачать» до сохранения** — ломает текущий ритуал «сначала документы, потом архив»
- **Затирать `unit_price` скидкой** — сломает целевую сумму
- **Две колонки прайс/скидка** — пользователь выбрал замену отображения
- **Чистить старые WEB-файлы на диске** — достаточно не показывать их в UI
- **Менять нумерацию архива / формат `КП-N`** — архив уже использует `str(kp_id)`
