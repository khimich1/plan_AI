# КП: «в производстве» у плиты только после кнопки

## Problem Statement

How might we дать менеджеру менять марки, добавлять и удалять плиты, скидку и доставку у КП «в архиве» и «на согласовании», если строка плиты с первой записи уже подписана «в производстве» и сохранение из-за этого откатывается?

## Recommended Direction

Подпись «в производстве» на строке плиты ставит кнопка «В производство», в той же записи, где КП становится «в работе». До этого момента статус строки пустой, `plan_id` пустой. Пустая подпись не входит в запрет удаления. Запрет остаётся для «в производстве», «в плане» и для заполненного `plan_id`.

Сейчас колонка `kp_plates.status` получает «в производстве» при первой вставке. Кнопка «В производство» меняет только статус КП, срок и обещание по дорожкам. Замена марки выбрасывает старый `line_id` и вставляет новый. Сохранение пытается удалить старую строку, видит подпись по умолчанию и откатывает всю транзакцию: ни марка, ни новая плита, ни скидка, ни доставка. Так застряли КП №30, №57 и №59. До плана они не дошли.

Цех эти плиты и сейчас не видит: в план попадают только строки «в производстве» у КП «в работе». После правки они попадут в цех в тот же момент — когда нажали кнопку.

Уже сохранённые плиты без плана у КП «в архиве» и «на согласовании» один раз лишаются ложной подписи. Строки «в плане», с номером плана и плиты КП «в работе», «На СГП» и «выполнено» не трогаем.

Отдельное слово вроде «в заказе» не заводим. Пустой статус нигде не считается производством. Новую подпись пришлось бы учесть в каждом запросе, который читает статус.

Отправка в 1С остаётся отдельной кнопкой. После успешного сохранения на согласовании снимок состава расходится, и «Отправить исправление» пишет `delta_`, когда номер счёта уже есть.

## Key Assumptions to Validate

- [x] На архиве и на согласовании одни и те же правки: марка, добавление, удаление, количество, цена, скидка, доставка
- [x] «В производстве» у плиты начинается с кнопки «В производство», не с первой записи строки
- [x] До кнопки статус строки пустой, без нового слова
- [x] После «В производство» конструктор по-прежнему закрыт: КП «в работе» не правим
- [x] Строка «в плане» или с номером плана не удаляется и не заменяется
- [x] Ложную подпись снимаем только у плит без плана, пока КП в архиве или на согласовании

## MVP Scope

**In**

- Вставка плиты явно пишет пустой статус и не берёт значение колонки «в производстве».
- Кнопка «В производство» в той же транзакции ставит «в производстве» плитам этого КП без номера плана.
- Одноразовая правка данных: `status` обнулить там, где он «в производстве», `plan_id` пустой, а КП «в архиве» или «на согласовании».
- Запрет удаления в `core/kp_persistence_service.py` не ослаблять для настоящих производственных строк.

**Out**

- Новая подпись статуса, новые кнопки, автозапись файла в 1С при «Сохранить».
- Правка состава КП «в работе».
- Статусы свай, ФБС, маршей и ступеней.

## Not Doing (and Why)

- Не ослаблять запрет для плит, которые уже в плане. У дорожки записан конкретный `id` строки.
- Не открывать конструктор для КП «в работе». Туда плиты попадают как раз кнопкой «В производство».
- Не писать файл в 1С при каждом «Сохранить». Номер счёта может ещё не прийти, правок бывает несколько. Кнопка «Отправить исправление» уже есть.
- Не заводить статус «в заказе». Пустого статуса достаточно, чтобы сохранение архива прошло и цех плиту не увидел.
- Не трогать плиты КП «в работе» при разовой правке данных. Иначе обещания по дорожкам и отбор плана потеряют остаток «в производстве».
