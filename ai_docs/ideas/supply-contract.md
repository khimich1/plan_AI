**Направление**: кнопка «Договор» в карточке архива — карточка покупателя или ручная форма, один номер на контрагента, реестр вместо Excel юриста, номер в шапке JSON для 1С

## Problem Statement

How might we выдать менеджеру в архиве номер договора поставки и бланк покупателя так, чтобы этот номер ушёл в уже собранный JSON для 1С, а юрист больше не вёл учёт в Excel?

## Recommended Direction

Договор — запись на контрагенте, не на каждом КП. В карточке архива кнопка «Договор». Если действующего договора нет, менеджер загружает карточку контрагента или заполняет форму сам. Картинка сверяется с полями тем же контуром, что распознавание КП. После подтверждения программа берёт следующий номер вида `1028/09/26`, ставит статус «нет» и печатает docx типового бланка. Следующее КП того же контрагента подставляет тот же номер.

Реестр (номер, дата, контрагент, менеджер, оригинал/ЭДО, скан) живёт в той же кнопке. Статус подписи меняет менеджер. В 1С статус не уходит и отправку не блокирует. В шапку тестового JSON `КоммерческоеПредложение` добавляется номер договора. 1С по этому JSON создаёт КП и заказ клиента; номер счёта совпадает с номером заказа и вместе со статусом заказа возвращается на наше КП.

## Key Assumptions to Validate

- [x] Один действующий договор на контрагента. Новый номер только явным действием после «отмена не будем работать». Отменённый номер другому клиенту не отдаётся.
- [x] Номер для 1С нужен до подписи. Статус «нет» отправку не держит.
- [x] Номер выдаём мы. Обратно приходят номер заказа (он же номер счёта) и статус заказа.
- [x] Статус подписи меняет менеджер в архиве. Отдельной роли юриста нет.
- [ ] Перед включением лист юриста читается заново. На 25.09.2026 последняя строка была `1027/09/26`. Если у одного контрагента две живые строки, человек выбирает номер.
- [ ] 1С примет номер строкой в шапке JSON. Рабочее имя поля — `НомерДоговора`, пока интегратор не назовёт своё.

## MVP Scope

Кнопка в архиве, форма покупателя, распознавание карточки со сверкой, печать docx по текущему бланку, реестр и смена статуса, выдача номера, подстановка номера в шапку будущего JSON. Разовая загрузка листа юриста, чтобы не завести второй договор уже известному клиенту.

## Not Doing (and Why)

- Спецификация к договору — отдельная задача, пользователь соберёт её позже.
- Доработка текста бланка — поля формы стабильны, печать подстроится, когда бланк обновят.
- Живая отправка в 1С и разбор ответа — обмена в коде ещё нет; этот контур только отдаёт номер сборщику JSON и принимает место для номера заказа и статуса.
- Суффикс `-КП` — на листе это разовая поправка покупателя, не правило.
- Новая роль «юрист» — архив уже открыт менеджеру и администратору.
- Приложение №1 (доверенность М-2) — заполняется в день самовывоза, не при создании договора.
- ИГК и казначейский счёт — покупатель сообщает о них отдельным письмом, в бланк не подставляем.

## Open Questions

Блокирующих нет. Служебное на включение: перечитать лист и разрулить две живые строки одного контрагента, если такие найдутся.
