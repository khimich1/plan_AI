# KP Target-Sum Discount + High-Discount Confirm

## Problem Statement
How might we дать менеджеру за секунды подогнать итог КП под бюджет клиента и при этом не дать «молча» поставить скидку выше 16% без явного подтверждения?

## Recommended Direction
Двусторонний ввод скидки в шаге результата визарда и в карточке архива:

1. **Целевая сумма (₽)** — менеджер вводит бюджет клиента (например 2 000 000). Система считает `discount_percent` так, чтобы **«Итого с НДС» (включая логистику)** совпало с целевой суммой.
2. **Скидка (%)** — как сейчас; при изменении % пересчитывается целевой/итоговый итог. Оба поля синхронизированы в обе стороны.

При эффективной скидке **> 16%** перед применением — модалка по образцу `ResetConfirmDialog` (очистка БД):

- Текст: **«ВНИМАНИЕ: ДЛЯ СКИДКИ ВЫШЕ 16% НЕОБХОДИМО ОДОБРЕНИЕ РУКОВОДСТВА.»**
- Ввод ключевого слова **`ПОДТВЕРЖДАЮ`** (кнопка ОК активна только после точного ввода).
- **ОК** — применить скидку; **Отмена** — откатить ввод, скидку не менять.

Порог единый для всех типов продукции (плиты, сваи, ФБС, ступени, марши и т.д.). Хранение по-прежнему через `discount_percent`; целевая сумма — UX-вход для обратного расчёта. Ролей руководителя и записи факта подтверждения в КП в v1 нет: это осознанное принятие риска менеджером, не реальный approve-gate.

## Key Assumptions to Validate
- [ ] База для обратного %: сумма с НДС **без скидки**, **включая логистику** — один ручной кейс с менеджером сходится с калькулятором
- [ ] Порог строго `> 16` (не `≥ 16`) для всех product types
- [ ] Confirm с keyword `ПОДТВЕРЖДАЮ` достаточно без роли «Руководство»
- [ ] Округления построчного `discounted_price` не ломают «попасть ровно в 2 млн» (допуск / стратегия округления)

## MVP Scope
- Поле «Целевая сумма (₽)» ↔ поле «Скидка (%)» (двусторонняя синхронизация)
- Целевая сумма = итог с НДС **с логистикой**
- Модалка при >16%: warning + keyword `ПОДТВЕРЖДАЮ` + ОК/Отмена
- Точки входа: `CalculationResultStep` (визард) и `OfferDetailsDrawer` (архив)
- Порог константой (позже — конфиг при необходимости)
- Без записи `discount_acknowledged_*` в БД

## Not Doing (and Why)
- Роли / approve руководителем — цель v1: скорость торга, не compliance-workflow
- Блокировка скачивания PDF/XLSX без approve — overkill
- Статусы КП `awaiting_approval` — отдельная фича
- Построчные разные скидки — ломает модель одной скидки на КП
- Смена модели ценообразования (скидка только на итог без пересчёта строк) — риск для экспорта/архива
- Аудит «кто подтвердил большую скидку» в метаданных КП — явно не нужно в v1

## Open Questions
- Допуск округления: требовать точное совпадение целевой суммы или допускать копейки/рубли из‑за построчного округления?
- При целевой сумме **выше** прайса без скидки: ошибка, скидка 0%, или «наценка» (сейчас модель только скидка 0–100%)?
- Keyword в UI показывать как подсказку `ПОДТВЕРЖДАЮ` (как при обнулении БД) — да, по тому же паттерну.
