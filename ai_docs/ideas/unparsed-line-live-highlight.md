# Подсветка нераспознанных строк при добавлении в wizard КП

_Дата: 28.08.2026 · Пересмотр: 28.08.2026 (после мерджа `web` → `aleksey_web` и декомпозиции контура КП, `70035ef`) · Статус: направление подтверждено, спека на ревью · Источник: idea-refine, боль «жёлтая плашка слишком поздно и с ней ничего нельзя сделать»_

**Спека:** [ai_docs/specs/unparsed-line-live-highlight.md](../specs/unparsed-line-live-highlight.md)

## Problem Statement

Как в поле ввода списка изделий сразу показать, какие строки не разберутся — построчно, для всех типов — так, чтобы в состав КП через текстовое добавление не попадали нераспознанные позиции, и мёртвая жёлтая плашка не ехала до шага 3?

## Что не изменилось после мерджа

Боль и UX-курс те же. Поле «Добавить к списку» / «Обработать текст» по-прежнему обычный `Textarea`. После отправки поле чистится, `unparsed_lines` живут в метаданных черновика, мёртвый список «Не попали в состав» — в `Kp*PreviewPanel`, дубль на шаге 3 в `CalculationResultStep`. На сверке с фото `PlateListEditor` уже красит «Не попало в расчёт» и нумерует строки. Слэш `ПБ 40,3/2,6-8п` парсер по-прежнему не ест.

Мердж GSM / графика поставки / обнуление БД на этот жест не влияет.

## Новые вводные (зачем пересмотр)

1. **Единый product pipeline.** `ProductDraftHandler` + `ProductDraftSpec` (`product_draft_config.py`) — один create/update на шесть типов. HTTP-контракт не схлопнули (P1: «URL не схлопываем», «не расширять скоуп на `/parse`»). Для этой идеи как раз время расширить `/parse`, а не плодить шестую копию preview.

2. **Лёгкий разбор для плит уже есть и фронт его не зовёт.** `POST /api/v1/commercial/parse` → `CommercialService.parse` → `PlateParserService.parse_plate_text`. Отдаёт `unparsed_lines`, `diagnostics`, `warnings`. Без сметы и без ILP. Для свай/ФБС/маршей/ступеней/мостовых такого пути нет: только `generate_preview` (там ещё прайс; у плит — ещё оптимизация). Живую подсветку **нельзя** вешать на `generate_preview`.

3. **Состояние мастера формализовано.** `WizardNextRequiredAction` знает `resolve_wide_plates` и `resolve_unpriced_plates`. Нераспознанные туда **не добавляем**: стоп только на «Обработать текст» / «Добавить к списку», не на «Готово, далее».

4. **Уже две карточки исключений.** Широкие плиты и «нет в прайсе» (`71f1c60`, вынесены в `commercial_plate_resolve.py`). Третью карточку для unparsed не делаем — чинят строку в поле.

5. **Append-циклы.** С шага 3 можно добавить другой тип (`append_batches`, пропуск клиента). Линт должен идти по **текущему** `product_type` цикла, не всегда «плиты».

6. **Фронт не декомпозирован.** Шесть `*InputStep.tsx` с копипастом карточки источника. Бэкенд теперь один pipeline; UI всё ещё шесть мест. Иначе подсветка разъедется.

## Recommended Direction

Живая подсветка **в том же поле, куда печатают**. Курс UX не меняется.

1. Пользователь вводит список. Проверка **фоном** (пауза ~0,5 с).
2. Неуспешные непустые строки краснеют тем же языком, что `PlateListEditor` (оверлей + номера строк). Парсер на TypeScript не копируем.
3. «Обработать текст» и «Добавить к списку» **серые**, пока проверка не закончилась **или** есть красная непустая строка.
4. Нажать можно, только когда все непустые строки нормальные.
5. Пустые строки не краснеют и не блокируют кнопку.
6. Плашка «Не удалось распознать строк: N» и «Не попали в состав» с предпросмотра и шага 3 убираем как основной сигнал текстового ввода.
7. «Готово, далее» / `next_required_action` не трогаем.

«Распознать фото» — сначала OCR; живая покраска до появления строк не действует. После OCR сверка списком как сейчас.

**Как проверять (после P1):** расширить существующий `POST /commercial/parse`: поле `product_type`, ответ — список строк с флагом parsed/unparsed (и короткой причиной). Внутри — только line-parser типа (`parse_line` / `parse_pile_line` / …), **не** `spec.generate_preview`. Для плит текущий `/parse` уже почти это; для остальных — тот же URL, другая ветка spec. Фронт: один хук дебаунса + подставить `PlateListEditor` (или его оверлей) вместо голого textarea в карточке источника.

## Key Assumptions to Validate

- [ ] Пауза ~0,5 с не орёт на полуслове и не держит кнопку серой слишком долго — 5–10 реальных списков, включая слэш `40,3/2,6`
- [ ] Расширенный `/parse` без preview/ILP укладывается в комфортную задержку — p95 на 5 / 30 / 100 строках, все типы
- [ ] В append-цикле другого типа (сваи после плит) подсветка идёт правильным парсером
- [ ] Операторы понимают, почему кнопка серая — сценарий «добавить ещё позиции»

## MVP Scope

- Подсветка поля ввода на **всех** типах; на фронте лучше общая карточка источника, иначе шесть одинаковых правок
- Фоновый `POST /commercial/parse?` / body с `product_type`; без `generate-preview` и без записи черновика
- Кнопка обработки/добавления неактивна, пока проверка в полёте или есть красные
- Убрать мёртвую плашку и «Не попали в состав» с предпросмотра и шага 3 как основной UX текстового ввода
- «Готово, далее» и wizard `next_required_action` не менять

## Not Doing (and Why)

- **Блокировка «Список верен» / «Готово, далее» / новый `resolve_unparsed`** — стоп только на кнопке обработки текста
- **Вызов `generate_preview` на каждый ввод** — у плит это ILP и смета; слишком тяжело и побочные эффекты
- **Второй парсер на TypeScript** — разъедется с бэкендом на шести типах
- **Третья карточка как wide / unpriced** — здесь правят строку в поле
- **Подсказки «вы имели в виду …?»** — рано
- **Слэш `40,3/2,6` в парсере** — отдельная задача; подсветка честно краснеет
- **Живая подсветка на фото до OCR** — там сверка после распознавания
- **Схлопывание 32 URL мастера** — вне скоупа (P1 это явно отложил); трогаем только `/parse`

## Open Questions

- Подпись серой кнопки: молчание, «Проверка…», или «Исправьте красные строки» — уточнить при вёрстке
- OCR-нераспознанное на сверке с фото: оставляем текущую подсветку списка; в эту идею не входит, можно ли там тоже серить «Список верен» — нет, курс был не блокировать сверку
- Выносить общую карточку источника из шести `*InputStep` сразу или сначала плиты с тем же хуком — предпочтение: общая карточка, иначе копипаст разъедется за неделю
