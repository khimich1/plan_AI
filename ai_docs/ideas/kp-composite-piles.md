# КП на составные сваи

> Ideation session: 2026-09-22  
> Контекст: прайс секций `Прайс на составные сваи от 18.09.2026.xlsx` (лист «Прайс», классы 15 / 20 / 22.5 / 25 / 30 на граните). Комплектация серии 1.011.1-10 вып. 8 — `банк знаний/Составные сваи — комплектация секций (серия 1.011.1-10 вып.8).xlsx`: 123 сваи (41 длина × 3 стыка), 102 уникальные секции. Стол цен файл с «составн» в имени отвергает («группа пока не ведётся»). GUID — лист «Сваи составные — только в 1С» в `Сопоставление GUID 1С и программа.xlsx` (72 имени, после нормализации сходятся 41 из 102 секций).  
> Образец: [`kp-piles.md`](kp-piles.md). Очередь пустого GUID: [`guid-demand-queue.md`](guid-demand-queue.md).

## Problem Statement

**Как дать менеджеру вставить заявку, где составная свая приходит и целиком (`С140.30-С`), и секциями (`С60.30-ВС.1`), и получить в КП канонические секции с ценой из свежего прайса и GUID из листа 1С — тем же путём, что у цельных свай?**

## Recommended Direction

### Выбор: клон цельных свай, взрыв по таблице серии, GUID не блокирует КП

Отдельный тип КП «Составные сваи». Оболочка как у цельных: текст, фото, ИИ, класс бетона, строгий прайс, PDF/XLSX, архив, без производства. Новое — граница входа.

Целая марка серии (`С140.30-С`, `С140.30-Св`, `С140.30-Св.ВП`) по таблице комплектации становится двумя строками секций с тем же количеством. `С140.30-С × 5` даёт `С60.30-ВС.1 × 5` и `С80.30-НС.1 × 5`. Уже пришедшая секция остаётся одной строкой. Написания `Сваи С 60.30-ВС.1`, `С 60.30-ВС.1`, латинские `C` / `B` сходятся в канон `С60.30-ВС.1` до поиска цены и GUID. Суффикс стыка — часть канона: стаканный (`-С`, секции `ВС` / `НС`), сварной (`-Св`, секции `ВСв` / `НСв`) и сварной с поперечным армированием (`-Св.ВП`, секции всегда с индексом `.6`) не схлопываются.

Одна и та же секция, пришедшая и из целой сваи, и отдельной строкой, в таблице КП суммируется. Исходный текст заявки остаётся в черновике.

```
[Создать КП] → … | Сваи | Составные сваи | …
                              ↓
                   Шаг 1: текст / фото / ИИ
                              ↓
              целая свая → 2 секции; секция → 1 строка
              канон С60.30-ВС.1, одинаковые секции суммируются
                              ↓
                   Таблица: Марка | Класс ▼ | Кол-во | Цена
                              ↓
                   Клиент → Результат → PDF/XLSX (только секции) → Архив
```

### Источники данных

| Что | Откуда |
|-----|--------|
| Раскрой целой сваи на две секции | Таблица комплектации серии, 123 строки. Парсер длины не вычисляет |
| Цена | `Прайс на составные сваи от 18.09.2026.xlsx`, лист «Прайс». Цена на секцию, не на целую сваю |
| GUID | Лист «Сваи составные — только в 1С». Точное совпадение канона приклеивается само. Пустой GUID — в очередь экономисту, сохранение КП не ждёт |
| Канон в КП, базе и PDF | `С60.30-ВС.1` — марка серии без пробела |

PDF и XLSX для клиента содержат только секции. Исходная марка сваи (`С140.30-С`) в документ клиенту не попадает.

### Ключевые продуктовые решения

| Решение | Выбор |
|---------|-------|
| Кто | Менеджер КП |
| Тип КП | Отдельный, клон цельных свай |
| Строка заявки «целая свая × N» | Две секции, у каждой количество N и своя цена |
| Строка заявки «секция» | Одна строка |
| Повтор одной секции в заявке | Сумма количества |
| Класс бетона | С строки заявки на обе секции; если нет — подсказка B25 и правка в таблице, как у цельных |
| Цена | Strict lookup канон + класс из прайса 18.09.2026 |
| GUID | Точное совпадение с листом 1С; иначе очередь, КП сохраняется |
| PDF / XLSX | Только секции в каноне |
| После сохранения | Архив + бейдж; без производства и СГП |
| Импорт прайса | Стол цен принимает этот файл (сейчас отвергает) |

## Key Assumptions to Validate

- [ ] Класс бетона в строке относится к обеим секциям — сверка с 2–3 реальными заявками
- [ ] Количество целой сваи копируется на каждую секцию, а не делится — тот же набор заявок
- [ ] Суммирование одинаковых секций в одной заявке понятно менеджеру — прогон смешанного списка: `С140.30-С × 2` и отдельно `С60.30-ВС.1 × 3` дают `С60.30-ВС.1 × 5`
- [ ] В заявках встречаются и целые марки, и секции — иначе таблица комплектации не окупается
- [ ] Раскроя вне 123 строк серии в заявках нет. Нет строки в комплектации — строка не разбирается, менеджер правит вручную
- [ ] Автопривязка GUID только при полном совпадении канона. Нечёткое сопоставление приклеит чужой GUID: 31 имя листа 1С не из серии (другое написание, «гранит», комплекты, целая `С190.35-Св.ВП`)

## MVP Scope

**In:**

- Тип КП «Составные сваи» по каркасу цельных
- Парсер и нормализатор алиасов к канону `С60.30-ВС.1`
- Взрыв целой марки по 123 строкам комплектации; секция остаётся собой
- Сумма одинаковых секций в таблице
- Импорт прайса 18.09.2026 в свою таблицу цен; стол цен этот файл больше не отвергает
- Таблица: марка, класс бетона, количество, цена
- PDF/XLSX только из секций
- Бейдж в архиве
- Точный GUID с листа «Сваи составные — только в 1С»; пустой — в существующую очередь экономисту

**Out:** см. Not Doing.

## Not Doing (and Why)

- Блокировка сохранения, пока нет GUID — в листе 1С нет 61 секции серии, КП встанет
- Нечёткое сопоставление GUID — 31 имя не из серии
- Цена из `Прайс сваи составные.xls` — там пустые продажные цены; цена только из xlsx от 18.09.2026
- GUID из `Прайс сваи составные.xls` — источник GUID один: лист «Сваи составные — только в 1С»
- Производство и СГП — у цельных свай этого нет
- Мостовые составные — другой прайс и другие марки
- Секции в каталоге цельных свай — другие марки (`С120.30-8` против `С60.30-ВС.1`) и другой прайс
- Целая свая одной позицией с ценой-суммой — в прайсе цены на сваю нет
- Исходная марка сваи в PDF клиенту — в документе только секции
- Вычисление раскроя кодом вместо таблицы серии — ошибка стыка даст не ту пару секций
