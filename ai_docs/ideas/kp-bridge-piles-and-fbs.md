# КП на мостовые сваи и ФБС

> Ideation session: 2026-08-05  
> Контекст: прайсы `банк знаний/Прайс на мостовые сваи от 03.08.2026.xlsx` (64 SKU) и `банк знаний/7_5 В прайс на ФБС  от 03.08.2026.xlsx` (14 SKU). Уже есть плиты, обычные сваи, ЛС, ЛМ.  
> Образец UX/спеки: [`kp-piles.md`](kp-piles.md) / [`../specs/kp-piles.md`](../specs/kp-piles.md) — **не** ЛМ.  
> Handoff: [`../develop/handoffs/2026-08-05-kp-multiproduct-ls-lm-to-fbs.md`](../develop/handoffs/2026-08-05-kp-multiproduct-ls-lm-to-fbs.md)

## Problem Statement

**Как дать менеджеру создавать отдельные КП на мостовые сваи и ФБС с тем же UX, что у обычных свай — текст/фото/ИИ, класс бетона per-line, цена строго из прайса, PDF/XLSX и архив — не смешивая каталоги с обычными сваями?**

## Recommended Direction

### Выбор: Clone свай по очереди, UI раздельно

Два новых `product_type` (рабочие имена: `bridge_piles`, `fbs`). Общая оболочка мастера как у свай. **Порядок: сначала мостовые сваи, потом ФБС.** В picker — отдельные карточки, не подтип «Сваи».

```
[Создать КП] → … | Сваи | Мостовые сваи | … | ФБС
                              ↓
                   Шаг 1: текст / фото / ИИ
                              ↓
                   Таблица: Марка [| вариант ▼] | Класс ▼ | Кол-во | Цена
                              ↓
                   Клиент → Результат → PDF/XLSX → Архив
```

**Почему так:**
- Критерий успеха задан явно: «как сваи» (`kp-piles`), не как ЛМ.
- Мостовые ≠ обычные сваи: другой прайс, другие марки (`C8-35T1…`), другие grades (только 25/30, разреженная матрица).
- ФБС — отдельный каталог с grades `7.5|20|22.5|25`.
- Точечный clone проверен на ЛС/ЛМ; generic framework — после этих двух.

### Ключевые продуктовые решения

| Решение | Выбор |
|---------|-------|
| Кто | Только менеджеры КП |
| Порядок | **Мостовые сваи → ФБС** (отдельные итерации) |
| UI vs обычные сваи | **Раздельно** (отдельная карточка picker) |
| UX / образец | Clone **свай** (`kp-piles`): grade dropdown, OCR, PDF с классом |
| Алиасы марок (`T` / `В`) | Lookup по синонимам (одна цена); в КП/PDF — **как вписал менеджер** (без подмены на канон) |
| Тип КП | Одно КП = один `product_type` |
| Цена | Strict lookup mark + grade из прайса |
| После save | Архив + бейдж; **без** производства / СГП |
| Нумерация | Общая серия `kp_id` |
| Импорт прайса | CLI, лист «Прайс» |

### Прайс — факты

**Мостовые сваи** (лист «Прайс»): 64 строки; колонки `25 | 30`; у каждой марки цена **только в одной** колонке; ~50 строк с алиасами `C8-35T4; C8-35В4`; смесь лат. `C` / кир. `С`.

**ФБС** (лист «Прайс»): 14 марок `ФБС 9.3.6-Т`…; колонки `7.5 | 20 | 22.5 | 25` (плотная матрица).

## Key Assumptions to Validate

- [ ] В заявках встречаются обе формы алиасов → UI выбора окупается
- [ ] Dropdown grades показывает **только классы с ненулевой ценой** для марки
- [ ] Если у марки один доступный класс — подставлять его автоматически
- [ ] Нормализация `C`/`С`, пробелов, `В`/`B` достаточна для парсера
- [x] **Default grade** для мостовых: один доступный → он; иначе B25 если есть
- [x] **Bulk grade:** skip строк без класса + warning (решение A)
- [ ] Default grade для ФБС: B25 или B7.5 — в SPECIFY ФБС

## MVP Scope

**In (итерация 1 — мостовые сваи):**
- Picker «Мостовые сваи» → `product_type=bridge_piles`
- Ввод текст + фото + ИИ
- Preview: марка, выбор вариации (если есть), класс бетона, qty, цена
- CLI import → `bridge_pile_prices`
- PDF/XLSX, архив, бейдж + фильтр
- Исключение из production / СГП

**In (итерация 2 — ФБС):** то же по образцу свай, `product_type=fbs`, grades из прайса ФБС

**Out:**
- Подтип обычных свай
- Смешанное КП
- Generic multi-product framework
- Производство / СГП
- UI-импорт прайса
- Оба продукта в одном PR

## Not Doing (and Why)

- **Смешение с `piles`** — другой каталог и grades; риск неверной цены
- **Silent synonym без UI** — менеджер должен видеть, какая форма уйдёт в КП
- **Generic framework сейчас** — после 2 клонов по образцу свай
- **ФБС в том же PR, что мостовые** — поэтапный rollout
- **Производство / СГП** — whitelist plates only

## Success Criteria

1. Менеджер делает КП на мостовые сваи **тем же путём**, что КП на обычные сваи
2. **100% цены** из прайса; вариации марки выбираются явно
3. ФБС добавляется следующей итерацией без переизобретения wiring
4. Обычные `piles` / plates / steps / marches не ломаются
