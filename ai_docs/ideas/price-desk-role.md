# Стол прайсов

> Дата: 2026-09-15. Статус: концепт согласован; спека [`ai_docs/specs/price-desk-role.md`](../specs/price-desk-role.md);
> план [`ai_docs/develop/plans/2026-09-15-price-desk-role.md`](../develop/plans/2026-09-15-price-desk-role.md).
> Источники: `банк знаний/Новая папка/прайсы/* от 07.09.2026.xlsx`,
> `Расчет новых цен на ПБ 17.08.2026.xls` (колонка Никиты).
> Рядом, но не это: [`guid-price-sync-loop.md`](guid-price-sync-loop.md) — выгрузки 1С и GUID.

## Problem Statement

Как дать экономисту самостоятельно подменять заводской прайс так, чтобы новые КП
считались по актуальным ценам — без доступа к КП и производству и без вызова
разработчика?

## Ключевые решения (зафиксированы)

1. **Отдельная роль `economist`.** Человек видит только стол прайсов. Не admin,
   не accountant (ГСМ), не manager. Паттерн как бухгалтер → `/gsm`.
2. **Один стол `/prices`, один drop-zone.** Экономист бросает файл, программа
   говорит, что это за группа, показывает дифф, человек подтверждает.
3. **Цена в КП берётся из `pb.db` в момент расчёта.** Отдельного «подхвата» нет.
   Сохранённые КП не пересчитываются: у строк уже стоит `unit_price`.
4. **Источник — заводская калькуляция, не 1С.** Листы «Цены / Расход / Себест / Прайс».
   Выгрузка «Прайс-лист» 1С сюда не кладётся.
5. **Плиты: колонка Никиты.** Лист «Прайс», «Цены по прайсу, который прислал Никита».
   Расчёт М400/М500 в КП не пишем. Нагрузки 16 и 21 у Никиты пустые — не импортируем.
   12,5 → `load_code=12`, как сейчас в `price_db`.
6. **Остальные группы: лист «Прайс» целиком.** Второй колонки «Никита» нет.
   Лист «Цена для покупателя» — пустой шаблон, не источник. Берутся текущие
   импортёры, стол их оборачивает.
7. **Группа — по имени файла, затем ровно один парсер.** «Кто вернул больше строк»
   запрещён: на комплекте 07.09 ФБС читается и как сваи, ступени — как B15,
   составные — как 510 строк цельных.
8. **Без подтверждения диффа запись не идёт.** Превью: дата, сколько изменилось,
   сколько новых, сколько пропало и останется со старой ценой (`INSERT OR REPLACE`).
9. **Составные сваи — отказ с текстом «группа пока не ведётся».** В КП продукта нет.
   Файл того же формата; грузить его в чужие таблицы нельзя.
10. **`.xls` и `.xlsx` оба принимаем.** Плиты приходят старым `.xls`.

Якоря в имени: `ФБС` / `ЛМ` / `ступен` / `мостов` / `цельн` / `составн` /
`Расчет новых цен на ПБ`. Дата в имени меняется, якоря — нет. Имя и содержимое
не сошлись → ошибка, не запись.

Ложные срабатывания, если выбрать парсер по числу строк: ФБС→pile 42 и bridge 14;
ЛМ→pile 35; ступени→pile 42 (все B15); мостовые→pile 128; составные→pile 510 и
bridge 102; цельные→bridge 315 (только B25).

## Key Assumptions to Validate

- [ ] Парсеры 07.09 по пяти группам дают счётчики из таблицы без правки листа
- [ ] Парсер плит: 277 цен Никиты, без 16/21, 12,5 как 12
- [ ] Экономист будет грузить сам, без «залей, пожалуйста»
- [ ] На следующем комплекте якоря в имени те же
- [ ] `INSERT OR REPLACE` достаточен, пока пропавшие марки видны в превью

## MVP Scope

1. Роль `economist` в том же ряду, что `accountant`: логин, ACL, пункт меню только
   «Прайсы», редирект на `/prices`.
2. Экран: дата текущего прайса по группам + drop-zone.
3. Загрузка → классификация → превью-дифф → подтверждение → `INSERT OR REPLACE`
   в существующие таблицы (для плит — новый парсер колонки Никиты).
4. Понятная ошибка на чужой/битый файл, на составные, на несовпадение имени и листа.

## Not Doing (and Why)

- **Составные сваи** — нет продукта в КП; отдельный проект (таблица, парсер, мастер).
- **Загрузчик 1С / очередь GUID** — другой файл и другая работа; см. `guid-price-sync-loop.md`.
- **Живая таблица цен и правки ячеек** — пока не доказан регулярный файловый цикл.
- **Вешать на admin / accountant** — ломает изоляцию, ради которой нужна роль.
- **Автоприменение без диффа** — один кривой Excel портит все новые КП.
- **Вычитание марок, которых нет в файле** — в MVP только показ «остались старые».
- **Автовыбор парсера по числу строк** — ложные попадания, таблица выше.
- **Колонки расчёта плит М400/М500 и нагрузки 16/21** — не продажный контур КП.
- **Лист «Цена для покупателя»** — пустой шаблон.
- **Пересчёт архивных КП** — цена уже в строке; успех = новые КП.
- **Слежение за папкой** — стол сам по себе и есть канал.

## Open Questions

- Черновик, открытый в момент заливки, при следующем превью может показать новые
  цены — для v1 оставляем: фиксировать цену в черновике не обещали.
- Журнал «кто / когда / какой файл» — со второго цикла; в v1 достаточно `imported_at`
  в прайс-таблицах (поле уже есть у свай/ФБС/ЛМ/ступеней).
- Дробные цены не-плит (1683.33…) — как в файле, как уже пишет CLI. Округление
  до рубля не делаем, пока экономист не попросит.
