# ГСМ: лента журнала машины — карточки транзакций + ПЛ, листание месяцев

## Problem Statement

Как превратить журнал машины в раскрытой строке из «календарь сверху, таблица ПЛ
снизу» в хронологическую ленту, где каждая транзакция (заправка/мойка) — карточка,
за которой следуют путевые листы, её закрывающие, а месяцы листаются стрелками
прямо в раскрытой строке — чтобы бухгалтер за секунды видел покрытие заправок
путевыми, не переключаясь между вкладками «Журнал» и «Транзакции».

## Recommended Direction

**Направление A: календарь с ‹ › + вертикальная лента по дням.**

`VehicleMonthCalendar` получает шапку со стрелками ‹ › (месяц назад/вперёд) и
становится самодостаточным: раскрытая строка больше не зависит от верхнего
фильтра периода. Календарь остаётся «картой дыр» и навигацией по месяцам.

Под календарём — вертикальная хронологическая лента выбранного месяца вместо
текущей таблицы ПЛ. Секция дня содержит: карточку транзакции (АЗС, литры, сумма,
время) и под ней карточки ПЛ этого дня (водитель, км, маршрут, бак). Связь
транзакция → ПЛ — тот же календарный день: это уже доменное правило генератора
(якорь fuel/wash порождает ПЛ на день якоря), консистентно с gap-логикой
`vehicleDayMap.ts`.

Транзакция без ПЛ — янтарная карточка-дыра с CTA «Сгенерировать» (та же
семантика, что янтарный день в календаре). ПЛ без транзакций — обычная карточка
рабочего дня. Пустые дни не рендерятся. Клик по ПЛ открывает существующий
`WaybillDayDrawer`. Итоги месяца (км, литры) из удаляемого `tfoot` переезжают в
компактную summary-строку над лентой.

Отклонённые альтернативы: мастер-детейл «календарь + день справа» (убивает обзор
месяца, сценарий «проверить покрытие» превращается в кликанье по 30 дням) и
карточки внутри укрупнённых ячеек календаря (нечитаемо при 10+ ПЛ в месяце,
мёртвая мобильная адаптация). Горизонтальная карусель карточек отклонена как
антипаттерн для данных: вертикальный скролл — естественная навигация по ленте.

## Key Assumptions to Validate

- [ ] **Same-day связь достаточна** — проверить на реальных данных Palisade: нет
  ли заправок, фактически закрываемых ПЛ соседнего дня (ночные смены). Если есть —
  правило расширяется отдельно.
- [ ] **Объём месяца умеренный** (десятки событий) — проверить на самой активной
  машине; если лента раздувается, добавить фильтр «только дыры».
- [ ] **Summary-строка итогов достаточна** — показать бухгалтеру, что потеря
  табличного сравнения (одометр, статусы построчно) компенсируется drawer'ом.

## MVP Scope

**Входит (frontend-only):**
- Пейджинг месяцев ‹ › в `VehicleMonthCalendar` (внутреннее состояние месяца,
  рефетч `useGsmWaybillsQuery` / `useGsmTransactionsQuery` с новыми границами).
- Лента дня: карточка транзакции + вложенные карточки ПЛ того же дня.
- Карточка-дыра (tx без ПЛ) с CTA → focus+scrollIntoView на «Сгенерировать»
  (переиспользовать существующий `focusGenerate`).
- Summary-строка итогов месяца (км, выдано литров).
- Удаление таблицы ПЛ из `VehicleWaybillJournal`; `WaybillDayDrawer` и
  `VehiclePeriodStrip` сохраняются.

**Не входит:** backend/core изменения, явная привязка tx↔ПЛ, вкладка
«Транзакции».

## Not Doing (and Why)

- **Мастер-детейл по дню** — убивает обзор покрытия месяца.
- **Карточки в ячейках календаря** — нечитаемо при 10+ ПЛ, мёртвая мобильная вёрстка.
- **Явная привязка tx→ПЛ в backend** — same-day правило уже покрывает домен;
  расширение только при подтверждённых ночных кейсах.
- **Окно ±1 день** — неоднозначность «какой ПЛ закрывает какую заправку».
- **Перестройка вкладки «Транзакции»** — скоуп ограничен раскрытой строкой машины.
- **Горизонтальная карусель** — антипаттерн для сканирования данных.

## Open Questions

- Нужен ли фильтр «только дыры» внутри ленты (если активные месяцы раздуются)?
- Состав карточки транзакции: достаточно АЗС/литры/сумма/время или нужны карта и
  вид топлива?
- Пейджинг месяца сбрасывается при сворачивании строки или запоминается?
