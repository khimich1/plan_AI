# Реестр договоров на контрагентов 1С

**Статус**: IDEATE  
**Дата**: 2026-10-27  
**Спека:** [`ai_docs/specs/reestr-dogovorov-na-kontragentov-1c.md`](../specs/reestr-dogovorov-na-kontragentov-1c.md)

## Problem Statement

Как при вводе КП снова показывать «нет 1С» только когда клиент не привязан к справочнику 1С, а в архиве подставлять уже существующий номер из реестра и не заводить второй договор?

## Recommended Direction

Два разных вопроса больше не смешиваются.

На шаге «Клиент» поиск снова идёт только по справочнику 1С, по названию и ИНН. Менеджер выбрал строку — на КП пишутся `counterparty_id`, имя, ИНН, КПП и код. Не выбрал и оставил свободное имя — `counterparty_id` пустой, бейдж «нет 1С» честный. Карточки договоров в этот поиск не входят: именно они после коммита `51814e0` подставляли имя без карточки 1С.

На этой машине `supply_contract` и `supply_contract_event` сначала очищаются, затем реестр загружается заново. Импорт сам строки не стирает: `0001/09/26` (ДСТрой 76) и `0006/09/26` (ХОРС) в реестре отсутствуют, без очистки они останутся. Сырой `Реестр договоров.xlsx` в импорт не встаёт — в нём три листа и колонка «Контрагент». Уже собран `/home/roman/Загрузки/Реестр договоров для загрузки.xlsx`: лист «ИНН без сомнений», 217 строк в колонках «номер договора», «имя контрагента», «ИНН». Импорт вставляет номер, имя, ИНН и дату из номера. Связь с карточкой 1С при этом не ставится.

Совпадение ищется только по ИНН. В реестре 261 строка, по ИНН однозначно стыкуется 217. Не вошли 44: у 18 ИНН нет карточки в справочнике, у 7 ИНН пустой, 4 упираются в две карточки 1С на один ИНН, 13 делят одну карточку 1С на несколько номеров, 2 карточки не отмечены клиентом. Название не связывает: «Ева Груп» и «ЕВА ГРУПП ООО» — один ИНН и разные имена.

В архиве, когда карточка 1С уже привязана, программа берёт её ИНН и ищет договор в `supply_contract`. Название 1С показывается рядом, чтобы строку узнали. Одна строка реестра пишет `counterparty_id`, и этот номер становится действующим договором. Несколько номеров на один ИНН — менеджер выбирает один: на одного контрагента база пускает только один действующий договор, остальные карточки остаются без связи. ИНН в договорах нет — на карточке КП текст «в реестре договора нет».

В JSON поле `НомерДоговора` ставит `attach_contract_number`. Номер берётся из строки `supply_contract`, у которой `counterparty_id` уже равен клиенту этого КП и статус не «отмена». Договор другого клиента штамп не принимает: владелец строки сверяется с id клиента.

Сейчас перед записью счёта и перед переводом в производство вызывается `link_unique_inn_contracts`. Он сам пишет `counterparty_id` на свободную карточку с тем же ИНН. Если таких карточек несколько, `select_contract_client_links` оставляет позднюю дату. После этого штамп видит уже «свой» договор, хотя секунду назад карточка клиенту не принадлежала. Этот вызов при отправке выключается. Связь появляется раньше: один номер на ИНН — сразу после загрузки, несколько — когда менеджер выбрал. Отправка новый номер не выбирает.

Уже созданные лишние карточки в продукте этот шаг не удаляет.

## Key Assumptions to Validate

- [ ] Цифры 261 / 217 / 44 получены сверкой файла с локальной `plita.db`. Перед применением тот же отчёт прогоняется на базе, куда реестр уже загружен.
- [ ] Источник договоров в архиве — таблица `supply_contract`, не повторное чтение xlsx. Иначе номер, выданный программой (`0006/09/26`), выглядит как «договора нет».
- [ ] Один действующий договор на контрагента 1С сохраняется. Три номера Секлюцкого остаются тремя карточками, к клиенту крепится один.
- [ ] Свободное имя на шаге «Клиент» остаётся. Бейдж «нет 1С» при пустом `counterparty_id` как раз это и показывает.

## MVP Scope

- Локально очистить `supply_contract` и `supply_contract_event` и загрузить лист «ИНН без сомнений» из `Реестр договоров для загрузки.xlsx`.
- Шаг «Клиент» снова ищет справочник 1С. Режим карточек договоров с этого шага уходит.
- По загруженным договорам `counterparty_id` ставится по ИНН: один номер — сразу, несколько — выбор менеджера, без ИНН — связь не ставится.
- В отправку 1С `НомерДоговора` идёт только из действующего договора этого контрагента.
- На карточке КП в архиве, если клиент 1С есть, а договора нет, виден текст «в реестре договора нет».
- Автовыбор позднего договора при отправке в 1С выключен.

## Not Doing (and Why)

- Удаление лишних карточек в продукте — отдельный шаг после отчёта. Локальная очистка семи программных номеров до загрузки реестра — не этот шаг.
- Привязка по похожему названию — так к договору прилипает чужая «ПСК» из восьми организаций.
- Повторное чтение xlsx при открытии карточки — правки менеджера живут в базе, файл их затрёт.
- Поиск карточек договора на шаге «Клиент» — из-за него бейдж «нет 1С» загорается при живом имени.
- Пачка «спорные ИНН» отдельным импортом — те же 44 строки разбираются листом «Не вошли».
- Смена правила «один действующий договор на контрагента» — исторические номера и так остаются карточками без связи.
