# Контур синхронизации GUID и цен «программа ↔ 1С»

> Дата: 2026-09-15 (раунд 1), 2026-09-17 (раунд 2). Статус: решения согласованы, к реализации.
> Спека раунда 2: `ai_docs/specs/guid-price-sync-round2.md`;
> план раунда 2: `ai_docs/develop/plans/2026-09-17-guid-price-sync-round2.md`.
> Источники: сверка «Сопоставление GUID 1С и программа.xlsx», «Дубли GUID в 1С.xlsx»,
> выгрузки 1С `банк знаний/Новая папка/GUID/*.xls`, ТЗ `docs/specs/1c-integration-tz-v2.md`.

## Problem Statement

Как сделать, чтобы каждое изделие из прайса программы имело GUID 1С (мост для счетов и выпуска),
каждое изделие 1С без нашей цены — получало цену, а цена всегда считалась только в программе?

## Ключевые решения (зафиксированы)

1. **Цена — только в программе.** В 1С цены «Продажная» фактически пустые (у свай 5% позиций);
   в счёт уходит наша цена, 1С — приёмник.
2. **GUID — единственный мост.** Никаких кодов и имён в документах.
3. **Пять состояний позиции** (см. таблицу ниже) — Excel-сводка становится рабочей очередью,
   а не разовым отчётом.
4. **Хранилище GUID — маппинг-таблица `nomenclature_guid`** в pb.db для 5 не-плитных групп:
   `(product_kind, mark, guid_1c, guid_1c_u, match_status, match_note, updated_at)`.
   Прайс-таблицы не трогаем (у них PK марка×класс — GUID дублировался бы по 5 строк).
5. **Плиты НЕ переносятся.** `prays_plity` уже есть мэппинг плит (56 981 GUID, 100%);
   цена плит — матрица `prices`, к GUID отношения не имеет; `nomenclature_id` уже прошит
   через КП → производство → СГП. Плитам нужны только две гигиенические правки
   (дубли строк, детерминированный `fetchone()`), не миграция.
6. **Счёт без GUID → блок целиком**, со списком «что завести в 1С». КП считается свободно.
7. **Дубль разрешает только человек.** Разово — файл «Дубли GUID в 1С.xlsx» (58 пар),
   выбранное заливаем со статусом `manual`. Автовыбора нет никогда.
8. **«у»-сваи: одна марка, одна цена, два GUID** (`guid_1c` + `guid_1c_u`).
   В счёт уходит GUID того варианта, который заказали; цена — как у обычной, по классу бетона
   (решение бухгалтерии от 14.09.2026).
9. **GUID возвращается только файлом.** Производство заводит карточку в 1С → выгрузка
   «Прайс-лист» (.xls) → загрузка файла в программу → сверка → GUID появляется сам.
   Ручного ввода GUID нет.
10. **«Только в 1С» → очередь «ввести цену».** Изделие с GUID, но без цены не участвует
    в расчётах, пока цена не введена. Цена вводится за штуку.
11. **Excel — окно для людей и bootstrap; БД — машинное хранилище.** После bootstrap-заливки
    программа работает с `nomenclature_guid`, Excel остаётся для бухгалтерии (дубли).

## Модель: пять состояний позиции

| В прайсе | В 1С | Состояние | Чьё действие | Объём (14.09.2026) |
|---|---|---|---|---|
| да | да, один GUID | ✅ готово | заливка GUID в программу | 57 251 (из них не-плит 271) |
| да | дубль (2+ GUID) | ⚠️ выбрать GUID | бухгалтерия → статус `manual` | 58 имён |
| да | нет | 🏭 завести в 1С | производство → reexport → GUID сам | 224 (сваи 123, мостовые 71, ступени 30) |
| нет | да | 💰 ввести цену | менеджер/производство; до цены — вне расчётов | ~98 (сваи 55, мостовые 27, ФБС 4, марши 3, ступени 9) |
| нет | да, группа не ведётся | ⏸️ вне контура | — | 232 (составные 72, перемычки 103, прогоны 21, фундаменты 32, площадки 4) |
| — | материалы | 🚫 вне контура | — | 2 323 |

Особые случаи: плиты «только в 1С» (229) — 223 покрыты матрицей длин (цена появится сама
после связи), 6 коротышей (0.58/13/15/15.8 дм) требуют решения о расширении матрицы.
«у»-карточки 1С без нашей марки (16) — цены не требуют, решаются вместе с plain-маркой.

## MVP Scope

1. **Excel-сводка → очередь**: колонки «Состояние»/«Действие», лист «Задачи»
   (две очереди: 🏭 завести в 1С / 💰 ввести цену), колонки ввода цены на листах
   «только в 1С» для 5 ведомых групп.
2. **Таблица `nomenclature_guid`** + bootstrap-заливка 271 однозначного GUID не-плит
   + 58 дублей после разметки бухгалтерией (статус `manual`).
3. **Загрузчик файла выгрузки в программу** (админка): парсинг .xls «Прайс-лист»
   (данные с 3-й строки, GUID — колонка 2, товар — 4, цена — 8) → сверка с
   `nomenclature_guid` → отчёт: «+N GUID, M ждут цены, K неоднозначных, J исчезли из 1С».
   Паттерны: endpoint — как `delivery_schedule.py /import`, диалог — как `ImportScheduleDialog`.
4. **Импорт введённых цен** из Excel → прайс-таблицы с валидацией (марка существует,
   цена > 0, класс известен). Для свай — по классам, с подстановкой «как у ближайшего
   соседа» (то сечение, ближайшая длина): авто-ступени опровергнуты данными
   (шаг между классами 79–599 руб без правила, 2 марки-аномалии).
5. **Идемпотентный перезапуск**: каждая загрузка файла переводит позиции между состояниями.

## Not Doing (and Why)

- **Перенос плит в `nomenclature_guid`** — `prays_plity` уже рабочий мэппинг; риск без пользы.
- **Новые прайс-группы** (составные сваи, перемычки, прогоны, фундаменты, площадки — 232) —
  заведение группы = отдельный проект (таблица, парсер, КП); помечаем «не ведётся».
- **Материалы 1С** (2 323) — сырьё, не продукция.
- **UI ввода цен** — пока Excel; UI — когда цикл покажет регулярный объём.
- **Дельта-синк номенклатуры по ТЗ п.2** — позже, с 1С-интегратором; загрузчик файлов
  остаётся ручным каналом до него.
- **Автовыбор GUID при дубле** — никогда.

## Open Questions

1. ~~**Сваи, ввод цены: 5 классов.**~~ — **решено 15.09: одна цена за штуку на изделие.**
   В прайс-таблице проставляется одинаковой по всем классам бетона; разница по классам —
   только ручной правкой, если производство попросит.
2. ~~**6 плит-коротышей** (0.58/13/15/15.8 дм): расширять матрицу цен или не продаём?~~ —
   **решено 17.09: матрицу не расширяем; коротыши — договорной ценой** (oneoff,
   механика `kp-unpriced-price-drawer`). Счёт коротыша без GUID блокируется как любая позиция.
3. ~~**Кто вводит цены** в очереди 💰: менеджер, производство или бухгалтерия?~~ —
   **решено 17.09: ввод на вкладке «Прайсы и 1С» (admin + economist)**; массовые
   обновления — через «Загрузка прайса»; Excel-очередь — запасной канал.
4. ~~**Custom-изделия** (`свая-колонна`, `СГС 80.35`, `13А*` — 11 марок)~~ —
   **решено 17.09: блокируем без исключений** (нет GUID → нет счёта). Офис заводит вручную.
5. ~~**Новые марки в 1С — сразу парой (plain + «у»)?**~~ — **решено 15.09: заводим только
   недостающее изделие.** Упреждающих пар нет: 22 марки с «у» в 1С → только plain;
   99 марок → только plain. «у»-карточка появляется через тот же контур, когда впервые
   понадобится (заказ с «у» → блок счёта → завести в 1С → reexport → GUID).
6. **Кто и когда делает reexport**: по запросу после каждого заведения или раз в день? —
   **открыто (процессное)**. Минимум зафиксирован 17.09: после заведения карточек офис
   грузит «Универсальный отчёт» (допустима частичная выгрузка с отбором).

## Решения 17.09.2026 (раунд 2)

**Ворота счёта (GPS-010 детализировано):**
- Одна позиция без GUID блокирует **весь счёт**, списком «что завести в 1С».
- Договорная цена не освобождает от GUID.
- Для «у»-свай нужен `guid_1c_u`; срез по «у» — по суффиксу марки (как в D11 линт-парити).
- Заведение карточек — в офисе (экономист), не на заводе; спецификация заводится
  позже на заводе — вне этого контура.

**Контур предупреждений:** шаг 3 мастера → мягкий Alert (не блокирует архив);
сохранение КП в архив → уведомление `kp_guid_missing` активным economist
(если ни одного — warning в лог); колокольчик — один раз на пару КП-марка;
задача живёт на вкладке «Прайсы и 1С» до закрытия; ворота при «Выставить счёт» — жёсткие.

**Вкладка «Прайсы и 1С»** (`/prices`, admin + economist): «Загрузка прайса» (как сейчас) +
«Выгрузка из 1С» (переезд диалога из шапки) + «Задачи по изделиям» (🏭/💰 из живых
таблиц, не Excel) + «Дубли GUID».

**Дубли (58 пар):** единый UX и endpoint для всех видов; решение принимает бухгалтерия
(офлайн), клик делает экономист; не-плиты → `nomenclature_guid.match_status='manual'`
+ аудит (chosen_by/at/note); плиты → override-таблица `plate_guid_choice`
(`prays_plity` не правим); выбранный GUID исчез из 1С → 409 + задача снова открыта.

**Форматы 1С:** старый «Прайс-лист» .xls и новый «Универсальный отчёт» .xlsx — оба;
у отчёта плавающая шапка (ищем по именам колонок) и возможные отборы
(частичная выгрузка → `disappeared` не считаем); цены в отчёте нет;
вес/объём — бонус в справочник весов. 1С первая по времени: наши марки, которых
нет в файле 1С, — 🏭 «завести в 1С».

**Ввод цены 💰:** гибрид — массовые цены через «Загрузка прайса», точечные 💰 и
коротыши — на вкладке, Excel — fallback; после ввода цены GUID сразу пишется в
`nomenclature_guid` со статусом `auto` (связь сразу готова к счёту).

## Отложено

- **Удаление/объединение дублей в 1С (58 пар)** — ждёт ответа бухгалтерии по файлу
  «Дубли GUID в 1С.xlsx». До ответа дубли в очереди помечаются ⚠️ «ждёт бухгалтерию»
  и не блокируют остальной контур. Известный риск: 5 пар с разными ценами
  (ПБ 54-6,6-12,5п; ПБ 72-9,0-12,5п+доб; Перемычки 5 ПБ 36-20п; ПБ 60-12-8п П1.3;
  ПБ 72-6,6-12,5п) — перед чисткой решить, какая цена верная.
