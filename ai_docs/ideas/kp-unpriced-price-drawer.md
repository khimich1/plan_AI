# КП: прайс слева и договорная цена на «нет в прайсе»

> Дата: 2026-09-15. Статус: направление подтверждено, к спеке.
> Источник: шаг 1 мастера, сваи C110.30-6 / C110.40-8.1 (B25) — «нет в прайсе».
> Рядом, но не это: [`unpriced-plates-replacement.md`](unpriced-plates-replacement.md) (замена нагрузки у плит),
> [`price-desk-role.md`](price-desk-role.md) (стол экономиста),
> [`guid-price-sync-loop.md`](guid-price-sync-loop.md) (Excel-очередь «ввести цену» в заводской прайс),
> [`kp-row-edit-delete-icons.md`](kp-row-edit-delete-icons.md) (карандаш qty/марки; ручная цена там была Out).

## Problem Statement

Как дать менеджеру на шаге состава КП **убедиться, что марки реально нет в прайсе**, увидеть соседние изделия с их ценами и **поставить договорную цену только в это КП** — не уходя в Excel и не записывая число в заводской прайс?

## Recommended Direction

На красных строках («нет в прайсе») появляется кнопка **«Прайс»**. Слева выезжает уже существующий `Drawer side="left"`: поиск по всему прайсу текущей группы. У каждой марки **своя** цена (марка × класс). Текущие дырки подсвечены как отсутствующие, рядом видны соседи.

Дальше менеджер вводит цену **в красную строку этого черновика**. Число живёт в `order_data.unit_price` с пометкой `price_source=oneoff`, **не** пишется в `pile_prices` / стол экономиста. Гейт «Нет цен для позиций» пропускает строку (`unit_price is not None`). Следующее КП с той же маркой снова покажет «нет в прайсе».

Это сознательный узкий разворот относительно «ручную цену не делаем»: только непрорасценённые строки, только это КП, каталог завода не трогаем.

## Locked answers (ideation 2026-09-15)

| Вопрос | Решение |
|---|---|
| Главная работа | Увидеть, что марки реально нет, и соседние цены |
| Кто вводит цену | Менеджер — договорную **только в это КП** |
| Что в панели | Весь прайс текущей группы с поиском |
| Направление | Справочник + договорная цена; заводской прайс не трогаем |

## Defaults на бывшие Open Questions

- PDF/XLSX клиенту — обычная цена, без слова «договорная». Пометка только во внутреннем предпросмотре.
- Скидка на шаге результата действует и на договорную, как на прайсовую.
- Смена класса бетона на красной строке **сбрасывает** договорную: снова lookup. Нашли в прайсе — прайс; нет — снова «нет в прайсе».
- MVP — все простые типы с `KpGradedPreviewPanel` (сваи, мостовые, ФБС, марши, ступени). **Плиты — нет** (у них замена нагрузки).
- Сигнал экономисту «эту марку запрашивали» — не делаем.

## Key Assumptions to Validate

- [ ] Семейства + поиск хватает на кейсе C110.30-6 / C110.40-8.1; весь список без запроса не нужен как стартовый вид.
- [ ] Коммерция и бухгалтерия принимают КП с маркой вне заводского прайса. Счёт без GUID по-прежнему блокируется контуром 1С.
- [ ] Qty-only PATCH сохраняет договорную; полный `generate_preview` (класс / «Список верен» заново) — нет, и это ок.
- [ ] Соседняя цена — подсказка для глаз, не автоподстановка в чужую марку.

## MVP Scope

Кнопка «Прайс» при `unit_price === null`. Левый Drawer: поиск по прайсу группы, пин отсутствующих, цены соседей. Поле договорной ₽/шт на красной строке → PATCH черновика, флаг `oneoff`. Wizard к клиенту разблокирован. PDF/XLSX берут `unit_price` из строки.

## Not Doing (and Why)

- **Писать в прайс-таблицы из мастера** — стол экономиста и Excel-очередь GUID.
- **Договорная на строке, которая уже в прайсе** — для этого скидка на результате.
- **Подставить цену соседа без смены марки** — клиент получит чужую марку по чужой цене.
- **Клик по соседу = замена марки** — карандаш уже меняет «как в списке».
- **Плиты** — другой смысл «нет в прайсе» и свой флоу; ILP нельзя кормить договорной «как будто производится».
- **Дамп всех строк без поиска как единственный вид** — старт: пин дырок + поиск.
- **Снимать блок счёта без GUID.**
