# КП: правка и удаление строки иконками

> Ideation locked: 2026-08-31  
> Спека: [`../specs/kp-row-edit-delete-icons.md`](../specs/kp-row-edit-delete-icons.md)  
> Related: [`kp-multi-nomenclature-append.md`](./kp-multi-nomenclature-append.md) (delete line на шаге 3), [`unparsed-line-live-highlight.md`](./unparsed-line-live-highlight.md)

## Problem Statement

**How might we** как менеджеру на месте поменять марку или количество одной позиции (с новой ценой) или убрать строку — на предпросмотре шага 1 и на шаге 3 — минималистичными иконками, с отменой этой операции, не путая её с откатом последнего добавления?

## Recommended Direction

Общий компонент действий строки: карандаш в квадрате и мусорка. Одинаково на «Состав КП (предпросмотр)» всех типов и на «Позиции» шага 3. Большое слово «Удалить» уходит.

- **Количество** — правка в строке, пересчёт цены этой линии. Без полного `generate_preview` / ILP на каждый qty.
- **Марка** — не свободное наименование. Короткое поле «как в списке» (`ПБ 28-5,3-8п`), парсер **этой** строки, затем цена. Если парсер не принял ввод — ошибка у строки.
- **Парсер вернул 0 или 2+ позиций** (в т.ч. wide split) — **принять как замену этой строки**: одна линия снимается, на её место встаёт то, что вернул парсер (пусто = строка исчезла; две = две вместо одной).
- **Широкие и «нет в прайсе»** — карточки и сценарии **как сейчас**. Карандаш **не блокируем**: ими как раз чинят ошибку менеджера, из-за которой строка попала в wide/unpriced.
- **Удаление** — сразу, существующий `DELETE .../lines/{line_id}`.
- **Отменить** — тост последней операции (удалили / сменили qty/марку / заменили строку). Кнопку отката последнего **пакета** не трогаем.

Предпросмотр прокидывает `line_id` из `order_data` (сейчас `buildKpPreviewRows` его выбрасывает).

## Key Assumptions to Validate

- [ ] После сверки менеджер ещё правит состав, глядя на цены — не всё ловят в textarea
- [ ] Qty-only достаточно без полного `generate_preview` / ILP
- [ ] Карандаш во время открытых wide/unpriced чинит причину, а не ломает эти блоки
- [ ] Замена 1→0 / 1→2 из парсера понятна и не хуже «отказать»
- [ ] Тост «Отменить» понятен и не путается с «отменить добавление»
- [ ] Один UI-блок на шесть предпросмотров, иначе иконки разъедутся

## MVP Scope

**In:**
- Общие иконки (карандаш в квадрате, мусорка) на шаге 1 (все типы) и шаге 3
- Шаг 3: «Удалить» → мусорка + карандаш
- `line_id` в строках предпросмотра
- PATCH qty и/или марки через парсер строки; замена строки результатом парсера (0 / 1 / 2+)
- Wide / unpriced UI без изменения контракта; карандаш доступен
- Тост undo последней операции строки
- RTL

**Out:** ручная цена, новая пустая строка, confirm-dialog, правка кликом по ячейке без карандаша, полный Excel, смена undo-last-batch

## Not Doing (and Why)

- **Ручная цена / добавить пустую строку** — другой продукт, не правка OCR-состава
- **Подтверждение удаления** — выбран undo; лишний клик
- **Правка кликом по ячейке без иконки** — нужен явный карандаш
- **Переиспользовать undo-last-batch** — это пакет, не строка
- **Полный ILP на каждый qty** — дорого и побочно для «93 → 90»
- **Переделывать карточки wide / unpriced** — оставляем как есть; карандаш рядом, не вместо них
- **Блокировать карандаш, пока wide/unpriced не закрыты** — тогда нельзя исправить ошибку менеджера, из-за которой блоки появились
