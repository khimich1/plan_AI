# Лента «поездки + заправки + мойки» (XL для будущей карты)

## Problem Statement

Как получить единый источник правды, где каждая поездка из пула путевых листов
обогащена фактом заправки и мойки (литры, цена, АЗС, адрес, координаты),
чтобы контролировать ГСМ и строить карту маршрутов с точками обслуживания?

## Recommended Direction

**Событийная лента (вариант B) + экспорт под карту (вариант E).**

Зерно данных — событие в хронологии дня машины:
`выезд A → приезд B → заправка 13:02 → выезд B → приезд A`.
Заправки и мойки — первоклассные точки маршрута, а не атрибуты-колонки.

Привязка: транзакция → день машины по ключу `(топливная_карта, дата)`.
Ключ уже существует: `топливная_карта` в пуле = `Карта` в транзакциях
(94% заправок попадают ровно на день поездки, 97% в окне ±1 день).
Позиция заправки фиксируется флагом `до_выезда / в_рейсе / после_возвращения` —
лента растворяет вопрос «к чему отнести вечернюю заправку»: хронология видна сама,
атрибуция остаётся вопросом отчётности.

Один источник правды: скрипт `scripts/build_gsm_trip_feed.py`, XL — его выгрузка;
те же данные позже подключаются слоем в `build_gsm_routes_map.py`.

Структура XL `ГСМ/поездки_заправки.xlsx`:

1. `лента` — события (дата, машина, карта, время, тип, адрес, lat/lon,
   литры/сумма/бренд/АЗС для заправок, км/водитель/норма для плеч).
2. `рейсы_дня` — агрегат дня машины: км, литры, нормативный расход, дельта.
3. `маршруты` — уникальные A↔B с частотами + типовые АЗС направления.
4. `вне_поездок` — транзакции без поездки в тот же день (суммы не теряются).

## Key Assumptions to Validate

- [ ] Дыра авг–дек 2025 в ПЛ окончательна (~35% транзакций, ~2400 л непривязываемы).
  Тест: если ПЛ появятся — пересборка скриптом должна быть тривиальной.
- [ ] Время выезда/возвращения в ПЛ — фактическое, не плановое.
  Тест: выборочная сверка с реальностью; лента — реконструкция, не GPS-факт.
- [ ] Любая из трёх карт (266/268/269) = Geely Tugella 848.
  Тест: подтверждение у держателей карт.
- [ ] Адреса АЗС из транзакций геокодятся с приемлемым покрытием.
  Тест: доля скоординированных адресов после прогона Nominatim ≥ 90%.

## MVP Scope

- Парсинг `ГСМ/транзакции/*.xls` (шапка на 3-й строке, отброс строк «Итоги:»,
  сверка сумм с итогами файлов).
- Джойн с пулом по `(карта, дата)`; 848 схлопывается по машине.
- Лента с типами событий и флагом позиции; листы 2–4 как выше.
- Геокодинг адресов АЗС/моек через существующий кэш `ГСМ/geo_cache/addresses.json` (Nominatim).

## Not Doing (and Why)

- Несопоставленные пары как предмет анализа — решено отбросить (отдельный лист
  `вне_поездок` только для сохранения денег/прозрачности).
- GPS-треки и проверка «АЗС по пути» — нет данных, адрес АЗС только текст.
- Доработка `карта_маршрутов.html` слоем АЗС/моек — следующий шаг после приёмки XL.
- Автоматическое пополнение транзакций из ЛК оператора — ручная выгрузка пока ок.
