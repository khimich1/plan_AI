# Идея: GSM — коридор бака при выборе маршрута и честные литры моек

Дата: 2026-08-24. Статус: idea, direction confirmed (ждёт спеки).
Контекст: обнаружено при приёмке [`gsm-fleet-overview-ux`](../specs/gsm-fleet-overview-ux.md)
на живых данных Palisade (О 521 УХ 44), август 2026.

## Problem Statement

How might we не получать красные дни и ложное расхождение литров там, где
солвер мог решить период сам?

Сейчас на двух мойках подряд (03.08 и 04.08) солвер ставит самый частый
маршрут (Кострома ↔ Ярославль, 190 км) и 04.08 уходит в минус:
бак 13,58 − 27,55 = **−13,97 л** → `manual_intervention`.
Расхождение литров в обзоре показывает **+2 л**, потому что мойки
импортированы с `qty_liters = 1.0` и попадают в Σ всех операций.

## Recommended Direction

**1. Коридор бака при выборе маршрута якоря** (основное).

В `_select_anchor_route_lookahead` (или в общем выборе якоря) перед
удлинением/частотой оставить только маршруты, где

`0 ≤ fuel_start + Q − burn(2×km) ≤ tank_volume`.

- Если никто не влезает **сверху** — как сейчас: удлинение под выжиг.
- Если никто не влезает **снизу** — взять самый короткий маршрут;
  `manual_intervention` только если даже минимальный круг уходит в минус.

**2. Мойка предпочитает короткий маршрут — но не ценой коридора.**

Для якоря без литров при прочих равных выбирать минимальный km из
попадающих в коридор. Если короткий маршрут сам уводит бак в минус,
брать длинный из коридора (лучше 190 км, чем красный день).

**3. Σ литров = только топливо.**

В обзоре флота и в итогах журнала транзакций считать
`SUM(qty_liters) FILTER (WHERE service_type = 'fuel')`.
Мойки не входят в сравнение с `fuel_issued`.

**4. Импорт моек без литров.**

Для `service_type = 'wash'` записывать `qty_liters = None`, даже если в
файле оператора стоит число. Старые записи не мигрируем — после п.3 они
не влияют на обзор.

## Key Assumptions to Validate

- [ ] Библиотека машины содержит короткий городской маршрут
      (проверено на Palisade: есть 6 км, 12 км круг, сжигает 1,74 л).
- [ ] Ужесточение выбора не ломает существующие «зелёные» периоды
      (регрессия `tests/test_gsm_generator.py`).
- [ ] `typical_station_ids` мойки уже покрывают короткие маршруты
      (проверено: станция Магистральная 8 в списке 6 км маршрутов).

## MVP Scope

- `core/gsm/generator.py`: коридор при выборе + предпочтение мойки.
- `app/repositories/gsm_repository.py`: `tx_liters` только fuel.
- `app/services/gsm_transaction_service.py`: `qty_liters=None` для wash.
- Тест: две мойки подряд (пн/вт), старт 41,13 л, бак 70 л, норма 14,5 →
  04.08 обычный день 12 км, без `manual_intervention`.

## Not Doing (and Why)

- **Соло-плечо** (один leg вместо круга) — для текущих баков/маршрутов
  минимальный круг уже влезает; добавлять новый тип дня избыточно.
- **Waypoints внутри плеча** — модель `LegPlan` остаётся `addr_a → addr_b`;
  станция уже учитывается через `typical_station_ids`.
- **Миграция старых `qty_liters = 1.0` у моек** — не нужна после фильтра
  в обзоре.
- **Изменение схемы БД** — правка только логика и SQL-агрегат.

## Open Questions

- Правило «мойка = короткий» распространять на все машины или только когда
  станция мойки не «typical» для длинного маршрута? (Сейчас оба коротких
  и длинний маршруты Palisade помечены typical для этой станции.)
