# КП: добавить другое наименование

> Ideation session: 2026-08-12  
> Контекст: визард КП (`commercial-offer`), сейчас инвариант «одно КП = один `product_type`».  
> Handoff-фон: [`../develop/handoffs/2026-08-05-kp-multiproduct-ls-lm-to-fbs.md`](../develop/handoffs/2026-08-05-kp-multiproduct-ls-lm-to-fbs.md).

## Problem Statement

**How might we** дать менеджеру в одном сеансе набрать в **одно КП** сколько угодно заходов распознавания (в т.ч. повтор одной номенклатуры) для одного заказчика — с **общей скидкой** и **одним итоговым документом** — без отдельных КП и ручной склейки?

## Recommended Direction

**Loop + sticky header + хронологический append.**

На шаге результата кнопка **«Добавить другое наименование»** → выбор номенклатуры → цикл OCR/ввода заново → позиции **дописываются в конец** текущего КП в порядке добавления → снова результат.

Клиент, менеджер, условия и **скидка** живут в шапке draft и **не сбрасываются**. Со 2-го цикла шаг клиента **пропускаем**. Скидка одна на всё КП: ввёл 6% — дальше везде 6%; изменение скидки пересчитывает все уже добавленные позиции.

Тип продукции — только способ выбрать прайс и парсер на этом заходе, **не** ось группировки документа. В UI результата и в PDF/XLSX строки идут **как добавляли**, без блоков по типу. В таблице нужна **колонка/пометка номенклатуры** (плиты / сваи / …) для читаемости.

Архив по задумке — черновики: незавершённый набор можно открыть и продолжить тем же loop.

Лимита на число заходов нет (на чертежах бывает >10, в т.ч. Плиты→Сваи→Плиты→…).

### Логистика в MVP — только ПБ

Рейсы считаются **только по весу плит (ПБ)** в заказе. Non-plates в массу доставки не входят (пока нет их веса/«цены» для доставки). Поле «стоимость рейса» активно, если в КП есть хотя бы одна plate-строка.

Target-sum: сумма продукции со скидкой **+** доставка от ПБ (если есть).

Спека: [`../specs/kp-multi-nomenclature-append.md`](../specs/kp-multi-nomenclature-append.md) (Q1=C, Q3=несколько бейджей, Q4=класс в имени / unified колонки, Q5=line_id).

### Удаление в MVP

- Удаление отдельных строк на result.
- Кнопка **«Отменить последний заход»** (служебные границы append в draft, без сегментов в PDF).

## Key Assumptions to Validate

- [ ] Менеджеру достаточно порядка добавления в документе — группировка по типу/этажу не нужна
- [ ] Одна общая скидка на всё КП — норма; отдельные скидки по заходам не требуются
- [ ] Export (PDF/XLSX) корректно печатает смешанные строки в хронологическом порядке с пометкой номенклатуры, одной суммой и одной скидкой
- [ ] Незавершённый multi-проходный draft нормально сохраняется/открывается из архива и продолжает loop
- [ ] 10+ заходов OCR в одном draft не ломают UX (размер state, «Назад», время пересчёта)
- [ ] Заглушка логистики понятна менеджеру и не блокирует отправку КП без доставки
- [ ] (later) Источник веса для non-plates и правило рейсов в mixed-КП согласованы с бизнесом

## MVP Scope

**In**
- Кнопка на result: «Добавить другое наименование»
- Переход к picker → полный цикл ввода/распознавания выбранной номенклатуры
- Append позиций в конец того же draft (хронологически)
- Sticky: клиент / менеджер / условия / скидка; client step со 2-го цикла skip
- Колонка номенклатуры в result и в документе
- Result и export: плоский список + общие totals по продукции + общая скидка
- Удаление строки + undo последнего захода
- Логистика: рейсы только от веса ПБ; non-plates не в cargo
- Дозапись уже сохранённого КП из архива (тот же `kp_id`)
- Несколько бейджей типов в архиве; unified колонки; класс в имени; `line_id` на строку
- Повтор номенклатуры разрешён; лимита на число заходов нет
- «Создать новое КП» по-прежнему сбрасывает всё

**Out (на потом)**
- Вес/доставка non-plates в рейсы
- Сегменты / подписи «Этаж N»
- Группировка в PDF по типу
- Разные скидки на разные заходы
- История версий PDF
- Расширение производства/СГП на non-plates

## Not Doing (and Why)

- **Склейка нескольких сохранённых КП в пакет** — нужен один номер и одна сумма, не обход
- **Корзина типов в начале** — менеджер идёт по чертежу кусками, заранее состав неизвестен
- **Сегменты/этажи в MVP** — выбран плоский порядок добавления
- **Фиксация/группировка по `product_type` в документе** — тип только для цикла ввода и колонки-пометки
- **Лимит числа заходов** — на чертежах бывает >10
- **Вес non-plates в доставку** — пока нет цены/веса для рейсов; считаем только ПБ
