# A — Менеджер видит завод (готовность КП)

> Ideation session: 2026-07-28  
> Контекст: roadmap [`2026-07-28-development-roadmap-cifra-context.md`](../develop/plans/2026-07-28-development-roadmap-cifra-context.md), направление **A**.  
> Связанные модули: архив КП (`OfferDetailsDrawer`, `ArchiveOfferList`), `completion_percentage`, `sgp_progress`, `kp_plates`, `completed_plates`, `SgpService`.  
> Зависит от: СГП MVP ✅ ([`sgp-warehouse.md`](./sgp-warehouse.md)).  
> Не делает: **J** (статус для клиента по токену), **B** (выдача/отгрузка).

## Problem Statement

**Как менеджер продаж может за минуту ответить клиенту о готовности заказа без звонка в цех, опираясь на фактические данные производства и СГП?**

## Recommended Direction

### Один блок «Статус производства» в карточке КП

Readiness отвечает на вопрос **«что с заказом прямо сейчас?»** — актуально только для КП, уже ушедших в производство.

```
┌─ КП №1847 ─────────────────────────────────────────────────────┐
│  ● КП ──● Производство ──● СГП ──○ Выдача ──○ Закрыто           │
│         72%                 14/20 на СГП                          │
├──────────────────────────────────────────────────────────────────┤
│  «14 шт на складе, 6 в производстве. Можно выдать 14 шт.»       │
│  [Подробнее ▼]  [Скопировать для клиента]                        │
├──────────────────────────────────────────────────────────────────┤
│  Позиция       Заказ  В плане  На СГП  Осталось   ← по клику   │
│  ПБ 59-12-8     10      4       6        0                       │
│  ПБ 71-12-8      8      6       0        2                       │
└──────────────────────────────────────────────────────────────────┘
```

**Пользователь:** менеджер продаж (архив КП, звонки клиентам).  
**Критерии успеха:** меньше звонков в цех; ответ клиенту за <1 мин без уточнений.

### Lifecycle-степпер (5 шагов, MVP)

| Шаг | Источник данных | MVP |
|-----|-----------------|-----|
| КП | КП в производстве | активен |
| Производство | `completion_percentage`, остаток в `kp_plates` | активен по данным |
| СГП | `sgp_progress` N/M, статус «На СГП» | активен по данным |
| Выдача | направление B | **серый, disabled** |
| Закрыто | после полной выдачи | **серый, disabled** |

Под степпером — одна строка: *«Выдача с СГП — в следующем обновлении»*.

Серые шаги 4–5 не обещают лишнего, но сохраняют mental model из roadmap; при запуске B UI не переделывается.

### Сводная фраза и «можно выдать»

- **«Можно выдать X шт»** = `SUM(qty)` на СГП с `kp_id` этого КП (физически на складе, ещё не выдано клиенту).
- Примеры:
  - `n=14`, `m=20`, в производстве 6 → *«14 из 20 шт на складе, 6 в производстве. Можно выдать 14 шт.»*
  - `n=0` → *«Заказ в производстве (6 шт). На складе пока нет.»*

Кнопка **«Скопировать для клиента»** — менеджер пересылает текст (J отложен).

### Таблица по позициям (lazy, по «Подробнее»)

Колонки: **Заказ | В плане | На СГП | Осталось**.

**Правило подсчёта «На СГП»:** всё qty на складе по позиции, включая закрыто wizard «с СГП» и отправленное с дорожки — единый баланс склада.

**Правило отображения:** статус «с СГП» **не выводится** отдельной колонкой или строкой статуса; показывается только баланс (Заказ / В плане / На СГП / Осталось).

Пример:

| Позиция | Заказ | В плане | На СГП | Осталось |
|---------|-------|---------|--------|----------|
| ПБ 59-12-8 | 10 | 4 | 6 | 0 |

*(3 закрыты wizard «с СГП», 3 с дорожки, 4 ещё в плане — в «На СГП» = 6, без отдельной колонки «с СГП».)*

Группировка по identity: `plate_name` + `length_m` + `width_m` + `load_class` (как strict match в СГП).

### Где показывать блок

| Раздел архива | Статус КП | Readiness |
|---------------|-----------|-----------|
| Архив | «в архиве» | ❌ |
| В производстве | «в работе», **«На СГП»** | ✅ |
| Выполнено | «выполнено» | ❌ в MVP |

**Важно:** видимость по **статусу КП**, не по активной вкладке — при поиске менеджер может открыть КП «в работе» из любого контекста.

```typescript
const showReadiness = ["в работе", "На СГП"].includes(offer.status);
```

«На СГП» — часть «В производстве» (бейдж N/M), не отдельный раздел; КП остаётся там до модуля выдачи B.

### Backend: read-only агрегация

Зависимостей от B/J нет, но нужен **единый read-model**, чтобы список и карточка не расходились.

**API (согласовано):**

- Summary (`completion_percentage`, `sgp_progress`, `summary_text`, шаги степпера) — расширить **`GET /archive/offers/{id}`** (`ArchiveOfferDetails`).
- Таблица позиций — **lazy** отдельным запросом (например `GET /archive/offers/{id}/readiness/positions`).

Сейчас в коде: `sgp_progress` есть в списке (`ArchiveOfferListItem`), но **нет** в `_to_details`; per-position breakdown **нигде не собран**.

### Что уже есть vs что добавить

| Данные | Список архива | Карточка КП | После A |
|--------|---------------|-------------|---------|
| `completion_percentage` | ✅ | ✅ | без изменений |
| `sgp_progress {n,m}` | ✅ | ❌ | ✅ в details |
| Степпер + фраза | ❌ | ❌ | ✅ |
| Таблица позиций | ❌ | ❌ | ✅ lazy |

## Key Assumptions to Validate

- [ ] Менеджеры перестанут звонить в цех, если видят N/M + сводную фразу — опрос через 2 недели после релиза.
- [ ] «Можно выдать = на СГП» не порождает лишних визитов самовывоза — счётчик «приехал, не забрал» (если появится B).
- [ ] Группировка по марке совпадает с тем, как менеджер формулирует заказ клиенту — UAT на 3 реальных КП.
- [ ] `completion_percentage` (72%) и N/M (14/20) не путают — подписи на степпере достаточны без обучения.

## MVP Scope

**In:**

- `KpReadinessService` (или аналог): summary + positions[], read-only.
- Расширение `ArchiveOfferDetails` полями readiness summary.
- Lazy endpoint для таблицы позиций.
- UI-блок в `OfferDetailsDrawer`: степпер, N/M, фраза, «Подробнее», «Скопировать».
- Показ только при `status ∈ {в работе, На СГП}`.

**Out:**

- **J** — публичная ссылка по токену (PDF, прогресс для клиента).
- **B** — резервирование, акт выдачи, списание при отгрузке; активация шагов «Выдача» / «Закрыто».
- Push-уведомления, дашборд C, ETA по дням/дорожкам.
- Readiness в разделе «Выполнено» (исторический снимок — после B).
- Feature-flag.

## Not Doing (and Why)

| Не делаем | Почему |
|-----------|--------|
| **J — статус для клиента** | Достаточно A + копирование текста; нет запроса на self-service портал |
| Активные шаги «Выдача» / «Закрыто» | Нет данных и процесса до модуля B |
| Отдельная колонка «с СГП» | Баланс «На СГП» уже включает wizard close-from-SGP |
| Readiness в «Выполнено» | Live-готовность не нужна; заказ закрыт для менеджера |
| Proactive alerts | Нет стабильного read-model и политики «когда пинговать» |
| Степпер из 3 шагов | Ломает roadmap-макет; переделка при запуске B |

## Open Questions (некритичные для spec)

- Кнопка «Обновить» в drawer vs refetch при открытии — достаточно refetch в MVP.
- Точный шаблон текста «Скопировать для клиента» (формальный/краткий) — зафиксировать в spec.
- Исправление бага: `sectionFromStatus` — «На СГП» должен мапиться в `in_production`, не в `archived` (отдельная задача в plan).
