# Нумерация списка плит при сверке

> **Спека:** [`ai_docs/specs/numbered-plate-review-list.md`](../specs/numbered-plate-review-list.md)  
> **План:** [`ai_docs/develop/plans/2026-08-22-numbered-plate-review-list.md`](../develop/plans/2026-08-22-numbered-plate-review-list.md)

## Problem Statement

How might we дать оператору КП устойчивый порядковый индекс позиций в «Списке плит для расчёта», чтобы сверять список с фото или текстом и не пропускать строки — не меняя содержимое, которое уходит в расчёт?

## Recommended Direction

Визуальный гуттер слева от редактора списка, по тому же принципу, что номера строк в редакторе кода.

Номер **не** входит в текст списка. Строка остаётся `ПБ 78-12-8н 2`. Нумерация считается на лету по непустым строкам: пустая строка без номера, следующая плита получает следующий номер. Так «позиция 3» совпадает с третьей плитой на фото, а не с третьей строкой textarea.

Реализация — опциональный проп существующего `PlateListEditor` (оверлей подсветки + прозрачный textarea). Включить только в карточке «Список плит для расчёта» (`PlateInputStep`). Остальные изделия не трогаем, пока не убедимся, что индекс реально ускоряет сверку.

Это минимальная версия идеи, которая не конфликтует с количеством в конце строки и с парсером.

## Key Assumptions to Validate

- [ ] Порядковый номер слева достаточно, чтобы сопоставить строку с N-й позицией на фото — проверить на реальном КП с 15+ плитами, не на списке из трёх строк
- [ ] Номер не нужно копировать вместе с маркой — если при сверке список пересылают в чат, гуттера в буфере не будет
- [ ] Выравнивание номера и строки держится при переносе длинной марки — иначе индекс начнёт врать визуально

## MVP Scope

**Входит**

- Номера слева в режиме сверки текущего источника (batch review)
- Только непустые строки, 1-based
- Только плиты
- Текст, драфт, парсер, подсветки (исправлено / не попало / шире / добор) без изменения семантики

**Не входит** — см. ниже

## Not Doing (and Why)

- **Префиксы `1.` в самом тексте** — ломают разбор и путаются с количеством
- **Сваи, ФБС, марши, ступени, мостовые сваи** — тот же редактор, но гипотезу проверяем на плитах
- **Счётчик «N позиций» в заголовке** — отдельный сигнал; не выбран
- **Переразметка количества (`×2`)** — другой UX-баг, не индекс сверки
- **Чекбоксы «сверено»** — новый сценарий, не взгляд «фото ↔ список»
- **Номера/подсветка регионов на фото** — в клиенте нет bbox; это уже другой продукт
- **Номера в превью КП после сверки** — задача про проверку источника, не про итоговое КП

## Open Questions

- Номер только у первой визуальной строки при переносе марки — или запрещаем перенос в этом поле?
- Нужны ли номера, когда фото нет и сверка идёт только с текстом? (скорее да: тот же редактор)
- После подтверждения партии номера исчезают вместе с режимом сверки — это ок, или индекс нужен и в обычном списке?
