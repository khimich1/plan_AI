# КП по индивидуальным ЖБИ: AI-черновик + карточка изделия

Дата: 2026-08-05. Статус: направление зафиксировано, MVP не начат.

## Problem Statement

Как помочь **менеджеру по продажам** готовить КП по индивидуальным ЖБИ (балконные плиты, цокольные балки и т.п.) за 10–15 минут вместо 1–2 часов работы отдельного инженера-расчётчика, не подставляя завод риском ошибки в цене?

Контекст: индивидуальные изделия — самый маржинальный продукт завода, и скорость выпуска документации — узкое место масштабирования. Стратегический горизонт: те же данные должны питать закупки и карточки производственных заданий.

## Recommended Direction

**A + C: OCR-черновик из PDF с экраном сверки, результат — карточка изделия.**

1. Менеджер загружает PDF чертежа → новый тип документа в существующем OCR-пайплайне (`core/ocr`, по образцу свай: `extract_piles` → `extract_izdelie`) → vision-модель извлекает по каждой марке: наименование, м³, масса, сталь по классам/Ø, количество, `source_pages`.
2. **Parser gate с арифметическими правилами** (не LLM) — главный механизм надёжности:
   - Σ стали по Ø = «Итого» ведомости (МКД11: 2,36+6,94+11,80+93,44+18,40 = 132,94 ✓)
   - масса/м³ ∈ [2400; 2600] кг/м³ (0,58 м³ → 1450 кг ✓)
   - Σ количеств по секциям = итогу по марке
   - масса с рабочего листа = массе в спецификации (поймало расхождение БП-2: 625 vs 675 кг — 675/0,27 = 2500 правдоподобнее)
3. Экран сверки: страница PDF слева, таблица справа, зелёные ячейки свёрнуты («проверено правилами»), менеджер правит только флаги (оценка: 3–7 ячеек на комплект).
4. Подтверждённый черновик сохраняется как **карточка изделия** (C) со статусами `draft → verified → in_kp → in_production` — фундамент под закупки (агрегация стали по Ø: МКД11 = ~5,9 т, из них A500C Ø12 — 3,15 т) и будущие карточки производства.
5. Расчёт — перенос формул Excel («Цены» + рецептура B30 + ОПР + наценка 1,2) в детерминированный код с юнит-тестами на цокольных балках. КП уходит клиенту со статусом «предварительный расчёт», пока инженер не закрыл флаги.

Почему не альтернативы: конфигуратор без OCR (B) не снимает боль снятия данных с чертежа и требует калибровки из истории карточек — фаза 2. Полный агент на LangGraph + RAG по ГОСТам (D) — преждевременная сложность: процесс линейный, ценность RAG недоказана, для расчёта цены ГОСТы не нужны (цены/рецептуры живут в прайсах).

## Key Assumptions to Validate

- [ ] **(Dealbreaker)** Vision-модель извлекает спецификации с A3-листов CAD-качества с точностью ≥90%. Тест: прогнать МКД11 через GPT-4o/GigaChat (провайдеры уже есть) — 1 день.
- [ ] **(Dealbreaker)** Менеджер сверяет черновик за ≤10 мин при подсветке только расхождений. Тест: UX-прогон на 2–3 реальных PDF.
- [ ] **(Важно)** Расчёт модуля = расчёт Excel до копейки. Тест: юнит-тесты на цокольных балках (файл «Цокольные балки 28.07.26-2.xlsx»).
- [ ] **(Важно)** Заказчики присылают CAD-экспорты, а не грязные сканы. Тест: собрать 5–10 последних чертежей от разных КБ (это же тестовый набор для недели 2).

## MVP Scope (4 недели, 1 разработчик)

| Неделя | Содержание | Выход |
|---|---|---|
| 1 | Промпт ИЖБИ + `extract_izdelie` + парсер; прогон МКД11 | ≥90% полей на 1 образце |
| 2 | Parser gate: правила 1–4; verify-политика; 3–5 реальных PDF | Таблица точности |
| 3 | Экран сверки (frontend) + endpoint в `commercial.py` | Менеджер сверяет черновик |
| 4 | Расчёт + генерация КП + карточка изделия (миграция БД) | КП из PDF за 10–15 мин |

В scope: один класс бетона на комплект (B30), линейный пайплайн, статус «предварительный расчёт» как страховка.
Издержки: ~$1–3 LLM-токенов на комплект (14 стр. A3 × 2 прохода) — несущественно.
Деградация: грязный скан → все ячейки жёлтые → тот же экран работает как удобный ручной ввод (модуль не ломается).

## Not Doing (and Why)

- **LangChain/LangGraph** — процесс линейный (извлечь → проверить → посчитать → выдать), агент окупается только при ветвлениях/ретраях; шаги оформлены чисто, переезд позже — небольшая операция.
- **RAG по ГОСТам** — ценность недоказана (для цены ГОСТы не нужны), retrieval по нормативке ошибается именно там, где ошибка недопустима; если делать — отдельный чат-справочник позже, не блокирующий КП.
- **Конфигуратор-оценка (B)** — фаза 2, когда в карточках накоплено 30–50 изделий для калибровки норм расхода стали (плиты БП: 90–230 кг/м³, балки: ~340 кг/м³).
- **Парсинг DWG/DXF** — пока нет подтверждённого доступа к исходникам от заказчиков; PDF покрывает текущий поток.
- **Полный автомат без человека** — риск ошибки в цене недопустим; человек в контуре — это фича, не компромисс.

- Где живут актуальные прайсы для листа «Цены» — ручное обновление или синхронизация с `закупки/`?
- Кто закрывает флаги «предварительного расчёта» — роль инженера в новом процессе (5 мин проверки вместо 2 часов расчёта)?
