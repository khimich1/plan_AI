# Модуль «ГСМ: путевые листы» (веб, роль accountant)

## Problem Statement

Как бухгалтеру за один сеанс превратить выгрузку транзакций по топливным
картам в комплект путевых листов, где каждый маршрут проходит через АЗС/мойку
из транзакции, а списание по нормам сходится с купленными литрами?

## Recommended Direction

Batch-генератор периода с полным балансом бака + экран проверки + ручной
конструктор ПЛ. БД веб-модуля — источник правды; `scripts/build_gsm_*`
становятся одноразовым импортом истории. Роль `accountant` (доступ:
`accountant` + `admin`). Экспорт: бланк «ПЛ DD.MM.YY.xls» (ОКУД 0345001).

Алгоритм генерации (гибрид, вытекает из баланса бака):

1. **Якоря:** каждая транзакция (заправка ИЛИ мойка) = день с ПЛ, АЗС/мойка —
   точка маршрута дня. Выходная транзакция (1 из 509 в истории) — якорь
   с флагом «проверить»; генератор по умолчанию работает по будням.
2. **Дожигание:** между якорями генератор добавляет дни из библиотеки маршрутов
   машины (150–250 км/день), чтобы сжечь заправленное: остаток ведётся
   сквозной по дням в коридоре `[0 … объём бака]`, одометр — нарастающим
   итогом. Количество дней — результат решения, а не входной параметр:
   `дней ≈ литры_периода / (норма × дневной_км)`.
3. **Маршрут якорного дня:** из библиотеки, где АЗС — типовая; если АЗС новая —
   подбор по минимальному `крюк_км` (механизм `routes_via`); крюк > порога
   (~13 км) → день уходит в ручной режим с подсветкой.
4. **Нормы:** лето/зима по ручному переключателю сезона (дата в настройках).
5. **Водитель дня:** основной водитель машины по умолчанию, замена из
   справочника одним кликом. Жёсткой привязки карта→водитель нет.

Справочники: машины (бак, нормы лето/зима, госномер), топливные карты
(привязка/отвязка к машине, архивация вместо удаления), водители (ФИО,
удостоверение + дата выдачи, табельный №, СНИЛС, активность), АЗС (адрес,
координаты, бренд).

## Key Assumptions to Validate

- [ ] Бланк: шаблон ПЛ конвертируется в .xlsx с сохранением формул
  (LibreOffice установлен, в файле 137 формул) — проверить на 1 файле
  до начала работ: fill через openpyxl → пересчёт/экспорт через soffice
- [ ] Транзакции — реальные закупки, маршруты библиотеки — реальные
  направления; система оформляет реальный расход, фактическое движение
  не проверяет (by design)
- [ ] Км библиотеки = утверждённые историей расстояния — сверить 2–3
  с одометрами ПЛ
- [ ] Стартовые данные на дату запуска: остаток в баке + одометр по каждой
  машине — одноразовый ввод бухгалтером
- [ ] Реквизиты всех 8 фактических водителей (в т.ч. Зубов, Пчелкина,
  Бахвалова — их нет в `Роману.xlsx`) + устранить расхождение удостоверения
  Лоншаковой (99 43 2835052 vs 99 43 283502)

## MVP Scope

- БД: `vehicles`, `drivers`, `fuel_cards`, `stations`, `transactions`
  (импорт xls), `route_library` (импорт из `пул_поездок.xlsx`), `waybills`,
  `tank_day_balance`
- Импорт: транзакции (парсер из `build_gsm_trip_feed.py`) + одноразовый
  импорт истории и библиотеки маршрутов
- Генератор периода: якоря + дожигание, баланс бака, одометр, будни,
  сезонный переключатель норм
- Экран проверки: период × машина, таймлайн остатка/одометра, правка дня
  (маршрут из библиотеки, водитель, км), пересчёт downstream-дней
- Ручной конструктор ПЛ; управление картами и водителями
- Экспорт zip с бланками «ПЛ DD.MM.YY.xls»

## Not Doing (and Why)

- **«Виртуальный клиент» для дальних новых АЗС** (поиск правдоподобного
  адресата по тематике ЖБИ на нужном расстоянии) — фаза 2; в v1 такой день
  уходит в ручной режим с подсветкой крюка
- **Карта в вебе** — есть `карта_маршрутов.html`, отдельная задача
- **GPS/реалтайм** — источник истины: транзакции + библиотека маршрутов
- **Автовыгрузка из ЛК оператора** — ручная загрузка xls достаточна
- **Мойки как учёт денег** — только точка маршрута в ПЛ
- **Жёсткая привязка карта→водитель** — отклонено: практика показала
  ротацию (8 водителей на 4 машины)

## Open Questions

- Порог крюка «новая АЗС далеко»: старт 13 км (авто-калибровка 2026-08-12),
  пересмотреть экспертно после первого отработанного периода
- Период генерации = период загруженной выгрузки (min/max дат файлов),
  а не жёсткий календарный месяц — подтвердить у бухгалтера на первом запуске

## Данные на старте (замер 2026-08-14)

- 4 машины, 6 карт, 8 фактических водителей, ~600 ПЛ истории (2025–2026)
- 509 транзакций: 450 заправок + 59 моек/прочих; выходных заправок: 1
- Библиотека: 610 маршрутов, 344 с типовыми АЗС; `geo_cache` с координатами
  станций и `крюк_км` (медиана 4,9 км)
- Типовая заправка 30–48 л vs типовой день ~18 л (190 км × 9,4/100) —
  обоснование гибридной модели дней
- Практика подписания ПЛ: Palisade — Шишов 95%; Monjaro — Кулигин 70%;
  848/952 — ротация, де-факто основные Скрябин и Зубов
