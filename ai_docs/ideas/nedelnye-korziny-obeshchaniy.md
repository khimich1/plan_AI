# Недельные корзины обещаний (подбор срока КП)

Дата: 2026-09-03. Статус: направление зафиксировано (idea-refine сессия), decisions locked.
Спека: [`ai_docs/specs/nedelnye-korziny-obeshchaniy.md`](../specs/nedelnye-korziny-obeshchaniy.md).
Связанные идеи: [`zavod-emkost-vizual-gate.md`](zavod-emkost-vizual-gate.md) (текущий подневной гейт ёмкости — заменяется корзинами в диалоге «В производство», остаётся в графике поставок), [`planirovanie-po-srokam-podlozhki.md`](planirovanie-po-srokam-podlozhki.md) (подложки добивают остаток недели поверх обещанного).

## Problem Statement

Как менеджеру по продажам быстро увидеть, когда заказ **реально** можно закрыть — с учётом уже запланированного и уже обещанного другим клиентам, — и закрепить этот срок так, чтобы цех не потерял его при смешивании КП в плане?

Контекст боли: сейчас диалог «В производство» подставляет «~N дней» из длины без учёта загрузки, а светофор-гейт считает сценарий «как если бы это КП ело дорожки одно». Срок КП не является ограничением плана: оптимизатор смешивает заказы ради реза, и обещанная дата может молча уехать. Менеджер угадывает срок, увеличивая «N дней» вслепую, пока не снимется красный.

## Recommended Direction

**Недельные корзины обещаний. Оптимизатор и недельное планирование производства не меняются.**

- **Формула известна уже при формировании КП:** Σ(длина × кол-во) → дорожки = ceil(м / 101 × буфер) → соло-дни = ceil(дорожки / ручка). Показ «~N дорожек» на финальном шаге мастера КП.
- **Корзина недели** = рабочие дни недели × ручка «дорожек/день для обещаний» (обычно 3, максимум 5). Ручка — политика обещаний, не ограничение производства: изменения логируются, применяются только к новым расчётам.
- **Накопление:** каждое обещание занимает дорожки в корзине; следующее КП видит ранее обещанное. Неделя заполнена — планируем в следующую.
- **Диалог подбора срока** показывает: первично — обещание (конец окна из корзин), вторично — начало, «если делать только его», «соло + дни до конца недели». Подсказка в неделях вместо «+N дорожек».
- **Двухъярусная бронь:** «Закрепить срок» = мягкий холд до конца дня (бейдж «срок закреплён до сегодня» в архиве; холды не блокируют, а показываются отдельным счётчиком поимённо); «В производство» = жёсткое обещание, запись в той же транзакции, что перевод КП.
- **Сторона плана (уровень 2):** блок «Обещано на эту неделю» в wizard с предвыбором; снятие обещанного КП требует причины + in-web уведомление менеджеру; обещание гасится при коммите плана (иначе двойной счёт). Остаток недели добирается бэклогом через существующие подложки.
- **Крупное КП (> корзины недели):** окно в нужное число недель подряд, обещание = конец последней; разрез по неделям — только для таких КП, остальные входят целиком или не входят.

## Key Assumptions to Validate

- [ ] **A1.** Буфер(я) покрывают реальность — калибровочный скрипт на 3–5 прошлых заказах (оценка дорожек vs факт в планах) **до постройки UI**; решит, оставить ли 1.15 в корзинном учёте или хватает зазора 3-vs-5. Прецедент: `scripts/validate_podlozhki_phase0.py`.
- [ ] **A2.** Уровня 2 (причина + уведомление) достаточно, чтобы планировщик не исключал обещанное — метрика: доля снятий с причинами после запуска; при высокой → структурный уровень (обещанное = фиксированный костяк плана недели).
- [ ] **A3.** Холды не будут массово спекулятивными («подержать место» для неподписанного клиента) — страховка: TTL до конца дня, отдельный счётчик, поимённая видимость; лимит на менеджера — только при факте злоупотреблений.
- [x] **A4.** Принято: смешивание КП не увеличивает потребность в дорожках сверх суммы по-КП оценок (каскадные резы, округление вверх по каждому КП). Оговорка: несовместимые плиты дорожку не делят — частично покрыто буфером.

## MVP Scope

**In:** оценка «~N дорожек» в мастере КП · журнал обещаний/холдов + TTL холда · котировка «план + обещания (+холды отдельно)» · диалог: обещание первично, начало/соло вторично · ручка с аудитом · блок «Обещано на эту неделю» + причина при снятии + in-web уведомление · погашение при коммите плана · жизненный цикл: удаление КП → освобождение, редактирование состава → пересчёт · один гейт на обоих путях move-to-production.

**Out:** ILP с дедлайнами · автоплан из диалога · СГП в формуле · мобилка · жёсткий блок коммита плана · лимиты холдов · структурный уровень.

## Not Doing (and Why)

- **Жёсткий блок плана** — после замыкания цепочки срыв всегда сознательное решение; достаточно причины + уведомления.
- **Фантомная занятость в `days_info`** — обещания живут в отдельном журнале и инжектятся только в расчёт котировки; план не трогаем.
- **Переписывание оптимизатора под дедлайны** — корзины дают гарантию дешевле.
- **Ночной сброс обещаний** — обещание клиенту не протухает; сгорает только холд.
- **Структурный уровень (фиксированный костяк плана)** — пока метрика A2 не докажет необходимость.

## Decisions (locked 2026-09-03)

- **Обещание клиенту:** первично неделя («готово к 12.09»), вторично «если только его: 05.09».
- **Ручка:** менеджер тоже может менять, каждое изменение логируется; применяется только к новым расчётам, данные обещания задним числом не пересчитываются.
- **Срыв обещания:** мягкий гейт — причина при исключении из плана + уведомление менеджеру; не блок и не авто-перенос.
- **Момент брони:** двухъярусно — холд на день при «Закрепить срок» (статус «на рассмотрении»), жёсткое обещание при «В производство».
- **Миграция:** чистый старт — старые КП «в работе» не становятся обещаниями; добираются в планы через существующий блок срочных. Следствие: первые недели корзины занижают реальную загрузку — принято осознанно.
- **Частичный вход:** обещание неделимо — одно КП, одна дата, гасится при полном планировании. Крупное КП (> корзины) занимает окно недель подряд уже на этапе обещания; «целиком» = «целиком внутри своего окна».
- **Холд в UI:** живёт в разделе «в архиве» бейджем «срок закреплён до сегодня» + «В производство» без повторного ввода срока. Новых секций архива нет.
- **Уведомления:** только внутри веба (бейдж в кабинете менеджера); бот не оживляем.
- **Холд на крупное КП** держит всё окно недель, TTL тот же.
- **Wizard:** крупное КП видно в каждой неделе окна («часть 1 из 2»), чтобы неделя не выглядела перегруженной без причины.
