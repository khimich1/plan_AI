(ждёт данные за июнь по 848 / Palisade и ответы бухгалтера).

Контекст: присланы 3 образца отчётов (`ГСМ/Отчет по использованию ГСМ*.xls`)
и папка `ГСМ/` с путевыми листами за 2025–2026.

## Problem Statement

How might we формировать бухгалтерский отчёт об использовании ГСМ за месяц
или произвольный диапазон из данных путевых листов и транзакций, чтобы
бухгалтерия получала готовый к подписи документ без ручной сборки в Excel?

Потребитель — бухгалтерия (списание ГСМ, комплект с путевыми листами).
Бланк нужен **пиксель-в-пиксель** как в образцах (печатают и подписывают).
Формат результата: zip = один .xls на машину, внутри блоки по месяцам.

## Что выяснено реверс-инжинирингом образцов

**Структура бланка** (блок на месяц, листы = годы, блоки идут друг под
другом): шапка «УТВЕРЖДАЮ / Директор ООО "ЖБК СТАРТ" ____ Шишов А.В.» +
дата; заголовок «за *месяц год*»; таблица «1. Расход топлива»: № п/п,
марка а/м, госномер, ФИО водителя, марка бензина, остаток на начало,
спидометр нач/кон, пробег, норма по приказу л/100км, расход по норме /
по факту, получено по смарт-карте, остаток на конец, примечание (дата) +
колонка назначения. ИТОГО + дубль-строка по марке бензина. Подвал:
«Бухгалтер ____ Никифорова Е.А.».

**Правила строк:**
- 1 строка = 1 путевой лист (1 день). Проверено: 10 ПЛ за май 2026 у
  848-й = 10 строк отчёта, даты 1-в-1.
- Многодневная поездка сливается в одну строку вручную («21-22 апр»).
- Пробег — нормативный из ПЛ («пройдено, км»), НЕ GPS (факт 1120 км →
  в отчёте 560 км плеча).
- Остатки/одометр — сквозная цепочка через строки и месяцы; та же цепочка
  уже живёт в самих ПЛ («остаток при выезде» ПЛ = конец прошлой строки).
- «По факту» ≡ «по норме» во всех образцах; остаток бака выводится из
  нормы (списание по нормам, формальность). Храним поля раздельно на
  будущее (телематика).
- «Получено ГСМ» — редакторская колонка: реальные транзакции карт
  прикрепляются к ближайшей строке (дата может съезжать ±1 день), плюс
  чеки водителей, которых нет в выписках (у 952: ИТОГО 352.8 = выписка
  326.43 + 26.37 чеком; у 848: 225.4 л вне выписок, одна реальная
  транзакция 52.22 выпала). Выписки режутся не по календарному месяцу.

**Якоря из бумажных ПЛ** (последний заполненный ПЛ; цепочки внутри папок
непрерывны):

| Машина | Последний ПЛ | Одометр | Бак, л | Сверка |
|---|---|---|---|---|
| Tugella О848ХР44 | 29.05.2026 | 75 124 | 12.51 | = ИТОГО отчёта за май ✓ |
| Tugella О952ХР44 | 26.05.2026 | 99 742 | 19.15 | = ИТОГО отчёта за май ✓ |
| Monjaro О165ХУ44 | 26.06.2026 | 61 884 | 7.21 | = ИТОГО отчёта за июнь ✓ |
| Palisade О521УХ44 | 29.05.2026 | 132 981 | 8.84 | отчёта нет, цепочка ПЛ цела ✓ |

Карты: 848 → ...266/...268/...269; 952 → ...265; Monjaro → ...263;
Palisade → ...271. Баки: 55/55/60/70 л. Ячейки ПЛ: одометр выезд
`r19:c77`, возвращение `r44:c76`, остаток выезд `r37:c70`, возвращение
`r38:c70`, выдано `r33:c70` (формат стабилен; Monjaro/Palisade — файлы
с 2-значным годом, Palisade — префикс «Новый ПЛ»).

## Recommended Direction

**0. Готовность ядра — блокеры закрыты 2026-08-25 ✔**

- **Сезонные нормы — ручной перевод кнопкой** (дат по приказу не знаем):
  журнал переключений `season_switches` в настройках, норма дня = режим
  последнего свитча ≤ дня, дефолт лето; кнопка «Перевести на
  зимний/летний режим» в справочниках. Ядро: `core/gsm/season.py`
  (единый pure-модуль для генерации, экспорта и настроек).
  Известное допущение: превью во фронте знает только текущий режим и
  дату (не весь журнал) — при 3+ переключениях превью дней до последнего
  свитча может расходиться с backend; для превью приемлемо.
- **Каскадный пересчёт:** `patch_waybill` пересчитывает последующие
  черновики и возвращает `rechained_draft_days`; если дальше есть
  confirmed/exported — 409 `gsm_chain_locked`, ничего не пишется.
- **Иммутабельность:** patch по confirmed/exported → 409
  `gsm_waybill_locked`.
- Тесты: backend 315 passed (новые test_gsm_season.py — 12 шт.),
  frontend 167 passed, tsc чистый.
- **Осталось из этапа 0 (следующий инкремент):** аудит
  (updated_at/updated_by + история ПЛ, лог force-регенераций); операция
  «закрыть период»; контроль свежести выписок; автобэкап БД перед
  массовыми операциями; маппинг `fuel_start` при импорте.

**1. Подготовка БД к актуальным данным (блокирующий этап).**

Источник истины — подписанный бумажный ПЛ **до точки перехода**, после
неё — БД. Списание идёт по нормам: «физической правды» в документе нет,
есть требование внутренней непротиворечивости цепочки, которую генератор
воспроизводит 1-в-1 (`apply_chain` = их Excel-формулы). Поэтому:

- **Точка перехода (cutover) на машину** = последний подписанный
  бумажный ПЛ (таблица якорей выше). Всё до якоря — история, сдана, не
  трогаем. Всё после — источник истины БД.
- **Сценарий «бумаги за июнь+ нет» — основной, не аварийный.** Июнь–июль
  догенерируем ретроспективно: реальные транзакции карт + генератор
  маршрутов в коридоре бака → предпросмотр бухгалтеру → confirmed.
  Отчёт и путевые рождаются из одних строк БД — расхождение пакета,
  возможное в их ручном процессе, у нас невозможно по построению.
- Импорт бумажных ПЛ из папки `ГСМ/<машина>/<год>/<месяц>/*.xls` в
  `gsm_waybill` (статус `confirmed`, source=import) — для периодов, где
  подписанная бумага существует: дата из имени файла, одометр/остатки/
  выдано из ячеек выше, водитель и маршрут с оборотной стороны. Папки
  `Не заполн` (пустые шаблоны-дубли) пропускать. Auto-версии за
  совпадающие даты перезаписываются бумагой.
- Разрешить конфликты с текущей БД:
  - **Palisade — двойная версия мая 2026 (главный конфликт).** БД 04.05
    стартует от бумажного якоря (128 327 ✓), но дальше система сгенерила
    свой май: те же заправки, другие км. Итог 29.05: БД 132 517 / 41.13 л
    против бумаги 132 981 / 8.84 л (Δ464 км, 32.29 л). Бумажные файлы
    названы «Новый ПЛ» — кто-то переделывал ПЛ после экспорта из системы.
    Августовские drafts продолжают БД-версию. Нужен ответ бухгалтера:
    какая версия мая подписана. Бумажная цепочка Palisade непрерывна
    01.2025→05.2026; дыры: авг–дек 2025 (+14 790 км, ни одного ПЛ) и
    14→18.04.2026 (+887 км). Для отчётов 2026 дыра 2025 не нужна —
    цепочка рестартует от якоря.
  - **Monjaro 26.06**: в БД draft 63064→63254 / 23.16→37.36, бумага
    61474→61884 / 13.91→7.21 (бумага подтверждена их июньским отчётом).
    Августовские exported (11.08, 17.08) продолжают БД-версию — выяснить,
    не ушли ли они на подпись.
  - **848**: `fuel_start` содержит «выдано» (21.45) вместо остатка на
    выезд (8.92) — проверить маппинг импорта; конечный остаток верен.
  - **952**: стык чистый (август стартует ровно от 99 742 / 19.15) ✓.
- **Сущность «ручная заправка» в БД** (машина, дата, литры, комментарий)
  — согласовано: чеки водителей вне выписок вводятся один раз, участвуют
  в цепочке наравне с карточными транзакциями, отчёт воспроизводим.
  Только-предпросмотр отклонён: правки теряются при регенерации и
  разрывают цепочку следующего месяца.
- Импорт выписок транзакций по картам (файлы `ГСМ/транзакции/*.xls`,
  периоды режутся не по календарю — дедуп по (карта, дата, кол-во)).
  Маппинг карт к машинам подтвердить: карта ...269 фигурирует и в отчёте
  848-й (54.87 на 04.05), и в бумажном ПЛ Palisade (52.22 на 12.05);
  ячейка карт 848-й в `Роману.xlsx` обрезана.

**Данные, которые нужно собрать (блокируют этап 1):**
1. Свежие выписки по всем картам по текущую дату — **единственный
   обязательный внешний документ**: ретроспективная генерация июня–июля
   без них невозможна (последние файлы обрываются 18.06–29.05, одна
   05.08).
2. Monjaro: подписаны/сданы ли августовские ПЛ (11.08, 17.08),
   экспортированные из ошибочной ветки (62 336→)? Если да — перевыпуск
   после пересадки цепочки на бумажный якорь 26.06.
3. Полный маппинг топливных карт к машинам (карта ...269 светится и у
   848-й, и у Palisade; ячейка в `Роману.xlsx` обрезана).
4. Бумажные ПЛ за июнь–август по 4 машинам — **если существуют**: тогда
   импортируем их вместо ретроспективной генерации (папка обрывается:
   848 — 29.05, 952 — 26.05, Palisade — 29.05, Monjaro — 26.06).
5. Palisade, только если бумага за май признана подписанной: пояснение
   скачка одометра 14.04→18.04.2026 (+887 км без ПЛ).

**2. Генератор отчёта (направление A).**

Кнопка «Отчёт ГСМ за период» на странице ГСМ → диапазон дат →
предпросмотр → zip: per-vehicle .xls по точному бланку + путевые листы
за тот же период (конвейер `gsm_export_service.py` уже умеет
xlsx→soffice→xls→zip). Данные: подтверждённые ПЛ за период (1 ПЛ = 1
строка), цепочка `apply_chain` от якоря, транзакции разложены по
ближайшим строкам.

**3. Предпросмотр с ручной правкой (обязательно).**

Перед выгрузкой бухгалтер видит таблицы по машинам и может: добавить
чек-заправку, перенести заправку на соседнюю строку, склеить
многодневную поездку. Без этого колонка «Получено» не сойдётся с их
практикой (см. реверс-инжиниринг).

**4. Валидация до выгрузки.**

Цепочка не разорвана (стыки остатков/одометра), `0 ≤ остаток ≤ бак`,
все транзакции периода распределены, норма соответствует сезону
(norm_summer/norm_winter, в образцах переключение с апреля: 10.3→9.4).

## Key Assumptions to Validate

- [ ] Правило «1 ПЛ = 1 строка» и склейка многодневных поездок —
      уточняется у бухгалтера (на подтверждении сегодня).
- [ ] Сценарий «бумаги за июнь+ нет»: БД — источник истины от последнего
      подписанного якоря, июнь–июль догенерированы ретроспективно.
      Тест: бухгалтер принимает сгенерированный июнь без бумажной базы.
- [ ] Пробный отчёт за закрытый месяц (май 2026, 848-я) сходится с их
      файлом по остаткам и одометру — **главный тест идеи**.
- [ ] Бухгалтерия примет программно-сгенерированный бланк как «тот же»
      (шрифты, объединённые ячейки, переносы).
- [ ] Сезонное переключение норм в настройках совпадает с их приказом.
- [ ] Palisade включаем в отчёт (в образцах отсутствует, но ПЛ и карта
      есть) — уточнить у бухгалтера.

## MVP Scope

- Этап 0 (ядро): сезонные нормы с `winter_end`, каскадный пересчёт
  цепочки при правке, иммутабельность confirmed, аудит изменений ПЛ.
- Импортёр бумажных ПЛ → `gsm_waybill` (confirmed, перезапись
  auto-версий за совпадающие даты) + скрипт сверки якорей и разрешения
  конфликтов Palisade/Monjaro + пересчёт августовских веток.
- Таблица ручных заправок (чеки) + учёт в цепочке баланса.
- Импорт транзакций уже есть — дедуп и контроль покрытия карт.
- Шаблон бланка .xlsx (копия «Образец») + сервис генерации
  per-vehicle блоков по месяцам из ПЛ/транзакций.
- Экран предпросмотра с правками заправок/склейки + кнопка выгрузки zip
  (отчёты + ПЛ одним архивом).
- Тесты этапа 0: январь считается по зимней норме, апрель — по летней;
  правка км в середине цепочки пересчитывает все последующие drafts;
  patch по confirmed → 4xx.
- Тест: отчёт за май 2026 по 848 == их `Отчет по использованию ГСМ
  2024.xls` (блок май) по всем числам.

## Not Doing (and Why)

- **Авто-генерация 1-го числа + Telegram-рассылка** (направление B
  полностью) — сначала ручная кнопка и доверие к данным; расписание —
  обещание качества, к которому надо прийти.
- **Реестр отчётов со статусами и версионированием** (направление C) —
  витамин до первого сданного отчёта.
- **Директорская аналитика перерасхода** (получено vs норма, рубли) —
  отдельная идея, не смешивать с бухгалтерским бланком.
- **Телематический «факт»** — колонка остаётся копией нормы.
- **Переписывание исторических листов 2023–2025** — генерим только от
  даты последнего подтверждённого якоря вперёд.
