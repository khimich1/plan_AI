# Переиспользование рейса — клон транспорта

> Ideation session: 2026-08-02  
> Контекст: раздел «Логистика», реестр рейсов.  
> Связанные: [`shipment-logistics.md`](./shipment-logistics.md), [`ai_docs/specs/shipment-logistics.md`](../specs/shipment-logistics.md)

## Problem Statement

Как логисту создать новый рейс за секунды, переиспользовав перевозчика, водителя, ТС, доверенность и класс из существующего рейса, без риска скопировать документы или состав?

## Recommended Direction

Кнопка **«Создать на основе»** в строке реестра. Создаётся новый рейс (`in_work`) на выбранную дату; из источника копируется **только транспортный блок**:

- `carrier_id` / перевозчик
- `driver_name`
- `vehicle_text`
- `vehicle_class`
- `proxy_no`

Заказы, состав, УПД, № заявки на фрахт, стоимость, внимание, статус — **никогда**. После создания открывается карточка нового рейса: логист выбирает КП (в диалоге создания) и собирает состав как обычно (`propose`).

**Успех:** меньше времени на ввод **и** меньше ошибок в ФИО/номерах ТС.

## Key Assumptions to Validate

- [ ] Логист реально жмёт «На основе» чаще, чем создаёт с нуля (наблюдение 2–3 дня пилота)
- [ ] `proxy_no` почти всегда можно копировать; иначе — убрать из набора
- [ ] Дата «сегодня» по умолчанию устраивает; иначе — мини-выбор даты перед create

## MVP Scope

- UI: действие в строке реестра («Создать на основе»)
- Backend: атомарное создание с копией транспорта (см. спеку)
- Копируем только 5 полей выше
- Не копируем: orders, items, upd_no, freight_request_no, planned_cost, attention, delivery_type, status

## Not Doing (and Why)

- Полный дубль рейса / состава — риск чужих плит и путаницы при списании
- Копирование УПД и № заявки — документы уникальны на рейс
- Шаблоны в справочнике перевозчиков — отдельная сущность без проверки спроса
- Автоподстановка last-by-carrier без кнопки — непрозрачно
- Вход из карточки рейса — тот же backend, второй UI позже
