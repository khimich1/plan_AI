# Очередь спроса GUID из архивного КП

> Дата: 2026-09-21. Статус: к реализации закрыта.
> Спека: `ai_docs/specs/guid-demand-queue.md`.
> План: `ai_docs/develop/plans/2026-09-21-guid-demand-queue.md`.
> Родитель: `ai_docs/ideas/guid-price-sync-loop.md`, спека раунда 2
> `ai_docs/specs/guid-price-sync-round2.md` (колокольчик при архиве есть, список на
> `/prices` — инвентаризация каталога, не спрос из КП).

## Problem Statement

How might we показать экономисту только марки и пары GUID, которые реально встретились
в только что сохранённом архивном КП — чтобы пришло оповещение и короткий список
«завести / выбрать», а не весь справочник дырок?

## Recommended Direction

При сохранении КП в архив тот же резолвер, что рисует жёлтый Alert менеджеру
(`check_invoice_guids`), записывает **открытые задачи спроса** по маркам без GUID,
без «у» или с невыбранным дублем. Колокольчик экономисту (`kp_guid_missing`) остаётся.
Вкладка «Прайсы и 1С» читает **только эти задачи**, не весь `nomenclature_guid` и не
все пары справочника.

Два раздела сохраняем: «Завести в 1С» (уйти в 1С и загрузить отчёт) и «Дубли GUID»
(выбор на месте). Список плоский по марке, КП в подписи:
`Свая · С 70.35-9у — КП №12, №18`. Задача закрывается сама: GUID появился после
выгрузки 1С или экономист запомнил выбор пары.

Это уже почти есть: архив вызывает `notify_kp_guid_missing` → `check_invoice_guids`,
но результат не становится очередью. Список на `/prices` — инвентаризация каталога.
Фильтровать справочник нельзя: сваи без «у» там лежат заранее. Нужна таблица факта
спроса.

## Key Assumptions to Validate

- [ ] Архив — правильный порог «это уже не черновик»; менеджеры не архивируют
      мусорный состав пачками
- [ ] Частичная выгрузка 1С закрывает задачу по той же марке (матч `C`/`С` и суффикс
      «у» срабатывает)
- [ ] Выбор GUID по паре из КП — на все будущие счета, не «только это КП» (как сейчас
      `manual` / `plate_guid_choice`)

## Locked decisions (бывшие open questions)

| Тема | Решение |
|------|---------|
| Где таблица | `pb.db`, рядом с `nomenclature_guid`. Закрытие задач — при импорте 1С, который уже открывает `pb.db`. Уведомления остаются в `plita.db` |
| Повторный архив | Если марка снова без GUID — задачу открыть снова (идемпотентный upsert). Если дырка закрыта — не трогать |
| Плиты | Да. Резолвер уже отдаёт плиты без GUID / с дублем без выбора в `missing` — иначе дырка КП не попадёт экономисту |
| «Ввести цену» | Не трогаем. Другая дырка: GUID уже есть, нет заводской цены |
| Старый архив | Не сканируем. Задача появляется только с новых сохранений в архив |
| UI разделов | Два списка, не один inbox: завести = файл, пара = клик |

## MVP Scope

**Входит**

- Запись спроса при архиве (мастер КП и `create_offer`); дедуп по марке, к задаче
  дописываются номера КП
- Только новые архивы
- `/prices`: «Завести в 1С» и «Дубли GUID» только из открытого спроса; неизвестная
  марка (нет строки в `nomenclature_guid`) тоже видна
- Колокольчик `kp_guid_missing` без смены контракта, ссылка на `/prices`
- Закрытие: импорт 1С дописал GUID / выбран дубль → задача сгорает
- Экономистов нет → warning в лог, задача на вкладке всё равно есть (спека A4)

**Не входит** — см. Not Doing.

## Not Doing (and Why)

- **«Ввести цену»** — другая дырка: GUID уже есть, нет заводской цены; не про заведение карточки
- **Прогон текущего архива** — зальёт экран старыми КП; выбрано «только новые»
- **Один inbox вместо двух разделов** — разные действия (файл vs клик); ядро — какие строки, не склейка UI
- **Пинг менеджеру «можно выставлять счёт»** — второй круг, после того как спрос заживёт
- **Ворота «В 1С» / сущность счёта** — `assert_invoice_guids` уже есть, к кнопке не цепляем
- **Колокольчик как единственная очередь** — прочитали и забыли, пока ждут заведения в 1С
