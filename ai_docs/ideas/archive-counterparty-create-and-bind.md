# Архив: занести контрагента из 1С в справочник и привязать к КП

**Направление**: поиск в архиве → если нет карточки, форма (имя / код 1С / ИНН / КПП) → одной кнопкой создать и привязать; GUID не обязателен в MVP

## Problem Statement

How might we дать менеджеру в карточке архива занести в программу контрагента, которого он уже завёл в 1С, сразу привязать его к КП и снять «нет 1С» — без живого API 1С и без возврата создания карточки в мастер расчёта?

## Recommended Direction

Сейчас архив умеет только выбрать **уже импортированную** карточку (`GET /counterparties/search` + `PATCH …/counterparty`). Кнопка «Занести контрагента» выглядит как создание, но без `id` из справочника неактивна. Мастер КП создание убрали специально: свободное имя туда, юрлицо — после 1С.

Правильное место — архив, **после** того как менеджер завёл клиента в 1С. UX: автокомплит как сейчас. Нашёл — привязал. Не нашёл — форма с названием, кодом 1С, ИНН, КПП (имя КП можно подставить). Одна кнопка создаёт строку в `counterparties` (`source=manual`) и привязывает это КП: снапшот имени/ИНН/КПП, бейдж «нет 1С» снимается, «В производство» открывается. На бэке — один атомарный вызов, не `POST` справочника плюс отдельный `PATCH` (иначе при сбое второй ноги карточка есть, а КП всё ещё без 1С).

GUID в форму не тащим. ТЗ счёта требует GUID+ИНН+КПП, но менеджер GUID из 1С не копирует, текущий xlsx-импорт его тоже не везёт. Код 1С — якорь: следующая выгрузка справочника должна `upsert` по `code_1c` и дописать `guid_1c`. Эта задача **готовит обмен**, а не запускает его. Если код набьют с опечаткой, GUID потом не пришьётся.

При 409 «код уже есть»: если существующая карточка — активный клиент, привязать её к КП, не плодить дубль. Если не клиент / неактивна — ошибка по-русски, как сейчас у `require_active_client`. Создание в мастере КП не возвращаем.

## Key Assumptions to Validate

- [ ] Менеджер копирует **код 1С** без опечаток — проверить на 2–3 реальных занесениях; иначе импорт GUID не склеится.
- [ ] Следующая выгрузка контрагентов из 1С научится отдавать GUID и делать upsert по `code_1c`. Без этого шага счёт в 1С всё равно не уедет. Проверить по ТЗ п.1/п.2 и текущему `scripts/import_counterparties.py` (колонок GUID нет).
- [ ] Одного действия в карточке КП хватит; отдельная очередь «без 1С» не нужна, пока таких КП единицы.
- [ ] После create+bind перезапись `customer_name` из карточки 1С допустима (как у текущего bind). Если отданные PDF нельзя трогать именем — не регенерировать файлы в этом MVP.

## MVP Scope

**Архив, КП «в архиве», `counterparty_id` пустой:**

- Автокомплит справочника остаётся. Выбор существующего клиента → привязка как сейчас.
- Если не найден: форма название / код 1С / ИНН / КПП. Название и код обязательны. ИНН/КПП — как в действующем `POST /counterparties` (необязательны, предупреждение при чужом ИНН).
- Одна кнопка: создать карточку-клиента и привязать к этому КП. Гейт производства после успеха — обычный.
- Пока «в архиве» — можно сменить карточку (как bind сейчас). Отвязать нельзя.

**Backend:**

- Атомарный create+bind (новый endpoint или расширение bind: если пришёл payload полей 1С, а не только `counterparty_id`).
- Повтор `code_1c`: привязать существующего активного клиента.
- `POST /counterparties` из мастера по-прежнему не звать. Мастер не менять.

**Не в этом MVP, но не ломать:** импорт xlsx, поиск, `require_active_client` на `move_to_production`.

## Not Doing (and Why)

- Живой API / поиск в 1С из приложения — обмена ещё нет, это чужая система.
- GUID обязателен в форме — рано; менеджер его не копирует, выгрузка его не везёт.
- Возврат «Добавить контрагента» в шаг «Клиент» мастера — снова теневые карточки до 1С.
- Создание без кода 1С — нечем склеить со справочником 1С, ломает правило «без 1С не в производство».
- Фильтр/очередь архива «нет 1С» — пока достаточно бейджа и формы в карточке.
- Регенерация PDF/XLSX на bind — как в предыдущей идее: имя обновится при следующем сохранении из конструктора.
- Смена контрагента у КП уже «в работе» / «выполнено» — гейт уже пройден.
- Сам обмен счетами с 1С — соседняя задача; здесь только якорь `code_1c` в справочнике.
