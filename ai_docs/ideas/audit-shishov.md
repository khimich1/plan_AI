# /audit под «Шишов»: реестр + модуль + дельта

Дата: 2026-08-28. Статус: **MVP implemented** (скилл + команда + реестр).
Это направление для скилла/команды, не для кода продукта.

Контекст: ~60 отчётов в `ai_docs/develop/audits/`, полный прогон
2026-08-28 дал Health Score **2.0/10** при уже закрытых P0; сравнение
двух прогонов 2026-08-02 пришлось делать руками
([audit-comparison](../develop/audits/2026-08-02-audit-comparison.md)).
Сейчас `/audit` — generic конвейер (архитектура → security → quality →
отчёт → optional auto-fix) на Composer 2, без `project-shishov`, без
прошлого отчёта, с переиспользуемыми ID.

## Problem Statement

How might we после куска работы (ГСМ, КП, раскладка, auth) за один
запуск получать на русском **что закрылось, что новое и какие P0 ещё
живы** — без повторного романа про SOLID, без фейковой оценки 0–10 и
без автофиксов, которые ломают политику доступа и домен?

## Recommended Direction

**A+B.** Аудит — это обновление журнала находок и ворота модуля, не
новый 500-строчный роман каждый раз.

**Реестр (A).** Живёт один журнал стабильных ID (`A1`, `S1`, `Q1` не
переезжают между прогонами). У каждой записи: статус
`open` / `resolved` / `wontfix` / `by-design` / `unreproduced`, скоуп,
доказательство, ссылка на спеку или коммит. Прогон **сначала читает
реестр и последний отчёт по скоупу**, потом ищет. «Не упомянули» ≠
закрыто. «Не воспроизвелось» — отдельный статус, не resolved.

**Запуск по модулю (B).** Default — не весь репозиторий.

| Команда | Скоуп |
|---------|--------|
| `/audit gsm` | `app/services/gsm_*`, `core/gsm/`, `frontend/src/features/gsm/` |
| `/audit kp` | коммерческий контур + доступ к КП |
| `/audit layout` | раскладка, ILP, `PlateOrderContext` |
| `/audit auth` | сессии, CSRF, roles |
| `/audit --since HEAD~N` | diff |
| `/audit --full` | редкая сверка реестра целиком (квартал, не привычка) |

У модуля — короткий доменный чеклист (инварианты, не SOLID): для ГСМ —
сходимость литров и month-close; для КП — политика архива vs IDOR; для
раскладки — явный контекст плит, не thread-local; для auth — cookies и
границы ролей. Generic OWASP/DRY — второй проход, не первый.

**Отчёт.** Русская шапка на одну страницу: дельта (закрыто / открыто /
новое / не воспроизвелось), 5–8 действий, список открытых P0/P1.
Приложение — подробности. **Без Health Score.** Метрика: число открытых
P0 и P1 в реестре по скоупу.

**Доказательство.** Critical/High без grep, теста или точной строки в
отчёт не попадают. Medium — в приложение или не пишутся, если нет
действия на этой неделе.

**Phase 5 (auto-remediation) — нет.** Отчёт только. Фиксы — явный
`/orchestrate`, спека или точечный `/implement`. [S1] IDOR 2026-08-28
уже оказался `by-design`; автофикс здесь опасен для денег, ILP и ГСМ.

Каркас A без B снова аудитит весь монолит. B без A снова выдаёт новые
ID на те же дыры. Оба нужны.

## Key Assumptions to Validate

- [ ] Субагент **переиспользует ID**, если реестр — первый пункт
      промпта. Как проверить: два `/audit gsm` подряд без правок кода;
      второй не должен плодить A37 на ту же god-функцию. Если ломается —
      координатору снова можно читать git/реестр самому (сейчас command
      это запрещает).
- [ ] `/audit gsm` будут запускать чаще, чем `--full`. Как проверить:
      после внедрения — три реальных прогона на живой работе (ГСМ или
      КП), не «ради скилла». Если всегда `--full` — реестр не окупится,
      хватит `--since`.
- [ ] Три доменных чеклиста (ГСМ, КП/доступ, плиты+раскладка) можно
      уложить **каждый ≤15 пунктов**. Как проверить: написать черновик
      и прогнать один модуль; если агент игнорирует чеклист — резать,
      не растить.
- [ ] Composer 2 + требование улики не плодит выдуманные grep.
      Как проверить: выборочно открыть 5 Critical/High из первого
      нового прогона; если >1 фейк — либо сильнее модель на доменном
      шаге, либо координатор верифицирует цитаты.

## MVP Scope

Один job: **после работы над модулем получить дельту на русском,
которой можно верить.** Не идеальный аудит индустрии.

**В MVP:**

1. Убрать Phase 5 из `.cursor/commands/audit.md` и
   `.cursor/skills/audit-workflow/SKILL.md`.
2. Убрать Health Score из шаблона отчёта; считать открытые P0/P1.
3. Default скоуп: спросить модуль или `--since`, не весь репо;
   `--full` только явно.
4. Завести `ai_docs/develop/audits/FINDINGS.md` (или рядом) — реестр.
   Первый наполнять **не с нуля**, а вынести открытые ID из
   `2026-08-28-full-project-audit.md` (с учётом уже `resolved` /
   `by-design`).
5. В каждый Task-промпт: прочитать `project-shishov` + реестр +
   последний отчёт по скоупу; отчёт **на русском**; шапка = дельта.
6. Три коротких доменных чеклиста в скилле: `gsm`, `kp`, `layout`.
7. Правило улики для Critical/High; `unreproduced` ≠ `resolved`.

**Первый тест MVP:** `/audit gsm` дважды. Второй отчёт — таблица дельты
относительно первого, без новых ID на старые дыры и без оценки /10.

## Not Doing (and Why)

- **Phase 5 / auto-fix Critical** — ломает by-design (доступ к КП),
  опасен для ILP/ГСМ/денег; фиксы только явным workflow.
- **Health Score 0–10** — потолки формулы уже давали 0.0 и 2.0 при
  живом прогрессе; цифра врёт чаще, чем помогает.
- **Full-project как default** — 20–30% «критичных файлов» всё равно
  смешивает вековой долг с текущим модулем; `--full` остаётся флагом.
- **Отдельная команда `/audit-шишов`** — две команды, путаница; правим
  существующий `/audit`.
- **Дашборд, красивый тренд, параллельные три аудитора** — не job MVP.
- **20 доменных чеклистов** — не будут читаться; только ГСМ, КП, раскладка.
- **Аудит `bot/` и `tests/archived/` как живой контур** — бот deprecated.
- **Менять модель Composer 2 в MVP** — отдельный спор про стоимость;
  сначала улики и реестр. Если фейковые цитаты — тогда модель.
