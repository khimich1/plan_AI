## Problem Statement

Как дать менеджеру довести длинную очередь фото до сверки без отказа «лимит загрузок», перераспознать выбранный кадр и сверять страницу с уже исправленным текстом — без повторной правки той же плиты в блоке замены ширины?

## Recommended Direction

Три дыры одного экрана сверки. Апскейл и новая модель не входят.

**1. Снять часовой кап OCR.** Очередь до 12 страниц, `COMMERCIAL_OCR_UPLOADS_PER_HOUR=10`. Каждый кадр — отдельная загрузка. 11-й файл и любой retry после десятого дают 429. Это и есть отказы в длинной очереди, не разрешение картинки. По умолчанию `0` = лимитер выключен (код и тесты на `>0` оставить).

**2. Кнопка «Перераспознать» — тупой retry выбранного фото.** Под карточкой «Исходное фото»: тот же `File` активной страницы → новый OCR → replace текста **этой** страницы. Не `append` в общий черновик. Если распознать не удалось — страница в ошибке, менеджер **сам** кладёт новое фото в конец очереди. Никакого мастера «заменить файл», авто-удаления, merge правок. Сознательный retry: ручные правки этой страницы сгорают.

**3. Сверять страницу с исправленным текстом.** Список справа после правки менеджера — источник истины для этой страницы. Блок «Нестандартная ширина» (и прочая сверка страницы: подсветка wide, блокировка «Список верен») считается по **текущему** тексту, не по замороженному OCR metadata.

Пример: в документе `34-15-10п 15`, OCR `44-15-10п 5`, менеджер исправил. Split и qty должны идти от `34-15-10п 15`, а не предлагать `34-3-10п 5`. Если в тексте уже нет ширины >12 дм — карточка wide не блокирует страницу.

## Locked decisions

| # | Тема | Решение |
|---|------|---------|
| D1 | Часовой кап | Выключить (`0`). Не поднимать до 40/200. Не трогать логин и `COMMERCIAL_UPLOAD_MAX_BYTES`. |
| D2 | Апскейл 4× / 8 МиБ | Не делаем. Отказы были от капа очереди. |
| D3 | Кнопка | Выбранная картинка. Везде (`ready` / `error` / `confirmed`). Полный replace текста страницы. |
| D4 | OCR не удался | Менеджер добавляет новое фото в конец очереди. Отдельный recovery UX не строим. |
| D5 | Сверка | На всех шагах ввода: страница сверяется с исправленным текстом редактора. |
| D6 | Merge при retry | Нет. Retry = новый OCR этой страницы (в т.ч. если было 2 строки из 10). |
| D7 | Авто-retry без кнопки | Нет. |
| D8 | Retry confirmed | Снова `ready` — список изменился, «Список верен» ещё раз. |

## Key Assumptions to Validate

- [ ] Отказы на 11-м+ фото / retry — наш 429 по `COMMERCIAL_OCR_UPLOADS_PER_HOUR`, не квота GigaChat. Проверка: заход >10 кадров до и после `0`.
- [ ] Retry не делает `append`: в черновике нет второй копии страницы. Проверка: 2 фото → retry второго → одна порция второго кадра.
- [ ] После правки `44-15-10п 5` → `34-15-10п 15` страница сверяется с новой строкой (split + qty 15). Проверка: тот же сценарий на сверке.
- [ ] `File` страницы `ready` ещё можно отправить. Проверка: кнопка на уже распознанном кадре, не только на `error`.
- [ ] После ошибки OCR существующее «добавить фото в очередь» достаточно. Проверка: fail → добавить ещё одно в конец → очередь идёт дальше.

## MVP Scope

**Входит**

- `COMMERCIAL_OCR_UPLOADS_PER_HOUR=0` — не считать загрузки.
- Кнопка «Перераспознать» в карточке «Исходное фото» на всех шагах (`ready` / `error` / `confirmed`; не `running`).
- Retry: тот же `File` → OCR → replace `batchReviewText` этой страницы; остальные не трогать. Неудача → статус ошибки, менеджер добавляет кадр сам.
- Сверка страницы с текстом редактора: wide-suggestion и гейт «шире стандартной» от текущих строк; карточка исчезает, если ширины >12 дм в тексте уже нет.
- Плиты на экране сверки. Кнопка retry — там, где уже есть выбранное фото; live-wide — только где есть `WidePlatesInlineSection`.

**Не входит:** апскейл, порог 8 МиБ, `OCR_MAX_API_CALLS`, живые OCR-corrections по `row_index`, авто-apply инструкции помощника, UI «заменить файл при ошибке», хранение фото на сервере.

## Not Doing (and Why)

- **Апскейл 4× / снять 8 МиБ** — отказы были от капа очереди; снято явно.
- **Поднять cap вместо нуля** — просили убрать. `0` = выкл.
- **Retry через существующий `append`** — дубли позиций, хуже бага.
- **Merge правок при retry / авто-перераспознать** — затрёт или смешает список; кнопка сознательная.
- **Мастер ошибки OCR** (предложить новое фото вместо кнопки) — менеджер и так добавляет кадр в конец очереди.
- **Переписывать жёлтые OCR-corrections** — другой ключ; не блок «замена ширины».
- **Лимит логина / размер файла 50 МиБ** — не OCR-очередь.
