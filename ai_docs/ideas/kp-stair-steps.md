# КП на лестничные ступени (ЛС)

> Ideation session: 2026-08-04 → 2026-08-05  
> Контекст: прайс лестничных ступеней (`банк знаний/Прайс на лестничные ступени от 03.08.2026.xlsx`, лист «Прайс», 42 SKU); мастер КП уже умеет плиты и сваи.  
> Аналог: [`kp-piles.md`](kp-piles.md) → реализовано как `product_type=piles`  
> Дальше по очереди (не MVP): ЛМ → ФБС → …

## Problem Statement

**Как дать менеджеру создать отдельное КП на лестничные ступени с тем же UX, что у свай — ввод текста/фото, цена строго из прайса по марке, PDF/XLSX и архив — без выбора класса бетона, пока в прайсе одна цена на марку?**

## Recommended Direction

### Выбор: Clone свай минус grade

Третий `product_type` (рабочее имя: `steps`). Общая оболочка мастера (`client → result → save`), шаг 1 / парсер / прайс / файлы — отдельные для ступеней. **Без UI и поля класса бетона.**

```
[Создать КП] → Плиты | Сваи | Ступени (ЛС)
                              ↓
                   Шаг 1: текст / фото / ИИ
                              ↓
                   Таблица: Марка | Кол-во | Цена
                              ↓
                   Клиент → Результат → PDF/XLSX → Архив
```

**Почему так:**
- Критерий успеха уже задан: «как сваи».
- В прайсе ЛС одна цена на марку (колонка «15» / В15) — dropdown бетона был бы шумом.
- ЛМ / ФБС добавим отдельными итерациями: у каждого продукта свои тонкости; generic framework — после 2–3 клонов.

### Ключевые продуктовые решения

| Решение | Выбор |
|---------|-------|
| Тип КП | Только отдельное: только ЛС в одном документе |
| Ввод | Текст + фото + ИИ (как у свай) |
| Класс бетона | Не в UI; цена не зависит от grade в текущем прайсе |
| Цена | `get_step_price(mark)` из `step_prices` |
| Ключ марки | Короткая марка: `ЛС11`, `ЛС14-1лев`, `ЛС11-Б-1`… |
| Неизвестная марка | Блокировать расчёт (strict match) |
| Выходные файлы | PDF/XLSX; колонки: марка, кол-во, цена, сумма |
| После сохранения | Архив + бейдж; **без** производства и СГП |
| Нумерация КП | Единая сквозная (`kp_id`) |
| Импорт прайса | CLI в MVP (как сваи), лист «Прайс» |

### Технический контур (черновик)

**Backend:**
- `product_type: "steps"` в metadata черновика и `kp_meta`
- `core/step_line_parser.py` — разбор `ЛС11-1лев 10` (марка + qty)
- `core/step_price_db.py` + таблица `step_prices(mark, price, …)` в `pb.db`
- OCR/ИИ-промпт под марки ЛС
- API: зеркало pile-эндпоинтов (`.../steps`), без grades
- `kp_steps` в `plita.db`; исключение из production wizard

**Frontend:**
- `ProductTypePicker`: + «Ступени»
- `StepInputStep` + preview-таблица без dropdown бетона
- Архив: бейдж «Ступени» + фильтр

## Key Assumptions to Validate

- [ ] **Марки в заявках** близки к прайсу (`ЛС14-1лев`), а не бытовые («ступень 11 левая») — 5–10 реальных заявок
- [ ] **Короткая марка** достаточна как ключ цены; полное имя из Excel — для импорта/опционально в PDF
- [ ] **OCR/ИИ в MVP** окупаются (полный clone свай); иначе урезать до текста
- [ ] **Суффиксы** `-1` / `-1лев` / `-2` / `-Б` / `-Б-1лев` парсятся однозначно
- [ ] **Шаги client/result** без step-специфичных полей

## MVP Scope

**In:**
- Выбор «Ступени» при создании КП
- Ввод текста + фото + ИИ
- Таблица: марка, кол-во, цена (без класса бетона)
- Импорт прайса CLI → `step_prices`
- Блокировка расчёта при неизвестных марках
- PDF/XLSX, сохранение в архив, бейдж + фильтр
- Исключение из производства / СГП

**Out (следующие этапы):**
- Лестничные марши (ЛМ), ФБС и прочие типы
- UI/матрица класса бетона
- Fuzzy-match марок
- Смешанное КП
- Производство / СГП для ступеней
- Калькулятор веса / объёма для доставки
- UI-импорт прайса
- Рефакторинг в generic «любой ЖБИ» framework

## Not Doing (and Why)

- **ЛМ / ФБС в этом релизе** — поэтапный rollout; сначала проверка на ЛС
- **Dropdown бетона** — в прайсе одна цена; не заставлять менеджера
- **Смешанное КП** — как у плит/свай; упрощает парсер и архив
- **Generic product platform** — premature abstraction; копируем сваи точечно
- **Каталог-галочки вместо парсера** — ломает критерий «как сваи»
- **Производство / СГП** — вне scope MVP (как у свай)
- **Отдельный счётчик КП** — одна серия `kp_id`

## Open Questions

1. Итоговый код `product_type`: `steps` vs `stair_steps` vs `ls`?
2. OCR в MVP целиком или текст-first, фото следом?
3. В PDF/XLSX: полное имя («Лестничные ступени ЛС11») или короткая марка?
4. Нормализация при импорте (в прайсе есть `ЛС14-Б` с лишним пробелом в полном имени) — правила ключа?

## Success Criteria

1. Менеджер делает КП на ЛС **тем же путём**, что КП на сваи
2. **100% цены** из `step_prices` — без ручного Excel
3. Менеджер **не выбирает бетон**
4. После приёмки ЛС путь ясен для следующих типов (ЛМ, ФБС)
