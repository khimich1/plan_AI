# UX для менеджера по продажам (веб-кабинет КП)

> Ideation session: 2026-07-08  
> Контекст: менеджер делает 5–20 КП в день из фото и переписки; Telegram не используется; канал — только веб.

## Problem Statement

**Как нам дать менеджеру по продажам быстрый и понятный путь «фото/текст → проверенный список плит → документы клиенту», без лишних шагов, технического жаргона и страха отправить ошибочное КП?**

## Recommended Direction

### Выбор: редизайн мастера в **3 шага** (с опцией упростить до 2 экранов позже)

Между вариантами «2 экрана» и «3 шага» рекомендуется **3-шаговая структура** как баланс скорости и безопасности:

| Шаг | Содержание | Что убрали из текущих 5 шагов |
|-----|------------|-------------------------------|
| **1. Плиты** | Ввод (текст/фото), OCR, **обязательная сверка** фото ↔ список, inline-разбор широких плит | Отдельный шаг «wide-plates» |
| **2. Клиент** | Имя клиента, условия (стандарт / индивидуальные), менеджер (авто = текущий пользователь) | Отдельный шаг «manager» |
| **3. Результат** | Расчёт, скидка/логистика, чеклист готовности, файлы (PDF / Excel / схема — по ситуации), сохранение | — |

**Почему не 2 экрана сразу:** основные сбои сейчас — OCR и перегруженность шагов; объединение «клиент + плиты» на одном экране рискует вернуть хаос. Три шага дают ~40% сокращение кликов vs текущих пяти, сохраняя чёткую mental model.

**Почему не «5 шагов, но красивее»:** пользователь готов к полному редизайну; косметика не решит «слишком много кнопок на шаге 1» и отсутствие экрана доверия к OCR.

### Центральный паттерн: экран сверки OCR

OCR **почти всегда** требует ручной проверки. Шаг 1 после распознавания перестраивается вокруг side-by-side:

- Слева: исходное фото (zoom, открыть в новой вкладке).
- Справа: редактируемый список плит с подсветкой проблемных строк (не распознано, широкая плита, OCR correction).
- Одна primary-кнопка: **«Список верен — далее»**; режимы «добавить/заменить», «ИИ» — в блоке «Дополнительно».

Язык UI — бизнесовый, без «backend», «нормализованный», «12 дм» → «шире стандартной, рекомендуем заменить на …».

### Менеджер: умный дефолт

В основном один менеджер, но бывают разные. На шаге 2:

- По умолчанию подставляется залогиненный пользователь (если есть в справочнике менеджеров).
- Смена — раскрывающийся блок «Другой менеджер», не отдельный шаг.

### Архив — равноправный модуль

Архив так же важен, как создание КП. Параллельно с редизайном мастера:

- Быстрый поиск и статусы (как сейчас, но с приоритетом в навигации).
- «Создать КП на основе №…» (копирование позиций + условий клиента).
- Редактирование скидки/логистики после сохранения (уже есть — сохранить и улучшить discoverability).

### Quick wins (можно до или параллельно редизайну)

- Скрыть пункт «Производство» в шапке для role=manager (сейчас ведёт на редирект).
- Переименовать кнопки шага 1: один primary «Распознать фото» / «Обработать текст».
- Чеклист на финале: ✓ N плит, ✓ клиент, ✓ сумма, ⚠ предупреждения.

## Key Assumptions to Validate

- [ ] **80%+ КП** начинаются с фото — проверить по логам OCR / метрикам `commercial_draft_service`
- [ ] **Залогиненный пользователь** мапится на запись менеджера в справочнике — проверить связь auth user ↔ managers API
- [ ] **3 шага** не хуже 2 экранов по времени — замерить на 5 реальных КП с менеджером (think-aloud)
- [ ] **Side-by-side** снижает долю ошибочных КП — сравнить % правок после OCR до/после (1 неделя)
- [ ] **«Копировать КП»** из архива используется ≥30% новых заказов — метрика после релиза v2
- [ ] Менеджеры **понимают разницу** «в работе» vs «в архив» при сохранении — короткий опрос; при нет — один режим по умолчанию + подсказка

## MVP Scope

### In (v1 редизайна)

- Новая структура мастера: 3 шага (`plates` → `client` → `result`)
- Шаг 1: один primary flow + блок «Дополнительно»; экран сверки фото ↔ список
- Inline UI для широких плит на шаге 1 (или collapsible секция перед «Далее»)
- Автовыбор менеджера + опциональная смена на шаге 2
- Условия: режим «стандартные» по умолчанию, переключение на индивидуальные
- Шаг 3: чеклист готовности; явные кнопки PDF / Excel / схема (набор зависит от контекста, не все сразу)
- Навигация: скрыть «Производство» для manager
- Человекочитаемые тексты ошибок и предупреждений

### Out (v1)

- Полный дашборд «рабочий стол менеджера» (последние КП, статистика дня)
- Server-side черновики (остаётся localStorage до отдельной задачи)
- «Копировать КП из архива» — **v2**, сразу после v1 мастера
- Telegram-бот
- Мобильная вёрстка
- AI-чат на каждом шаге

## Not Doing (and Why)

- **2 экрана в v1** — риск спрятать edge cases (широкие плиты, mixed conditions); вернёмся после метрик 3-шагового flow
- **Сохранение 5 шагов с новым скином** — не решает заявленные боли (OCR + перегруз)
- **Gamification / onboarding-туры** — power user 5–20 КП/день; нужен конвейер, не обучалка
- **Единый «Скачать всё» без выбора** — клиентам нужны разные наборы файлов (`all_files`)
- **Удаление выбора менеджера** — иногда оформляют за коллегу; прячем, не удаляем

## Open Questions

- Как связать `auth user` с `manager_id` в справочнике — поле в профиле, email, ручной mapping?
- Нужен ли **единый дефолт** для save mode («в работе» vs «архив») или оставить три варианта с пояснением?
- Приоритет v2: **копирование из архива** vs **server-side черновики** — что болезненнее для менеджера?
- Допустимо ли **автопереход** на шаг 2 после успешной сверки OCR без явного «Далее»?
