# Calendar brush planning (кисть на сетке)

> Ideation session: 2026-07-23  
> Контекст: планировщик производства; эволюция calendar-first.  
> Предыдущее направление (per-day через DayDrawer) реализовано; UX пересматриваем.

## Problem Statement

**Как планировщику задать N заранее, выделить диапазон дней мышкой на сетке (без drawer) и при необходимости подкрутить N на отдельных днях — чтобы быстрее собрать `fill_targets` и уйти в выбор плит?**

## Recommended Direction

### Выбор: кисть + правка N на сетке

Sticky-бар планирования:

1. Пресет **«Дорожек: N»** (кисть).
2. На сетке: клик / Shift+клик / drag по рабочим дням — дни попадают в корзину с текущим N.
3. Уже выбранный день: inline-правка N на ячейке или чипе (без drawer).
4. CTA: «🚀 Начать планирование →» / «Дозаполнить →» по kind корзины (как в текущем calendar-first).

```
┌─ Календарный план ──────────────────────────────┐
│  [сетка: клик / Shift-диапазон / drag]          │
│  выбранные дни подсвечены · N видно на ячейке   │
├─────────────────────────────────────────────────┤  ← sticky
│ Дорожек: [3]  │ 23.07·3 ✕  24.07·3 ✕  25.07·5 ✕ │
│ [Очистить]  [🚀 Начать планирование →]          │
└─────────────────────────────────────────────────┘
```

Drawer — только просмотр содержимого дня и документы, **не** для набора корзины.

Backend не меняем: тот же `fill_targets`.

### Почему это направление

- Бьёт в боль: меньше кликов, выбор на сетке, N задаётся заранее.
- Сохраняет гибкость: разный N через inline-правку после «покраски».
- Переиспользует корзину, kind-валидацию (empty vs partial) и экран выбора плит.

## Key Assumptions to Validate

- [ ] Drag/Shift на месячной сетке удобнее точечных кликов — 1 сессия с планировщиком
- [ ] Разделение жестов «выбрать день» vs «открыть день» понятно (режим «Планирую» или отдельные hit-zones)
- [ ] Inline N достаточно для «разный N», drawer для этого не нужен
- [ ] Правило «не смешивать empty и partial» остаётся и понятно при кисти

## MVP Scope

**In:**

- Пресет N в sticky-баре
- Выбор на сетке: клик + Shift-диапазон (drag — если успеем)
- Корзина чипами + inline/чип-правка N
- Убрать добавление в корзину из DayDrawer
- Dual CTA и валидация kind — сохранить

**Out (Not Doing):**

- Автораздача «бюджета» дорожек по дням
- Смешанная корзина (empty + partial)
- Backend changes / изменение `fill_targets`
- Полноценный drag-select, если Shift-диапазона хватает для первой проверки

## Not Doing (and Why)

- **Планирование через drawer** — конфликтует с «всё на сетке»
- **Глобальный мастер «N + стартовая дата»** — уже отвергнут calendar-first
- **Одна кнопка на новый план и дозаполнение** — разная семантика
- **Авто-N = max слотов без пресета** — убирает контроль «заранее указать N»

## Open Questions

- Режим «Планирую» (toggle) vs всегда-кисть при клике по дню с свободными слотами?
- Drag обязателен в MVP или достаточно Shift+клик диапазона?
- Что делать с уже реализованным flow «DayDrawer → Добавить в план» — удалить сразу или feature-flag?
