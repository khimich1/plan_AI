# ГСМ: календарь машины в раскрытой строке

**Дата:** 2026-08-24. **Статус:** direction confirmed, к спеке.
**Источник:** idea-refine сессия 2026-08-24 (рамка: бухгалтер закрывает месяц;
вариант A — сетка месяца в раскрытой строке обзора).

## Problem Statement

How might we дать бухгалтеру по клику на машину карту выбранного месяца,
где в каждом дне видно транзакцию и путевой, а день с заправкой/мойкой без ПЛ
сразу виден — без путаницы с «красными днями» бака и без ощущения, что пустой
июль «сломался»?

## Recommended Direction

Сетка месяца живёт **в уже раскрытой строке** обзора (клик по имени машины как
сейчас). Период сетки = «С / По» шапки. Журнал ПЛ и лента остаются ниже:
календарь — карта, журнал — детали.

В клетке дня два независимых маркера: **транзакция** (fuel/wash в эту дату) и
**ПЛ**. Подсветка-дыра — только если есть транзакция и нет ПЛ на эту дату.
Красный бак (`manual_intervention`) — второе кольцо на дне, у которого ПЛ
уже есть. Ходовой день с ПЛ без заправки не красить.

Пустой месяц (Palisade, июль) не прыгает молча в август: 31 клетка + текст
«в периоде нет движений». Баннер хвоста — **не в этом срезе**: прыжок в месяц
незакрытых ПЛ (июнь Monjaro) требует даты в `/overview`, которой сейчас нет.

Технически MVP почти весь на клиенте: уже есть `GET /gsm/waybills?vehicle_id&from&to`
в раскрытии и `GET /gsm/transactions?vehicle_id&from&to`. Склейка по `date` /
`substr(ts,1,10)`. Новый endpoint не обязателен.

Это painkiller на закрытии месяца: сейчас дыра видна только как статус
«Требуется генерация» на всю машину или как пустой журнал не в том месяце.

## Key Assumptions to Validate

- [ ] Бухгалтер смотрит **календарный месяц**, а не произвольный from–to.
      Если период не один календарный месяц — сетка по всем дням выбранного
      диапазона (дефолт), дни вне диапазона не рисуем.
- [ ] «Транзакция без ПЛ» = нет ПЛ с `date` в тот же календарный день, что
      `ts` транзакции (ночёвка/заправка в 23:50 не съезжает на соседний день).
- [ ] Несколько транзакций в один день — одна клетка, дыра если **ни одного**
      ПЛ в этот день. Мойка и топливо в один день — один маркер tx.
- [ ] Подсветка дыр меняет поведение (генерация / смена периода), а не «просто
      красивее ленты». Проверка: август Palisade / Monjaro глазами бухгалтера.

## MVP Scope

**In**

- Сетка в `VehicleWaybillJournal` (или соседний блок над лентой) на выбранный
  `from…to`.
- Клетка: номер дня, маркер tx, маркер ПЛ; дыра = tx без ПЛ; красный бак =
  отдельный стиль.
- Клик по дню с ПЛ → существующий drawer; клик по дыре → фокус на
  «Сгенерировать» текущего периода (не генерация одного дня).
- Пустой период: сетка + «нет движений», без автопрыжка.

**Out этого MVP:** мини-календари на всех машинах; генерация по одному дню;
бак нач/кон в клетке; подсветка «ПЛ без транзакции»; замена журнала;
умный баннер хвоста (`open_before_from`).

## Not Doing (and Why)

- **Четыре мини-календаря на обзоре** — шум, клик по строке теряет смысл.
- **Красить ПЛ без заправки** — нормальные ходовые дни, календарь станет
  сплошным «алармом».
- **Молча менять период при пустом месяце** — пропадёт, какой месяц смотрят;
  у `/overview` нет дат снаружи периода.
- **Генерация кликом по клетке на одну дату** — солвер работает периодом
  якорей, не днём; это другой срез.
- **Дублировать журнал в клетке** (маршрут, бак, одометр) — это уже таблица
  снизу.
- **Умный баннер «открыть месяц хвоста»** — нужен аддитивный контракт
  `/overview` (`open_before_from`). Отдельная идея/задача, Ask first.

## Open Questions

- Закрыто для MVP: сетка = все дни выбранного диапазона; один маркер tx на
  день; баннер хвоста — отдельная задача.
- Остаётся: если `from…to` пересекает границу месяца (15.07–14.08) — одна
  лента дней или две сетки месяцев? Дефолт, пока не оспорен: одна лента дней
  диапазона, без разбиения на два календаря.
