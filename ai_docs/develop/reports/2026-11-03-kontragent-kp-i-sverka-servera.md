# Отчёт: КП нового контрагента и сверка с сервером

**Дата:** 2026-11-03  
**Статус:** разбор и выкладка в git сделаны. На сервер новый экран договора не выкладывался.  
**Код приложения в этой сессии:** не менялся. В `web` ушли уже готовые коммиты.

## Задача

Понять, как посчитать КП клиенту, которого нет в 1С и у которого нет договора. Затем зафиксировать готовые изменения в git и сверить сервер с локальной веткой, чтобы выкладка договоров не оборвала обмен с 1С.

## Как программа ведёт такого клиента

Контрагента в мастере заводить не нужно. КП считается и уходит в архив по одному имени. В 1С и в производство оно не выходит, пока на карточке архива нет живого кода 1С и действующего договора.

1. В мастере остаётся набранное имя. Идентификатор контрагента не ставится. Кнопка «В архив» сохраняет КП. PDF и Excel можно отдать заказчику с этим рабочим именем. В архиве бейдж «нет 1С», «Отправить в 1С» неактивна.
2. Карточку заводят в 1С и берут оттуда код. В архиве, пока КП «в архиве», его заносят кнопкой «Занести контрагента». Выдуманный код создаёт только местную строку: счёт узнаёт клиента по коду.
3. После привязки, если договора нет, появляется «в реестре договора нет». Можно привязать уже известный номер или «Собрать договор». Следующий номер выдаётся один раз вместе с первым полным бланком.
4. «Отправить в 1С» доступна, когда есть контрагент, действующий договор и GUID позиций. Статус становится «на согласовании». Номер счёта приходит ответом 1С.
5. «В производство» — только из «на согласовании» и только для плит: номер счёта, отметка оплаты и сохранённая спецификация. Сваи, ступени, марши, мостовые и составные сваи, ФБС этой кнопкой не уходят.

Хост `himych`, каталог `/opt/plan_zavod`, контейнер `plan_zavod-backend-1`. Это не git-репозиторий: сборка берёт файлы с диска, а не ветку `web`.

Обмен уже работает и совпадает с локальным `app/main.py`. В контейнере заданы `EXCHANGE_EXPORT_DIR=/data/exchange/to_1c` и `EXCHANGE_IMPORT_DIR=/exchange/from_1c`. Оба каталога смонтированы отдельно от тома базы и сейчас пустые: 1С файлы забрала. КП №183 на сервере «на согласовании», номер счёта `782`. В локальной базе этого КП нет.

## Вывод по выкладке

Сборка текущего диска сервера новый экран договора не принесёт. Чтобы он появился, на диск сначала кладут файлы из `web`, затем собирают backend и frontend по отдельности.

Обмен и база при этом не страдают, если оставить оба монтирования, не подменять `plita.db` и не выполнять `docker compose down -v`. КП №183 повторно не отправлять.

Поменяется правило счёта. У клиентов из сверки 30 октября номер останется прежним. Клиент, которому договор подставлялся только в момент отправки, получит «Нет действующего договора поставки», пока номер не занесут вручную.
