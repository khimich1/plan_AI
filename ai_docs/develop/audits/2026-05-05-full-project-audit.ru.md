# Отчёт по аудиту проекта

**Дата**: 2026-05-05  
**Объём**: Весь проект (с фокусом на критические пути по регламенту)  
**Провели**: senior-reviewer + security-auditor + reviewer  

## Краткое резюме

В проекте Shishov выявлены **критические проблемы архитектуры, безопасности и качества кода**, требующие немедленного устранения. Имеются множественные критические уязвимости в аутентификации и авторизации, шаблоны с **глобальным изменяемым состоянием** в модуле оптимизации и **перевёрнутые зависимости** в слое доступа к БД. В кодовой базе проявляются антипаттерны «бог-модулей» и **недостаточное покрытие тестами** относительно сложности модулей. **Итоговый Health Score: 0.0/10** — проект **не готов к продакшену** и требует срочного архитектурного рефакторинга до развёртывания.

**Ключевые риски**:
- **Обход аутентификации**: у админских обработчиков Telegram-бота **нет проверок авторизации** (доступен любому пользователю)
- **Гонки**: глобальное изменяемое состояние в `OptimizationService` **без синхронизации**
- **Обход путей (path traversal)**: **нет валидации** идентификатора черновика в API commercial
- **Слабые секреты**: **значение по умолчанию** для `APP_SECRET_KEY` в настройках

## Критические проблемы (исправить немедленно)

### [A1] Глобальное изменяемое состояние в OptimizationService — гонки

**Категория**: Архитектура  
**Серьёзность**: Critical  
**Место**: `core/optimization.py` (OptimizationService, legacy_runtime)  
**Влияние**: **Порча данных, недетерминированное поведение при параллельных запросах**  
Общее изменяемое состояние (`legacy_runtime`) без блокировок приводит к гонкам под нагрузкой. Это противоречит идиоматичным паттернам async/await и может вызывать «тихие» сбои в продакшене.

**Что сделать**:
- Перепроектировать `OptimizationService` на **неизменяемые структуры** или состояние **на один запрос**
- Убрать изменяемые атрибуты уровня класса; использовать DI для состояния в области запроса
- Если нужен кэш — потокобезопасный кэш (например, `functools.lru_cache` с блокировкой или Redis)
- Если общее состояние неизбежно — примитивы синхронизации (`asyncio.Lock`)

**Затронутые файлы**:
- `core/optimization.py` (порядка строк ~50–2696 по отчёту)
- `app/api/routers/` (любой маршрут, использующий OptimizationService)

### [A2] Перевёрнутая зависимость: db_config импортирует app.core.settings

**Категория**: Архитектура  
**Серьёзность**: Critical  
**Место**: `core/db_config.py` (импорт из `app.core.settings`)  
**Влияние**: **Риск циклических зависимостей, жёсткая связь, усложнение тестов и конфигурации**

**Что сделать**:

- Оставить в `core/db_config.py` минимум: пул, разбор URL и т.п.
- Передавать настройки в `db_config.py` **параметрами**, не импортировать из `app.core.*`
- Правило: модули `core/` **не импортируют** `app/` (строгое слоение)

**Затронутые файлы**:
- `core/db_config.py`
- `app/db/session.py` (создать при отсутствии)
- Все места импорта `db_config`

### [A4] Жадные тяжёлые импорты в `core/__init__.py`

**Категория**: Архитектура  
**Серьёзность**: High  
**Место**: `core/__init__.py`  
**Влияние**: **Медленный старт приложения, больший расход памяти, риск циклических импортов**

**Что сделать**:
- Перейти на **ленивые импорты**; подгружать при обращении
- Использовать `__getattr__` для ленивых импортов на уровне модуля (PEP 562)
- Либо экспортировать только символы, без `from X import *`
- Явно задокументировать публичный API

**Пример**:
```python
# Было (плохо):
from .optimization import OptimizationService
from .visualization import ChartGenerator
from .commercial import PricingEngine

# Стало (хорошо):
__all__ = ["OptimizationService", "ChartGenerator", "PricingEngine"]

def __getattr__(name):
    if name == "OptimizationService":
        from .optimization import OptimizationService
        return OptimizationService
    raise AttributeError(f"module {__name__} has no attribute {name}")
```

### [S6] Path traversal по `draft_id` — отсутствует валидация

**Категория**: Безопасность  
**Серьёзность**: High  
**Место**: `app/api/routers/draft_store/` или `commercial.py` (обработка `draft_id`)  
**Влияние**: **Обход каталогов (`../../../`) для доступа к чужим черновикам или файлам**

**Что сделать**:
- Валидировать формат `draft_id`: только UUID или безопасный алфавит, без разделителей путей
- По возможности выбирать по ID из БД, а не собирать путь к файлу из пользовательского ввода
- Проверка владения: `WHERE draft_id = ? AND user_id = ?`

**Пример**:
```python
@router.get("/drafts/{draft_id}")
async def get_draft(draft_id: str, current_user: User = Depends(get_current_user)):
    # Validate format
    if not re.match(r"^[a-f0-9\-]{36}$", draft_id):  # UUID format
        raise HTTPException(status_code=400, detail="Invalid draft_id")
    
    # Query by ID (not path!)
    draft = await db.execute(
        select(Draft).where((Draft.id == draft_id) & (Draft.user_id == current_user.id))
    )
    if not draft:
        raise HTTPException(status_code=404)
    return draft
```

### [S9] Отсутствуют security-заголовки — XSS / clickjacking

**Категория**: Безопасность  
**Серьёзность**: Medium  
**Место**: `app/main.py` (middleware)

**Суть**: Нет `X-Frame-Options`, `X-Content-Type-Options`, `Content-Security-Policy`.

**Что сделать**:
```python
from starlette.middleware.base import BaseHTTPMiddleware

app.add_middleware(SecurityHeadersMiddleware)

class SecurityHeadersMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        response = await call_next(request)
        response.headers["X-Frame-Options"] = "DENY"
        response.headers["X-Content-Type-Options"] = "nosniff"
        response.headers["X-XSS-Protection"] = "1; mode=block"
        return response
```
