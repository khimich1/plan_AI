## Критические замечания

### A1 — Расхождение контракта оркестрации (критично, архитектура)

**Где:** `frontend/src/pages/commercial-offer-create/`, `frontend/src/features/commercial-offer/`, `app/services/commercial_workflow_service.py`

**Суть:**  
Два параллельных «оркестратора» ведут состояние мастера без формального контракта:

- **Клиент:** шаги по enum `WizardStepId`, навигация через React state и мутации запросов.
- **Сервер:** `CommercialWorkflowService.calculate_draft()` и метаданные `current_step` задают бизнес-прогресс.

**Последствия:**

- UI может перейти на следующий шаг без POST `/calculate`; метаданные сервера устаревают.
- Расхождение черновика и намерения сервера; пересчёт может не выполняться когда нужен.
- Итоги в `draft.totals` на клиенте могут конфликтовать с пересчётом на сервере.
- Контракт не формализован; имена полей неявны.

**Рекомендации:**

1. Зафиксировать контракт конечного автомата (схема Pydantic), например `WizardStateResponse` с полями `current_step`, `can_proceed_to`, `next_required_action`, `validation_errors`.
2. Источник истины для шага — сервер; переход на следующий шаг после обязательного POST `/calculate`.
3. Кнопки в UI завязать на `can_proceed_to` из ответа.
4. Синхронизировать enum `WizardStepId` между фронтом и бэкендом.

### S-H01 — Обход путей в DraftStore (критично, безопасность)

**Где:** `app/services/commercial_service.py` (склеивание путей DraftStore), см. также `draftStorage` на фронте

**Суть:**  
Если файлы лежат как `DRAFT_DIR / {user_id} / {draft_id} / {filename}`, злоумышленник может передать в `filename` последовательности `../` и выйти из каталога.

**Последствия:**

- Чтение/запись произвольных файлов в пределах дерева пользователя.
- Риск утечки чужих черновиков при пересечении границ владения.

**Рекомендации:**

1. Санитизация имени; отклонять `..`, `/`, `\`, абсолютные пути; после `resolve()` убеждаться, что путь остаётся под `base`.
2. Либо детерминированные имена: `{draft_id}_{field}.{ext}` без пользовательских компонентов пути.

*Дополнение:* в актуальном `DraftStore` введена валидация `draft_id` и проверка, что путь остаётся внутри `drafts_dir` — перепроверьте все остальные места склейки путей (вложения, сгенерированные файлы).

## Высокий приоритет

### A2 — «Божественный» модуль CommercialWorkflowService (высокий, архитектура)

**Где:** `app/services/commercial_workflow_service.py` (~940 строк)

**Суть:**  
Сервис совмещает расчёт, генерацию файлов, разрешение состояния черновика и широкие плиты — нарушение единой ответственности.

**Последствия:**  
Сложность тестирования, рост связности, риск циклических зависимостей с эндпоинтом `commercial.py` при доступе к приватным хелперам.

**Рекомендации:**  
Вынести подсервисы: расчёт черновика, оркестрация мастера, генерация КП; собирать через DI в `commercial.py`; контракты через протоколы.

---

### A3 — Дублирование денежной логики (клиент vs сервер) (высокий, архитектура)

**Где:** `frontend/src/features/commercial-offer/`, `app/services/commercial_workflow_service.py`

**Суть:**  
Клиент считает итоги самостоятельно; сервер — через `calculate_draft()`. До синхронизации возможны разные цифры.

**Рекомендации:**  
Сервер — единственный источник истины для сумм; на клиенте показывать только `draft.totals` с сервера; при необходимости — ETag/контрольная сумма при сабмите.

---

### A4 — AppHeader жёстко связан со стором мастера (высокий, архитектура)

**Где:** `frontend/src/app/layout/AppHeader.tsx`

**Суть:**  
Шапка напрямую использует мост к стору черновика (`hasDraft`, `resetDraft`). Хром приложения связан с одним бизнес-сценарием.

**Рекомендации:**  
Колбэки без привязки к домену (`onClose`, `onReset`, навигация), контейнер на уровне страницы, композиция через layout.

### A5 — API вызывает приватный метод workflow (высокий, архитектура)

**Где:** `app/api/v1/endpoints/commercial.py` (ранее ~279–284), `app/services/commercial_workflow_service.py`

**Суть:**  
Эндпоинт вызывал `_resolve_generated_file()` вместо публичного интерфейса.

**Рекомендации:**  
Публичный метод вида `get_or_generate_file(...)` на сервисе workflow.

*Состояние:* в текущем `commercial.py` для скачивания используется `workflow.get_or_generate_file(safe_name)` — пункт считается закрытым при сохранении поведения и тестов.

### S-H02 — IDOR: нет проверки владения черновиком по пользователю (высокий, безопасность)

**Где:** `app/api/v1/endpoints/commercial.py`

**Суть:**  
Операции с `draft_id` без привязки к текущему пользователю позволяли бы читать/менять чужие черновики при угадывании id.

**Рекомендации:**  
`owner_user_id` в метаданных черновика; dependency `verify_draft_ownership`; 403 при несовпадении.

*Состояние:* реализовано в `app/dependencies/commercial_draft.py` и подключено к маршрутам с `{draft_id}` — перепроверьте, что **все** эндпоинты, где id передаётся иначе (query, form), тоже защищены.
