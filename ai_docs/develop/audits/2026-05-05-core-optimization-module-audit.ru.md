## Архитектурные Находки

### 🔴 Критичные проблемы (2 шт.)

#### **[A1] Конфликт имён пакета и модуля — exec shim в `core/optimization/__init__.py`**

- **Тип:** Namespace collision
- **Описание:** Пакет `core/optimization/` и модуль `core/optimization.py` создают конфликт при импорте. Динамический `exec()` в `__init__.py` для передачи символов усложняет:
  - Статический анализ (IDE, type checkers теряют информацию)
  - Отладку и навигацию в коде
  - Поддержку версионирования
- **Риск:** Непредсказуемое поведение импортов, скрытые зависимости
- **Текущее решение:** Временный exec-шим вместо явного API
- **Рекомендация:** Переименовать в `core/optimization_v2/` и явно экспортировать из `__init__.py`

#### **[A2] Изменяемые глобальные переменные — утечка состояния между запросами**

- **Тип:** Mutable global state
- **Переменные:** `OPT_PLAN`, `BEST_OFFSET`, `LAST_ERROR` в `core/optimization.py`
- **Проблема:** Без блокировки потокобезопасности при параллельных вызовах:
  - Запрос А устанавливает `OPT_PLAN`
  - Запрос Б читает `OPT_PLAN` от А (загрязнение данных)
  - Состояние оптимизатора становится недетерминировано
- **Риск:** Data corruption, race conditions в production
- **Рекомендация:**
  - Перенести в контекст запроса (FastAPI `Depends` или thread-local)
  - Использовать `threading.Lock()` с контекстным менеджером
  - Рассмотреть Pydantic models для состояния

## Находки по Безопасности

### 🟠 Высокие приоритеты (2 шт.)

#### **[S1] Debug-логирование обходит контроль доступа к OPT_DEBUG_LOG**

- **Проблема:** Функция `_log_debug_to_file()` пишет в файл без проверки:
  - Приватный флаг `OPT_DEBUG_LOG` может быть установлен извне
  - Пути файлов не валидируются
  - Нет аудита кто и когда включил debug
- **Риск:** Утечка чувствительных данных, массовое логирование в production
- **Рекомендация:**
  ```python
  # Вместо глобального флага:
  DEBUG_ENABLED = False  # ← спрятано
  
  # Использовать конфиг:
  class OptConfig(BaseSettings):
      debug_mode: bool = Field(default=False, description="Требует SERVICE_ADMIN role")
      debug_log_dir: str = Field(default="/tmp/opt_logs")
  ```

#### **[S2] Утечка состояния модуля между запросами (Cross-request leakage)**

- **Проблема:** Глобальные переменные модуля сохраняют состояние:
  - `OPT_PLAN` остаётся от Запроса A в Запросе B
  - `LAST_ERROR` могут прочитать неавторизованные пользователи
  - Thread-unsafe в async-контексте
- **Риск:** Data exposure, timing attacks, race conditions
- **Рекомендация:**
  - Перенести в `RequestContext` с lifetime=request
  - Использовать `contextvars` для async-safety
  - Очищать состояние после каждого цикла

### 🟡 Средние приоритеты (3 шт.)

#### **[S3] Потенциальная угроза через `exec()` при импорте**

- **Проблема:** `core/optimization/__init__.py` использует:
  ```python
  exec(f"from {module_name} import *")
  ```
- **Риск:** Если `module_name` загружается из ненадёжного источника → RCE
- **Текущее состояние:** Значения hardcoded, но требует аудита при изменении
- **Действие:**
  - Заменить на явный импорт: `from .ilp_model import *`
  - Никогда не строить `exec()` из пользовательского ввода
  - Добавить проверку: `assert module_name in ALLOWED_MODULES`

#### **[S4] Небезопасное построение пути файла в `get_debug_log_path()`**

- **Проблема:** Путь строится как:
  ```python
  debug_path = f"{OPT_DEBUG_DIR}/{filename}"
  ```
- **Риск:** Path traversal — если `filename = "../../etc/passwd"`
- **Действие:**
  ```python
  from pathlib import Path
  safe_path = Path(OPT_DEBUG_DIR) / Path(filename).name  # только имя файла
  safe_path.resolve().relative_to(Path(OPT_DEBUG_DIR).resolve())  # валидировать
  ```

#### **[S5] Утечка PII в debug-логах**

- **Проблема:** Логируются полные данные заказов, цены, контакты без маскирования
- **Риск:** Compliance violation (GDPR, ПДДаС), утечка коммерческих данных
- **Действие:**
  - Маскировать: email → `u***@example.com`, phone → `+7 *** 12 34`
  - Использовать `structlog` с фильтрацией чувствительных полей
  - Ограничить ротацию логов: `maxBytes=10MB, backupCount=3`

## Находки по Качеству Кода

### 🟠 Высокие приоритеты (2 шт.)

#### **[Q1] Несоответствие между ключами proportional slot и canonical demand_2d**

- **Файл:** `order_dispatch.py:188-191`
- **Проблема:**
  ```python
  # ожидается key = "2x3x0.1"  (proportional_key)
  # но проверяется key = "2x3"    (canonical без thickness)
  if key not in residual_balance:  # ← MISMATCH
      residual_balance[key] = 0
  ```
- **Последствие:** Слоты не учитываются, остатки спутаны
- **Действие:** Нормализовать на один формат ключей

#### **[Q2] In-place мутация в `_build_residual_balance_constraints()`**

- **Файл:** `ilp_model.py`
- **Проблема:**
  ```python
  def _build_residual_balance_constraints(slots):
      for slot in slots:
          slot['used'] = 0  # ← мутирует входной объект!
  ```
- **Последствие:** Невидимые побочные эффекты, сложность отладки, нарушение функционального стиля
- **Действие:**
  ```python
  def _build_residual_balance_constraints(slots):
      return {slot['id']: 0 for slot in slots}  # ← копия
  ```
