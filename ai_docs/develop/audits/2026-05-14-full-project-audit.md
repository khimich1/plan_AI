## Критические проблемы (исправить немедленно)

### [A1] Циклическая связность `core` ↔ `viz_modules`
**Категория:** Архитектура  
**Локализация:** импорты визуализации из `core` и обратные импорты из `viz` в `core`.  
**Влияние:** риск циклических импортов, нестабильных порядков инициализации, затруднённого тестирования и рефакторинга; рост связности между слоями.  
**Исправление:** ввести явную границу (порты/фасады, события или тонкий «adapter» слой), направить зависимости односторонне (например, домен/ядро не импортирует визуализацию; визуализация зависит от абстракций).

### [A2] Дублирование `PlateOrder`: приложение vs `core` + глобальное состояние
**Категория:** Архитектура  
**Локализация:** параллельные реализации/пути `PlateOrder` в приложении и в `core`; `plate_runtime_state` / `apply_to_globals`.  
**Влияние:** расхождение поведения, гонки и непредсказуемость состояния между запросами/воркерами; сложность сопровождения.  
**Исправление:** единый источник истины для модели заказа и состояния; убрать или инкапсулировать глобальные мутации; явный lifecycle (контекст запроса, DI, репозиторий).

### [A3] Наследие мутаций `OPT_*` у потребителей оптимизации
**Категория:** Архитектура  
**Локализация:** потребители оптимизации продолжают опираться на глобальные/устаревшие `OPT_*` несмотря на мостинг через TLS.  
**Влияние:** скрытая связность и латентные баги при параллелизме; затрудняет вынос оптимизации в отдельный сервис.  
**Исправление:** завершить миграцию на явный контекст оптимизации; убрать чтение/запись глобальных `OPT_*` из бизнес-путей; договориться об одном API для параметров прогона.

### [S1] Дефолтный секрет подписи сессий
**Категория:** Безопасность  
**Локализация:** значение вида «change-this-secret-key-in-env» как допустимый дефолт для подписи.  
**Влияние:** при деплое без смены секрета возможна **подделка сессий** и полный обход аутентификации.  
**Исправление:** **запретить запуск в production без заданного секрета**; ротировать ключ; короткоживущие session id; аудит всех сред, где остался дефолт.

## Проблемы высокого приоритета

**Архитектура**

- **[A4]** `core/visualization.py` — «божественный» модуль: сконцентрированы разнородные обязанности; разбить на подмодули/сервисы по ответственности.
- **[A5]** Обработчики `bot` тянут и `core`, и `app.services` напрямую — нарушение границ слоёв; ввести фасады/use-cases и DI.
- **[A6]** «Ручки» масштабирования частичны/не используются: `redis_url`, `database_url`; сильная привязка к ФС — унифицировать конфиг, документировать режимы, убрать мёртвые параметры или довести до рабочего контура.
- **[A7]** Авторизация **загружает полный список пользователей на каждый запрос** — узкое место и антипаттерн; кэш, индекс по id, lazy-load или claims в токене/сессии.
- **[A8]** Сервисы создаются в телах роутов вместо `Depends` — усложняет тестирование и единообразие жизненного цикла; перейти на зависимости FastAPI.

**Безопасность**

- **[S2]** Cookie сессии: **`Secure=False`** — риск перехвата в смешанных сетях; включить `Secure` в prod, явная политика для dev.
- **[S3]** **Нет защиты от перебора** на логине — rate limiting, блокировка/задержка, капча при необходимости, мониторинг.
- **[S4]** **Offers API:** отсутствует **конфиденциальность на уровне строк** между ролями — ввести row-level/политику доступа, фильтрацию по владельцу/организации, проверки в сервисе и репозитории.
- **[S5]** Сборка production-plan **протекает внутренние ошибки** через `str(exc)` клиенту — маскировать, логировать server-side, возвращать стабильные коды/сообщения.

**Качество кода**

- **[Q1]** **Голые `except`** в `plan_manager`, обработчиках бота — заменить на конкретные исключения, логирование, re-raise где уместно.
- **[Q2]** `core/kp_db.py` — монолит ~3955 строк + `print`; декомпозиция по доменам, логгер, тесты на критические пути.
- **[Q3]** `bot/handlers/commercial.py` — перегруженный FSM-файл; выделить состояния, хендлеры, сервисы.

## Проблемы среднего приоритета

**Архитектура**

- **[A9]**–**[A14]** Перекрёстный `_legacy_order_context`; фасад `config_and_data`; дубли путей `settings` / `project_paths`; предупреждения печати в viz procurement; разделение домена `core` vs `app`; «порты» закупок внедрены частично — довести границы, убрать дубли, единая конфигурация путей.

**Безопасность**

- **[S6]** **Полный ростер** в hot path аутентификации — см. [A7], снизить объём данных и частоту загрузки.
- **[S7]** OCR limiter **процесс-локальный**; обработка сторонним ИИ — учитывать квоты, PII, политику хранения, единый gateway.
- **[S8]** **Глобальное изменяемое** состояние оптимизации/плит — целостность и гонки; изоляция по запросу/задаче.
- **[S9]** Валидация архива **пробрасывает текст исключений** наружу — нормализовать сообщения, не светить внутренности.

**Качество кода**

- **[Q4]** Дубли `_warn_missing_reinforcement` / `layout_sequence` — DRY, общий модуль.
- **[Q5]** «Строковый» маппинг ошибок через `ValueError` в offers endpoint — явные коды/типы ошибок, схемы ответов.
- **[Q6]** **Нет тестов** на `OffersService`/роутер — добавить интеграционные и контрактные тесты.
- **[Q7]** Web router **почти не покрыт** тестами — приоритет критичных маршрутов.
- **[Q8]** В `finalize.py` заглушено/проглочено **debug-логирование** — восстановить полезные логи без шума в prod.

## Следующие шаги

1. **Немедленно (до любого публичного деплоя):** убрать дефолтный signing secret, **ротировать** ключ, запретить старт без `SECRET_*`; включить **Secure-cookie** и политику для среды; закрыть **Offers API** от горизонтального доступа между ролями (row-level / ownership); перестать отдавать **внутренние исключения** клиенту в production plan build.
2. **Текущий спринт (структура):** спроектировать разрыв цикла **core↔viz**; консолидировать **PlateOrder** и убрать `apply_to_globals` из горячего пути; завершить отказ от **`OPT_*` в потребителях**.
3. **Текущий спринт (наблюдаемость и качество):** заменить голые `except`; начать распил `kp_db.py` и `commercial.py`; ввести `Depends` для сервисов в роутерах.
4. **Следующий спринт:** средние пункты A9–A14, S7–S9, Q4–Q8 (инфра закупок, лимитеры OCR, сообщения об ошибках, тесты Offers/web).
5. **Бэклог:** низкоприоритетные A15–A18, S10–S14, Q9–Q13 (заголовки, CORS, пины, логирование, чистка артефактов).
