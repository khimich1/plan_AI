## Критические проблемы (исправить немедленно)

### [A1] Инверсия зависимостей между `core` и приложением  
**Категория**: архитектура  
**Где**: `core/db_config.py` импортирует `get_settings` из `app.core.settings` — общий пакет `core` зависит от слоя FastAPI-приложения, а не наоборот.  
**Влияние**: размытие границ слоёв, риск циклических импортов, невозможность вынести `core` как переиспользуемую библиотеку.  
**Исправление**: перенести общие параметры подключения к БД в нейтральный модуль конфигурации (например, env/dataclass в `core` или интерфейс, который приложение заполняет через DI), чтобы `core` не импортировал `app.*`.

### [S1] Подделка сессионных токенов при дефолтном секрете  
**Категория**: безопасность  
**Где**: `app/core/settings.py` (поле `APP_SECRET_KEY` со слабым значением по умолчанию), подпись в `app/security/session.py`.  
**Влияние**: при выкладке без смены секрета в окружении злоумышленник может сгенерировать валидные `app_session` и выступать от имени пользователей — компрометация аутентификации.  
**Исправление**: обязательная настройка сильного секрета через переменные окружения в production, ротация при утечке, отказ старта при дефолтном значении (fail-fast).

## Высокий приоритет (исправить в ближайшее время)

### Архитектура

- **[A2]** «Божественный» модуль `app/planning/plan_manager.py` (~1400 строк): валидация, ФС, JSON/метаданные, календарь (`core.work_calendar`, `core.kp_db`), треки — **разбить** на сервисы/модули с одной ответственностью.

- **[A3]** Перегруженные сервисы: `commercial_workflow_service.py`, `production_planning_service.py` (~1000 строк), `day_view_service.py` (~578) — **декомпозиция** по сценариям и интерфейсам.

- **[A4]** `get_current_user` в `app/dependencies/auth.py` вызывает `AuthRepository.list_users()` на каждый запрос — **заменить** на загрузку по id + кеш/индекс, убрать полное сканирование.

- **[A5]** Дублирующее представление PlateOrder: `app/domain/models/plate_order.py` и `core/domain/plate_order.py` + реэкспорты — **единая доменная модель** или явный antif corruption layer и мапперы.

- **[A6]** Роутеры создают сервисы вручную (`ProductionService()`, `CommercialService()` и т.д.) — **Depends-фабрики** для жизненного цикла и тестируемости.

### Безопасность

- **[S2]** Флаг `secure=False` для cookie при логине (API и web) — **включать Secure для HTTPS**, корректная политика для dev/prod через настройки.

- **[S3]** Отсутствие rate limiting на эндпоинтах входа — **throttling / lockout / CAPTCHA** по необходимости.

- **[S4]** Повтор A4 с точки зрения доступности: полная перестройка карты пользователей на запрос — **см. [A4]**.

### Качество кода

- **[Q1]** Нет интеграционных тестов FastAPI/TestClient для `/api/v1/production/*`, `/offers`, `/managers`, `/auth` — **добавить** минимальные smoke + негативные кейсы с фикстурой сессии.

- **[Q2]** `production_planning_service.py` ~1045 строк, смешанные ответственности — **выделить** запросы, сборку треков, валидацию в отдельные модули с тестами.

## Средний приоритет (спланировать на спринт)

### Архитектура

- **[A7]** `legacy_runtime()` меняет глобальное состояние `core.optimization`; корректность завязана на middleware изоляции — **документировать контракт**, сузить мутацию или заменить на явный контекст.

- **[A8]** `plan_manager`: `sys.path`, хранилище под `bot/data/plans` — **конфигурируемые пути**, отказ от правки `sys.path` там, где возможно.

- **[A9]** `core/config_and_data.py` как монолитный фасад с `__getattr__` — **упростить** границу экспорта.

- **[A10]** Две линии конфигурации: `app/core/settings.py` vs `core/config` — **согласовать** источник правды или явно разделить «web» и «расчётный» конфиг с документированными правилами.

### Безопасность

- **[S5]** `detail=str(exc)` в `production.py`, `archive.py` — **централизованные handlers**, пользователю — код/обобщённое сообщение, детали — только в лог.

- **[S6]** CORS с `allow_credentials=True` и `allow_headers=["*"]` — **минимальный** список заголовков.

- **[S7]** CSRF при cookie-сессии и Lax SameSite — **оценить** топологию фронта; при необходимости double-submit, SameSite=Strict для части сценариев, заголовков для API.

- **[S8]** Offers/KP: только роли, без проверки владения/строкового уровня — **политики доступа** к объектам по `manager_id` или эквиваленту при многопользовательской изоляции.

- **[S9]** Запись чувствительных отладочных данных на диск в `core/kp_db.py` — **флаг окружения**, ротация, права доступа или отключение в production.

### Качество кода

- **[Q3]** Несогласованные типы `filter_method` / `Literal` между сервисами — **общий тип**, убрать `type: ignore`.

- **[Q4]** Сырые `dict` из production endpoints — **Pydantic response_model**.

- **[Q5]** `CreatePlanRequest` с голыми `list`/`dict` — **вложенные модели** или `dict[str, Any]` с явной схемой.

- **[Q6]** Дублирование SQL-INSERT в тестах — **фабрики в `conftest`**.

- **[Q7]** `app/web/router.py` ~1014 строк — **шаблоны/функции сборки страниц**.

- **[Q8]** Разрозненные `get_debug_log_path` и прямые `open` — **единый logging/NDJSON** под флагом.

- **[Q9]** Массовые `# type: ignore` в core — **сузить типы**, `TYPE_CHECKING` для опциональных зависимостей.
