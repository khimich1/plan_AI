# Отчёт аудита: модуль ГСМ

**Дата**: 2026-08-11  
**Область**: модуль ГСМ (`scripts/build_gsm_trip_pool.py`, `scripts/build_gsm_routes_map.py`, связанные тесты, `ГСМ/geo_cache/`, сгенерированный HTML)  
**Кто аудировал**: senior-reviewer + security-auditor + reviewer  
**Модель**: Composer 2.5-fast (запрошенный slug `composer-2-fast` в среде недоступен)

## Краткое резюме

**Оценка здоровья**: **6.0 / 10**

Расчёт: старт 10; Critical 0 → 0; High 14 × 0.5 (потолок −3); Medium 32 × 0.1 (потолок −1) → **6.0**

| Серьёзность | Архитектура | Безопасность | Качество кода | Итого |
|-------------|-------------|--------------|---------------|-------|
| Critical    | 0           | 0            | 0             | **0** |
| High        | 3           | 3            | 8             | **14** |
| Medium      | 6           | 6            | 20            | **32** |
| Low         | 5           | 5            | 6             | **16** |

**Рекомендация**: критических блокеров нет. До шаринга HTML и до коммита `ГСМ/` — закрыть High по XSS, добавить `ГСМ/` в `.gitignore`, починить устаревший кэш треков.

Модуль подходит как личный offline-инструмент учёта маршрутов: два CLI-скрипта собирают Excel-пул и Leaflet-карту с кэшем на диске. Архитектура прагматичная, но монолитная; риски безопасности — в сгенерированном HTML (stored XSS) и незащищённых артефактах с ПДн; качество неравномерное — routes_map хорошо покрыт тестами, парсинг trip_pool хрупкий и почти без тестов.

**Метрики области**: `build_gsm_trip_pool.py` (~710 строк), `build_gsm_routes_map.py` (~1876 строк), `test_build_gsm_trip_pool.py` (4 теста), `test_build_gsm_routes_map.py` (35 тестов), `addresses.json` (~244 адреса, ~177 с координатами), `routes.geojson` (434 линии).

## High (исправить в ближайшее время)

### [A1] Устаревшие линии в append-only кэше `routes.geojson`

**Категория**: Архитектура  
**Где**: `scripts/build_gsm_routes_map.py` — `build_routes_geojson()` (~876–971), `write_map_html()` (~1177–1180, 1384–1405)  
**Влияние**: при смене координат геокода меняется `cache_key`, но старая Feature с тем же `(машина, address_a_norm, address_b_norm)` не удаляется. На карте могут остаться и старая, и новая линия. Подтверждено тестом `test_build_routes_identity_hit_requires_matching_cache_key`. Ручные правки в `addresses.json` усиливают риск.  
**Исправление**: при совпадении identity и другом `cache_key` — заменять/удалять старую Feature; при сохранении опционально чистить «сироты».

### [A2] God-модуль — `build_gsm_routes_map.py` (~1876 строк)

**Категория**: Архитектура  
**Где**: весь файл; HTML/JS в `write_map_html` (~1161–1679)  
**Влияние**: один файл держит Excel I/O, Nominatim, OSRM, упрощение линий, кэш GeoJSON, расчёт nearest, ~500 строк inline Leaflet/HTML/JS. Нарушение SRP; любое изменение UI/кэша/роутинга бьёт в одно место.  
**Исправление**: выделить пакет `gsm/`: `address.py`, `geocode.py`, `osrm_cache.py`, `geojson.py`, шаблон карты; CLI оставить тонким оркестратором.

### [A3] Неверное направление зависимости — импорт `normalize_address` через `sys.path`

**Категория**: Архитектура  
**Где**: `scripts/build_gsm_routes_map.py:24–28` импортирует из `build_gsm_trip_pool.py`; дубль `_as_str` в обоих скриптах  
**Влияние**: пайплайн карты зависит от скрипта сборки Excel, а не от нейтрального общего модуля. Переименование trip_pool ломает routes_map.  
**Исправление**: вынести `scripts/gsm/address.py` с `normalize_address`, `_as_str`; оба скрипта импортируют оттуда; убрать мутацию `sys.path`.

### [S1] Stored XSS — неэкранированные поля в Leaflet popup

**Категория**: Безопасность  
**Где**: `write_map_html` — JS `popupHtml()` (~1305–1316), `bindPopup` (~1393)  
**Влияние**: свойства GeoJSON (`машина`, `адрес_A`, `адрес_B`…) склеиваются в HTML без экранирования. Злонамеренный текст в путевом → Excel → GeoJSON/HTML выполняется при клике по линии.  
**Исправление**: экранировать все динамические значения (`escapeHtml` или DOM + `textContent`); добавить XSS-тесты с payload в фикстурах.

### [S2] Stored XSS — `innerHTML` в списке ближайших маршрутов

**Категория**: Безопасность  
**Где**: `renderNearest()` (~1559–1571)  
**Влияние**: те же поля через `li.innerHTML` на каждый поиск адреса, без клика по линии.  
**Исправление**: строить элементы через DOM API / экранировать строки; покрыть тестами.

### [S3] Кэши и выгрузки с ПДн не в `.gitignore`

**Категория**: Безопасность  
**Где**: `ГСМ/geo_cache/*`, `ГСМ/пул_поездок.xlsx`, `ГСМ/карта_маршрутов.html`; в `.gitignore` нет правила на `ГСМ/`  
**Влияние**: адреса, организации, номера, водители, карты ГСМ, координаты готовы к случайному `git add`. HTML встраивает полный список известных адресов.  
**Исправление**: добавить `ГСМ/` (или точечные маски) в `.gitignore`; зафиксировать в доке, что артефакты только локальные.

### [Q1] DRY — дублирование `_as_str`

**Категория**: Качество  
**Где**: trip_pool:95–102, routes_map:116–123  
**Влияние**: одинаковый хелпер в двух файлах.  
**Исправление**: общий модуль (см. [A3]).

### [Q2] DRY — обогащение из реестра повторяется трижды

**Категория**: Качество  
**Где**: `fact_to_row`, `round_to_row`, `build_routes` в trip_pool  
**Влияние**: риск расхождения при смене колонок реестра.  
**Исправление**: один хелпер `enrich_from_registry(...)`.

### [Q3] Хрупкий парсинг — жёсткая раскладка ячеек ПЛ

**Категория**: Качество  
**Где**: `parse_waybill()` (~241–302)  
**Влияние**: фиксированные координаты xlrd без проверок и без тестов; смена шаблона ПЛ тихо портит данные.  
**Исправление**: фикстуры `.xls`, карта ячеек в доке, по возможности — поиск по заголовкам.

### [Q4] Сложность — монолитный генератор HTML

**Категория**: Качество  
**Где**: `write_map_html()` (~1161–1679)  
**Влияние**: ~450 строк JS внутри Python f-string; сложно ревьюить и тестировать.  
**Исправление**: вынести JS в шаблон/файл; Python только подставляет JSON.

### [Q5] Обработка ошибок — exit 0 при ошибках парсинга

**Категория**: Качество  
**Где**: `build_gsm_trip_pool.main` (~700–706)  
**Влияние**: ошибки печатаются, но процесс всегда успешен — CI не поймает частичный сбой.  
**Исправление**: ненулевой код выхода при непустом `errors`; опционально `--strict`.

### [Q6] Узкий catch в CLI trip_pool

**Категория**: Качество  
**Где**: `main()` ловит только `FileNotFoundError`  
**Влияние**: битый реестр/xlsx даёт traceback; у routes_map обработка шире.  
**Исправление**: выровнять с routes_map.

### [Q7] Слабое покрытие тестами пайплайна trip_pool

**Категория**: Качество  
**Где**: 4 теста vs 35 у routes_map; нет тестов `parse_waybill`, `load_registry`, `build_routes`, `run`…  
**Влияние**: регрессии парсинга Excel почти невидимы.  
**Исправление**: фикстурные тесты парсера и end-to-end `run`.

### [Q8] Мёртвый путь — метаданные `RouteAb` не используются

**Категория**: Качество  
**Где**: `load_routes_ab` читает марку/номер/топливо; `make_route_feature` и попапы их не берут  
**Влияние**: лишний I/O и обманчивая модель данных.  
**Исправление**: либо показывать в попапах, либо не загружать.

## Low / предложения

### Архитектура

- **[A10]** Жёсткие координаты ячеек ПЛ — ок для фиксированного шаблона; задокументировать карту.
- **[A11]** Два уровня нормализации адресов — разделить ответственность в доке.
- **[A12]** Нет миграции схемы `addresses.json` по `version`.
- **[A13]** «Локальный» HTML всё равно тянет CDN/тайлы/Photon в рантайме.
- **[A14]** Нет пакета `gsm/` — нормально для личного инструмента, мешает интеграции в продукт.

### Безопасность

- **[S10]** Нет XSS-регрессионных тестов.
- **[S11]** Зависимости без жёсткого pin/lockfile.
- **[S12]** OSM/Photon в рантайме — ожидаемо по спеке.
- **[S13]** Секретов в коде нет — **OK**.
- **[S14]** SSRF через подмену хоста — **не применимо** (фиксированные URL).

### Качество

- **[Q29]** Смешение кириллических и английских ключей в GeoJSON.
- **[Q30]** Опечатка «не заполненые» в маркерах папок.
- **[Q31]** Непрозрачный ключ сортировки в `build_routes`.
- **[Q32]** Тонкая обёртка `enrich()`.
- **[Q33]** Разная устойчивость CLI trip_pool vs routes_map.
- **[Q34]** Мелкие хелперы кэша без прямых тестов.
