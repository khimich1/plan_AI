## 1. Краткое резюме (Executive Summary)

Модуль `core/ocr_gpt.py` — центральная точка распознавания таблиц железобетонных плит через OpenAI GPT-4o Vision. Реализация **работоспособна и прагматична**: чистая функция `parse_gpt_response` покрыта тестами, внешние зависимости не образуют циклов. При этом модуль совмещает инфраструктуру (HTTP-клиент OpenAI), оркестрацию, промпт, парсинг, оценку стоимости и CLI — без портов, DI и единого конфига.

**Критических уязвимостей не выявлено**, однако **13 находок высокой важности** (архитектура, безопасность, качество данных) создают риски для production: утечка коммерческих изображений и данных в сторонний API, отсутствие таймаутов и лимитов, проглатывание ошибок, слабая валидация количества плит, прямое чтение произвольных путей к файлам в боте без rate limit и авторизации.

Веб-путь (`commercial_workflow_service`) частично компенсирует риски (валидация загрузки, rate limiting на уровне API), но **Telegram-бот обходит эти меры**, импортируя модуль напрямую.

## 3. Проблемы высокого приоритета (High)

### Архитектура

#### [A1] Слой приложения напрямую зависит от инфраструктуры

| | |
|---|---|
| **Категория** | Архитектура |
| **Локация** | `app/services/commercial_workflow_service.py:18, 744–749`; `bot/handlers/commercial.py:250–258` → вызов `core.ocr_gpt.recognize_text_smart` |
| **Влияние** | Невозможность подменить OCR в тестах без патчей; жёсткая привязка к OpenAI; дублирование политик (API vs бот) в разных местах. |
| **Исправление** | Ввести порт `OcrRecognitionPort` (protocol/ABC) в `app/ports/` или `core/ports/`; реализацию `GptVisionOcrAdapter` в `app/infrastructure/`; регистрация через DI/FastAPI `Depends` и фабрику для бота. |

#### [A2] Раздвоение конфигурации API-ключа

| | |
|---|---|
| **Категория** | Архитектура |
| **Локация** | `core/ocr_gpt.py:113` (`os.getenv('OPENAI_API_KEY')`) vs `core/config/settings.py:46` (`Settings.openai_api_key`) |
| **Влияние** | Бот и API могут работать с разными источниками конфига; ключ есть в Settings, но модуль его не использует. |
| **Исправление** | Принимать `Settings` или `api_key: str` в конструкторе адаптера; единая точка загрузки `.env` при старте приложения. |

#### [A3] Ошибки проглатываются — возврат `None`

| | |
|---|---|
| **Категория** | Архитектура |
| **Локация** | `core/ocr_gpt.py:84–89` — `except Exception`, `traceback.print_exc()`, `return None` |
| **Влияние** | Вызывающий код не различает «пустой ответ GPT», «нет ключа», «таймаут», «сеть»; сложная диагностика в production. |
| **Исправление** | Типизированные исключения (`OcrRecognitionError`, `OcrConfigurationError`); логирование через `logging.exception`; проброс или Result-объект с `error_code`. |

#### [A4] Нет таймаутов и повторных попыток к OpenAI API

| | |
|---|---|
| **Категория** | Архитектура |
| **Локация** | `core/ocr_gpt.py:136–158` — `client.chat.completions.create(...)` без `timeout` |
| **Влияние** | Зависшие coroutine в async-обработчиках бота/API; исчерпание пула воркеров при сбоях OpenAI. |
| **Исправление** | `httpx.Timeout` / `timeout=` в клиенте; retry с exponential backoff для 429/5xx; circuit breaker при деградации. |

#### [A5] Нарушение SRP — всё в одном модуле

| | |
|---|---|
| **Категория** | Архитектура |
| **Локация** | `core/ocr_gpt.py` целиком (~357 строк): клиент, промпт, парсер, фасад, cost, `__main__` |
| **Влияние** | Сложность сопровождения, ревью и тестирования; высокий порог для изменений промпта без затрагивания I/O. |
| **Исправление** | Разделить: `ocr_prompt.py`, `ocr_parser.py`, `gpt_vision_client.py`, `ocr_service.py` (фасад). |

## 8. Сильные стороны

1. **Чистая зависимость внутрь** — `ocr_gpt.py` не тянет bot/app обратно; циклических импортов нет.
2. **`parse_gpt_response`** — изолируемая pure-функция с понятной валидацией и **покрытием тестами** (`tests/test_recognition_pipeline.py`).
3. **Фасад `recognize_text_smart`** — удобная точка входа для двух каналов (бот и API).
4. **Промпт** детально описывает бизнес-правила (запятые в маркировке, запрет округления) — снижает типичные ошибки LLM.
5. **Веб-путь** (`commercial_workflow_service`) удаляет temp-файл в `finally` и опирается на `Settings` для режима OCR — образец для унификации бота.
6. Поддержка **нового и legacy** формата полей (`raw_name` / `name`) упрощает миграцию контракта.
