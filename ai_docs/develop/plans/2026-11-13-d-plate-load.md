## Overview

Экономист заводит карточку плиты в 1С и грузит тот же файл, что уже принимает кнопка «Загрузить выгрузку 1С». Сейчас файл `Плиты ПБ 13-2_6-8п.xlsx` разбирается и обрывается текстом «Плиты не загружаются в nomenclature_guid.» Запись идёт в `prays_plity`: имя и GUID, строка по GUID добавляется или обновляется, строки вне файла остаются. Один GUID на имя, совпавшее с открытым спросом, гасит строку «нет GUID 1С» уже существующим `sweep_guid_demand`. Два GUID на одно имя остаются двумя строками, и их показывает уже существующий список «Дубли GUID».

Окно `Import1cDialog`, список групп и кнопка на строке плиты не меняются. Группа остаётся «определить по имени файла». Новый эндпоинт не заводится.

Локально. `./run+logs.sh` не останавливать. Деплой не входит. Коммит только по просьбе.

## 1. Что проверено по коду

Чтение репозитория и файла из «Загрузок» 2026-11-13. Живую `pb.db` открывали только на чтение.

### C1. Где обрыв

`POST /api/v1/nomenclature/import-1c` (`app/api/v1/endpoints/nomenclature.py`) зовёт `NomenclatureImportService.import_file`. Для `.xlsx` вид решает `_resolve_xlsx_kind` (`app/services/nomenclature_import_service.py`). Имя файла с «плит» даёт `infer_product_kind` → `None` (`core/nomenclature_sync.py`). Имена строк с «плит» или `ПБ`/`ПК` и номером дают `infer_product_kind_from_names` → `"plate"`. Дальше исключение `_MSG_PLATES`. До записи и до каталога весов выполнение не доходит.

Явный `product_kind` из алиасов `plate` / `plates` / `plity` / `плита` / `плиты` падает там же, в `resolve_import_product_kind`, ещё до разбора. В выпадающем списке этих значений нет (`NOMENCLATURE_PRODUCT_KINDS` во `frontend/src/features/nomenclature/types/nomenclature.ts`). Пустой вид уходит на сервер как отсутствие поля (`nomenclatureApi.ts`).

`.xls` с «плит» в имени до этой фразы не доходит: `import_xls` зовёт `resolve_import_product_kind` до парсера и получает «Не удалось определить группу изделий по имени файла».

`sync_pricelist` плиты пропускает: `_coerce_kind` для алиаса плиты возвращает `None`, `_skipped_report` кладёт строки в `unmatched_1c` и в `nomenclature_guid` не пишет (`tests/test_nomenclature_sync.py`, `test_plates_unknown_kind_not_inserted`). Снимать исключение и отдавать плиты в `sync_pricelist` нельзя: отчёт будет пустым, карточки не появится.

### C3. Куда писать

`prays_plity` в `pb.db` — две колонки, без индекса и без уникальности:

```sql
"Уникальный идентификатор (Номенклатура)" TEXT
"Товар" TEXT
```

На 2026-11-13 в таблице 56 981 строка. Имена с «Плиты » — 56 979. GUID в нижнем регистре, без фигурных скобок, повторов GUID нет. Имени `Плиты ПБ 13-2,6-8п` и этого УИД в таблице нет. Рядом уже лежат карточки той же ширины (`Плиты ПБ 17-2,6-10п` и другие): префикс «Плиты » не отрезать.

Чтение карточки — `find_plate_card` (`core/kp_db_nomenclature.py`): точное имя, затем варианты, затем `LIKE`. Этот модуль остаётся чтением. Запись — новый `core/plate_card_import.py`.

### C4. Строка очереди гаснет тем же sweep

В `guid_demand` открыта ровно эта марка: `product_kind=plate`, `mark=Плиты ПБ 13-2,6-8п`, `field=guid_1c`, `reason=нет GUID 1С`. `sweep_guid_demand` (`core/guid_demand.py`) гоняет `check_invoice_guids`. Один GUID на точное имя даёт карточку, open-строка становится resolved. Два GUID на имя дают `PLATE_DUP`, поле спроса уходит в дубль. Список дублей плит уже собирается из `prays_plity` (`core/guid_queue.py`, `_plate_duplicate_tasks`). Отдельный писатель дублей не нужен.

Импорт уже коммитит, затем вызывает `sweep_guid_demand`, затем коммитит снова (`NomenclatureImportService._sync_and_commit`). Плиты идут тем же порядком на том же соединении `pb.db`, после вставки, чтобы sweep увидел новую строку.

`useImport1cMutation` после успеха сбрасывает ключ `nomenclature` (`useNomenclatureQueries.ts`). Список задач перечитывается. Кнопку файла на строку плиты не добавлять: тихий вход уже есть, строка уходит сама, когда имя совпало и GUID один.

### C5. Что остаётся у не-плит

Ветка `sync_pricelist` для `pile`, `bridge_pile`, `fbs`, `stair_flight`, `stair_step` не меняется. Явный вид из списка по-прежнему сильнее имени файла: выбранные «Сваи» и файл плит идут в сверку свай, как сейчас. `apply_universal_report_weights` плиты пропускает (только ФБС, марши, ступени). На ветке плит каталог весов не открывать.

Подпись группы в отчёте уже есть: `productKindLabel("plate")` → «Плиты».

## 2. Architecture Decisions

- **A1. Тот же вызов.** `POST /api/v1/nomenclature/import-1c`, тот же `Import1cResponse`. `product_kind` ответа — `"plate"`. Нового эндпоинта, новой таблицы и пункта «Плиты» в списке нет.
- **A2. Когда ветка плит.** Пустой вид и (имя файла содержит «плит» или все распознанные имена — плиты). Явный алиас плиты — тоже эта ветка. Явный вид из `PRODUCT_KINDS` эту ветку не включает. Смешанные имена без «плит» в имени файла по-прежнему 422 «Не удалось однозначно определить группу».
- **A3. Запись.** Один проход: прочитать существующие GUID в словарь по нижнему регистру, затем для каждой строки файла с непустым именем и GUID. GUID уже есть — обновить «Товар», если текст другой; текст тот же — строка без изменений. GUID нет — вставить. Повтор того же GUID в одном файле не плодит вторую строку, имя берётся последнее. Регистр и скобки GUID приводятся к виду парсера: нижний регистр, без `{}`.
- **A4. Чужие строки не трогать.** `DELETE` нет. `disappeared` в ответе всегда пустой, и для частичного `.xlsx` с «Отбор», и для полного `.xls`. `mode` по-прежнему `partial` только когда парсер увидел «Отбор»; `.xls` остаётся `full`. Ноль исчезнувших при полной выгрузке — ожидаемый отчёт, не повод чистить каталог.
- **A5. Два GUID на одно имя.** Обе строки остаются. Импорт не выбирает GUID и не кладёт их в `ambiguous`. Список «Дубли GUID» увидит их сам. Если на это имя висел спрос «нет GUID 1С», sweep переводит его в дубль, а не закрывает.
- **A6. Ответ.** `new_guids` — вставленные, `updated_guids` — сменившие имя, `unchanged` — тот же GUID и то же имя. `waiting_price`, `ambiguous_count`, `disappeared_count`, `unmatched_1c_count`, `weights_updated` — 0. Поле записи — `guid_1c`, марка — имя из файла как есть. Списки режутся уже существующим `IMPORT_1C_LIST_LIMIT`.
- **A7. Экран и сверка не-плит.** `Import1cDialog.tsx` не открывать. `sync_pricelist` плиты по-прежнему не пишет в `nomenclature_guid`. `test_plates_unknown_kind_not_inserted` остаётся зелёным без смены смысла. Текст `_KIND_HELP` в эндпоинте больше не обещает 422 на плиты: плиты пишутся в `prays_plity`; составные и смешанный ЛМ без параметра по-прежнему 422.

### PL-001: Запись карточек плиты по GUID

**Цель.** Есть функция, которая добавляет и обновляет строки `prays_plity` по GUID и не удаляет отсутствующие.

**Файлы:** `core/plate_card_import.py` (новый); `tests/test_plate_card_import.py` (новый). Два файла. `core/kp_db_nomenclature.py` не открывать.

**Как.** `apply_plate_cards(conn, rows) -> PlateCardReport`. Строка входа — имя и GUID (подойдут и `PricelistRow`, и `UniversalReportRow`: у обеих есть `name` и `guid`). `CREATE TABLE IF NOT EXISTS` с теми же двумя колонками, что в живой базе; на существующей таблице это пустая операция, колонки не добавлять. Словарь GUID читается одним `SELECT`. Сравнение GUID — по нижнему регистру без скобок. Запись в одной транзакции вызывающего: функция сама не коммитит.

**Приёмка:**

- [x] Новый GUID вставляет одну строку с именем файла как есть (`Плиты ПБ 13-2,6-8п`). Соседняя строка другого GUID остаётся.
- [x] Повтор того же GUID и того же имени не добавляет строку и попадает в `unchanged`. Другое имя того же GUID обновляет «Товар» и попадает в `updated`. Второй GUID на то же имя вставляет вторую строку; первая остаётся.
- [x] Пустой GUID или пустое имя пропускаются. В файле дважды один GUID — в таблице одна строка, имя последнее.

## Risks and Mitigations

| Риск | Impact | Mitigation |
|------|--------|------------|
| Полный `.xls` плит воспримут как замену каталога | High | A4: нет `DELETE`, `disappeared` всегда пустой. Тест PL-002 держит третью строку |
| Снятие исключения отдаст плиты в `sync_pricelist` | High | A2: отдельная ветка до `sync_pricelist`. Старый тест пропуска плит не менять |
| Поиск GUID по одной строке на каталоге в 57 тыс. | Med | Один `SELECT` в словарь, не запрос на строку |
| Имя без префикса «Плиты » не закроет спрос | High | A3: имя писать как в файле. Спрос в базе уже с префиксом |
| Выбранная в списке группа сваи молча запишется как плиты | Med | A2: явный вид из `PRODUCT_KINDS` сильнее имени файла |
| Правка окна «заодно» | Med | `Import1cDialog.tsx` не открывать. Сброс списка уже есть |

## Не делать

- **`nomenclature_guid` для плит.** Ветка плит туда не пишет. `sync_pricelist` по-прежнему пропускает плиты.
- **Замена `prays_plity`.** Строк вне файла не удалять. Индекс и новые колонки не добавлять.
- **Выбор среди двух GUID.** Импорт не пишет `plate_guid_choice` и не заполняет `ambiguous`.
- **Окно и кнопка на строке.** `Import1cDialog` не переписывать. Пункта «Плиты» в списке нет. На строке плиты кнопки файла нет.
- **Цена плиты и каталог весов.** Прайс завода, матрица `prices` и `apply_universal_report_weights` этой веткой не вызываются.
- **Живая 1С, деплой, коммит.** Карточка создаётся в 1С, к нам приходит файл. Коммит только по просьбе. `./run+logs.sh` не останавливать.
- **Заодно не делать:** новый эндпоинт, новый пакет, правка `core/kp_db_nomenclature.py`, `core/guid_demand.py`, `core/guid_queue.py`, `core/nomenclature_sync.py`.
