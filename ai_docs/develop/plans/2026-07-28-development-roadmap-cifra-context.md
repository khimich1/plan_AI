## Контекст CIFRA · ФЗ-140 · согласование с владельцем

**28.07.2026** · draft

---

# Главный вывод

> **Сначала** — выдача с СГП (наёмный перевозчик + самовывоз) и видимость для менеджера.  
> **Затем** — дашборд и обмен с 1С.  
> **Параллельно** — цены ПБ и целостность оптимизатора.  
> **ЭТрН** — продолжение отгрузок через 1С + ЭДО, не отдельный продукт.  
> **CIFRA** — ориентир по болям рынка, **не замена** «Шишов».

**СГП MVP уже работает.** Следующий шаг — замкнуть цикл «склад → клиент».

# 1. Что такое «Шишов»

**Внутренняя веб-система** завода ЖБ плит (ПБ).  
Цепочка: **КП → производство → СГП → (далее) выдача клиенту**.

| | |
|---|---|
| **Не** | SaaS, CRM для бетонных заводов, копия CIFRA |
| **Да** | Инструмент конкретного предприятия: раскладка плит, дорожки, учёт qty |

### Роли

| Роль | Задачи |
|------|--------|
| **Менеджер** | КП, архив, скидки, логистика в смете, перенос в производство |
| **Производство** | Планы, календарь, дорожки, документы смены, **СГП** |
| **Админ** | Полный доступ, сброс БД |

Канал — **React SPA** (веб). Telegram-бот в репозитории есть, но не целевой.

### Особенность завода

- На заводе **есть миксер** — бетон готовится **внутри** для формовки плит (производственный узел).
- Это **не** парк миксеров с доставкой товарного бетона на стройки (как в буклете CIFRA).
- **Собственного автопарка нет.** Вывоз плит: **наёмный перевозчик** или **самовывоз клиента**.

---

# 2. «Шишов» vs буклет CIFRA

| | **Шишов** | **CIFRA (буклет)** |
|---|-----------|---------------------|
| Продукт | ЖБ **плиты** (шт, марки) | Товарный **бетон** (м³, рейсы) |
| Производство | Оптимизатор 2D, дорожки | Слоты БСУ, АСУ ТП |
| Склад | **СГП** с qty-инвариантами | Не акцент |
| Логистика | logistics_cost, 2 сценария вывоза | GPS, диспетчеризация парка |
| ЭТрН | Планируется через 1С | «Из коробки» в их CRM |

**Что берём из идей CIFRA:** менеджер видит завод и склад, отгрузка/выдача, аналитика, единый контур данных, подготовка к ФЗ-140.

**Покупать CIFRA как замену — нецелесообразно.** Развиваем свою систему под те же бизнес-цели.

# 4. Что уже работает — и что нет

| Блок | Статус |
|------|--------|
| Wizard КП (OCR, PDF/XLSX, логистика) | ✅ |
| Архив (поиск, скидки, перенос в производство) | ✅ |
| Производство (планы, календарь, DayDrawer) | ✅ |
| Оптимизатор 2D, plate audit | ✅ |
| **СГП** (send, unlink/relink, close-from-SGP, XLSX) | ✅ **MVP** |
| Qty-инварианты, regression-тесты | ✅ |
| **Выдача / отгрузка** (списание с СГП, «выполнено») | ❌ **следующий шаг** |
| Готовность КП для менеджера (единый экран) | ❌ в работе |
| Обмен с 1С | ❌ greenfield |
| ЭТрН / ФЗ-140 | ❌ через 1С + ЭДО |

### Жизненный цикл КП сегодня

```
  КП сохранено ──▶ В производстве ──▶ На СГП ──▶  ???  ──▶ Выполнено
       │                  │               │         ↑          (зарезерв.)
       │                  │               │         │
       │            план · дорожки   остаток ещё    │
       │            частично         производится     │
       │                                              │
       └──────────────── «На СГП» ≠ «у клиента» ─────┘
                              ▲
                              └── главный разрыв: нет выдачи
```

**Ключевой принцип:** плиты на СГП — ещё не у клиента. Статус «выполнено» зарезервирован под **выдачу** — это и есть главный разрыв.

# 5. Контекст: ФЗ-140 и ЭТрН

**С 01.09.2026** перевозочные документы (в т.ч. **ЭТрН**) — в электронном виде через **ГИС ЭПД**.

| Сценарий | Что это значит для нас |
|----------|------------------------|
| **Наёмный перевозчик** | ЭТрН актуален — коммерческая перевозка плит |
| **Самовывоз клиента** | Завод фиксирует **выдачу**; ЭТрН часто через 1С/бухгалтерию |

**Подход:** не строим свой модуль ГИС ЭПД.

```
  «Шишов»          1С           Оператор ЭДО        ГИС ЭПД
 (отгрузка)  ──▶  (УПД)   ──▶  (ЭТрН)        ──▶  (реестр)
```

# 6. Куда движемся — целевой цикл

```
  КП ──▶ Производство ──▶ СГП ──▶ Выдача ──▶ У клиента
                                  │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
            Наёмный перевозчик            Самовывоз клиента
                    │                           │
                    └─────────────┬─────────────┘
                                  ▼
                         Списание с СГП
                         (частично или всё)
                                  │
                    ┌─────────────┴─────────────┐
                    ▼                           ▼
            Ещё остаток на СГП          Весь заказ у клиента
            (вернуться в цикл)                 (DONE)
```

**Цель:** один непрерывный контур от КП до «у клиента», с qty-инвариантами на каждом шаге.

# 7. Направления развития — карта

| Группа | Направления |
|--------|-------------|
| **Операционный контур** | **A** Готовность КП · **B** Выдача/отгрузка · **C** Дашборд |
| **Качество данных** | **D** Цены ПБ · **E** Оптимизатор · **F** Рез донора с СГП |
| **Интеграции** | **G** 1С · **H** ЭТрН через ЭДО |
| **UX и рост** | **I** Wizard менеджера · **J** Статус для клиента · **K** Onboarding |
| **Стратегия** | **L** Новые типы ЖБИ · **M** Мульти-завод |

### Кратко по направлениям

| ID | Направление | Суть | Зависимости |
|----|-------------|------|-------------|
| **A** | Готовность КП | Один экран в карточке КП — ответ клиенту без звонка в цех | Нет (read-only) |
| **B** | Выдача / отгрузка | Списание с СГП, два типа вывоза, акт, статус DONE | СГП MVP ✅ |
| **C** | Дашборд | Залежалые на СГП, загрузка планов, выдачи vs поступление | После B |
| **D** | Цены ПБ | Единый расчёт цены без silent fallback | Параллельно |
| **E** | Оптимизатор | Golden suite, жёстче блокировать lost_plates | Параллельно |
| **F** | Рез донора с СГП | Рез + донор с склада в плане | После стабильной B |
| **G** | 1С | Заказ · отгрузка → бухгалтерия · УПД | После B; нужно ТЗ |
| **H** | ЭТрН | Метаданные → 1С → ЭДО → ГИС ЭПД | B + G |
| **I** | UX wizard | 3 шага, side-by-side OCR | Независимо |
| **J** | Статус для клиента | Ссылка по токену — прогресс, PDF | После A |
| **K** | Onboarding | Guided tour, демо-данные | После I |
| **L, M** | ЖБИ · мульти-завод | Новые типы изделий, несколько заводов | После контура + 1С |

# 8. Приоритет B — выдача с СГП (следующий шаг)

**Закрывает главный разрыв:** «на СГП» ≠ «у клиента».

```
                         ┌─────────┐
                         │   СГП   │
                         └────┬────┘
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
           Наёмный перевозчик    Забирает клиент
           (перевозчик, адрес,    (кто забрал, акт)
            дата)                       │
                    │                   │
                    └─────────┬─────────┘
                              ▼
                 Выбор партий · qty · списание
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
            Статус КП · N/M      PDF/XLSX акт
                 · audit
```

| Тип | Поля | ЭТрН |
|-----|------|------|
| Наёмный | перевозчик, адрес, дата, позиции | стык с 1С/ЭДО |
| Самовывоз | кто забрал, дата, акт | часто через 1С |

---

# 9. Приоритет A — готовность КП (параллельно с B)

**Идея из CIFRA:** менеджер видит завод без звонка в цех.

Данные **уже есть** в системе: `completion_percentage`, `sgp_progress {n,m}`, позиции в планах.

```
┌─ КП №1847 ──────────────────────────────────────────────┐
│  ● КП ──● Производство ──● СГП ──○ Выдача ──○ Закрыто   │
│         72%                 14/20 на СГП                 │
├──────────────────────────────────────────────────────────┤
│  «14 шт на складе, 6 в производстве. Можно выдать 14.»  │
└──────────────────────────────────────────────────────────┘
```

Read-only агрегация — **не блокирует B**, можно делать параллельно.

# 10. Рекомендуемая последовательность

```
                    СГП MVP ✅
                         │
         ┌───────────────┼───────────────┐
         │               │               │
         ▼               ▼               ▼
    B Выдача        A Готовность    D Цены ПБ  ─┐
    / отгрузка         КП            E Оптимиз.  │ параллельно
         │               │                      │
         └───────┬───────┘                      │
                 ▼                              │
            C Дашборд                           │
                 │                              │
                 ▼                              │
            G ──▶ 1С                            │
                 │                              │
                 ▼                              │
            H ЭТрН                              │
                 │                              │
                 ▼                              │
         L, M — стратегия          F Рез донора ◀┘ (после B)
```

| Шаг | Направление | Зачем |
|-----|-------------|-------|
| **1** | **B — Выдача/отгрузка** | Без этого СГП — тупик; основа для 1С и ЭТрН |
| **2** | **A — Готовность КП** | Параллельно с B; быстрый win для менеджера |
| **3** | **C — Дашборд** | Когда есть выдачи и aging на СГП |
| **4** | **G — 1С** | Нужен факт отгрузки из B |
| **5** | **H — ЭТрН** | Через 1С+ЭДО; приоритет для наёмного сценария |
| **∥** | **D, E — цены и оптимизатор** | Параллельно; доверие к системе |
| **6** | **F — рез донора** | После стабильной B |
| **7** | **I → K — UX и onboarding** | Снижение порога входа |
| **8** | **J — статус клиента** | После A; опционально |
| **9** | **L, M — ЖБИ, мульти-завод** | После операционного контура и 1С |

# 11. Сознательно вне scope

| Из буклета / рынка | Почему не делаем |
|--------------------|------------------|
| CRM CIFRA / amoCRM / Битрикс | Внутренняя система завода |
| GPS, приложение водителя | Нет своего парка |
| Диспетчеризация миксеров на стройку | Бетон — сырьё для плит, не продукт |
| Слоты БСУ под м³ | Другой тип производства |
| Свой модуль ГИС ЭПД | Стандарт — 1С + ЭДО |

*Опционально позже:* учёт загрузки бетонного узла (миксер) в плане дня — если подтверждено как узкое место.

# 12. Вопросы для решения

1. Подтверждаем **два сценария вывоза** (наёмный / самовывоз)?
2. Примерная **доля** наёмный vs самовывоз (приоритет UI в B)?
3. Кто оформляет **акт/ТТН** и будет подписывать **ЭТрН**?
4. **1С:** кто даст ТЗ на обмен?
5. Нужен ли **учёт миксера** (бетон для формовки) в плане дня?
6. **J — статус для клиента** — нужен или достаточно панели A?
