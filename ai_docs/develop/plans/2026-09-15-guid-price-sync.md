# Implementation Plan: Контур синхронизации GUID и цен «программа ↔ 1С»

> **Идея (спека):** [`ai_docs/ideas/guid-price-sync-loop.md`](../../ideas/guid-price-sync-loop.md)
> **ТЗ:** [`docs/specs/1c-integration-tz-v2.md`](../../../docs/specs/1c-integration-tz-v2.md)
> **Дата:** 2026-09-15
> **Статус:** план на согласовании

## Overview

Каждое изделие прайса программы получает GUID 1С (мост для счетов и выпуска),
каждое изделие 1С без нашей цены — цену за штуку. Цена считается только в
программе; GUID — единственный мост; обмен с 1С — только файлами выгрузки
«Прайс-лист» (.xls). Excel-сводка превращается из разового отчёта в рабочую
очередь с пятью состояниями; машинное хранилище GUID — новая таблица
`nomenclature_guid` в pb.db для 5 не-плитных групп. Плиты не мигрируют
(`prays_plity` — уже рабочий мэппинг), им — только гигиенические правки.

Объёмы на 14.09.2026: ✅ 57 251 (не-плит 271) · ⚠️ дубли 58 (ждут бухгалтерию)
· 🏭 завести в 1С 224 · 💰 ввести цену ~98 · ⏸️ вне контура 232 · 🚫 материалы 2 323.

## Architecture Decisions

- **Пять состояний позиции**: ✅ готово / ⚠️ дубль (ждёт бухгалтерию) /
  🏭 завести в 1С / 💰 ввести цену / ⏸️ вне контура. Каждая загрузка выгрузки
  1С идемпотентно переводит позиции между состояниями.
- **`nomenclature_guid`**: `(product_kind, mark, guid_1c, guid_1c_u,
  match_status, match_note, updated_at)`, PK `(product_kind, mark)`.
  `match_status`: `auto | manual | ambiguous | missing`. Прайс-таблицы не
  трогаем (PK марка×класс — GUID дублировался бы по 5 строк).
- **«у»-сваи**: одна марка, одна цена, два GUID (`guid_1c` + `guid_1c_u`).
  Заводим в 1С только недостающее изделие, упреждающих пар нет (решение 15.09).
- **Цена «только в 1С»**: одна цена за штуку на изделие; для свай пишется
  одинаковой по всем классам бетона (решение 15.09). Авто-ступени между
  классами опровергнуты данными (шаг 79–599 руб).
- **Дубли разрешает только человек** — файл «Дубли GUID в 1С.xlsx» у
  бухгалтерии; выбранное заливаем со статусом `manual`. Автовыбора нет никогда.
  До ответа бухгалтерии дубли — ⚠️ «ждёт бухгалтерию», контур не блокируют.
- **GUID возвращается только файлом**: производство заводит карточку →
  выгрузка «Прайс-лист» → загрузка в программу → сверка → GUID сам.
  Ручного ввода GUID нет.
- **Паттерны загрузки файла**: endpoint — как
  `app/api/v1/endpoints/delivery_schedule.py /import`, диалог — как
  `frontend/src/features/delivery-schedule/components/ImportScheduleDialog.tsx`.
