# План: серверные контрагенты как локальные

**Дата:** 2026-10-30  
**Статус:** PLAN, на ревью. На сервер ничего не выкладывалось.  
**Спека:** [`ai_docs/specs/server-kontragent-kak-lokal.md`](../../specs/server-kontragent-kak-lokal.md)  
**Не это:** образ бэкенда, широкая плита, коммит `7d0c9b7`, тестовые контрагенты 4406–4414, журнал `supply_contract_event`, копирование всей `plita.db`.

## Подход

Справочник 1С уже совпадает по живым клиентам. Расходится код мастера КП и реестр договоров. Код выкладывается первым: пока на сервере старый `archive_service.py`, отправка сама вызывает `link_unique_inn_contracts` и может привязать договор до того, как реестр дописан.

Образ бэкенда не собираем. Два Python-файла копируются в работающий контейнер и на диск `/opt/plan_zavod`, затем контейнер перезапускается. Перезапуск сохраняет `price_desk_service.py` от 29 октября. Фронтенд собирается из исходников на диске сервера после замены трёх tsx. Серверный `frontend/nginx.docker.conf` с лимитом 50 МБ не подменяется: его забирает `frontend/Dockerfile`.

Реестр правится одной транзакцией с `foreign_keys=ON`. Id строк не переносятся. Существующие номера сервера не переименовываются. Совпадение номера — первая тройка целых «число/число/число».

Порядок внутри транзакции:

1. Удалить события пяти удаляемых договоров, затем сами строки: `0788/01/25`, `0793/02/25`, `0794/02/25`, `0807/03/25`, `0853/07/25`.
2. Поставить `0002/10/26` статус «отмена не будем работать». Реквизиты этой строки не трогать. Это освобождает индекс для клиента 403 до вставки `752/09/24`.
3. На 170 общих номерах с пустым `counterparty_id` записать локального клиента. `0998/07/26` и `0787/01/25` не обновлять: клиент уже тот же, реквизиты заполнены.
4. Вставить 211 локальных номеров по именам колонок: номер как в локальной базе, `counterparty_id`, ИНН, `imported_name`, статус «нет», `created_by_user_id` = 1. Среди них `752/09/24`, `459/02/23`, `651/03/24`.

Ожидаемый итог: 391 строка. `counterparties` остаётся 4405. `KP_offers` не меняется.

## Порядок

Только последовательно. Параллельно можно лишь положить три tsx и два py после снимка базы: сборка фронтенда и перезапуск бэкенда ждут свои файлы, транзакция ждёт новый код.

1. Локально `.venv/bin/pytest tests/test_kp_invoice_existing_contract.py -q`. Снимок локальной базы через `sqlite3.backup` в отдельный файл. В снимке 383 договора, у id 403 номер `752/09/24`, у id 3379 номер `651/03/24`.
2. На сервере `.backup` в `/data/plita.db.bak-before-contract-sync-20261030`. Записать число строк `KP_offers` и `counterparties`.
3. Скопировать пять файлов. Три tsx — в исходники фронтенда на диске. Два py — и на диск `/opt/plan_zavod/app/...`, и в контейнер `/app/app/...`.
4. Собрать и поднять только фронтенд: `docker compose -f docker-compose.split.yml build frontend`, затем `up -d --no-deps frontend`.
5. `docker restart plan_zavod-backend-1`. Не `build backend` и не `up` с пересозданием бэкенда.
6. Контрольная точка кода. Поиск МД-СТРОЙ, отсутствие `link_unique_inn_contracts` в контейнерном `archive_service.py`, наличие `import_pile_prices_from_xlsx`, health 200, `client_max_body_size 50m`.
7. Транзакция реестра из снимка шага 1.
8. Контрольная точка данных по критериям спеки.

## Риски

| Риск | Как снижаем |
|---|---|
| Вставка `752/09/24` раньше отмены `0002/10/26` упирается в `idx_supply_contract_one_active` | Отмена стоит вторым шагом транзакции, вставка — последним. При ошибке транзакция откатывается. |
| Копия `plita.db` без WAL теряет 160 договоров от 15:32 | Только `Connection.backup`. Перед транзакцией в снимке проверяется число 383. |
| Сборка фронтенда затирает лимит 50 МБ | Не копируем `nginx.docker.conf`. После сборки читаем лимит в контейнере. |
| Пересоздание бэкенда стирает прайс свай | Образ не собираем, контейнер не создаём заново. После restart функция импорта на месте. Копия `price_desk_service.py` на диске сервера остаётся запасной. |
| Удаление пяти договоров при живых событиях ломает внешний ключ | Сначала события этих пяти id, потом строки. Ключи включены. |
| Два текста одного номера дают вторую строку | Вставка только для тройки, которой на сервере ещё нет. Текст уже лежащего номера не меняем. |
| Старый код привязывает договоры, пока идёт перенос | Реестр пишется после restart бэкенда с новым `archive_service.py`. |

## Контрольные точки
