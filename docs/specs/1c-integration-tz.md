## Интеграция «1С:Комплексная автоматизация» ↔ приложение расчёта КП (завод ЖБИ)

**Версия:** 1.0  
**Дата:** 13.07.2026  
**Заказчик:** [наименование организации]  
**Исполнитель:** [1С-франчайзи / интегратор]

---

## 1. Цель

Связать учётную систему **1С:Комплексная автоматизация** с внутренним веб-приложением для формирования коммерческих предложений (КП) на железобетонные плиты:

- получать из 1С справочные данные и привязки к документам КП;
- передавать в 1С рассчитанное КП для обновления документа **«Коммерческое предложение»**.

Обмен — через **JSON-файлы** в общей папке (без HTTP API на первом этапе).

---

## 2. Состав работ

### 2.1. Выгрузка из 1С (фоновый регламент)

**Источник:** 1С:КА → **Приёмник:** папка обмена приложения.

Периодическая выгрузка (интервал согласовать, ориентир — 5–15 мин) JSON со строками:

| Поле | Описание |
|------|----------|
| `Номенклатура` | Наименование позиции |
| `УИД` | Уникальный идентификатор номенклатуры (GUID) |
| `Контрагент` | Наименование |
| `ИНН`, `КПП` | Реквизиты контрагента |
| `НомерКП` | Номер документа КП в 1С |
| `УИДКП` | Уникальный идентификатор документа КП (GUID) |

Формат: UTF-8, одна выгрузка — один файл с массивом записей. Имя файла — с меткой времени. Обработанные файлы перемещать в `archive/` или помечать иначе, чтобы не читать повторно.

### 2.2. Загрузка в 1С (по событию)

**Источник:** JSON из приложения → **Приёмник:** документ **«Коммерческое предложение»** в 1С:КА.

Триггер: появление файла в папке `import/` (имя и схема — по согласованию).

Минимальный состав данных в файле:

- идентификация КП: `УИДКП` (если есть) и/или `НомерКП`;
- контрагент: наименование, ИНН, КПП;
- шапка: дата, менеджер, скидка %, условия оплаты/доставки, срок исполнения, логистика;
- табличная часть: позиции с `УИД` номенклатуры (или наименованием), количество, цена, сумма.

**Поведение:** найти документ КП по `УИДКП` / `НомерКП` и **обновить** (не создавать дубликат). При ошибке — файл в `error/`, запись в журнал 1С.

---

## 3. Требования к стороне приложения (зона заказчика)

Заказчик обеспечивает:

- общую сетевую папку, доступную серверу 1С и серверу приложения;
- чтение выгрузки 1С и сопоставление `УИД` с номенклатурой в `pb.db` (`prays_plity`);
- формирование JSON при сохранении КП (поля — п. 2.2);
- хранение связки `kp_id` приложения ↔ `УИДКП` / `НомерКП`.

Со стороны приложения уже есть: клиент (`customer_name`), менеджер, позиции плит (`order_data`), `nomenclature_id`, суммы, условия. **ИНН/КПП клиента** — добавить в форму КП при внедрении интеграции.

---

## 4. Нефункциональные требования

- Кодировка JSON: UTF-8.
- Идемпотентность: повторная загрузка того же файла не дублирует строки документа.
- Логирование успехов и ошибок с указанием имени файла.
- Права на папки обмена — только учётные записи 1С и приложения.

---

## 5. Приёмка

1. Выгрузка из 1С появляется в папке, приложение читает и сопоставляет номенклатуру.
2. После расчёта КП в приложении в 1С обновляется соответствующий документ «Коммерческое предложение» (контрагент, строки, суммы).
3. Ошибочный файл (битый JSON, не найден КП) — в `error/`, без «тихого» пропуска.
4. Демонстрация на тестовой базе 1С:КА с не менее чем 3 позициями и 2 контрагентами.
