# ✅ Готово: Сохранение КП в базу данных

## Что сделано

Добавлена возможность сохранять коммерческие предложения в базу данных `plita.db` с указанием сроков выполнения.

## Изменённые и новые файлы

### 📝 Новые файлы:
1. **`core/kp_db.py`** — модуль для работы с БД (405 строк)
   - Создание таблиц
   - Сохранение КП
   - Получение КП по номеру
   - Получение всех КП по статусу
   - Обновление статуса
   - Сохранение/извлечение файлов XLSX

2. **`plita.db`** — база данных SQLite (создаётся автоматически)
   - Таблица `KP_offers` — основная информация о КП
   - Таблица `kp_plates` — плиты в каждом КП
   - Таблица `kp_files` — файлы XLSX
   - Таблица `kp_meta` — метаданные (статус)

3. **`test_kp_db.py`** — тестовый скрипт для проверки работы БД

4. **Документация:**
   - `СОХРАНЕНИЕ_КП_В_БД.md` — подробная документация (200+ строк)
   - `КАК_ИСПОЛЬЗОВАТЬ_СОХРАНЕНИЕ_КП.md` — быстрый старт
   - `ИЗМЕНЕНИЯ_СОХРАНЕНИЕ_КП.md` — этот файл

### 🔧 Изменённые файлы:
1. **`bot/states.py`**
   - Добавлено состояние `waiting_execution_terms` для ввода сроков

2. **`bot/keyboards.py`**
   - Добавлена функция `save_to_db_kb()` для клавиатуры с кнопками "Сохранить" / "Не сохранять"

3. **`bot/handlers/commercial.py`**
   - Добавлен импорт модуля `kp_db`
   - Изменена функция `generate_all_documents()` — теперь предлагает сохранить КП в БД
   - Добавлены 3 новых обработчика:
     - `callback_save_kp_to_db()` — обработчик кнопки "Сохранить в БД"
     - `receive_execution_terms()` — обработчик ввода сроков
     - `callback_skip_save_kp()` — обработчик кнопки "Не сохранять"

4. **`core/__init__.py`**
   - Добавлен импорт модуля `kp_db`

## Структура базы данных

### Таблица `KP_offers` (основная):
```sql
kp_id               — порядковый номер (автоматически)
creation_date       — дата создания КП
customer_name       — имя клиента
manager_name        — имя менеджера
discount_percent    — процент скидки (0-100)
subtotal            — сумма без НДС
vat_amount          — сумма НДС (20%)
total_amount        — общая сумма с НДС
delivery_conditions — условия поставки
payment_conditions  — условия оплаты
execution_terms     — сроки выполнения (то, что вводит пользователь)
```

### Таблица `kp_plates` (плиты):
```sql
kp_id              — связь с KP_offers
position_number    — номер позиции в КП (1, 2, 3...)
plate_name         — название плиты (например: "ПБ 78-12-8п")
length_m           — длина в метрах
width_m            — ширина в метрах
load_class         — класс нагрузки (800, 1000 и т.д.)
qty                — количество штук
unit_weight        — вес одной плиты в кг
total_weight       — общий вес позиции
discounted_price   — цена за единицу (со скидкой)
```

### Таблица `kp_files` (файлы):
```sql
kp_id      — связь с KP_offers
xlsx_file  — сам файл XLSX (хранится как BLOB — двоичные данные)
file_path  — путь к файлу на диске
```

### Таблица `kp_meta` (метаданные):
```sql
kp_id   — связь с KP_offers
status  — статус КП:
          • "в работе" (по умолчанию)
          • "выполнено"
          • "отклонено"
          • "в ожидании"
```

## Как это работает в боте

### Старый процесс (ДО изменений):
1. Создание КП → Отправка файлов → Конец

### Новый процесс (ПОСЛЕ изменений):
1. Создание КП
2. Отправка файлов
3. **Предложение сохранить в БД** ← НОВОЕ
4. Если "Сохранить":
   - Ввод сроков выполнения
   - Сохранение в БД
   - Подтверждение с номером КП
5. Если "Не сохранять":
   - Возврат в главное меню

## Что можно делать с сохранёнными КП

### Через код (Python):
```python
from core import kp_db

# Получить КП по номеру
kp = kp_db.get_kp_by_id(1)

# Все КП в работе
all_kp = kp_db.get_all_kp_by_status('в работе')

# Обновить статус
kp_db.update_kp_status(1, 'выполнено')

# Получить файл XLSX
xlsx_data = kp_db.get_xlsx_file(1)
```

### Через SQL:
```bash
# Просмотр всех КП
sqlite3 plita.db "SELECT * FROM KP_offers;"

# КП в работе
sqlite3 plita.db "SELECT * FROM KP_offers 
JOIN kp_meta ON KP_offers.kp_id = kp_meta.kp_id 
WHERE status='в работе';"

# Сумма всех КП за день
sqlite3 plita.db "SELECT SUM(total_amount) FROM KP_offers 
WHERE creation_date='19.12.2025';"
```

## Устранение проблем

### Бот не предлагает сохранить КП
- Перезапустите бота: `./stop_bot.sh && ./start_bot.sh`
- Проверьте логи: `tail -f logs/bot_*.log`

### Ошибка "ModuleNotFoundError: No module named 'kp_db'"
- Убедитесь, что файл `core/kp_db.py` существует
- Проверьте `core/__init__.py` — там должен быть импорт `kp_db`

### База данных не создаётся
- Проверьте права на запись: `ls -la plita.db`
- Попробуйте создать вручную: `python3 -c "from core.kp_db import init_schema; init_schema()"`

### Ошибка при сохранении файла XLSX
- Файл должен существовать на момент сохранения
- Если файла нет, сохранится только путь (это нормально)
